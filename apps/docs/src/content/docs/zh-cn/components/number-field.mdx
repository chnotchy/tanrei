当产品要把一个数字当作数字来读取时，使用数字字段：数量、尺寸、百分比、金额。用户按所在区域设置的写法键入它，或者用方向键、字段末尾的两个按钮来步进。这个字段的绘制方式和尺寸，与相同变体、相同尺寸的文本字段一致。

**组成部分**是一个[字段](/zh-cn/components/field/)和一个[数字输入框](/zh-cn/components/number-input/)。字段是框架：标签、必填或选填标记、帮助文本和错误。数字输入框是控件：方框、数字、它的单位和两个步进按钮。数字字段自己什么都不绘制，也没有令牌：它的每个属性都是这两者之一的属性，原样交给它们。

数字字段已经是一个字段：它绝不放进[字段](/zh-cn/components/field/)里。标签在别处的地方——滑块旁边、表格的单元格里——单独使用[数字输入框](/zh-cn/components/number-input/)。

它是一个块，放在哪里就和那里一样宽，它的方框会把它填满。它没有自己的宽度：想要窄一些的字段，就把它放进窄一些的地方。

在 Web 上它是 `<tanrei-number-field>`。其他平台尚未实现。

### 用法

`value` 是一个数字；字段里没有数字时是 `null`。它在用户**确认**时改变——焦点离开字段、按下 Enter，或者步进——而不是每按一次键就改变。用户键入期间，文本归用户所有：不拒绝任何内容，不改写格式，不限制到范围之内，也不取整。这期间文本读作什么数字，由 `input` 带出。

### 下一层

用它的两个成员手写出来的同一个字段，画面是一样的，对辅助技术来说也是同一个微调按钮（spin button），名称、描述和状态都相同：

需要数字字段没有提供的排布方式时，就往下走一层：

| 你需要 | 使用 |
| --- | --- |
| 标签、方框、帮助文本和错误 | 数字字段 |
| 在框架里面、方框的旁边或下方放你自己的东西 | 一个[字段](/zh-cn/components/field/)，里面放一个[数字输入框](/zh-cn/components/number-input/)和你自己的元素 |
| 只要方框，放在位于别处的标签之下：滑块旁边、表格的单元格、工具栏 | 单独的[数字输入框](/zh-cn/components/number-input/)，由它自己的 `label` 命名 |

到了下一层，变的是各样东西写在哪里。`name`、`value`、范围和单位写在数字输入框上，这时它就是表单遇到的那个控件，它的事件也在它上面监听。`label`、`error`、`disabled` 和必填与否仍然写在字段上，由字段传给控件：不要设置输入框自己的那几个。数字字段做的事，没有一件是手写的字段和数字输入框做不到的。

### 字段

| 部件 | 它是什么 |
| --- | --- |
| 标签 | 属于字段：位于容器上方（`stacked`）。在 `filled` 和 `outlined` 中由数字输入框绘制，浮在方框里面，字段不绘制标签行。它就是无障碍名称，无论它是画出来的，还是用 `labelHidden` 隐藏的 |
| 必填和选填标记 | 属于字段，位于标签之后：`requirement="required"` 时是“必填”小标签、星号，或者什么都不画；`optional` 时是“选填”小标签。浮动标签带的是星号 |
| 输入框 | 属于数字输入框：以文本形式呈现的数字。编辑期间是用户键入的内容；其余时候是已确认的数字，按区域设置的写法显示。只有一行，放不下时滚动 |
| 前缀、后缀 | 属于数字输入框：数字前后的固定文本，例如货币符号或单位。它们属于方框，绝不属于值 |
| 步进按钮 | 属于数字输入框：末尾的两个按钮，第一个减小，第二个增大。把 `steppers` 设为 false 就不绘制它们 |
| 辅助文本 | 属于字段：一行帮助文本。字段处于错误状态时，错误文本取代它的位置（设计系统两者都保留时，绘制在它的下方）：`error` 为 true 时是 `errorText`，文本不是数字时是 `invalidText`。无论有没有步进按钮，它都从方框的文本内边距处开始，到那里结束 |

三种变体，以及 `small`（40）、`medium`（48）和 `large`（56）三种尺寸，都是文本字段的。默认系统只提供 `stacked`。

数字字段没有自己的令牌。它的方框读取[数字输入框的令牌](/zh-cn/components/number-input/#规格)，它的各行读取[字段的令牌](/zh-cn/components/field/#规格)，两个步进按钮读取[按钮的令牌](/zh-cn/components/button/#规格)，无论这些令牌设置在哪里。要改动某一个实例，就在它上面设置成员的令牌：`style="--tanrei-comp-field-label-gap: 0.75rem"`。

两个步进按钮是并排的 medium 尺寸 text 按钮。在默认系统下，它们占去字段宽度中的 88，每一个都是完整的触摸目标。它们绝不会画得更小，也绝不上下叠放：一行里容不下它们时，就把它们关掉。按键仍然可以步进。

### 值和文本

| 何时 | 发生什么 |
| --- | --- |
| 用户键入、粘贴或听写 | 什么都不改。`input` 带出文本读作的数字，或者 `null` |
| 焦点离开，或者按下 Enter | 文本被确认：低于 `min` 时提高到 `min`，高于 `max` 时降低到 `max`，按 `maxFractionDigits` 取整，成为值，并按区域设置的写法写回。值有变化时触发 `change` |
| 文本为空 | 值变为 `null` |
| 文本不是数字 | 文本保留。值变为 `null`，字段进入错误状态并显示 `invalidText`——没有 `invalidText` 时显示它的 `errorText`——同时触发 `entryerror` |
| 产品设置 `value` | 无论之前键入了什么，都显示这个数字。不触发任何事件，这个数字也不会按 `min` 和 `max` 修正 |

已确认的数字用区域设置的数字和小数分隔符书写，小数位数在 `minFractionDigits` 和 `maxFractionDigits` 之间，不带分组分隔符——这样显示出来的内容可以原样再键入一遍。

文本按字段的 `locale` 宽松地解读；`locale` 为空时，按页面的语言解读：

- 数字两侧和数字内部的空格会被忽略。
- 数字之前的连字符减号、减号或加号是正负号。
- ASCII 数字、区域设置自己的数字和全角数字都算数字。
- 数字之间的区域设置分组分隔符会被忽略：在英语中，`1,234.50` 读作 1234.5。
- 键入或粘贴进来的前缀和后缀会被忽略：`12 px` 读作 12。
- 字母、指数、两个分隔符，或者单独一个正负号，都不是数字。

字段绝不在两种区域设置之间猜测。在以逗号为小数分隔符的德语中，`1.500` 读作 1500，`1.5` 读作 15。

数字和它的单位是连成一体书写的。前缀写在数字之前，后缀写在数字之后，方向按单位自身所用文字的书写方向，与页面的方向无关。所以“44 px”“$ 120 USD”和“40 %”在阿拉伯语或希伯来语的页面里，读起来与在英语页面里一样；用阿拉伯字母或希伯来字母写的单位，则位于数字的左侧。步进按钮和标签跟随页面。`align="end"` 让数字紧靠它的单位：单位用拉丁字母或符号书写时，在两种方向下都靠右。要让拉丁字母的货币代码位于数字的左侧，就让后缀以一个从右到左标记（U+200F）开头。

### 步进

| 输入 | 发生什么 |
| --- | --- |
| 上方向键、下方向键 | 按 `step` 步进 |
| Page Up、Page Down | 按 `step` 的十倍步进 |
| 按下步进按钮 | 步进一次。按住不放时会重复：半秒之后开始，先是每秒十次，然后每秒二十次 |
| Home、End、左方向键、右方向键 | 在文本中移动插入点 |
| 滚轮、拖动 | 什么都不发生。页面照常滚动 |

一次步进会走到步长网格上的下一个数字，网格从 `min` 算起（没有 `min` 时从零算起）：步长为 5 时，12 向上步进到 15，向下步进到 10。它按十进制计算，所以 0.2 步进 0.1 得到 0.3。空的字段会步进到范围允许的、离零最近的数字。

`step` 说明一步走多远。它不限制可以键入什么：步长为 5 时，键入的 12 仍然是 12。只接受某些数字时，请校验值并设置 `error`。

### Web 上绘制方式的不同之处

- 这个元素的 shadow root 里有一个 `<tanrei-field>`，其中放着一个 `<tanrei-number-input>`。导入数字字段，两者也随之完成定义。
- 数字字段是与表单关联的元素，也是它的表单遇到的唯一控件。它接受 `name`，无论区域设置显示成什么样，都以普通的十进制数字（`12.5`）提交它的值。重置时回到 `value` 属性（attribute）的值；在 `requirement="required"` 且没有数字时报告缺少值，在文本不是数字时报告输入有误。
- 它是一个块，和它所在的地方一样宽。在不给宽度的地方，长标签会让它比自己的方框更宽：这时请给它一个宽度。
- 部件就是成员的部件，沿用它们自己的名称：来自字段的 `label`、`label-icon`、`requirement-label` 和 `supporting-text`；来自数字输入框的 `container`、`outline`、`active-indicator`、`input`、`prefix`、`suffix` 和 `stepper`。`label` 和 `requirement-label` 指向两者中画出来的那一个；`field-label` 和 `number-input-label` 只指向其中一个。两个成员本身是部件 `field` 和 `number-input`。
- `entryerror` 的 `detail.text` 是输入框的 `invalidText`，没有提供时为空。detail 的类型是数字输入框的：`TanreiNumberInputInputDetail` 和 `TanreiNumberInputEntryErrorDetail`。
- `steppers` 对应含义相反的属性（attribute）`no-steppers`，`readOnly` 对应 `readonly`。
- `input` 是带有 `detail.value` 的 CustomEvent。`change` 和 `action` 是普通事件：从元素上读取 `value`。除非 `action` 被取消，否则随后会请求表单提交。
- 没有 `locale` 时，字段读取最近的 `lang` 属性（attribute），其次是浏览器的语言。
- 除了区域设置的分隔符之外，只要该区域设置不用句点分组，句点也读作小数分隔符。
- 翻页键在它自己的十步网格上步进：步长为 2 时，从 42 按 Page Up 得到 60。
- 在 iOS 和 iPadOS 上，可以键入负数时，字段会请求完整键盘，因为那里的小数键盘没有减号。
- 在元素定义之前，它没有尺寸。请预留高度。

## 指南

### 数字字段、文本字段还是滑块

| 方面 | 数字字段 | 文本字段 | 滑块 |
| --- | --- | --- | --- |
| 里面是什么 | 一个数字 | 任意文本 | 某个范围内的一个数字 |
| 选择方式 | 键入或步进 | 键入 | 拖动 |
| 适合 | 已经知道的值 | 不是数量的数字串 | 凭感觉选出的值 |

邮政编码、卡号、电话号码和一次性验证码都由数字组成，但不是数量：没有人会给邮政编码加一。它们请使用[文本字段](/zh-cn/components/text-field/)。

### 推荐

- 写一个标签，说明计数的是什么，并让它在表单中保持可见。
- 把单位放进 `suffixText`，把货币符号放进 `prefixText`。
- 后缀读出来不合适时，提供 `valueText`：`×` 用“1.5 倍”。
- 编写 `invalidText` 时要说明该键入什么：“请输入数字。”
- 整数把 `maxFractionDigits` 设为 0。这样键盘上就没有分隔符。
- 给出 `incrementLabel` 和 `decrementLabel`：写在字段上，或者用 `setWords()` 为整个产品只给一次。Tanrei 不自带任何文字：没有名称的步进按钮仍然会绘制，用指针按下时仍然步进，但不提供给辅助技术，因为在那里微调按钮自己就能步进。

### 避免

- 不要把数字字段用于不是数量的数字串。
- 不要在 `input` 时保存。每按一次键它都会触发；`change` 才带有已确认的值。
- 不要指望 `min` 和 `max` 修正你自己设置的值。它们作用于用户确认的内容。
- 不要把选择单位的控件放进字段里面。在旁边放一个[下拉选择框](/zh-cn/components/select/)。
- 不要把数字字段放进字段。它已经是一个字段；字段框住的控件是[数字输入框](/zh-cn/components/number-input/)。
- 不要为了把方框放在你自己的标签下面而隐藏数字字段的标签。请使用数字输入框。

### 组件负责的部分

- 输入框是一个微调按钮（spin button）。它的名称是 `label`，无论是画出来的还是隐藏的，绝不是占位符。
- 它的值是已确认的数字，它的范围是 `min` 和 `max`。
- 显示出来的辅助文本或错误文本是它的描述；字段为选填时，还会加上 `optionalText`。
- `error` 为 true 或文本不是数字时，它暴露为无效；`requirement` 为 `required` 时，暴露为必填；只读时，暴露为只读。
- 字段获得焦点期间出现的错误，会以礼貌（polite）的方式朗读一次——文本不是数字时也一样。
- 步进按钮是由 `decrementLabel` 和 `incrementLabel` 命名的按钮；没有人命名的那一个对辅助技术隐藏。它们不在焦点顺序中，因为方向键在输入框里就能步进；通过触摸浏览的用户仍然能找到它们。
- 按下步进按钮不会移动焦点，所以不会唤起屏幕键盘。
- 输入法正在组合输入时，字段不解读任何内容，也不处理任何按键。
- 滚轮绝不会改变数字。
- 字段的点击区域满足最小目标，每个步进按钮都是完整的目标。
- 文本放大到 200% 时，标签和帮助文本会换行。数字保持在一行里，并且可以滚动。
- 在强制颜色模式下，字段会多出一道边线，错误靠文字和无效状态来表达。
- 在从右到左的布局中，步进按钮和标签会镜像：步进按钮位于左端。数字和它的单位按单位自身所用文字的写法书写：用拉丁字母或符号写的单位位于数字之后，从左到右书写；用页面的文字写的单位位于数字的左侧。朗读的内容不变。

Web 上的已知差距：

- Chromium 读出数字时不带单位：它从输入框里的文本取得值文本，而略过字段指定的那一个。单位重要时，请在标签里写明。
- 文本放大到 200%、窗口宽度为 320 时，带有步进按钮、前缀和较长后缀的字段会比窗口还宽，因为它绝不会比自己容纳的内容更窄。这时请关掉步进按钮。
- 在元素定义之前，什么都不绘制。

### 需要你做的事

- 为每个数字字段提供 `label`。
- 在字段上编写 `invalidText`。`requiredText`、`optionalText`、`incrementLabel` 和 `decrementLabel` 可以写在字段上，也可以用 `setWords()` 为整个产品只给一次。Tanrei 不自带任何文字；缺少的文字会在开发时报告。参见[产品的文字](/zh-cn/foundations/words/)。
- 自己校验值，设置 `error`，并编写说明如何改正这个数字的 `errorText`。
- 给滑块和它旁边的数字输入框相同的名称。
