提示块是页面流中的一条通知：你把它放在哪里，它就待在哪里，宽度与所在位置相同，内容在多久它就在多久。它默认是一条说明，像它前面的段落一样在原地朗读，从不获得焦点。

在 Web 上它是 `<tanrei-callout>`。其他平台尚未实现。

### 用法

正文就是元素自己的内容。标题用 `headline` 属性给出；如果标题是你自己的内容或者是一个标题元素，就放进 `title` 插槽。图标集里的字形放进 `icon` 插槽，你自己的按钮或链接放进 `actions` 插槽。

## 指南

### 消息条、提示块、对话框

这三者只需区分一次，依据是它们位于哪里、停留多久：

| 组件 | 它是什么 | 位于哪里 | 停留多久 | 是否朗读 |
| --- | --- | --- | --- | --- |
| [消息条（Snackbar）](../snackbar/) | 应用刚刚做完的事或刚刚发生的事的结果。 | 在内容之上，窗口的边缘。 | 很短，或者直到被关闭。 | 总是。 |
| 提示块 | 属于内容一部分的通知。 | 在页面流中，你放置它的地方。 | 内容在多久，它就在多久。 | 只在它为回应某件事而出现时（`live`）。 |
| [对话框](../dialog/) | 用户必须先回答才能继续的问题。 | 在一切之上，带遮罩。 | 直到得到回答。 | 通过获得焦点。 |

**横幅**——针对整个页面或屏幕、位于其内容上方的通知——并不是第四种东西。它就是一个放在该区域内容上方的提示块，通常带 `live`，通常带一个操作或关闭按钮。请把它放在所涉及区域的阅读顺序的最前面。

某个字段下方的消息（这个值不是日期）也不是提示块：它是这个字段自己的辅助文本。

### 如何选择外观

| `variant` | 绘制什么 | 用于 |
| --- | --- | --- |
| `tonal`（默认） | 柔和的填充。 | 大多数提示块。 |
| `outlined` | 没有填充，只有一道细线。 | 位于着色表面上或有填充的卡片里的提示块（填充在那里会看不出来），以及许多提示块挨在一起的地方。 |

在每种语义状态下，这道细线都是系统唯一的那道细线。语义状态从不给它上色。

### 语义状态

`status` 为 `default`、`info`、`warning`、`error` 或 `success`：这些名称也是消息条和 Tag 使用的名称，在整个系统里含义相同。语义状态绘制它的颜色和字形（`info`、`warning`、`error`、`check_circle`），并决定带 `live` 的提示块如何朗读。除此之外它不改变任何东西。

| 你要写的是 | 使用 |
| --- | --- |
| 说明：值得知道的事 | `status="info"` |
| 注意：需要留心的事 | `status="warning"` |
| 危险：会出问题的事 | `status="error"` |
| 小贴士：读者可以采纳的建议 | `status="default"`，在 `icon` 插槽里放字形 `lightbulb`，标题写“小贴士” |

小贴士不是成功：没有什么事成功了。`icon` 插槽接受图标集里的任何字形，有没有语义状态都可以，所以“实验性”和“此版本新增”也不需要新的取值。那个词写在标题里。

### 尺寸

| `size` | 标题 | 正文 | 用于 |
| --- | --- | --- | --- |
| `medium`（默认） | 14，行高 20 | 14，行高 22 | 控件之间的提示块：表单、面板、对话框。 |
| `large` | 16，行高 24 | 16，行高 26 | 以文字为主的页面里的提示块。 |

这就是长文排版的两种尺寸。变化的只有文本样式：内边距、字形和关闭按钮都相同。

### 标题

`headline` 是纯文本，从不是标题元素。大多数提示块的标题只是一条说明的标签；如果页面大纲里列出五次“说明”，页面反而更差。如果提示块开启了页面上用户会导航前往的一个部分，请在 `title` 插槽里放一个级别符合大纲需要的标题元素。提示块会像绘制任何标题一样绘制它，既不改变它的角色，也不改变它的级别。

在服务端渲染的页面上，请用 `title` 插槽给出标题：`headline` 属性由元素绘制，所以在元素定义之前不会显示。

### 正文

直接放在元素里的文字采用提示块的文本样式和颜色。长篇的块（段落、列表、表格、代码块）放进一个与提示块尺寸一致、不限制行长的长文排版容器：

```html
<tanrei-callout status="info">
  <div class="tanrei-prose" data-measure="false">…渲染出来的 Markdown…</div>
</tanrei-callout>
```

长文排版不带颜色，所以在任何填充上都能阅读，其中的链接带下划线。放在正文里的组件保留自己的样式。在限制行长的长文排版中，提示块像文本块一样受行长限制；在其他任何地方，它都撑满所给的宽度。

### 操作和关闭

操作是你自己的[按钮](../button/)或链接，一到两个。请使用 `outlined` 或 `text` 按钮：`tonal` 按钮的填充与不带语义状态的 tonal 提示块相同，在那里看不出是按钮。提示块把它们排成可以换行的一行，除此之外什么都不做：按下其中一个时它不会关闭。

`closable` 绘制一个关闭按钮：一个小尺寸、只有图标的[按钮](../button/)，由 `close-label` 命名，变体由 `--tanrei-comp-callout-close-button-variant` 决定（默认系统中是 tonal）。在 tonal 提示块上，它用提示块自己的文字颜色绘制：一个由这种颜色变成半透明的圆，里面是同色的字形，因此在每种状态的填充上都看得见；在没有填充的 outlined 提示块上，它就是和别处一样的按钮。它像所有按钮一样响应悬停、焦点和按下。按下它会把 `open` 设为 false 并触发 `dismiss`。提示块从不自己关闭，也不响应 Escape。用户关闭之后，请记住这一点：每次访问都重新出现的可关闭提示块只是噪音。对旁边内容加以限定的注意事项不应该可以关闭。

### 为回应某件事而出现

`live` 用于在用户操作过程中出现或变化的提示块：提交之后对表单错误的汇总，或者告知文件已在用户不知情时发生更改的通知。请用 `open="false"` 把它留在页面里，在适用时设置 `open`。

<DemoFrame label="带 live 的提示块，为回应一次按下而显示" plain column>
  <tanrei-button variant="outlined" onclick="document.getElementById('callout-demo-live').open = true">提交表单</tanrei-button>
  <tanrei-callout id="callout-demo-live" live open="false" status="error" headline="有 3 个字段需要处理" closable close-label="关闭" style="inline-size: min(100%, 34rem)">请输入姓名，选择开始日期，并填写可以收信的地址。</tanrei-callout>
</DemoFrame>

```html
<tanrei-callout id="errors" live open="false" status="error" headline="有 3 个字段需要处理">
  请输入姓名，选择开始日期，并填写可以收信的地址。
</tanrei-callout>

<script type="module">
  form.addEventListener('submit', (event) => {
    if (!form.checkValidity()) {
      event.preventDefault();
      document.querySelector('#errors').open = true; // 朗读一次，立即打断（assertive）
    }
  });
</script>
```

带 `live` 的提示块在显示时，以及在标题、正文或语义状态变化时朗读一次：`default`、`info` 和 `success` 以礼貌（polite）的方式朗读，`warning` 和 `error` 以立即打断（assertive）的方式朗读。页面加载时就已经在页面标记里的提示块，在那一刻不会朗读。

在 Web 上，页面加载之后由你的脚本添加进页面的带 `live` 的提示块会被朗读。元素无法区分一个提示块是为回应某件事而添加的，还是随单页应用的新视图一起添加的，所以如果通知只是新视图的一部分，就不要加 `live`。

### 在元素定义之前

正文、标题插槽和操作都是元素自己的子元素，所以它们就在文档里：页面内搜索能找到，可以被翻译、被选中，没有脚本也能阅读。`@tanrei/web/callout.css` 为尚未定义的提示块提供它将来的框——内边距、文本样式、为字形和关闭按钮留出的空间，而 `open="false"` 时则什么都没有——所以元素定义时任何东西都不会移动。在那之前，它显示时不带填充、字形和关闭按钮。

### 推荐

- 用文字说出语义状态。“警告：请先备份”无需更多说明；警告上的“无障碍”则需要 `status-label="警告"`。
- 按语义状态在各处的含义来使用它们。建议不是成功。
- 把一组要点放进一个提示块，而不是连续放几个提示块。

### 避免

- 不要给写在页面里的说明使用带 `live` 的提示块。静态内容不是警报。
- 不要嵌套提示块，也不要在页面顶部叠放几个：分量相同的通知并排在一起会相互抵消。
- 不要既把焦点移到错误汇总上，又朗读它。长表单的第一个错误可能在屏幕之外，适合把焦点移到汇总上；短表单适合朗读汇总，并把焦点移到第一个出错的字段。
- 不要指望靠颜色来传达语义状态。在强制颜色模式下，每个提示块都是一道边线，加上文本颜色的文字。

## 无障碍

<ComponentAccessibility name="callout" />

### 组件负责的部分

- 它是一条说明（`role="note"`），由标题命名；没有标题时由 `status-label` 命名。带 `live` 时它改为实时区域：`role="status"`，警告或错误则为 `role="alert"`。
- `status-label` 作为单独的短语在标题和正文之前朗读（“警告，……”），从不绘制。`status` 为 `default` 时它会被忽略。
- 字形对辅助技术隐藏。
- 以文本给出的标题是纯文本。`title` 插槽里的标题元素保留自己的级别。
- 它不是焦点顺序中的停靠点，也从不移动焦点。Tab 先到达正文里的链接和控件，然后是操作，最后是关闭按钮。
- 焦点在提示块内时关闭它，焦点会回到进入提示块之前持有焦点的元素，所以下一次 Tab 会到达其后的内容。
- 关闭按钮就是一个按钮：它的点击区域会扩展到最小目标；在 tonal 提示块上，它的字形和焦点环使用提示块的文字颜色，在默认系统的每种状态和配色方案中，相对于按钮都保持至少 6:1。
- 文本放大时，所有内容都会换行并变大；字形和关闭按钮留在第一行。
- 在强制颜色模式下，每种外观都会多出一道文本颜色的边线，字形会完整绘制。
- 在从右到左的布局中，字形移到右侧，关闭按钮移到左侧，图标集标记为需要镜像的字形会被镜像，从左到右书写的标题保持自己的顺序。
- 未知的变体、尺寸或语义状态，既没有标题也没有正文的提示块，没有用文字给出的语义状态，没有名称的关闭按钮，以及没有语义状态却设置了的 `status-label`，会在调试构建中报告。

### 需要你做的事

- 检查每个提示块的文字是否说出了它的语义状态。组件无法判断标题有没有说出来。
- 用页面的语言来写 `status-label` 和 `close-label`。
- 只给为回应某件事而出现或变化的提示块使用 `live`。
- 给操作一个合适的标签。按钮的标签只有一行，所以在窄屏幕上文本放大时，长标签可能比提示块还宽。
