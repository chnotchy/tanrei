树视图显示一个供用户浏览或在其中做选择的结构：项目的文件、设计系统的令牌、产品的文件夹。包含其他项的行带有 V 形箭头，可以展开和折叠。设置 `selection` 后，可以选择一项或多项，树会告诉你选中的是哪些。

它不是导航。产品的各个去处是导航抽屉，页面的各个标题是目录，折叠起来的内容是折叠面板。那些组件保留链接和按钮，每一个都是焦点顺序中独立的停靠点。树只占一个停靠点，在其中用方向键移动，因为它可能有成千上万行。

在 Web 上，它是包在你自己的嵌套列表外面的 `<tanrei-tree-view>`。列表留在文档里，所以在没有脚本运行的地方，页面会把整个层级结构显示为嵌套列表。其他平台尚未实现。

### 你要写的内容

| 部件 | 在 Web 上 |
| --- | --- |
| 树的名称 | `label` 属性，使用你的产品的语言。 |
| 一个项 | 一个 `<li>`。它的第一个子元素就是它的行：一个 `<span>` 或一个 `<div>`。 |
| 标签 | 行的文本，放在一个元素里：`<bdi>`。它可以包含行内内容，例如一段行内代码。 |
| 辅助文本 | 带 `data-supporting-text` 的元素，位于标签的元素之内、标签之后。 |
| 图标 | 行里的一个 `.tanrei-icon`，里面是字形的名称。树自己没有代表文件夹或文件的字形。 |
| 展开时的图标 | 父项的 `.tanrei-icon` 上的 `data-open-icon`：展开期间画的字形，比如 `folder` 旁边的 `folder_open`。 |
| 后置内容 | 行里带 `data-trailing` 的元素：一个标签（Tag）、一个色块。树只安放它，不给它加样式。 |
| 后置文本 | 行里带 `data-trailing-text` 的元素：一个数量、一个大小、一个值。只占一行。 |
| 项自己的子项 | 行之后、同一个 `<li>` 之内的一个 `<ul>`。 |

行也可以把标签直接写成纯文本，外面不包 `<bdi>`。行有辅助文本时，以及名称的方向可能与页面不同时（例如阿拉伯语页面上的文件名），请使用 `<bdi>`。

| 写在 `<li>` 上 | 含义 |
| --- | --- |
| `data-value` | 用来标识这个项。没有它，这个项就无法被选择。在树内必须唯一。 |
| `data-open` | 父项显示它的子项。用户展开或折叠父项时，树会设置或移除它。 |
| `data-expandable` | 这个项将会包含你尚未给出的子项。它会得到一个 V 形箭头；`toggle` 表明它已展开时，再给出它的子项。 |
| `data-loading` | 你正在获取它的子项。它展开期间，下方会画出一个加载行，带有树的 `loading-label`。 |
| `data-disabled` | 用户无法选择、展开或折叠它。方向键仍然可以到达它。 |
| `data-supporting-position` | 设为 `inline` 时，把辅助文本放在标签后面、同一行上。不设时，辅助文本在标签下方。 |

| 事件 | 何时 | `detail` |
| --- | --- | --- |
| `change` | 用户更改了选择。在树上触发。 | 更改之后的 `value`（单选）或 `values`（多选） |
| `toggle` | 用户或浏览器的页面内查找展开或折叠了一个父项。在 `<li>` 上触发，并且冒泡。 | `open` |
| `rename` | 用户就地给一个项起了新名字。在 `<li>` 上触发，并且冒泡。 | `label`（去掉首尾空白的新名字）和 `previous` |
| `create` | 用户为 `create()` 请求的新项起了名字。在树上触发。 | `label`、`parent`、`within` 和 `after`（它所在的和它之前的 `<li>`，没有则为 `null`） |
| `filterchange` | 用户更改了筛选文本：键入、删除、粘贴、清除按钮或 Escape。在树上触发。 | `value`，即新的文本（`filter-value` 已经是这个值） |

你自己做出的更改，不会触发这些事件中的任何一个。

| 方法 | 作用 |
| --- | --- |
| `edit(li)` | 像 F2 一样，在一个项的名字上打开输入框。仅在树为 `editable` 时有效。 |
| `create({ parent, icon })` | 在选中项旁边加一行新行，带一个空输入框用来起名。返回是否加上了。 |
| `focusFilter()` | 把焦点移到筛选输入框，并选中其中的文本。仅在树为 `filterable` 时有效。可以把它绑定到你自己的、整个窗口都有效的按键上。 |

## 指南

### 它是不是树视图

| 你手上的是 | 使用 |
| --- | --- |
| 供人浏览或在其中做选择的结构 | 树视图 |
| 产品的各个去处，以链接的形式 | 导航抽屉 |
| 一个页面的各个标题 | 目录 |
| 折叠在几个标题行之下的内容 | 折叠面板 |
| 只有一级的项 | 列表 |

### 按下时发生什么

| 项 | 按它的行 | 按它的 V 形箭头 |
| --- | --- | --- |
| 可以选择，是父项 | 选择它 | 展开或折叠它 |
| 可以选择，是叶子项 | 选择它 | — |
| 不能选择，是父项 | 展开或折叠它 | 展开或折叠它 |
| 不能选择，是叶子项 | 什么也不发生 | — |

一次按下绝不会做两件事。用户选择一个文件夹时，不会因为它同时折叠了而找不到自己原来的位置。

当 `selection` 为 `single` 或 `multiple`、项有 `data-value` 并且没有被禁用时，这个项可以被选择。单选时，再次按下已选中的项不会改变任何东西。多选时，每个项都是单独选择的：选择父项并不会选择它包含的项。

选择之后做什么由你决定。响应 `change`，在树旁边的窗格里显示选中的文件，或选中令牌的编辑器。行里不放任何控件：请把操作放在树的旁边。

### 选择与折叠着的父项

树把选中填充画在项自己的行上。它不会因为父项下面有选中的项而标记父项，也不会为了显示选择而展开折叠着的父项。如果选中的项应当在视野之内，请在它上面的各级父项上设置 `data-open`：路径是你知道的。

### 密度

| `density` | 单行文字的行 | 用于 |
| --- | --- | --- |
| `regular`（默认） | 48 | 既用触摸、也用指针操作的产品。 |
| `compact` | 32 | 用指针浏览的工具，以及文字页面里的一棵小树。 |

compact 的行比指针目标还矮。这是可以接受的，因为它是按名称明确要求的，从来不是默认值。对触摸而言，两种密度下行的高度都达到触摸目标。

使用 `chevron="none"` 时，图标指定了展开字形（`data-open-icon="folder_open"`）的父项用字形表示展开和折叠，按下字形即可展开或折叠。没有图标的父项通过按下它的行来展开或折叠；但如果按下行会选择它，则选择优先，由方向键来展开。方向键始终可以展开和折叠。

`expandable="false"` 会去掉展开和折叠本身：每个父项都显示为展开，没有箭头，也没有切换，没有哪一行带有展开或折叠的状态。用于始终完整显示的结构。

### 引导线

`guides="shown"`（或不带值的属性）从每个展开的父项向下画一道细线，位于它所包含的各行旁边。`guides="hover"` 只在指针位于树上方或焦点在树内时才画。在很深的树里使用它，因为那里单靠缩进已经看不出哪些行是一组的。线位于父项行中第一个前置元素的中心下方：开头的箭头；没有则为图标；再没有则为标签的起点。它不占空间；缩进为 0 时不画。

### 缩进

| `indent` | 子项从哪里开始 |
| --- | --- |
| `auto`（默认） | 从父项标签开始的位置：每一级的距离取决于父项行中标签之前的内容——开头的箭头、图标。标签之前什么都没有的行，按该级的缩进令牌把子项向里移。 |
| 数字 | 比父项多缩进这么多像素。`0` 不设层级缩进，也不画引导线。 |

### 图标及其位置

`icon-space="auto"`（默认）在同一级有其他行带图标时，也为没有图标的行保留图标的位置，使同一级的标签对齐成一列。`always` 为每一行保留，`never` 只在有图标的行保留。`icon-gap` 以像素设定图标与标签之间的距离；保持 `auto` 时为令牌 `comp.tree-view.icon.gap`，两种密度相同。

### 高亮

`highlight="indented"`（默认）从该级开始的位置绘制行的填充、悬停与按下以及焦点环，让填充体现层级。`highlight="full"` 则像文件浏览器那样横跨整棵树绘制。两种情况下点击区域都是整个宽度。

### 单行

标签和辅助文本各占一行，放不下的部分用省略号截断。被截断的文本在悬停和键盘聚焦时在工具提示中完整显示，按 Escape 可隐藏；无障碍名称始终是完整的标签。设置 `label-wrap` 和 `supporting-wrap` 后，它们改为换行。辅助文本位于标签下方；在 `<li>` 上加 `data-supporting-position="inline"` 会把它放在标签后面、同一行上。请把标签放进它自己的元素（`<bdi>`）：直接写在行里的标签会换行。

### 固定的父项

在可滚动的框中，所显示的行之上那些展开的父项的行，会像编辑器的粘性滚动一样固定在框的顶部，它们的子项从下面滚过。最多固定 `sticky-max` 行（2），里层的父项优先。固定的就是这些行本身：按下固定的父项会将它折叠，键盘移到被它们遮住的行时，会滚动到固定行的下方。`sticky-parents="false"` 关闭此功能。不在自己的滚动框中的树不会固定任何行。

### 选择多项

| 按键或操作 | 多选时 |
| --- | --- |
| Space、Enter、按下 | 选择或取消选择该项，并把它作为锚点。 |
| Shift+下、Shift+上 | 移动焦点，并选择从锚点到焦点行的范围；往回移动会缩小范围。 |
| Shift+Space、按住 Shift 按下 | 选择从锚点到该行的范围。 |
| Ctrl+Shift+Home、Ctrl+Shift+End | 选择从焦点行到所显示的第一行或最后一行。 |
| Ctrl+A | 选择所显示的、可以选择的所有行。 |

在 Apple 平台上用 Command 代替 Ctrl。每次操作只触发一次 `change`。


### 重命名和新项

设置 `editable` 后，双击一行的标签，或在有焦点的行上按 F2，名字会进入一个输入框，并选中扩展名之前的部分。按 Enter 或离开输入框即确定新名字；按 Escape 则放弃。树自己从不更改标签：它触发 `rename`，如果你接受这个名字，就由你来设置标签。

```js
tree.addEventListener('rename', (event) => {
  const li = event.target;
  if (renameFile(li.dataset.value, event.detail.label)) li.querySelector('bdi').textContent = event.detail.label;
});

newFileButton.addEventListener('click', () => tree.create({ icon: 'draft' }));
newFolderButton.addEventListener('click', () => tree.create({ parent: true, icon: 'folder' }));
tree.addEventListener('create', (event) => {
  const li = makeItem(event.detail.label, event.detail.parent);
  event.detail.after ? event.detail.after.after(li) : tree.querySelector('ul').append(li);
});
```

`create()` 会在选中项旁边、同一层加一行树自己的行，带一个空输入框。在给出名字之前，你的数据里什么也不会加。`create` 带着这个名字，你据此加上的项会获得焦点。按 Escape 或名字为空时，什么也不会留下。用 `edit-label`（“名称”）或 `setWords({ editLabel })` 给输入框起名。

### 大型的树

树给它什么就显示什么，它不滚动，也不会只绘制视野之内的行。请把它放进你自己的滚动框里。

- 大的父项在展开时再给出它的子项：给它标上 `data-expandable`，并在 `toggle` 表明它已展开时加上它的 `<ul>`。获取期间设置 `data-loading`。
- 只有显示出来的行才有开销。折叠着的父项的子项在它展开之前不会被加样式、排版或朗读。
- 无论树有多大，一行的改动只会重新计算这一行的样式。

### 筛选

设置 `filterable` 后，树会在第一行上方画一个筛选输入框，它固定在你的滚动框顶部，被固定的父项排在它下面。用户键入的内容会把树缩小到标签中含有它的那些行；清空输入框，树就恢复原样。

- **什么算匹配。** 标签中含有键入的每一个词的行算作匹配，每个词可以出现在标签中的任何位置，顺序不限，不区分大小写、字符的宽度（全角与半角）和字母上的附加符号。只比较标签，不比较辅助文本、后置文本和值。还没有给出子项的父项（`data-expandable`）不会被搜索。
- **留下的内容。** 不匹配的行被隐藏。包含匹配项的父项保留，因自身名称而匹配的父项连同内容整体保留。
- **父项临时展开。** 包含匹配项的折叠父项会为了筛选而画成展开的样子。它的 `data-open` 不变，也不会触发 `toggle`，所以清空输入框后它会重新折叠。筛选期间用户自己展开或折叠的父项归用户所有：它保持用户留下的状态。
- **第一个匹配项随时可取。** 焦点在输入框中时，第一个匹配的行会画成获得焦点的样子，输入框把它作为自己的活动后代。按 Enter 会像在那一行上按 Enter 一样取用它：选中它，或者展开、折叠一个不能选择的父项。按下方向键会把焦点移到它上面，进入树中。Escape 清空输入框；在某一行上按 Escape 会清空筛选，让用户停在找到的项上，看到它周围的项。
- **在行上按“/”** 会把焦点移到输入框；其他字母仍然像以前一样，按开头的字母跳到对应的行。树只在行上监听这个键，也不会画出提示。`filter-shortcut` 可以换成别的键，`focusFilter()` 则让你绑定一个对整个窗口都有效的键。
- **数量。** 筛选期间，结果顶部会用低调的一行说明有多少行匹配（`filter-count-text`），一行都不匹配时则显示 `filter-empty-text`。设置 `filter-count-hidden` 后不画数量，但仍会告诉辅助技术。
- **不标记匹配项。** 筛选后留下的行就是结果，所以每一行看起来都和不筛选时一样，就像代码评审中的文件树或文档网站侧边栏的筛选那样。树从不改动你的标签文本。

如果你用别的方式判断匹配——在服务器上查找、排序，或者比较标签以外的内容——就不要设置 `filterable`，把符合条件的项交给树，在包含它们的父项上设置 `data-open`，并在你自己的状态文本里说明有多少项符合。

### 很深的树与很窄的窗口

每一级都比上一级更靠里。如果这样会让某行的标签从树宽度的一半之后才开始，这一行最多只缩进到让标签正好从一半处开始，所以名称始终保有一半的宽度。辅助技术仍然会得知真正的层级。

### 在服务器上渲染

除了选中填充之外，一切都在脚本加载之前画好；选中填充在元素定义时才出现。要让它出现在第一帧里，请自己在选中项的行上写 `aria-selected="true"`。

### 推荐

- 用你的产品的语言写 `label`；只要有项可能处于加载中，也要写 `loading-label`；要重命名或给新项起名时，也要写 `edit-label`。`loading-label` 和 `edit-label` 也可以用 `setWords({ loadingLabel, editLabel })` 为整个产品只给一次。
- 字形由你自己指定：文件夹和文件是你的产品里的种类，不是树的。
- 让名称保持完整。标签会换行，绝不会被截断。

### 避免

- 不要在行里放链接、按钮或输入框。树的任何按键都到不了它。
- 不要把树用于网站的页面。链接是通过浏览器和屏幕阅读器列出链接的那些方式被找到的。
- 不要靠移动焦点来选择。方向键负责移动；Enter 和 Space 负责选择。
- 不要在可筛选的树的行上把“/”另作他用。请把 `filter-shortcut` 设为别的键，或者不设任何键。

### 组件负责的部分

- 元素是一个以 `label` 命名的 `tree`。每一行是一个 `treeitem`，每个嵌套列表是一个 `group`，所以级别来自嵌套关系。
- 父项的行带有 `aria-expanded`。可以选择的行带有 `aria-selected`，值为 true 或 false。禁用的行带有 `aria-disabled`，正在加载的父项带有 `aria-busy`。
- 标签是行的名称。辅助文本、后置内容的文本和后置文本依次构成它的描述。
- 树只占一个停靠点。Tab 进入时，落在上一次获得焦点的行上；没有的话，落在第一个显示出来的选中行上；再没有，就落在第一行上。
- 下方向键和上方向键在显示出来的行之间移动。右方向键展开父项，再按则进入其中。左方向键折叠它，再按则退到外面。在从右到左的布局中，左右方向键互换。
- Home 和 End 前往第一行和最后一行。键入字母会移到标签以这些字母开头的下一行。`*` 展开与获得焦点的行同级的所有折叠着的父项。
- Enter 和 Space 做的事与按下这一行相同。选择从不跟随焦点。
- 设置 `editable` 时，F2 在有焦点的行的名字上打开输入框。Enter 确定名字，Escape 放弃，焦点回到这一行。输入法正在组字时，这两个键都归输入法。输入框的名称是 `edit-label`，新行是它那一层里带有输入框的树项。
- 使用 `chevron="none"` 时，展开和折叠由字形和 `aria-expanded` 告知，从不只靠颜色，方向键始终可以展开和折叠。使用 `expandable="false"` 时，没有哪一行带有 `aria-expanded`；分组仍然告知层级。
- 多选时，Shift 加方向键或 Space 选择从锚点开始的范围，Ctrl（Command）加 Shift 加 Home 或 End 选择到第一行或最后一行，Ctrl（Command）加 A 选择所显示的全部。
- 固定的父项行就是这些行本身，所以辅助技术在原位置只会遇到每一行一次。
- 展开、折叠和选择都由行自己的状态来表明。不会朗读任何内容，焦点也不移动。
- 父项折叠时如果获得焦点的行在它里面，焦点就交给这个父项。获得焦点的行被移除时，焦点交给它后面的那一行。
- 焦点环画在行的内部，所以滚动框不会把它裁掉。在禁用的行上，焦点环仍以正常的浓度绘制：行变淡，焦点环不变淡。
- V 形箭头、图标和引导线对辅助技术隐藏。加载行也是隐藏的：由父项说明它正忙。
- 标签和辅助文本各占一行；被截断的文本在悬停和键盘聚焦时在工具提示中完整显示，按 Escape 可隐藏，指针可以移到工具提示上，无障碍名称始终是完整的。设置 `label-wrap` 和 `supporting-wrap` 时，文本为 200% 时它们会换行，行会增高。
- 在强制颜色模式下，选中的行采用系统的选中颜色，并加上一道边线。
- 筛选输入框是一个以 `filter-label` 为名称的搜索字段，位于树之前，是一个独立的停靠点，所以树仍然只占一个停靠点。它表明自己控制着这棵树，把第一个匹配项作为自己的活动后代，它的清除按钮以 `filter-clear-label` 为名称。
- 被筛选隐藏的行对辅助技术来说也不存在了，所以用户听到的每一个层级、位置和数量都是筛选之后的。键入停顿一秒后，树旁边的一个状态会以礼貌（polite）的方式说明有多少行匹配，或者一行都不匹配，焦点不会移动：这是树唯一会朗读的内容。结果顶部画出的数量对辅助技术隐藏，辅助技术听到的是这个状态。
- 匹配的行不加标记，因此没有只靠颜色传达的信息，行的名称仍是完整的标签。
- 调试构建会报告：空的 `label`、没有标签的项、直接写在行里的标签、行里的控件、不对应任何项的值、两个值相同的项、未知的 `density`、`selection`、`chevron`、`guides`、`icon-space` 或 `highlight`、不是数字的 `indent` 或 `icon-gap`、在 `chevron="none"` 下没有图标的父项、没有 `edit-label` 的输入框、没有 `filter-label` 的筛选输入框、没有名称的清除按钮，以及包含不止一个组合键的 `filter-shortcut`。

### 需要你做的事

- 给每个可以选择的项一个在树内唯一的 `data-value`。
- 获取失败时，由你自己说明：写在树的旁边，或者作为一个用标签说明这一点的项。子项到达时，树不会朗读任何内容。
- 多选时，如果每个选中的项必须靠填充以外的东西来区分，请在后置内容里放一个你自己的标记。
- 把很长的树放进带有名称或标题的滚动框里，让用户知道框里是什么。
- 设置 `filterable` 时，给输入框一个说明它筛选什么的 `filter-label`（“筛选文件”），并为 `filter-count-text`、`filter-empty-text`、`filter-clear-label` 和 `filter-placeholder` 提供你的文字，可以写在树上，也可以用 `setWords()` 一次性给出。
