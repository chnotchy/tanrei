### 用法

列表只有一种项 `list-item`，每一项把产品的内容作为子元素。`orientation` 把项排成一列（`vertical`，默认）或一行（`horizontal`）；`wrap` 让项折到下一行，形成网格；`gap` 设置项之间的间距（`none`、`small`、`medium`、`large`）；`dividers` 在不折行的列表中于项之间绘制细线。

项默认是静态的。静态项自身不绘制任何东西，也不添加间距：内容就是项本身，并且可以包含产品自己的控件。`interactive` 使项成为一个按钮；`href` 使项成为一个链接，浏览器像对待任何链接一样对待它（可以在新标签页中打开、复制其地址；`target="new"` 在新标签页中打开并为项加上 `open_in_new` 标记，由 `targetLabel` 说明这一点）。`selection` 为 `single` 或 `multiple` 的列表是列表框，其项是按 `value` 选择的选项。交互项、链接和选项会为内容加内边距、绘制所有状态，并以 `label`（若为空则以内容的文本）命名。

`reorderable` 让用户调整项的顺序，无论是一列、一行还是网格。每一项在开头绘制一个手柄，表示它可以移动。可拖动的不只是手柄，而是整个项：鼠标移动几个像素后即拿起，手指或触控笔则需长按，因此滑动仍会滚动页面（触摸手柄会立即开始拖动）。其他项会滑开让路，被拿起的项浮在它们上方跟随指针，放下时落入自己的位置。

拖动从来不是唯一的方式。手柄是一个按钮：按下它或按 Enter 会打开一个包含四种移动的菜单（移到开头、前移一位、后移一位、移到末尾）。使用键盘时，在手柄上按 Space 拿起项，方向键每次移动一位（Home 和 End 移到第一位和最后一位），Space 或 Enter 放下，Escape 放回原处。每一步都会播报。

顺序是产品的数据，所以列表从不自行改变它。每种移动方式都会触发 `move`，其中 `from` 是项的索引，`to` 是它要到达的索引，均从 0 开始计数。请据此重新排列你的项。随后列表会绘制项交换位置的过程，让焦点保持在被移动项的手柄上，并告诉辅助技术它现在的位置。如果在 `comp.list.motion.reorder-duration` 的时间内你没有做任何改变，这次移动即被视为拒绝：项回到原位，也不会播报。

文字由产品提供：手柄的名称（`dragHandleLabel`，列表会在占位符 `{label}` 处填入项的名称）、它的说明（`dragHandleHint`）、菜单中的四种移动，以及要播报的三句话（`liftedText`、`movedText`、`cancelledText`，占位符为 `{label}`、`{position}` 和 `{count}`）。可以在列表上提供，也可以用 `setWords()` 为整个产品提供一次。在一行的列表中，把一列中的“上移”“下移”写成“左移”“右移”。

## 指南

### 何时使用

列表用于一组同类事物，供用户浏览、打开、选择或排列：消息、人员、文件、照片、设置、选择器的选项。需要跨列比较数值时用表格；从按钮打开的一小组操作用菜单。

列表自身不绘制任何东西：没有背景，项周围没有内边距，也不滚动。把它放在表面上、卡片中或屏幕的滚动视图里，并通过内容赋予每一项所需的外观。

### 四种项

| 种类 | 如何得到 | 它是什么 | 用于 |
| --- | --- | --- | --- |
| 静态 | `selection` 为 none、`interactive` 为 false、没有 `href` | 内容本身。没有焦点，也没有悬停或按下。 | 只供阅读的项，以及包含自己控件的项。 |
| 交互 | `interactive` | 列表项中的一个按钮。 | 每一项都会改变某些东西或就地打开它。 |
| 链接 | `href` | 列表项中的一个链接，外观与交互项完全相同。Enter 打开它，Space 不会。 | 每一项都前往一个有自己地址的页面。 |
| 选项 | `selection` 为 single 或 multiple | 列表框的一个选项，带有选中状态和对勾。 | 从项中选择。 |

一个列表可以混合静态项、交互项和链接项。可选列表只包含选项。可调整顺序的列表只包含静态项，且永远不是列表框：操作、链接或选项靠按下来使用，而按下会被拖动占用。

### 可调整顺序的列表

- 当顺序有意义且由用户决定时使用 `reorderable`：字体栈中的字族、主屏幕上的版块、附件中的文件、队列。对于很长的列表，请改为提供排序方式。
- 在 `move` 处理函数中，或在框架重新渲染后尽快重新排列你的项。你可以移动已有的元素，也可以渲染新的元素：列表会按位置和名称找到被移动的项。
- 当内容的文本不能很好地命名项时，为它设置 `label`：名称是手柄名称的一部分，因此两个项的手柄可以区分开，而且它也是播报的内容。
- 每句话都要完整书写，并包含其占位符。列表不会自行拼接短语，所以词序遵循你的语言。
- 你放在项中的控件（例如删除该项的按钮）在手柄之后保留自己的焦点位置。请用项的名称为它命名（“删除 Inter”）。删除拥有焦点的项时，列表会把焦点移到接替其位置的项的手柄上；删除这件事请由产品自己告知。

### 选择模式

| 选择 | 列表是 | 选择一个选项时 |
| --- | --- | --- |
| 无（默认） | 列表 | 不选中任何东西。交互项触发自己的 click。 |
| 单选 | 列表框 | 选中该选项并取消之前选中的项。再次选择它不会取消选中。 |
| 多选 | 多选列表框 | 切换该选项的开和关。 |

方向键只移动焦点；当用户按 Space 或 Enter，或轻点项时，选择才会改变。选中的选项以选中填充色和末尾的对勾绘制，每个选项都会保留对勾的空间，使内容对齐。

### 有字形和没有字形的行

当列表项包含[列表行](/zh-cn/components/list-row/)，而只有部分行有前置字形（`leadingIcon`）时，由 `iconSpace` 决定其他行的文本从哪里开始：

| iconSpace | 没有字形的行 |
| --- | --- |
| `auto`（默认） | 只要列表中另有一行画了字形，就为字形保留空间并留空，使所有标题从同一条线开始。在没有任何行画字形的列表中，文本从行的起始处开始。 |
| `always` | 每一行都保留该空间，即使没有任何行画字形。 |
| `never` | 不保留空间：文本从行的起始处开始。 |

无论怎样排列、处于哪种模式，列表都统一决定它的所有行。行的 `leading` 插槽中的头像、图片或控件不计入，也不在其旁边保留空间，因为它的尺寸由你决定，并且每行不同。[菜单](/zh-cn/components/menu/)、[树视图](/zh-cn/components/tree-view/)和[导航抽屉](/zh-cn/components/navigation-drawer/)也有同样的 `iconSpace`，取值和默认值都相同。

### 推荐做法

- 为可选列表设置说明选项是什么的 `label`，为可调整顺序的列表设置说明项是什么的 `label`。
- 前往页面的项使用 `href`，就地执行的项使用 `interactive`。
- 在两个列表之间放一个标题来划分区块。列表没有自己的区块标题。

### 避免的做法

- 不要在交互项、链接项或选项中放入按钮、链接、开关或任何其他控件。项是一个元素，辅助技术无法到达其中的控件，而且按下控件也会激活该项。
- 不要把选项用于立即执行的操作。列表框用于选择值。
- 不要自己绘制拖动手柄或移动按钮：`reorderable` 会绘制手柄，它的菜单就是无需拖动的移动方式。

## 无障碍

<ComponentAccessibility name="list" />

### 组件负责的事项

- 没有选择的列表以列表公开，每一项是带有位置和列表项数的列表项。交互项是列表项中的一个按钮，链接项是其中的一个链接。可选列表是以 `label` 命名、带有方向的列表框；每一项是带有选中状态的选项。
- 含有交互项、链接或选项的列表是一个 Tab 停靠点。按排列方式对应的方向键（一列中上下、一行中左右，在从右到左的布局中反转；网格中也可跨行移动）在项之间移动，不会循环。Home、End 和输入查找都可用。静态项不获得焦点；其中的控件保留自己的 Tab 停靠点。
- 在可调整顺序的列表中，每个手柄都是一个菜单按钮，名称为填入项名称的 `dragHandleLabel`，说明为 `dragHandleHint`，并且是独立的 Tab 停靠点。它的菜单只需单次按下就能移动项，满足 WCAG 关于凡是能拖动完成的操作都能不拖动完成的要求（2.5.7）。Space 为键盘拿起项（2.1.1）。
- 一个礼貌的实时区域会播报：键盘拿起了项、每一步将放下的位置、移动生效后的位置，以及按 Escape 后放回原处。
- 被拖动的项带着拖动时的填充色和阴影跟随指针；其他项以重排动效滑开。在减少动效的设置下，除指针下的项外，其余一切都立即移动。在强制颜色模式下，被拖动的项以高亮色描边。
- Escape 把被拖动的项放回原处，不会同时关闭包含列表的对话框。长按项不会打开浏览器的菜单。
- 交互项、链接和选项不小于最小目标尺寸，焦点环绘制在其内部，并随文字放大而变大。
- 调试版本会报告：没有名称的项、没有标签的可选列表或可调整顺序的列表、值为空或重复的选项、不指向任何选项的选择、交互项或选项中的控件、没人提供的文字、可选列表上的 `reorderable`，以及列表没有定义的 `iconSpace`。

已知的平台差异：

- SwiftUI、Compose、Flutter 和 React Native 提供的是旧版列表，没有本次修订的内容：还没有方向、折行、间距、内容插槽或调整顺序。

### 你需要做的事

- 为可选列表和可调整顺序的列表设置 `label`。
- 用产品的语言为可调整顺序的列表提供文字。没有它们，手柄仍可使用但没有名称，也不会播报任何内容。
- `move` 触发时重新排列你的项。列表没有改变任何东西。
- 为 `target` 为 `new` 的链接项设置 `targetLabel`，例如“在新标签页中打开”。
- 不要在交互项、链接和选项中放入控件。需要自己控件的项保持静态。
- 数据量大时，自行构建延迟加载的列表，并在平台需要时说明项数。列表不滚动，也不虚拟化。
