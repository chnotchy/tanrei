## 指南

### 何时使用

加载指示器用于你无法判断时长的短暂等待：列表正在获取下一页、控件正在保存、预览正在渲染。它说明有事情正在进行，但不说明要花多久。

如果等待可能持续几秒以上，或者你能够测量它已经进行到哪里，请改用[进度指示器](/zh-cn/components/progress-indicator/)。一个数值，哪怕是粗略的，也会让漫长的等待更容易忍受。

### 如何选择尺寸

| 尺寸 | 默认系统中的指示器 / 容器 | 用途 |
| --- | --- | --- |
| Small | 16 / 24 | 在控件里代替图标，例如正在保存的按钮。 |
| Medium | 24 / 32 | 放在一行文本旁边。这是默认尺寸。 |
| Large | 40 / 48 | 等待内容的空白区域或整个视图。 |

### 带容器

带容器的形式把指示器画在它自己的抬升的圆形上。指示器浮在内容之上时使用它，例如下拉刷新时，或者位于图片或列表之上时，这样无论背后是什么，它都看得见。指示器位于素净的表面上时，保持内嵌即可。

### 显示延迟和入场

转眼就结束的等待不应该显示任何东西。所以指示器先等待再显示：在默认系统中是 300 毫秒，从它被插入的那一刻算起。然后它淡入。比这段延迟更短的等待，永远不会显示一个一闪而过的标记。在延迟期间，指示器已经占据它的完整尺寸，所以它出现时，旁边的任何东西都不会移动。

在等待开始时插入指示器，在等待结束时移除它。延迟从插入时算起：只是被隐藏后再次显示、没有被移除的指示器不会再等一次；重新插入的指示器会再等完整的一段延迟。

延迟和入场效果由系统为所有指示器统一决定。只有在某一个指示器需要不同的节奏时，才在它上面单独设置：

- `showDelay` 是以毫秒为单位的等待时间。`0` 表示指示器一插入就显示，适合应当立即回应按下的忙碌按钮。
- `entrance` 是 `fade` 或 `grow`。grow 让指示器在淡入的同时从中心放大。默认值 `auto` 采用系统的选择。
- `enterDuration` 是以毫秒为单位的入场时长。`0` 表示指示器立即完整显示。

你设置的值会原样使用：动效调节量不会缩放它。不设置某个属性，就采用系统的值。

### 推荐

- 给它一个说明正在加载什么的标签：写“正在加载消息”，不写“正在加载”。如果它旁边显示了说明文字，请使用同样的措辞。
- 把它放在内容将要出现的位置，这样内容到达时，用户看的正是那个地方。
- 用它代替控件里的图标时，保持控件的尺寸不变，这样周围的任何东西都不会移动。
- 除非某个指示器需要另一种节奏，否则把延迟交给系统决定。

### 避免

- 不要把它用于可以测量的等待，或可能持续很久的等待。请使用进度指示器。
- 不要为同一次等待显示多个指示器。每个正在加载的区域一个就够了。
- 屏幕上只有一部分在加载时，不要让它盖住整个屏幕。让其余部分保持可用。
- 不要用给它着色的方式表示出了问题。应当停止指示器，并显示一条消息。
- 不要把指示器一直留在原处，只在两次等待之间把它隐藏。要移除它，这样下一次等待才会开始新的延迟。

## 无障碍

<ComponentAccessibility name="loading-indicator" />

### 组件负责的部分

- 显示之后，它以平台的“忙碌”状态提供进度条角色，以标签作为名称，没有数值。Flutter 目前还没有进度条角色和忙碌状态，所以在那里它只提供标签。
- 在显示延迟期间，它完全不在无障碍树之内：没有角色，没有名称，没有忙碌状态。短到看不见的等待，同样也听不到。
- 它从不可聚焦，出现或消失时也不会自行朗读。
- 用户要求减弱动态效果时，圆弧停止转动，改为一个完整的圆环轻缓地改变不透明度，每秒至多一次；容器保持静止。grow 入场变为淡入。显示延迟保持不变：它是等待，不是动效。
- 在看不见它的时候，它的动画会停止——在所有平台上，应用处于后台时都是如此；在平台能够判断的情况下，它被滚出视野或位于隐藏的屏幕上时也是如此——看得见时再恢复。
- 空的标签会在调试构建中报告。

### 需要你做的事

- 在加载期间把正在加载的区域标记为忙碌（在 Web 上是 `aria-busy`），从等待开始时就标记，不要等指示器的延迟结束；并在内容到达时告知用户：在实时区域（live region）里放一条消息，或者在内容是用户主动请求的情况下，把焦点移到新内容上。
- 如果你更改了颜色，请让指示器的颜色相对于它背后的表面至少保持 3:1 的对比度，带容器的指示器的颜色相对于它的容器也是如此。这个运动的标记是表明有事情正在进行的唯一信号。
