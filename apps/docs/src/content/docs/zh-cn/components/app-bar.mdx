### 用法

应用栏是一块布局区域，不是浮层。它在屏幕顶部占据自己的高度，内容从它下方开始，应用栏本身从不获得焦点。

它容纳两类项：起始侧的一个 `navigation` 项（返回、菜单或关闭），以及末尾侧最多三个 `action` 项。两者都是你自己提供的纯图标[按钮](/zh-cn/components/button/)，各有自己的标签和自己的点击处理；如果它通向某个地方，则有自己的 `href`。应用栏只负责排列它们，从不改变它们的样式。每个平台用各自的插槽接收这些项：在 Web 上是带 `slot="navigation"` 和 `slot="actions"` 的子元素，在 SwiftUI 上是 `navigation` 和 `actions` 视图构建器，在 Compose 上是 `navigationIcon` 和 `actions` lambda，在 Flutter 上是 `leading` 和 `actions:`，在 React Native 上是 `navigation` 和 `actions` 节点。

标题是屏幕的名称，也是屏幕的标题元素（heading）。在 Web 上它叫 `headline`，因为 HTML 的全局属性 `title` 会让整个应用栏出现工具提示。

**滚动后。** 只要有内容位于应用栏下方，应用栏就呈现滚动后的外观。把屏幕的滚动视图连接到应用栏，它就会自己设置 `scrolled`：在 Web 上用 `scroll-target`（默认是文档），在 SwiftUI 上用 `.tanreiAppBarScrollSource()`（加在容纳应用栏的 `.safeAreaInset` 之后），在 Compose 上用通过 `Modifier.nestedScroll` 连接的 `scrollBehavior`，在 Flutter 上靠页面的滚动通知，在 React Native 上用 `useAppBarScroll()`。没有连接时，请自己设置 `scrolled`。

**系统栏。** 应用栏的颜色会延伸到它上方的状态栏、摄像头挖孔或窗口标题栏之下。它的内容则留在这些区域的下方，并位于两侧的边衬区（insets）之内。Web 读取 `env(safe-area-inset-*)`，Compose 接收 `windowInsets`（默认是状态栏和水平方向的屏幕挖孔），Flutter 读取 `MediaQuery` 的 padding，SwiftUI 则用 `.safeAreaInset(edge: .top)` 放置应用栏。React Native 没有安全区域 API，Tanrei 也不引入安全区域方面的依赖，所以边衬区只能来自属性。请把窗口的 `insets` 交给 `TanreiProvider`（如果你使用 `react-native-safe-area-context`，把它的 `useSafeAreaInsets()` 直接传过去）。应用栏自己的 `insets` 属性会替换它所指定的那几条边，因此不在窗口顶部的应用栏要传入 `{ top: 0 }`。

## 指南

### 何时使用

在屏幕顶部使用应用栏，用来说明用户身在何处，带他们返回或打开菜单，并提供属于整个屏幕的少量操作：搜索、分享、账户。一个屏幕只有一个应用栏。

要在应用的各个顶级目的地之间切换，请使用导航栏或导航抽屉。应用栏的菜单按钮可以打开[模态导航抽屉](/zh-cn/components/navigation-drawer/)。Tanrei 没有底部应用栏：在 compact 屏幕底部放置操作，是[工具栏](/zh-cn/components/toolbar/)的职责。

### 如何选择尺寸和标题位置

| 选项 | 效果 | 适用于 |
| --- | --- | --- |
| Small（默认） | 只有一行：导航按钮、标题和操作。 | 大多数屏幕，以及所有从另一个屏幕进入的屏幕。 |
| Large | 在顶部一行的下方，用单独的一行显示更大的标题。内容滚动时，它随滚动距离一比一地折叠进顶部一行，顶部一行的标题同时淡入。内容回到顶端时，它重新展开。 | 产品的顶级屏幕，在那里标题也是这个屏幕的标志。 |
| `titleAlignment` 为 start（默认） | 标题紧跟在导航按钮之后。 | 大多数应用栏。 |
| `titleAlignment` 为 center | 标题相对于整个应用栏居中，并在两侧等量收窄，因此绝不会伸到按钮下面。 | 沿用 iOS 居中标题的产品。展开的大标题始终从起始侧开始。 |

设计系统可以增加尺寸。在 SwiftUI、Compose、Flutter 和 React Native 上，比 small 更高的尺寸会像 large 一样拥有单独的标题行。在 Web 上，设计系统增加的每个尺寸都有单独的标题行。`m3-like` 预设目前还没有 Material 的 medium 尺寸。

### 滚动

- **底边保持不动。** 在默认系统中，应用栏在静止时和有内容位于其下方时都会画出底边的一条细线。应用栏和应用外壳的页眉一样，是一个留在原位的区域的边缘，所以这条线不会随滚动出现或消失。
- **也可以跟随滚动。** 把 `dividerVisibility` 设为 `scroll`（在 Web 上是 `divider-visibility`），底边就只在有内容位于应用栏下方时才画出，让这条线本身说明内容已经移动。设计系统可以用 `sys.behavior.divider-visibility` 为所有应用栏、面板和对话框作出这一选择，或者用 `comp.app-bar.outline.visibility` 只为应用栏作出选择。`cupertino` 和 `m3-like` 按照它们的原型选择 `scroll`。
- **平的外观与滚动后的外观。** 内容停在顶端时，应用栏是平的。一旦有内容位于它下方，应用栏就呈现滚动后的外观：在 `m3-like` 中是带色调的容器，在 `cupertino` 中是有填充的容器。这一变化按应用栏的状态动效缓动完成；在减弱动态效果时则立即完成。
- **大号应用栏只有在完全折叠之后才算滚动后的状态。** 在此之前，折叠本身已经表明内容移动了。
- **应用栏留在原处。** 内容向下滚动时它不会隐藏。隐藏是屏幕的滚动行为，不是应用栏的。

### 项

- 一个应用栏最多放一个导航按钮：从另一个屏幕进入的屏幕用“返回”，顶级屏幕用“菜单”，全屏任务用“关闭”。
- 操作不要超过三个。其余的放进溢出菜单：一个打开 Tanrei 菜单的“更多选项”图标按钮。第四个操作和第二个导航按钮会在调试构建中报告，但仍会绘制出来。
- 按钮的外观与在其他任何地方相同。应用栏只负责排列它们，从不给它们改色。
- 通向某个地方的按钮是链接：给它一个 `href`。这样，通向父页面的返回按钮，或打开某个页面的帮助操作，就是真正的链接，画出来仍是同样的按钮。沿历史记录返回的返回按钮仍然是按钮。
- 在 Web 上，[搜索](/zh-cn/components/search/)可以以图标触发器的形式（`bar` 设为 `icon`）作为操作之一：一个纯图标按钮，用来打开搜索的对话框或全屏视图。

### 品牌

产品可以把自己的标志放进栏中，作为通往首页的链接。把地址（`brandHref`，Web 上为 `brand-href`）和产品名称（`brandLabel`）交给栏：栏会在你提供的图片外绘制一个链接，并用该名称为它命名，同时对辅助技术隐藏这些图片，因此名称只会被读一次。栏把品牌放在导航按钮之后，占一个与图标按钮同样大小的单元格；除非你的图片自带颜色，否则会给它 `comp.app-bar.brand.color`。

- **一张图片。** 把一个标志文件放进 `slot="brand"`，高度为 `comp.app-bar.brand.image.height`。
- **只有符号。** 放进 `slot="brand-symbol"`，高度为 `comp.app-bar.brand.symbol.size`，位于图标按钮的图标所在的位置。
- **只有文字标。** 放进 `slot="brand-wordmark"`，高度为 `comp.app-bar.brand.wordmark.height`。
- **符号和文字标一起。** 两者都提供。默认（`brandLayout` 为 `lockup`）时它们并排，间距为 `comp.app-bar.brand.lockup.gap`，按 `comp.app-bar.brand.lockup.alignment` 对齐。此时符号与文字标同高（`comp.app-bar.brand.lockup.symbol.size`）。
- **按窗口宽度切换。** 两者都提供，并把 `brandLayout` 设为 `responsive`（Web 上为 `brand-layout`）：窗口为 medium 或更宽时，栏显示文字标；为 compact 时显示符号，两者从不同时显示。在应用外壳中，它跟随外壳的窗口类别。

栏会为每张图片确定尺寸，并保持其比例。不要用标题来写产品名称：标题是屏幕的名称。SwiftUI、Compose、Flutter 和 React Native 尚未绘制品牌。

本站的页眉在任何宽度下都只显示 Tanrei 的文字标。

### 推荐

- 把标题写成屏幕的名称，例如“收件箱”或“季度报告”。保持简短：它只占一行，放不下时以省略号截断。
- 副标题用来提供有助于区分两个相似屏幕的背景信息：账户、状态、编辑时间。
- 为所有顶级屏幕选定一种尺寸，为其余屏幕选定另一种。

### 避免

- 不要在插槽里放图标按钮以外的任何东西：不放文本字段，不放搜索框，不放标签页，不放分段控件。一排标签页应放在应用栏下方，更下方的[标签页视图](/zh-cn/components/tab-view/)可以与它关联。
- 不要把“新建”这样的主要操作放进应用栏。请使用主操作按钮。
- 不要让标题出现第二行，也不要把它做成链接。

## 无障碍

<ComponentAccessibility name="app-bar" />

### 组件负责的部分

- 应用栏没有自己的角色，也永远不可聚焦。Tab 键按阅读顺序从导航按钮依次移到各个操作。每个按钮保留自己的角色、名称和最小目标，带 `href` 的按钮会暴露为链接。
- 标题会暴露为屏幕的标题元素；在 Web 上，除非 `heading-level` 另有指定，它是一级标题。副标题紧随其后朗读。空标题什么也不绘制，也不暴露标题元素。
- 大号应用栏在折叠过程中会绘制两个标题，但只暴露一个：展开的标题只要还有一部分可见，就暴露它；应用栏折叠完成后，暴露顶部一行的标题。标题元素绝不会被朗读两次。
- 应用栏不是地标。它是不是页面的横幅（banner），只有你知道。
- 文本变大时，应用栏的各行会随之变高，因为行高只是最小高度。标题和副标题始终只占一行，即使在 200% 时也是截断而不是换行，所以应用栏绝不会把内容挤走。辅助技术仍能获得完整的标题。图标按钮不会缩放。
- 应用栏的方向取决于它所在的位置。在从右到左的布局中它会镜像：导航按钮在右，操作在左。图标集标记为需要镜像的图标（例如返回箭头）由它自己的按钮镜像，而不是由应用栏镜像。
- 标题和副标题各自按自身文本的方向排布，与周围的文本相互隔离。从右到左的布局中，一个从左到右书写的名称会保持原有顺序，并且在它自己的末尾截断，绝不在开头截断。
- 操作超过三个、导航按钮超过一个，以及使用了设计系统中没有的尺寸，都会在调试构建中报告。

已知的平台差距：

- SwiftUI、Compose、Flutter 和 React Native：`dividerVisibility` 要等这些平台跟上。在此之前，它们像 `scroll` 一样，只在有内容位于应用栏下方时才画出底边。
- SwiftUI、Compose、Flutter 和 React Native：从右到左的规则（在图标集标记之处镜像图标、标题按自身方向排布）要等这些平台跟上，带 `href` 的按钮也是如此。
- Web：所有尺寸都跟随 `rem`，因此调大浏览器的文本大小时，图标按钮会随文本一起变大。只放大 Tanrei 的文字则不会。
- Web：如果大号应用栏跟随文档自身的滚动，又以 `position: sticky` 位于文档流中，那么内容除了随滚动移动之外，还会因应用栏的折叠而移动，于是在应用栏折叠期间，内容的移动速度是平时的两倍。请把会折叠的应用栏放在某个滚动元素（`scroll-target`）的上方，或放在固定的页眉里。
- Web：每个图标按钮都位于一个单元格中，其大小等于当前所用指针的最小目标，鼠标是 44；因此两个操作的中心间距是 52，而 Compose 和 Flutter 按 48 的触摸目标计算，画出来的间距是 56。
- SwiftUI：应用栏只有在 iOS 18 和 macOS 15 及以上才会跟随它的滚动视图。在此之前什么都不会连接，应用栏按 `isScrolled` 的值绘制。
- SwiftUI：对已连接的大号应用栏设置 `isScrolled: true`，它会按折叠后的样子绘制，但在布局中仍保留展开时的高度，所以内容停在顶端时，上方会露出一段空隙。
- SwiftUI：系统栏隐藏时，应用栏通过替换导航控制器的 pop 手势 delegate，让边缘滑动返回继续可用。这一点只在 iOS 26.5 上验证过。大号应用栏一次只暴露一个标题这一点，尚未用 VoiceOver 验证。
- Flutter：大号的 `TanreiAppBar` 不会随内容一起折叠，因为盒状 widget 无法随它下方的滚动视图收缩。它忽略滚动通知，保持展开，只有在 `scrolledUnder` 为 true 时才按折叠后的样子绘制。需要会折叠的应用栏时，请使用 `TanreiSliverAppBar`。
- Flutter：`preferredSize` 读取不到主题，所以报告的是无界的高度。Scaffold 会让应用栏自行决定尺寸，但你自己的布局用不了这个数值。
- Compose：滚动停在哪里，折叠就停在哪里，所以大号应用栏可能停在折叠到一半的位置。它不会像 Material 的应用栏那样，在快速滑动之后吸附到完全展开或完全折叠。规格并不要求吸附。
- React Native：要让大号应用栏随内容一比一地折叠，需要像上面的示例那样，把应用栏叠放在滚动视图之上，并给内容加上与应用栏等高的内边距。折叠、边衬区以及屏幕阅读器朗读的内容，尚未在真机上验证。
- 所有平台：在 `cupertino` 下，44 点高的顶部一行在容纳图标按钮时会变为 48，因为图标按钮的触摸目标是 48，而最小目标优先。在 Web 上，它只在粗略指针下才变高，因为鼠标的目标是 44。大号应用栏展开的那一行也比 cupertino 的容器高度高 1 点。
- 所有平台：有副标题时，展开的标题在应用栏完全折叠之前就已被遮住。这段时间里暴露哪个标题，规格尚未说明。各平台都在展开的标题被遮住的那一刻，把标题元素移到顶部一行。

### 需要你做的事

- 给每个应用栏一个标题。它是屏幕的标题元素。
- 给每个图标按钮一个标签，例如“返回”或“搜索”。
- 在 Web 上，如果页面已经有一级标题，请设置 `heading-level`；如果应用栏是页面的横幅，请用 `<header>` 包住它。
- 连接屏幕的滚动视图，或者自己设置 `scrolled`，让应用栏在内容位于其下方时有所体现。
- 在 React Native 上，把窗口的边衬区传给 `TanreiProvider`。在 React Native 和 Compose 上，不在窗口顶部的应用栏要使用不同的边衬区（`insets={{ top: 0 }}`，或你自己的 `windowInsets`）。
- 标题要简短。以省略号截断的标题仍会被完整朗读，但视力正常的用户只能看到它的开头。
