跑马灯文本是放在过窄位置里的一行产品文本。静止时，它读起来和任何被截断的行一样：从行的起点开始，在被截断处以省略号结尾。在触发条件持续期间——默认是指针悬停在它上面，或它所在的控件获得键盘焦点时——它以稳定的速度（以每秒像素数给出）横向滚动，让文本的每一部分都经过视野；然后回到起点并停下。把指针移到上面第一行试试。第二行放得下，所以从不移动：文本放得下的跑马灯文本就是一行普通文本。

它适合行宽固定、文本通常很短但有时会变长的地方：列表行的标题、导航栏或抽屉中的标签、纸片、正在播放的内容名称、表格的单元格。如果大多数时候截断的行就够用，另一种做法是保留截断，并在[工具提示](/zh-cn/components/tooltip/)中给出完整文本：工具提示一次显示全部，不移动任何东西。

### 用法

Web 和 React 示例展示的是当前规格。SwiftUI、Compose、Flutter 和 React Native 处于计划阶段，尚未提供跑马灯文本。

## 指南

### 何时使用

当一行必须保持为一行、宽度由布局固定，而人有时需要看到被截断的部分时，使用跑马灯文本：播放列表某一行中很长的歌名、因语言而变长的目的地标签、装着名字的纸片。这一行保持自己的高度和位置，只在被要求时才展示其余部分。

不要把它用于人必须完整阅读才能采取行动的文本——警告、错误、选择的条件、金额、操作说明。移动的文本读起来慢，也容易错过。给这类文本所需的行数，让它换行。

### 如何选择触发条件

| 触发条件 | 适用于 |
| --- | --- |
| `hover-or-focus` | 默认值，几乎在任何地方都是正确的选择：人用指针指向它，或用键盘到达它所在的控件时，它都会移动，因此两种人看到的是同样的东西。 |
| `hover` | 键盘用户会快速浏览的长列表：焦点经过时每一行的标题都开始移动，带来的干扰多于帮助。 |
| `focus` | 主要用键盘或遥控器操作的表面中的行，在那里悬停没有意义。 |
| `always` | 正在播放的内容名称，以及类似的、人只是瞥一眼而不会去指向的行。它从显示起就自行移动，需要一种暂停的方式（见“无障碍”）。 |

触发条件的范围是这一行所在的控件——列表行、纸片、目的地——而不只是这一行本身：指针指向该行的任何位置，都会让它的标题移动。悬停只算精细指针，例如鼠标或笔；触摸不会让它开始移动。

### repeat 还是 bounce

- **`repeat`**（默认）把文本朝起始边移动，直到其末尾经过，同时一份副本隔着一段间距跟在后面，因此这一行从不变空，并回到开始时的样子。它读起来像滚动字幕，适合要移动一段时间的行。
- **`bounce`** 把文本移动到末尾进入视野为止，在那里停下，然后移回。它不绘制副本，因此末尾和开头不会并排出现。它适合只移动一次、让人短暂看一眼末尾的行。

两者都按文本的书写方向移动：从左到右的文本向左移动，从右到左的文本向右移动，与周围页面的方向无关。

### 速度和停顿

- **`speed`** 以每秒像素数表示，而不是一轮所需的时间，因此长标题和短标题以相同的速度移动。交给令牌 `comp.marquee-text.speed`，让产品中每一行移动的文本保持同一速度。文字放大时，速度随文字一起变大，在任何字号下每秒经过的字符数都相同。
- **`startPause`** 是每一轮之前文本在起点停留的时间，用来读出开头。使用 `trigger="always"` 时，它也是第一轮开始前的等待时间。
- **`endPause`** 在 `bounce` 时，是文本在末尾进入视野后停留、再移回之前的时间。
- **`iterations`** 是一次触发播放多少轮，然后文本停在起点。保持为 null 时，各轮会一直进行，直到指针离开或焦点移走；对 `always` 而言，则一直持续到这一行不再显示。设置一个让动效保持简短的轮数，才能让悬停或聚焦触发的动效满足无障碍要求（见下文）。

停顿是阅读的时间。产品中加快或放慢动画的动效设置不会缩短它们。

### 文案

让文本足够短，使人很少需要看到它移动：跑马灯是为偶尔比其他标题更长的那个标题准备的，而不是把一句话塞进纸片的办法。把用来区分各项的内容放在开头，不移动也能读到。文本可以包含行内内容，例如一段粗体；它始终只有一行。

### 推荐

- 把这一行放在人会指向或聚焦的控件中，让触发条件的范围覆盖整行。
- 设置 `iterations`，让每次悬停或聚焦只播放一小段，然后停下。
- 为 `trigger="always"` 的行提供暂停的方式：它自己的播放控件，或产品中暂停页面上所有动态部分的控件。

### 避免

- 不要把它用于人必须完整阅读才能采取行动的文本。给这类文本单独的行。
- 不要在同一屏上放好几行一直移动的文本。一行移动的文本就会吸引目光；好几行会彼此争夺注意力，也会与屏幕上的其他一切争夺。
- 不要为了开始移动而把这一行本身做成按钮或链接。它是文本；人按下的是它周围的控件。
- 不要为了把长文本塞进一小段动效而缩短停顿。缩短文本，或用其他方式完整显示它。

## 无障碍

<ComponentAccessibility name="marquee-text" />

### 默认设置可能与 WCAG 2.2.2 冲突

[Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)（WCAG 2.2.2，A 级）要求：自动开始、持续超过五秒、并与其他内容同时呈现的动效，可以由人暂停、停止或隐藏。Tanrei 的默认设置本身并不满足这一点，体现在两个方面，如何满足由产品决定。

1. **`trigger="always"` 默认不绘制播放控件**（`playbackControl` 为 false）。与其他内容并列、持续移动超过五秒的行，需要一种暂停的方式。可以设置 `playbackControl`，这一行就会在末尾绘制一个仅含图标的暂停和播放按钮，由 `pauseLabel` 和 `playLabel`，或产品文字中的 `marqueePauseLabel` 和 `marqueePlayLabel` 命名；也可以把产品自己用来暂停页面上所有动态部分的控件绑定到 `paused`。两者都没有却一直移动的行，会在调试构建中报告。
2. **在 `hover`、`focus` 和 `hover-or-focus` 下，`iterations` 为 null 时，各轮会一直播放，直到指针离开或焦点移走。** WCAG 的 Understanding 文档把由悬停或聚焦开始的动效算作自动开始的动效，并指出只有在焦点离开时才停止的动效不算一种停止它的方式。要满足 2.2.2，请设置 `iterations`，让动效在五秒内结束。对于很长的文本，一轮可能就已经超过五秒：缩短文本或提高速度，或用其他方式显示完整文本。

指针停在这一行上或焦点在其内部时，以及这一行不在视野中或页面被隐藏时，它会让动效停在原处。这让它更容易阅读，但并不是停止它的方式。

### 组件负责的部分

- 只有文本放不下时才移动。文本放得下的行绘制普通文本，什么也不启动。
- 在请求减弱动态效果时（WCAG 2.3.3），它从不移动。悬停或聚焦时，它不经动效、每次一个视口宽度地显示隐藏的部分，并在每个视图上停留，因此文本的每一部分仍然都能看到；`trigger="always"` 的行保持截断，不绘制播放控件。
- 辅助技术在这一行所在的位置，把文本作为文本完整地朗读一次。副本、省略号和渐隐对辅助技术隐藏，动效不改变它读到的任何内容，也不播报任何内容。
- 这一行不是焦点停靠点。Tab 会到达它所在的控件，以及绘制出来时的播放控件。
- 播放控件是 text 变体、small 尺寸的按钮，文本移动时显示图标集的暂停字形，暂停时显示播放字形。Enter 或 Space 切换它，焦点留在按钮上，并触发 `pausedChange`。它的目标满足最小目标。
- 在从右到左的布局中，播放控件位于这一行的左端；文本按它自己的方向移动。
- 在强制颜色模式下，文本采用平台赋予其周围元素的颜色，边缘被裁切而不是渐隐。
- 它没有自己的文字。既没有从实例也没有从产品文字获得名称的播放控件仍会绘制，并在调试构建中报告；未知的 `trigger` 或 `loop`，以及超出范围的速度、停顿或轮数也会报告。

Web 组件不是 HTML 的 `<marquee>` 元素。该元素[已弃用](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/marquee)，会忽略减弱动态效果，人也无法暂停它。

### 需要你做的事

- 按上文满足 WCAG 2.2.2：为每一行 `trigger="always"` 提供暂停的方式，并设置让悬停或聚焦开始的动效在五秒内结束的 `iterations`。
- 用页面的语言为播放控件提供两个名称，在实例中提供，或在产品文字中统一提供一次：“暂停滚动文本”和“播放滚动文本”说明了按钮的作用。
- 不要把人必须完整阅读的文本放进跑马灯：截断的行会对从不触发动效的人隐藏这部分内容。
- 一屏最多放一行一直移动的文本，也不要把它放在人正在阅读的长文本旁边。
