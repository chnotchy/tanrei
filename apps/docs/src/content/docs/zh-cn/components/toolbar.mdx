### 用法

工具栏容纳一组相关的控件：操作、切换按钮、打开菜单的按钮、[带菜单的按钮](/zh-cn/components/button-with-menu/)。它的项就是你自己的 Tanrei [`Button`](/zh-cn/components/button/) 和带菜单的按钮，各有自己的标签、点击处理和状态。工具栏按阅读顺序排列它们，把各组分隔开，在它们之间移动键盘焦点，并把放不下的项收进溢出菜单。它从不改变它们的样式，所以工具栏里的纯图标 `Button`，外观和行为与在其他任何地方相同。

它有六类项：

- `action`：纯图标的 `Button`。“粗体”这样的切换按钮就是设置了 `toggle` 的 action。
- `button`：带标签的 `Button`，也可以是切换按钮，例如一个开或关的筛选条件。
- `menu-button`：锚定了 Tanrei [菜单](/zh-cn/components/menu/)的 `Button`，例如“排序”或“插入”。菜单是你自己的，放在它的 `Button` 旁边。工具栏不负责菜单的布局。
- `button-with-menu`：一个主操作，加上一个放相关操作的菜单。两半各是方向键的一个停靠点。
- `group`：一串相关的项，例如“粗体”“斜体”和“下划线”。它自己不绘制任何东西。当这种分组对用户有意义时，给它一个 `label`，例如“文字样式”。
- `separator`：两个不在组里的项之间的一条线。在 Web 上它是一条[分隔线](/zh-cn/components/divider/)，工具栏像绘制两组之间的线那样绘制它。

**内嵌（默认）。** 内嵌的工具栏位于你的布局放置它的地方，就在它所作用的内容之中：表格上方、编辑器顶部、列表旁边作为一排筛选条件。它的长度就是它的项所需要的长度，绝不超过布局允许的长度。在默认系统中，它没有自己的表面、阴影或边缘，两端与周围的内容对齐。

**停靠。** 停靠的工具栏横跨屏幕的底边。它的颜色会延伸到主屏幕指示条或手势条之下，它的项则留在其上方，并位于两侧的边衬区（insets）之内。Web 读取 `env(safe-area-inset-bottom)`，SwiftUI 用 `.safeAreaInset(edge: .bottom)` 放置工具栏，Compose 接收 `windowInsets`（默认是导航栏），Flutter 读取 `MediaQuery` 底部的 padding。React Native 从工具栏的 `insets` 属性或从 `TanreiProvider` 获得边衬区，因为 Tanrei 不引入安全区域方面的依赖。

**悬浮。** 悬浮的工具栏不会自己定位，[主操作按钮](/zh-cn/components/main-action-button/)也是这样。由你的布局来放置它：通常居中放在内容底部的上方；纵向时则放在内容末尾边的旁边。

Web 和 React 的示例展示的是当前规格。SwiftUI、Compose、Flutter 和 React Native 待跟进：它们提供的仍是工具栏和按钮的上一版。在上一版中，除非另行指定，工具栏是停靠的，只容纳 `Button`，放不下的项会滚动，纯图标的操作是一个独立的图标按钮。在跟上之前，这些平台的示例展示的是上一版。

## 指南

### 何时使用

工具栏用来放置一组作用于用户眼前内容的控件：编辑器上方的“粗体”“斜体”和“链接”；表格上方的“筛选”“排序”和“下载”；一封打开的邮件的“归档”“删除”和“移动”；绘图上方的画笔和橡皮擦；地图上的缩放和定位。这些控件作用于当前内容或当前选择，而不决定用户接下来去哪里。

屏幕的标题、返回入口以及一两个全局操作，请使用顶部的[应用栏](/zh-cn/components/app-bar/)。要在应用的各个顶级目的地之间切换，请使用[导航栏](/zh-cn/components/navigation-bar/)。停靠的工具栏和导航栏绝不出现在同一个屏幕上：两者都要占用底边。

### 内嵌、停靠还是悬浮

| 变体 | 所在位置 | 项 | 适用于 |
| --- | --- | --- | --- |
| Inline（默认） | 就在内容之中，由你的布局放置；在默认系统中没有自己的表面 | 彼此靠拢，需要多长就多长，每个项都为自己的触摸目标留出空间 | 页面某一部分的控件：编辑器的格式、表格的操作、一排筛选条件 |
| Docked | 横跨底边并与之齐平，颜色延伸到系统栏之下 | 沿宽度铺开，彼此间距相等 | 手机上详情屏幕的操作：一封打开的邮件、一张照片、一份文档 |
| Floating | 内容之上一块圆角、抬升的表面，由你的布局放置 | 彼此靠拢，需要多长就多长，每个项都为自己的触摸目标留出空间 | 位于内容之上的工具，而周围的内容应保持可见：画布、地图 |

停靠的工具栏始终是横向的。内嵌或悬浮的工具栏可以是纵向的，位于内容旁边。同一个产品可以在一个屏幕上内嵌工具栏，在另一个屏幕上停靠工具栏，在第三个屏幕上让工具栏悬浮。设计系统增加的变体采用内嵌的结构，并使用自己的值。

停靠的工具栏把它的项沿宽度铺开，项与项之间的距离绝不小于它的间隙（默认系统中为 16）。内嵌或悬浮的工具栏让它的项彼此靠拢：相邻两项之间隔开的距离，只够让每个项沿这一排保有自己的触摸目标，且绝不小于间隙（默认系统中内嵌为 4，悬浮为 0）。大号按钮彼此相接，中号按钮相隔 8，小号按钮相隔 16。工具栏绝不会为此把某个项加宽或改变它的样式，而且无论用鼠标还是触摸，间距都相同。

### 项

- 大多数操作使用 `text` 变体的纯图标[按钮](/zh-cn/components/button/)。工具栏最终要引向的那个操作（例如“发送”或“完成”）应当更醒目：用 filled 的纯图标按钮，也可以配上 `wide` 宽度；如果文字比图标更容易理解，就用带标签的 filled 按钮。
- `narrow` 的纯图标按钮适合有许多小操作的工具栏。它画出来比它的目标窄，工具栏会在它与相邻项之间为这个目标留出空间。
- 用来开启和关闭某项功能的操作（“粗体”“静音”），做成带 `toggle` 的纯图标按钮。开或关的筛选条件，做成带 `toggle` 的带标签按钮。每个按钮都保有自己的选中状态和自己的朗读内容。
- 对于提供几条命令供选择的控件，把一个[菜单](/zh-cn/components/menu/)锚定到工具栏里的某个 `Button` 上。对于有若干变化形式的主操作，例如“保存”和“另存为”，请使用[带菜单的按钮](/zh-cn/components/button-with-menu/)。
- 保持顺序稳定。用户靠位置寻找操作，各个屏幕上项的位置变来变去的工具栏很难学会。
- 只有一个项的停靠工具栏会把它居中。请考虑一下，这个项是不是更应该放在内容里。

### 组与分隔符

把相关的项放进一个组：“粗体”“斜体”和“下划线”；“撤销”和“重做”；“放大”和“缩小”。工具栏会把两个组分隔开，也会把一个组与不属于任何组的项分隔开，方式与设计系统在别处分隔各部分时相同：在默认系统中是一条短线，两侧各留 8 的空间；在以空间作为分隔方式的设计系统下，则是 16 的空白，没有线。只有当某个工具栏有它自己的理由时，才在它上面设置 `separation`。分隔符项在两个不在组里的项之间绘制同样的线。

工具栏绝不在任何一端画线，也绝不让两条线并排出现。当分组对用户有意义时（“文字样式”），给组一个 `label`，让屏幕阅读器读出它的名称。没有标签的组只把它的项分隔开，什么也不朗读。

### 项放不下时

工具栏绝不会让项换行或缩小。当它的项需要的空间超过它所拥有的，它会从末尾开始一次隐藏一个项，并在剩下的最后一个项之后显示一个溢出按钮。这个按钮打开一个菜单，按原有顺序列出被隐藏的项，带着它们的标签、图标和状态：操作成为菜单项，切换按钮成为复选项，菜单按钮成为子菜单，带菜单的按钮成为它的主操作，后面跟着一个子菜单。选择其中一项，所做的事与被隐藏的项完全相同。用 `overflow-label`（“更多操作”）为溢出按钮命名，或者用 `setWords({ toolbarOverflowLabel: … })` 为整个产品命名一次。

用 `toolbar-overflow="never"` 标记必须留下的项，例如“发送”或“完成”：工具栏会改为隐藏它前面的项。如果绝不隐藏的项仍然放不下，这一排其余的部分会滚动。要让每个项都留在这一排里、改为滚动而不隐藏任何项，请设置 `overflow="scroll"`。

隐藏哪些项，在工具栏绘制之前就已决定，并在它的长度变化的那一帧里重新决定，所以绝不会出现某个项先被画出来又被隐藏的情况，这一排也绝不会跳动。

### 推荐

- 按工具栏中的控件所做的事来给它命名：“格式”“邮件操作”。
- 对眼下不适用的操作，请禁用它而不是移除它，这样其他操作就不会移位。
- 排列各项时，把用户最需要的放在前面：工具栏从末尾开始隐藏。
- 放置悬浮的工具栏时，避开用户在使用它时需要看到的内容，也避开导航栏和系统边衬区。

### 避免

- 不要在工具栏里放文本字段、滑块或一组纸片（Chip）。它们各自都需要方向键，而工具栏正是用方向键来移动焦点的。搜索应当放在应用栏或页面里。
- 不要在同一个屏幕上同时使用停靠的工具栏和导航栏。
- 不要为了让工具栏显得突出而改变项的样式。请改为给按钮选用 tonal 或 filled 变体。
- 不要在工具栏里放导航目的地。它的项是作用于内容的控件。

## 无障碍

<ComponentAccessibility name="toolbar" />

### 组件负责的部分

- 工具栏是一个 Tab 停靠点，遵循 WAI-ARIA 的 toolbar 模式。Tab 进入工具栏时，落在上次拥有键盘焦点的项上，否则落在第一个未禁用的项上；再按一次 Tab 就离开工具栏。一个有八个切换按钮的格式工具栏，按一次 Tab 就能越过，而不是八次。
- 在工具栏内部，沿其轴向的方向键移动到下一项或上一项，并在两端循环：横向工具栏用右、左方向键，纵向工具栏用下、上方向键。Home 和 End 移动到第一项和最后一项。在从右到左的布局中，左方向键移动到下一项。组里的项就是工具栏的项，带菜单的按钮的两半各是一个停靠点，分隔符会被跳过，溢出按钮是最后一个停靠点。
- 移动焦点绝不会激活某个项。Enter 和 Space 对获得焦点的项起作用，效果与该项自身的行为一致，所以切换按钮照常切换。
- 锚定在某个项上的菜单打开期间，按键归菜单处理。菜单关闭时，焦点回到打开它的那个项。
- 当获得焦点的项因工具栏变窄而被隐藏时，焦点移到溢出按钮上。
- 方向键会跳过禁用的项，禁用的项也永远不会成为 Tab 停靠点，因为禁用的按钮不可聚焦。
- 这里的游动焦点与列表、菜单和标签页在各平台上使用的是同一套。
- 在有 toolbar 角色的平台（Web、React Native）上，工具栏暴露为一个由 `label` 命名的 toolbar，并带有它的方向。SwiftUI、Compose 和 Flutter 没有这个角色：在这些平台上，它是一个由 `label` 命名的组，按顺序包含它的各个项。
- 带 `label` 的组暴露为一个以该名称命名的组。组与组之间的线暴露为分隔符。
- 溢出按钮暴露为一个打开菜单的按钮，带有它的展开状态；它的菜单包含每一个被隐藏的项，各带自己的名称和状态。
- 每个项保留自己的名称、角色、状态和目标。工具栏不给它们添加任何东西，也从不改变它们的样式。
- 相邻两项的点击区域绝不重叠。在停靠的工具栏中，它们在间隙的正中相接；默认系统的间隙（16）足够宽，每个项在那里同样能保有完整的 48 触摸目标；间隙更窄的设计系统会让项与项之间的目标变窄。在内嵌或悬浮的工具栏中，无论使用哪种指针，各项之间的距离都恰好够每个项沿这一排保有一个触摸目标的长度，所以窄的或小的按钮绝不会被相邻项挤占。在没有相邻项的一侧，项保有完整的目标。
- 当 `overflow` 为 `scroll` 时，获得键盘焦点的项如果已滚出可见范围，工具栏会把它完整地滚入可见范围。
- 文本变大时，工具栏沿垂直于其轴向的方向变大，以容纳它的项。它不会缩放这些项。
- 调试构建会报告：缺少 `label`、工具栏没有任何项、某个项不属于任何一类、停靠的工具栏被设为纵向、溢出按钮缺少名称，以及未知的变体、方向、overflow 或 separation。

已知的平台差距：

- SwiftUI、Compose 和 Flutter 没有 toolbar 角色。屏幕阅读器读到的是一个有名称的组，而不是工具栏，各个包的 README 都说明了这一点。这个组不暴露它的方向。
- SwiftUI、Compose、Flutter 和 React Native 待跟进：它们没有内嵌变体，没有组或分隔符，没有溢出菜单，而且只接受 `Button` 作为项。
- Web：停靠的工具栏读取 `env(safe-area-inset-bottom)`，除非页面的 viewport meta 带有 `viewport-fit=cover`，否则它的值是零。
- Web：纵向工具栏的溢出菜单在溢出按钮下方打开，而不是在它旁边，因为菜单没有侧向的放置方式。
- Web：内嵌或悬浮的工具栏从它的父元素测量自己可以占用的空间。如果在一个 flex 行中，工具栏的空间由它的兄弟元素而不是父元素决定，那么只有当它的父元素或它的项改变尺寸时，它才会重新决定哪些项放得下。
- Web：项在滚动时，某个项在垂直于工具栏轴向的方向上超出工具栏的部分都会被裁掉：它的点击区域、它的焦点环或光晕、elevated 按钮的阴影。不显示滚动条。
- 在 SwiftUI 上，这一个 Tab 停靠点是面向键盘的焦点组：全键盘控制（Full Keyboard Access）用方向键在它的各项之间移动，用 Tab 离开它。这些按键是作为规则测试的，尚未用真实键盘验证。
- SwiftUI：项在滚动时，末端项的点击区域止于工具栏的边缘。尺寸变化使这些项开始滚动或不再滚动时，它们会被重新创建，所以项会失去键盘焦点，或中断正在进行的按下。
- 在 React Native 上，Tab 停靠点和方向键只在连接了硬件键盘时才起作用，与标签页那一排的情况相同。
- React Native 有 toolbar 角色，但没有办法暴露方向，所以纵向的工具栏不会朗读为纵向。
- React Native：悬浮工具栏的宽度、硬件键盘上的按键、把获得焦点的项滚入可见范围，以及 VoiceOver 和 TalkBack 是否朗读工具栏，都只在 Jest 中验证过，没有在真机上验证。
- 在 `m3-like` 下，工具栏绘制的是默认系统的值：Material 的工具栏取值要等保真度参考覆盖到它。Material 的 vibrant 工具栏会给它的项改色，这无法绘制，因为工具栏从不改变项的样式（模仿差距 `toolbar-vibrant-color`）。

### 需要你做的事

- 给工具栏一个 `label`，用你的产品语言给每个项各自的标签（纯图标的操作也不例外），并用 `overflow-label` 或你产品自己的文字给溢出按钮一个名称。
- 里面只放 Tanrei `Button` 和带菜单的按钮，可以单独放、放进组里，或给它们锚定菜单。
- 操作不适用时，请禁用它；原因不明显时，在附近说明原因。
- 菜单按钮的菜单由你自己打开和关闭，就像对待任何菜单一样。
- 放置悬浮的工具栏时，不要让它盖住工具栏打开期间仍然需要的内容。
