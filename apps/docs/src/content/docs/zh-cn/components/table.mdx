表格用于有两个维度的数据：价目表、套餐对比、带类型和默认值的设置项列表、几样东西在几个平台上的状态、用户要处理的记录。列标题可以请求让各行按这一列排序，没有行的表格显示你的空状态，各行下方的状态行容纳你的句子和你的分页。行可以各用一个复选框来选择，也可以用单选按钮只选一行，正在等待行到来的表格会说明自己正忙。表格自己从不排序、筛选、获取数据或分页：给它什么行，它就按给它的顺序画什么行。它不调整列宽。

在 Web 上，它是包在你自己的原生 `<table>` 外面的 `<tanrei-table>`。这个元素没有 shadow root，表格也从不会被设成别的 `display`，所以爬虫、复制粘贴到电子表格，以及屏幕阅读器的表格导航，遇到的都是一个普通的 HTML 表格。其他平台尚未实现。

`@tanrei/web/table.css` 在任何脚本运行之前就画出整个表格。元素自己也会把同一份样式表加进页面，所以只加载了脚本的页面同样能得到画好的表格，只是晚一会儿。

### 你要写的内容

| 部件 | 在 Web 上 |
| --- | --- |
| 列 | `<thead>` 唯一那一行里的一个 `<th scope="col">`。它的文字就是列标题。 |
| 列的对齐方式 | 列标题单元格上的 `data-align="start"`、`"center"` 或 `"end"`。`end` 用于需要相互比较的数字。 |
| 文本不换行的列 | 列标题单元格上的 `data-wrap="false"`，用于标识符、日期和数字。 |
| 行 | `<tbody>` 里的一个 `<tr>`。表尾行是 `<tfoot>` 里的一个 `<tr>`。 |
| 单元格 | 一个 `<td>`。里面是文本、组件，或者什么都没有。 |
| 行标题 | 作为第一个单元格的 `<th scope="row">`，同时在元素上设置 `row-headers`。 |
| 名称 | 一个 `<caption>`；如果表格上方的标题已经为它命名，则用元素上的 `label`。 |
| 可排序的列 | 列标题单元格上的 `aria-sort="none"`、`"ascending"` 或 `"descending"`，以及包在其文字外面的 `<button type="button">`。单元格上的 `data-value` 是 `sort` 事件带出的名称。 |
| 没有行 | `<tbody>` 里的一个 `<tr data-part="empty">`，其中只有一个 `<td colspan>`，里面放你的空状态。 |
| 状态行 | 表格之后的一个 `<div data-part="status">`，里面放一个 `<p role="status">` 和你的分页。你没有写这个段落时，元素上的 `status` 会写出它。 |
| 可以选择的各行 | 元素上的 `selection="multiple"`（最多只选一行时用 `selection="single"`），以及每一行里作为第一个单元格的 `<td data-part="selection">`。 |
| 可以选择的一行 | `<tr>` 上的 `data-value`，以及它的选择单元格里的一个 `<tanrei-checkbox label-hidden>`，`single` 时则是一个 `<tanrei-radio-button label-hidden>`。`<tr>` 上的 `data-selected` 表示它已被选中。 |
| 针对所有行的复选框 | 表头行的选择单元格里的一个 `<tanrei-checkbox label-hidden>`。元素上的 `select-all-label` 为它命名。`single` 时这个单元格留空。 |
| 加载中的表格 | 元素上的 `loading`。 |
| 占位行，代表尚未到达的行 | 一个 `<tr data-placeholder aria-hidden="true">`，它的单元格留空，或者放一个骨架屏占位符。 |

元素会把列标题单元格上的对齐和换行设置带给这一列的每个单元格。要让它们在脚本运行之前就绘制出来，请像本页的演示那样，在每个单元格上重复 `data-align` 和 `data-wrap`。

可排序的列，是一个说明各行当前顺序的列标题单元格，它的文字外面包着你自己的按钮：

```html
<th scope="col" aria-sort="ascending" data-value="name"><button type="button">名称</button></th>
<th scope="col" aria-sort="none" data-value="price" data-align="end"><button type="button">价格</button></th>
```

样式表让整个列标题单元格成为这个按钮，并根据 `aria-sort` 画出标记：各行没有按这一列排序时是双向箭头，按它升序排列时是向上的箭头，按它降序排列时是向下的箭头。你不用写任何图标。请加载 `@tanrei/web/icons.css` 和图标字体，因为这些标记是图标集中的字形。

表格从不排序。按下按钮会触发 `sort`，屏幕上什么都不变；由你为各行排序，并写上新的 `aria-sort`：

```js
table.addEventListener('sort', (event) => {
  const { column, index, direction } = event.detail; // 'price', 2, 'ascending' | 'descending'
  showRows(sortedBy(column, direction));              // 你的数据、你的比较方式，或者你的服务器
  for (const th of headerCells) th.setAttribute('aria-sort', th.dataset.value === column ? direction : 'none');
});
```

`direction` 是用户请求的方向：`ascending`；如果各行已经按这一列升序排列，则是 `descending`。没有清除排序的第三次按下。你不必给出用户请求的顺序：可以把各行排成另一种顺序，也可以不按任何顺序排列。

对于由服务器排序的表格，请用链接代替按钮：`<a href="?sort=price&order=asc">价格</a>`，指向另一种顺序的同一个表格。它不需要脚本就能工作。这时 `sort` 会在浏览器跟随链接之前触发，`event.preventDefault()` 则让页面留在原处。

在表格之后、元素之内写状态行：把你的句子放在一个作为状态的段落里，再加上你的分页。

```html
<tanrei-table>
  <table>…</table>
  <div data-part="status">
    <p role="status">第 1–20 件，共 132 件</p>
    <tanrei-pagination label="商品的页面" variant="compact" size="small" page="1" count="7" previous-label="上一页" next-label="下一页" count-text="第 {page} 页，共 {count} 页"></tanrei-pagination>
  </div>
</tanrei-table>
```

句子位于起始边缘，分页位于末尾；两者并排放不下时，分页排到句子下方。状态行不随各列横向滚动；如果表格的各行在自己的框内滚动，它会留在表格底部。表格什么都不数，也不写任何文字：“第 1–20 件，共 132 件”是你的，用你的语言写。你更改段落的文本时，新的文本会以礼貌（polite）的方式朗读给辅助技术的用户。如果你的 HTML 里没有这个段落，元素上的 `status` 属性会替你写出它。你自己写了段落时，被朗读的就是你写的那一个，这个属性不改变任何东西。

放在末尾的是尺寸为 `small` 的[分页](/zh-cn/components/pagination/)：像这里一样用紧凑形式，或者在用户按页码跳转时用带页码的形式。如果让用户选择每页显示多少行，就在分页之前放一个用于此事的[下拉选择框](/zh-cn/components/select/)，并把两者放进一个由你布局的元素里；当前显示的行的范围是你的句子，不属于分页。[上一页/下一页链接](/zh-cn/components/previous-next-links/)不放在这里：它们通向有标题的页面，而不是同一个列表中的行。表格只负责摆放你给它的内容：页面变化时，由你更换行和句子。

在元素上设置 `selection="multiple"`，并让每一行都以一个选择单元格开头。在表头行里，这个单元格放针对所有行的复选框。在表体的行里，它放这一行的复选框，行则用 `data-value` 带上你用来识别这条记录的名称：

```html

    <caption>需要补货的商品</caption>
    <thead>

        <th scope="col">名称</th>
        <th scope="col" data-align="end">价格</th>
      </tr>
    </thead>
    <tbody>
      <tr data-value="grinder" data-selected>
        <td data-part="selection"><tanrei-checkbox label-hidden checked></tanrei-checkbox></td>
        <th scope="row">手摇磨豆机</th>
        <td data-align="end">399.00</td>
```

选择由表格保存。用户更改某个复选框时，元素会在那一行上写 `data-selected`，让表头行的复选框与各行保持一致，并触发一次 `selectionchange`，其中带有所有选中行的值，按行的顺序排列：

```js
table.addEventListener('selectionchange', (event) => {
  if (!(event instanceof CustomEvent)) return;       // 见下面的说明
  const { values } = event.detail;                   // ['grinder', 'scale']
  // 你的句子，用你的语言，写进你自己写的那个段落
  table.querySelector('[role="status"]').textContent = `已选择 ${values.length} 件，共 ${total} 件`;
});
```

- 要自己选中某一行，就在它的 `<tr>` 上写 `data-selected`；去掉这个属性，这一行就不再被选中。元素会选中或取消选中这一行的复选框，不触发任何事件。
- 一行是否被选中，写在这一行自己身上（`data-selected`）。你换一种顺序重新给出的行，原来选中的仍然选中，没有选中的仍然没有选中；第一次交给表格的行，只有它自己这样标明时才是选中的。
- 没有 `data-value` 的行不能被选择。请像表尾行那样，把它的选择单元格留空。
- 表头行的复选框，在所有行都被选中时是选中的，只有一部分行被选中时是半选的，没有可以选择的行时是禁用的。它代表的是交给表格的那些行，绝不代表其他页的行。
- 选择列不是数据列。`row-headers` 和 `sticky-first-column` 指的是它后面的那一列，`sort` 事件的 `index` 也不把它计算在内。
- 在可以选择的行上任何位置按下，都会像按下复选框一样改变它的复选框。单元格里的链接、按钮和输入框保留各自的按下行为；拖动、选择文本、双击中的第二次点击以及按住修饰键的点击都不会改变任何东西。整行作为一个整体绘制悬停和按下状态；键盘操作仍然在复选框上。

浏览器自己也有一个名为 `selectionchange` 的事件，用于文本选区的变化；单元格里的文本字段发出的这个事件会经过表格。表格的事件是带有 `detail.values` 的 `CustomEvent`，浏览器的则不是。请像示例那样检查这一点。

对于没有脚本也必须能用的页面，请使用原生复选框。复选框为 `checked` 的行，仅凭样式表就会画成选中的样子，这些复选框也会随你的表单一起提交：

```html
<tr data-value="grinder">
  <td data-part="selection"><input type="checkbox" name="product" value="grinder" checked aria-label="选择手摇磨豆机" /></td>
```

### Markdown

Markdown 渲染器输出的是一个裸的 `<table>`。请在构建时把它包起来；Tanrei 不会在运行时移动你的内容。用 rehype 只需一小步：

```js
import { visit, SKIP } from 'unist-util-visit';

/** 把文档里的每个表格包进 <tanrei-table>。 */
export function rehypeTanreiTable() {
  return (tree) =>
    visit(tree, 'element', (node, index, parent) => {
      if (node.tagName !== 'table' || parent?.tagName === 'tanrei-table') return;
      parent.children[index] = { type: 'element', tagName: 'tanrei-table', properties: {}, children: [node] };
      return SKIP;
    });
}
```

渲染器自己在单元格上写的 `align="right"` 会被读作 `end`，`align="left"` 读作 `start`，所以在从右到左的页面上，“数字靠右”就变成了“数字靠末尾”。

## 指南

### 它是不是表格

有行有列的数据才用表格。不要用表格把东西并排摆放：辅助技术会为每个单元格朗读行、列和行列标题，对并非表格性质的内容来说这只是噪音。并排摆放请用布局。

没有第二个维度的一组键和值，更接近描述列表，而不是表格。

### 密度

| `density` | 只有一行文字的行的高度 | 用于 |
| --- | --- | --- |
| `regular`（默认） | 46 | 供人阅读的表格：行数不多，单元格会换行。 |
| `compact` | 32 | 供人扫读的表格：几百行，标识符和值。 |

行没有自己的高度。它与其中最高的单元格一样高。

### 区分各行

| `separation` | 绘制什么 |
| --- | --- |
| `auto`（默认） | 设计系统选定的方式：在默认系统中是一道细线。 |
| `divider` | 行与行之间、表头行下方和表尾行上方各一道细线。 |
| `gap` | 留空，不画线。 |

`striped` 每隔一行用一种柔和的颜色填充表体的行。它用于有许多相似行的宽表格，视线横向移动时容易跟丢所在的行。它可以与任何一种分隔方式组合。

### 列

- 列按自己的内容确定宽度。列绝不会比其中不可断开的内容更窄，长文本的列则占用短列留下的空间。
- 文本会换行，绝不截断。标识符不在内部断开，而是把所在的列撑宽。
- 数字列靠末尾对齐，让数位对齐。文本留在起始侧。只有标记，或者在每一行里都是同一类答案的单个词，才居中。
- 只在不得不这样做的地方自己指定列宽（在列标题单元格上写 `style="width: …"`）。它会取代由内容得出的宽度。

### 放不下的时候

- 表格在自己的框内滚动，而不是让页面滚动。框的某条边上的一道细线，表示这条边之外还有列。
- `sticky-first-column` 让第一列始终可见，其余各列在它下面滚动。当它会占去框的一半以上时，它会自行放开，所以手机屏幕绝不会被固定的那一列占满。
- `sticky-header` 让表头行在各行滚动时始终可见。它在你的布局限制了表格高度的地方起作用（元素上的 `max-block-size`）；它不跟随页面。
- 如果表格位于页面表面之外的另一种表面上（卡片、对话框），并且让表头行或第一列始终可见，或者带有状态行，请把 `--tanrei-comp-table-sticky-container-color` 设为那个表面的颜色。这些部分用这个颜色填充，这样从它们下面经过的行和列才不会透出来。

### 排序指引

- 用户会凭某一列去找某一行时，才让这一列可排序：名称、日期、金额、类别。备注列不属于这种情况。
- 每个可排序的列都画出标记，静止时也画，这样在触摸屏上也能看出哪些列标题可以按下。
- 一次只按一列排序。第二个排序键要用你自己的控件。
- 想让新的顺序被朗读出来，就在状态行里说明（“已按价格从高到低排序”）。表格自己什么都不朗读。
- 带有可排序列的表格，表头行在 regular 密度下至少高 44；用于触摸时，两种密度下都是 48。

### 选择行指引

- 用户要同时对几条记录执行操作（删除、导出、移动）时，才让他们选择行。只针对一条记录的操作，放在它所在的行里。
- 答案是一条记录时（套餐、地址、作为对比基准的版本），用选择一行（`single`）。不要用它来打开记录。
- 在行上任何位置按下都会选择它。如果一行还要打开它的记录，请为此在行标题里放一个链接，而不是靠按下整行。
- 在状态行里说明选中了多少行（“已选择 3 件，共 132 件”）。表格什么都不数。
- 把对选中的行执行操作的按钮放在表格上方。按钮是你的；表格告诉你选中了什么。
- “全部 132 件”要用你自己的控件来提供。表头行的复选框选择的是交给表格的那些行，绝不是其他页的行。
- 每个复选框都是焦点顺序中的一个停靠点。一页的行数要控制在用户可以用 Tab 逐个走完的范围内，其余的分页。一个表格的单选按钮合起来只算一个停靠点。
- 带有复选框或单选按钮的行在 regular 密度下至少高 44；用于触摸时，两种密度下都是 48。紧凑的行在使用指针时仍然紧凑。
- [Tag](/zh-cn/components/tag/) 和[行内代码](/zh-cn/components/inline-code/)在你没有选择其他变体时都是 tonal 的；在默认系统中，tonal 的填充与选中行的填充几乎相同，所以在选中的行上看不出它们的形状。它们的文字仍然可读。在可以选择行的表格里，请使用 outlined 的 Tag。

### 加载指引

- 首次加载用占位行，数量与你预计的行数大致相当。
- 更换顺序或换页时保留原有的行。不要用占位行或[加载指示器](/zh-cn/components/loading-indicator/)替换用户正在读的行。
- 在状态行里写“正在加载”，结束后说明到达的内容（“第 1–20 件，共 132 件”）。
- 清除 `loading` 时移除占位行。留下来的占位行仍然会被画出来，并在调试构建中报告。

### 没有行与状态行

- 没有行的表格使用空状态，说明为什么没有行、接下来该做什么。回应搜索或筛选的空状态应设置 `live`，这样结果才会被朗读。
- 状态行只用来说明表格现在显示的内容：共有多少行，显示的是其中哪些。对行执行操作的按钮应放在表格上方。

### 推荐

- 给每个表格一个名称：人人都看得到的说明文字；如果上方的标题已经说明了它是什么，则用 `label`。
- 只要第一列说明了每一行是什么，就把它写成行标题（`<th scope="row">` 加 `row-headers`）。
- 没什么可说的单元格就留空。如果“没有”本身就是信息（“不可用”），就把它写出来。

### 避免

- 不要用表格给屏幕排版。
- 不要指望靠条纹或颜色来传达含义。单元格里的状态应是一个词，或者是一个用标签文字写明这个状态的 Tag。
- 不要为了填满空单元格而在里面放一个破折号。
- 不要让行可以被按下，也不要在列标题里写你自己的排序标记或顺序。列标题只有按上面的 HTML 写法才变得可以按下，别无他法。行靠它的复选框或单选按钮来选择，可以打开的行则不属于表格。
- 不要在表格加载期间把它变淡或禁用。

## 无障碍

<ComponentAccessibility name="table" />

### 组件负责的部分

- 原生表格始终是表格：行、列标题、行标题和单元格都是浏览器自己的，无论有没有条纹、采用哪种密度、是否正在滚动、是否固定了某一列或表头。
- 说明文字为表格命名。没有说明文字时，`label` 成为表格的 `aria-label`，不绘制。两者都有时，名称是说明文字。
- 表格在自己的框内滚动时，这个框是焦点顺序中的一个停靠点，排在单元格里的任何东西之前，同时也是一个以表格名称命名的区域。方向键、Page Up、Page Down、Home 和 End 可以滚动它。不滚动的表格不增加停靠点。
- 焦点环画在框的边缘以内，所以不会被裁掉。
- 如果表格每行的第一个单元格是普通的 `<td>`（渲染出来的 Markdown），并且设置了 `row-headers`，元素会给它们加上行标题角色。
- 在从右到左的布局中，各列从右侧排起，滚动从右侧开始，固定的第一列位于右侧，每个单元格的文本保持自己的方向：数字绝不会被颠倒。
- 文本放大到 200% 时，列宽会重新计算；放不下的地方，表格在自己的框内滚动。
- 在强制颜色模式下，每条线都是文本颜色；带条纹的表格无论采用哪种分隔方式都会画出行线，因为这个模式会去掉填充。
- 可排序列的列标题单元格是带有顺序（`aria-sort`）的列标题，其中你的按钮以列标题的文字命名。标记对辅助技术隐藏。
- 排序按钮是焦点顺序中的一个停靠点。Enter 和 Space 按下它；它是链接时，只有 Enter。按下之后焦点仍留在它上面。如果你把表头行连同各行一起替换了，焦点会移到同一列的新按钮上。
- 排序按钮的焦点指示画在它的列标题单元格内部；用键盘聚焦的按钮如果被固定的第一列或状态行挡住，会被带到看得见的地方。
- 空状态所在的那一行是只有一个单元格的一行。表格不给它添加任何角色和文字。
- 状态行的段落是一个状态：它的文本变化时会以礼貌（polite）的方式朗读，不移动焦点；首次绘制时什么都不朗读。
- 在强制颜色模式下，排序按钮的标签和标记采用按钮的文本颜色，已排序的列只靠它的箭头来表明。
- 没有脚本时，排序按钮、它们的标记、空状态所在的那一行和状态行照样绘制，排序链接也能工作。`sort` 事件需要脚本。
- 可以选择行的表格仍然是表格。它不获得 grid 角色，行不获得选中状态，也没有任何按键把焦点从一个单元格移到另一个单元格。行的复选框或单选按钮的选中状态说明这一行已被选中。
- 表头行的复选框会说明自己是选中还是未选中，半选时则说明是混合；没有可以选择的行时是禁用的。
- 每个复选框都是焦点顺序中单独的一个停靠点：先是表头行的复选框和排序按钮，然后是每一行的复选框。Space 选中或取消选中它。
- 行的复选框或单选按钮没有自己的名称时，以这一行的行标题单元格命名。
- 在 `single` 下，单选按钮合起来是一个停靠点：Tab 停在已选中行的单选按钮上（一行都没选中时停在第一行的上），再按一次 Tab 就离开表格。方向键移到下一行或上一行的单选按钮并选中那一行，到头后从另一端继续。每个单选按钮会连同行的名称、状态以及它在其中的位置一起读出，例如“选择团队版，单选按钮，已选中，第 2 个，共 3 个”。它们不包在单选组里，因为单选组无法容纳表格的行。
- 在选择单元格里的任何位置按下，都是按下其中的复选框。某个复选框有焦点时，如果你替换了各行或重新排列了各行，焦点会移到 `data-value` 相同的那一行的复选框上。
- 对指针来说，可以选择的行是其复选框的更大的目标。行不会得到角色、焦点停靠点或选中状态，所以键盘和屏幕阅读器面对的仍是那个已命名的复选框，行里的文本也仍然可以选择和复制。
- 在强制颜色模式下，选中行的填充消失，复选框或单选按钮仍然说明这一行已被选中。
- 设置了 `loading` 期间，表格以忙碌状态暴露给辅助技术（`aria-busy`）。占位行对辅助技术隐藏，所以用户听到的是表格正忙，而不是一行行空无一物的内容。加载开始或结束时，表格自己什么都不朗读。
- 没有脚本时，选择列、选中的行（`data-selected`，或者已选中的原生复选框）和占位行照样绘制，原生复选框也能在你的表单里工作。让表头行的复选框保持一致，以及 `selectionchange` 事件，都需要脚本。没有脚本时，行不显示悬停状态和指针光标，在复选框旁边按下也不会改变任何东西。
- 没有名称的表格、未知的密度、分隔方式或选择方式、写在表体之前的表尾行、单元格数多于或少于列数的行、没有列标题的可排序列、同时排序的两列、没有名称的行复选框、同时被标为选中的多行、`single` 下种类不对的控件，以及不在加载中的表格里的占位行，会在调试构建中报告。

### 需要你做的事

- 给表格命名。会滚动却没有名称的表格是一个焦点停靠点，用户无法把它与别的停靠点区分开。
- 给每一列一个列标题单元格，并把行标题标记为行标题。列标题和行标题是结构，不是样式。
- 需要两级列标题或合并单元格的表格，请尽量保持简单。它们按 HTML 的方式工作，但这个组件没有任何部分是围绕它们设计的；拆分表格通常更清楚。
- 单元格里可以按下的东西（链接、按钮）保留自己的名称、焦点和目标尺寸。请给它留出空间。
- 为各行排序之后，在列标题单元格上写上新的 `aria-sort`：其中一个写 `ascending` 或 `descending`，其他可排序的列写 `none`。不要把这个属性留在没有按钮的列标题上。
- 状态行的段落没有文本时，也要把它留在页面里，这样你下一次给它的文本才会被朗读。
- 用 `select-all-label` 为表头行的复选框命名；表格没有行标题时，用各行复选框的 `label` 为它们命名。
- 加载开始和结束时，都在状态行里说明。这是这一变化唯一会被朗读的地方。

### 文字

Tanrei 不自带任何文字。表格只向你要其中一段，即表头行复选框的名称：元素上的 `select-all-label`，或者用 `setWords()` 给出的 `selectAllLabel`。另外两段由你写在自己的 HTML 里。

| 文字 | 在哪里给出 |
| --- | --- |
| 表头行复选框的名称（“选择所有商品”） | 元素上的 `select-all-label`，或者用 `setWords({ selectAllLabel: '选择所有行' })` 为所有表格只给一次。 |
| 行的复选框或单选按钮的名称（“选择手摇磨豆机”） | 这一行的 `<tanrei-checkbox>` 或 `<tanrei-radio-button>` 上的 `label`，或者原生控件上的 `aria-label`。有行标题时可以不写：行标题会为复选框命名。 |
| 状态行的句子（“已选择 2 件，共 4 件”“正在加载”） | 状态行的段落；你不写段落时，用元素上的 `status`。 |

没有为表头行的复选框命名时，它照样绘制、照样能用，但没有无障碍名称，调试构建会报告缺少这段文字。
