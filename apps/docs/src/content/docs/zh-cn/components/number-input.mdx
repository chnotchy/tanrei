数字输入框就是[数字字段](/zh-cn/components/number-field/)里的那个方框，单独拿出来：容器、数字、它的前缀和后缀，以及两个步进按钮。它上方没有标签行，下方没有帮助文本和错误文本。

用户读到的标签位于别处时，就单独使用它：

| 位置 | 用户读到的标签 | 输入框的 `label` |
| --- | --- | --- |
| 滑块旁边，同一个行标题之下 | 这一行的标题 | 与滑块的相同的词：“缩放比例” |
| 表格的单元格 | 列标题 | 列和行：“数量，橡木书桌” |
| 工具栏里的一个尺寸 | 旁边的字形或文本 | 它设置的是什么：“字号” |

单独使用时，输入框需要它自己的 `label`。它就是无障碍名称。stacked 的输入框绝不会把它画出来；filled 或 outlined 的输入框把它画成浮在方框里的标签。

它是一个**高级**组件：一个不带任何附加功能的控件，供自己动手组合的产品使用。大多数表单需要的是[数字字段](/zh-cn/components/number-field/)，也就是放在字段里的这个输入框，可以直接使用。

**使用它的组件**是[数字字段](/zh-cn/components/number-field/)。要自己用字段框住它，就把它放进[字段](/zh-cn/components/field/)，由字段为它命名、描述它、把它标记为必填，并让它进入错误状态。

它是一个块，宽度与所在的位置相同，单独使用和放在字段里都是如此。它没有自己的宽度：想要窄一些的方框，就给它一个窄一些的位置。

在 Web 上它是 `<tanrei-number-input>`。其他平台尚未实现。

### 用法

`value` 是一个数字；输入框里没有数字时是 `null`。它在用户**确认**时改变——焦点离开、按下 Enter，或者步进——而不是每按一次键就改变。在此期间，`input` 带有文本当前读作的数字。

### 与滑块搭配

滑块适合凭感觉选择的值，数字输入框适合已经知道的值。把它们放在你自己的标题之下的同一行里，给两者相同的名称、范围和步长，并像上面的示例那样，把各自的 `input` 写进对方的 `value`。后缀读出来不通顺的地方，给出 `valueText`：`×` 对应“1.5 倍”。有了滑块，那两个按钮就不必要了，`no-steppers` 把它们去掉；方向键仍然可以步进。

### 手写在字段里

用字段包住一个数字输入框，就是把数字字段拆开来写。输入框自己的 `label` 留空：由字段为它命名。`label`、`error`、`disabled` 和必填设置写在字段上；`name`、`value`、范围和单位写在输入框上。

```html
<tanrei-field label="数量" required required-text="必填"
  supporting-text="每笔订单最多 99 件。">
  <tanrei-number-input name="quantity" min="1" max="99" invalid-text="请输入数字。"
    increment-label="增加" decrement-label="减少"></tanrei-number-input>
</tanrei-field>
```

  </tanrei-field>

只有输入框知道的事，由它告诉所在的字段。字段的帮助文本与方框里的文本对齐：无论是否绘制步进按钮，它都从方框的文本内边距处开始，也在文本内边距处结束。filled 或 outlined 的输入框自己画出字段的标签，让它浮在方框里，所以字段不绘制标签行。文本不是数字时，字段会进入错误状态，显示输入框的 `invalidText`；输入框没有给出时，显示字段自己的 `errorText`。

没有什么需要你动手去保持同步：数字输入框没有字符计数。

数字和它的单位是连成一体书写的。前缀写在数字之前，后缀写在数字之后，方向按单位自身所用文字的书写方向，与页面的方向无关。所以“44 px”“$ 120 USD”和“40 %”在阿拉伯语或希伯来语的页面里，读起来与在英语页面里一样；用阿拉伯字母或希伯来字母写的单位，则位于数字的左侧。步进按钮和标签跟随页面。`align="end"` 让数字紧靠它的单位：单位用拉丁字母或符号书写时，在两种方向下都靠右。要让拉丁字母的货币代码位于数字的左侧，就让后缀以一个从右到左标记（U+200F）开头。

### 哪些属于输入框，哪些属于字段

| 方面 | 数字输入框 | 包着它的字段 |
| --- | --- | --- |
| 绘制 | 方框、数字、占位符、前缀和后缀、两个步进按钮，以及浮在 filled 或 outlined 方框里的标签 | stacked 输入框上方的标签行、必填或选填标记、帮助文本、错误文本 |
| 保存 | 值、范围和步长、它在表单中的位置、事件 | 什么都不保存 |
| 告诉辅助技术 | 一个微调按钮（spin button）：它的值、它的范围、它的值文本 | 名称、帮助文本或错误文本、必填、无效、禁用 |

三种变体和三种尺寸——`small`（32）、`medium`（40）和 `large`（56）——都是文本输入框的；方框的绘制方式和尺寸，与同一变体、同一尺寸的[文本输入框](/zh-cn/components/text-input/)相同。默认系统只提供 `stacked`。

两个步进按钮是并排的 medium 尺寸 text 按钮。在默认系统下，它们占方框宽度中的 88，每一个都是完整的触摸目标。它们绝不会画得更小，也绝不会上下叠放：一行里放不下它们的地方，就把它们关掉。按键仍然可以步进。它们用 Button 自己的令牌绘制，绝不会处于错误状态。

方框里发生的事——[值和文本](/zh-cn/components/number-field/#值和文本)、文本在某个区域设置下怎样解读，以及[步进](/zh-cn/components/number-field/#步进)——在单独使用、放在字段里和用在数字字段里时都一样，只在数字字段的页面上写一次。

### 单独使用，没有字段

- **名称**是 `label`。`labelHidden` 让 filled 或 outlined 的输入框不把它画出来。
- **错误**是 `error`，由你来设置：方框画成错误状态，并暴露为无效。输入框没有错误文本。请在它旁边用文字说明哪里不对，或者用字段框住它。
- **不是数字的文本**会被保留，值变为空，方框画成错误状态，并触发带有 `invalidText` 的 `entryError`。`invalidText` 会加进输入框的描述；没有任何东西把它画出来。
- **必填**要由字段来说明。单独使用的输入框没有必填设置：表单需要回答的地方，请自己校验。

### Web 上绘制方式的不同之处

- 这个元素是与表单关联的元素。有 `name` 时，无论区域设置下显示成什么样，它都把值作为普通的十进制数字（`12.5`）提交；它重置为 `value` 属性（attribute）的值，在导航返回时恢复，跟随被禁用的 `<fieldset>`；所在的字段说明它必填而它为空时报告缺少值，文本不是数字时报告输入有误。
- 数字在 shadow root 里的原生 `<input type="text">` 中编辑，这个元素带有微调按钮的角色和各项值。它不是浏览器自带的数字输入控件。
- 这个元素是一个块。`focus()` 会把焦点交给原生元素；在方框上、步进按钮之外的任何地方按下，也会让它获得焦点。
- `steppers` 对应的是含义相反的属性（attribute）`no-steppers`，`readOnly` 对应的是 `readonly`。
- `input` 是带 `detail.value` 的 CustomEvent。`change` 和 `action` 是普通事件：请从元素上读取 `value`。除非 `action` 被取消，否则随后会请求表单提交。`entryerror` 是 CustomEvent，它的 `detail` 是 `{ reason, text }`：`text` 是输入框的 `invalidText`，没有给出时为空。类型是 `TanreiNumberInputInputDetail` 和 `TanreiNumberInputEntryErrorDetail`。
- 部件：`container`、`outline`、`active-indicator`、`label`、`requirement-label`、`input`、`prefix`、`suffix`、`stepper`。它没有插槽。
- 没有 `locale` 时，输入框读取最近的 `lang` 属性（attribute），其次是浏览器的语言。
- 除了区域设置自己的分隔符之外，只要这个区域设置不用句点分组，句点也读作小数分隔符。
- 翻页键与滑块一样，在步长自己的网格上走十步：步长为 2 时，在 42 上按 Page Up 得到 62，再按一次得到 82。
- 在 iOS 和 iPadOS 上，可以键入负数时，输入框会请求完整键盘，因为那里的小数键盘没有负号。
- `increment-label` 和 `decrement-label` 留空时，从产品的文字里读取（`setWords()`）。
- 在元素完成定义之前，它没有尺寸。请预留方框的高度。

## 指南

### 数字输入框、数字字段，还是手写的字段

| 你需要 | 使用 |
| --- | --- |
| 标签、方框、帮助文本和错误 | [数字字段](/zh-cn/components/number-field/) |
| 只要方框，标签位于别处：滑块旁边、表格的单元格、工具栏 | 数字输入框，由它自己的 `label` 命名 |
| 在框架里面、方框旁边或下方放你自己的东西 | 一个[字段](/zh-cn/components/field/)，里面放一个数字输入框和你自己的元素 |
| 不表示数量的数字：邮政编码、卡号 | [文本字段](/zh-cn/components/text-field/) |
| 在某个范围内凭感觉选择的值 | [滑块](/zh-cn/components/slider/) |

### 推荐

- 给单独使用的输入框一个 `label`，措辞与可见的标签相同，或者把可见的标签和它所在的位置合起来表达的意思说出来：“数量，橡木书桌”。
- 让单独使用的输入框靠所在的位置得到宽度：网格的一列、一个单元格、工具栏里有宽度的一项。
- 把单位写进 `suffixText`；后缀读出来不通顺的地方，给出 `valueText`。
- 给出 `incrementLabel` 和 `decrementLabel`：写在输入框上，或者用 `setWords()` 为整个产品只给一次。
- 只要你需要的是方框上方的标签、帮助文本和错误，就使用数字字段。

### 避免

- 不要为了省下标签的位置，在表单里使用单独的输入框。哪里都看不到标签的输入框，对每个看到它的人来说都只能靠猜。
- 不要把占位符当作标签。一有人键入它就消失，而且它绝不是名称。
- 不要在字段里的输入框上设置 `label`、`error` 或 `disabled`。把它们写在字段上，标签和帮助文本才会随之变化。
- 不要把数字字段放进字段。它本身已经是字段；字段框住的控件是数字输入框。
- 不要在 `input` 时保存。每按一次键它都会触发；带有已确认的值的是 `change`。

## 无障碍

<ComponentAccessibility name="number-input" />

### 组件负责的部分

- 它是一个微调按钮。它的名称是它自己的 `label`；它没有 `label` 时，是包着它的字段的标签。占位符绝不是名称。
- 它的值是已确认的数字，它的范围是 `min` 和 `max`，它的值文本是 `valueText`，或者带上前缀和后缀的数字。
- 它的描述是字段给它的内容：帮助文本或错误文本。单独使用并处于输入错误时，描述是 `invalidText`。
- 处于错误状态或文本不是数字时，它暴露为无效；所在的字段说明它必填时，暴露为必填；只读和禁用时，也分别暴露出来。
- 步进按钮是以 `decrementLabel` 和 `incrementLabel` 命名的按钮；没有人为它命名的那一个对辅助技术隐藏。它们不在焦点顺序里，因为在输入框上用方向键就能步进；靠触摸探索的人仍然找得到它们。
- 按下步进按钮不会移动焦点，所以不会唤出屏幕键盘。
- 输入法正在组合输入时，输入框不解读任何内容，也不处理任何按键。滚轮绝不会改变数字。
- 焦点由方框自己的边缘来显示，无论来自键盘还是指针。点击区域满足最小目标，每个步进按钮都是完整的目标。
- 浮动标签后面的星号对辅助技术隐藏：必填状态已经说明了这一点。
- 文本放大到 200% 时，浮动标签会换行，数字保持在一行之内并滚动。在强制颜色模式下，方框会多出一道边线。在从右到左的布局中，步进按钮和标签会镜像：步进按钮位于左端。数字和它的单位按单位自身所用文字的写法书写：用拉丁字母或符号写的单位位于数字之后，从左到右书写；用页面的文字写的单位位于数字的左侧。朗读的内容不变。
- 当一行放不下并排的数字和步进按钮时（例如在窄窗口中把文本放大到 200%，并带有前缀和较长后缀），步进按钮会移到数字下方单独的一行，位于方框的末端。它们绝不会被隐藏，因为在触摸屏上它们是步进的唯一方式。
- 缺少名称会在调试构建中报告。

Web 上的已知差距：

- Chromium 读出数字时不带单位：它从输入框里的文本取得值文本，而略过输入框指定的那一个。单位要紧的地方，请把它写进标签。

### 需要你做的事

- 用 `label` 为每个单独使用的输入框命名。它旁边可见的文本并不能为它命名。
- 单独使用的输入框可能出错的地方，要用辅助技术读得到的文字说明哪里不对：一条与页面关联的、你自己的消息，或者包着输入框的字段。
- 即使没有字段显示 `invalidText`，也要把它写上：它会随输入框一起朗读。
- 给滑块和它旁边的数字输入框相同的名称。
