设计系统应当默认就让人觉得恰当，并在你改动一处时跟着你变化。Studio 把这个想法做成了可以上手摆弄的东西：选一个基础系统、转一个调节量、挑一种颜色、改一个令牌、添加一个你自己的令牌——然后导出那个小小的[层文件](/zh-cn/foundations/design-systems/#设计系统是一个层)，里面写的正是你改了什么，除此之外什么都没有。

这里没有任何东西是示意图。预览是一个真实的系统作用域，里面是真实的组件和图标——一个带前置图标的按钮、一个选中时图标会填充的切换按钮，以及以未选中和选中两种状态绘制的同一组图标，所以图标集、`sys.icon.weight` 和 `sys.icon.fill.*` 和颜色一样看得见。文本用你选择的字体栈排印，用的是这个浏览器里确实有的字体：字体栈排在第一位的字体族没有安装在这里时，Studio 会在控件旁边说明——这时预览显示的是回退字体，而你的产品必须加载那款字体。Studio 绝不会从任何字体托管服务获取任何东西。预览应用的正是 `tanrei build` 会为你的层写出的那张样式表——由同一套引擎、输出器和无障碍检查在你的浏览器里计算出来。仓库里的测试用 CLI 流水线构建 Studio 的层，并要求整张样式表、全部六个配色方案中的每个令牌取值以及每条警告都一致。

## 四个层次，一个文件

定制是分形的：几个滑块就够用，而完全的掌控也从不遥远。每个层次编辑的都是**同一个** `<id>.system.json`；层次是这个文件的一种视图，而不是它的一种模式，所以切换时什么都不会丢。

| 层次 | 适合 | 你看到的 |
|---|---|---|
| **Essentials** | 快速配置 | 一个基础系统、一种品牌色和四个滑块——文字大小、间距、圆润程度、标题对比 |
| **Groups** | 一个领域一个领域地过一遍 | 全部八个调节量及其理由、每个调色板（一个种子色，或色相 + 色度，外加一张表，列出它固定为精确颜色的色调）、三种字体、图标集、形状（一个圆角平滑滑块，0–1，其中 0.6 是 iOS 圆角）、行为选择、每个组件的尺寸和变体连同常用的编辑项——按尺寸分别编辑，针对你选中的那种尺寸——以及你的层添加了什么 |
| **Every token** | 一个一个地动手改 | 一棵可搜索的树，包含每个令牌——解析后的取值（颜色按配色方案分别给出）、种类、由哪个层设置、它的描述和使用指引、有哪些令牌跟随它——以及一个编辑器，只提供对该令牌合法的操作 |
| **Source** | 更喜欢直接看文件的人 | JSON 本身，在你输入时由 schema 和令牌引擎校验，引擎的消息一字不差地显示出来 |

**Source** 里还不能解析的文本是一份草稿：你去看其他层次时（层次切换器会显示“Source has invalid edits”）以及重新加载之后，它都会原样保留；它绝不会保存到你的文件里；在草稿能够解析之前，预览和其他层次停留在最后一份能解析的文本上。

在 Essentials 中，**Spacing** 会按比例带动尺寸单位：控件的高度必须容得下它的内边距，而构建检查的正是这一点。在 Groups 中单独设置 `dial.size.unit` 之后，Essentials 就不再动它。

## 各个控件写入什么

| 你做的事 | 层得到的内容 |
|---|---|
| 选择基础系统 | `"extends"` |
| 拨动一个调节量 | `dial.*` 上的 `"$value"`，附带 `reason` |
| 选择种子色或色相 + 色度，声明或去掉一个调色板 | `"palettes"` 中的一个条目——`null` 表示去掉继承来的调色板 |
| 把调色板的某个色调固定为精确的颜色 | 该调色板的 `source.tones`——`{ "40": "#e60012" }`；新的一行以生成的颜色为初始值 |
| 排列 **Brand**、**Plain** 或 **Mono** 的字体族顺序，选择通用回退字体，把平台的字体放在第一位 | `ref.typeface.*` 上的 `{ "$value": ["IBM Plex Sans", "system-ui", "sans-serif"], "reason": "…" }` |
| 选择图标集——一个可变字体族，或每种选中状态一个字体族——以及它的字重和填充 | `ref.typeface.icon` 或 `sys.icon.family.*`、`sys.icon.weight`、`sys.icon.fill.*` 上固定的 `$value` |
| 拖动圆角平滑滑块 | `sys.shape.corner-smoothing` 上的 `{ "$value": 0.6, "reason": "…" }`——一个 0–1 的量，含义与 Figma 相同（[形状](/zh-cn/foundations/shape/#圆角平滑)） |
| 选择按下如何得到反馈、焦点长什么样 | `sys.behavior.*` 上的 `{ "$value": 1, "reason": "…" }`——你选的是**名称**（`ripple`、`glow`）；文件里存的是它的位置 |
| 缩放一个令牌 | `{ "scale": n }`——相对于它所继承的值的比例，仍然由它的调节量驱动 |
| 重新指向一个令牌 | `{ "$value": "{another.token}" }` |
| 固定一个令牌 | `{ "$value": …, "reason": "…" }`——不受任何调节量影响；有了理由才会写入 |
| 替换一条规则 | `{ "derive": … }`——调节量上的系数、颜色角色的色调表、状态用的 `mix` 或 `alpha` |
| 编辑模式规则 | `"rules"`——悬停、聚焦、按下和禁用的样子，一次作用于所有组件 |
| Add…：添加一种尺寸或变体、序列中的一个级别、一个你自己的令牌 | `"vocabulary"` 下的一条声明，必须带 `rationale` |

Typefaces、Icons、Shape 和 Behaviour 写入的是固定值，而固定值需要理由：这四组各问一次，并预先填好（“Brand typeface.”），它写入的每个固定值都带着你的措辞。在 **Every token** 中，种类选择按名称挑选，从不以数字输入；字体栈则是与 Groups 中相同的有序列表。预览里的按钮是真的，所以 `ripple`、`dim`、缓和过渡的圆角和焦点光晕，就是 `<tanrei-button>` 在这个浏览器里用这些令牌实际画出的结果。字阶预览会画出每种字体的一个标题、一段连续文本、一个标签和一段代码——以及你的层添加的每种文本样式——预览栏上的 **Emphasized** 开关会按各自角色的字重加上该字体族的 `sys.typescale.emphasis.*` 级差重新绘制它们，直接取自样式表。当某个选择什么也画不出来时——例如所有按下不透明度都是 1 的情况下选择 `dim`，默认系统就是如此——构建自己的警告会一字不差地显示在控件下方，警告提到的令牌则是通往其编辑器的链接。

保持基础取值不动的控件什么也不写，所以一个没碰过的 Studio 导出的是 `{ "id", "extends" }`，构建结果与基础系统完全相同。有效的层所能包含的任何内容，在这里都可以编辑——导入一个层时，不会有任何东西被搁在一边。

## 扩充词汇

**Add…**（在 Groups 和 Every token 中）用来声明新的东西。一种尺寸只需一行——`{ "from": "large", "scale": 1.5 }`——在你添加之前，Studio 会显示这一行所创建的每个令牌及其解析结果；添加之后，每个成员都可以单独覆盖，构建的高度警告也会实时显示，因为默认的缩放比例很少正好适合内边距。变体从另一个变体克隆而来，它的交互状态由系统的模式规则赋值。你自己的令牌位于你的层的命名空间内（`acme.comp.rating.star.size`），显示在预览的“Your tokens”之下；重命名层时，这个命名空间也随之重命名。添加的尺寸和变体会立刻由真实的 `<tanrei-button>` 绘制出来。

## 用在你自己的文件上

`tanrei studio` 在本地提供这个 Studio，并让它指向你产品的层文件：你一边编辑，改动一边保存到文件；**Build** 运行 `tanrei build`；文件在背后发生变化时——被编辑器修改，或执行了 `git checkout`——Studio 会让你选择重新加载，还是保留当前打开的内容。它绝不会悄悄覆盖。只有当 schema、层链的规则和令牌引擎都接受这个层时，保存才会写入——服务器询问的是引擎本身，并用引擎的消息作答——所以无论发送它的是哪个程序，磁盘上的文件始终是 `tanrei build` 能构建的文件。这个应用还会从它自己的地址提供 Tanrei 内置系统所指定的文本字体和图标字体（Inter、Noto Sans JP、Roboto Mono、Roboto、Material Symbols Rounded 和 Outlined），所以预设是用它自己的字体绘制的。

产品可以把自己的层叠起来——`acme-app.system.json` 扩展它旁边的 `acme.system.json`。`tanrei studio` 会把你的文件旁边的那些层以只读方式交给 Studio，Studio 在浏览器里解析整条层链，与处理内置系统时完全一样；父层在磁盘上发生变化时，一切都会重新计算。

## 它做不到的事

在这个页面上，Studio 背后没有文件，所以扩展了你自己某个层的层无法在这里导入——请用 `tanrei studio` 打开它，它知道旁边有哪些文件。除了提供它的站点之外，Studio 绝不从别处获取字体：该站点不提供、你的浏览器也没有的字体族会被指出名字，预览则如实显示回退字体。它的“预览等于构建”测试比较的是 Web 样式表、令牌包和警告；原生平台的输出由 `tanrei build` 从同一个模型生成。
