## 从一开始就为保持同步而设计

<CardGrid>
  <Card title="两个唯一可信来源" icon="description">
    由人手写的契约只有两种：设计令牌和组件规格。各平台的代码、这份文档和状态矩阵全都由它们推导而来，一旦彼此出现偏离，CI 就会失败。
  </Card>
  <Card title="对等，而非相同" icon="extension">
    每个平台得到的令牌、状态和无障碍语义都相同，但 API 的形态保持各自的习惯：Compose 中是 `enabled`，Flutter 中是把 `onPressed` 设为 null，SwiftUI 中是 `.disabled(_:)`。
  </Card>
  <Card title="经过验证的结构" icon="menu_book">
    参考、系统、组件三层令牌；颜色角色；字阶；按主题和对比度级别生成的色调调色板。外观克制，接近单色。
  </Card>
  <Card title="从结构上保证无障碍" icon="verified">
    每个主题、每个对比度级别下的对比度配对都在构建时校验。外观尺寸从不决定点击区域，焦点环是每份可交互组件规格的组成部分。
  </Card>
</CardGrid>
