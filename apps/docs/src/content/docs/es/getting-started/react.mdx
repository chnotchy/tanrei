`@tanrei/react` envuelve cada elemento personalizado de `@tanrei/web` en un componente de React de verdad, con propiedades y controladores de eventos tipados. Los envoltorios se generan a partir del manifiesto de elementos personalizados, así que siempre coinciden con los elementos que envuelven.

<ReleaseNotice platform="web" registry="npm" pkg={["@tanrei/react", "@tanrei/web"]} />

## Instalación

Se requiere React 18 o posterior.

### Desde npm

```sh
npm install @tanrei/react @tanrei/web
```

### Desde el código fuente

Para usar el código fuente tal como está en `main`, haz lo mismo que con el [paquete Web](/es/getting-started/web/) (Git, Node 22.22 o posterior, pnpm 12): compila los dos paquetes en un clon del repositorio y empaquétalos,

```sh
git clone https://github.com/chnotchy/tanrei.git
cd tanrei
pnpm install
pnpm --filter @tanrei/web --filter @tanrei/react build
pnpm --filter @tanrei/web --filter @tanrei/react pack --pack-destination ../tanrei-packages
```

y luego instala los dos archivos empaquetados en tu proyecto con un solo comando, para que el paquete de React encuentre el paquete Web a su lado:

```sh
npm install path/to/tanrei-packages/tanrei-web-*.tgz path/to/tanrei-packages/tanrei-react-*.tgz
```

## Uso

Carga las hojas de estilo una sola vez, antes de que se rendericen los componentes: `tanrei.css` es la base de la página, los tokens y todas las demás hojas de estilo del paquete en un archivo. Para cargarlas una a una, consulta la [guía de Web](/es/getting-started/web/).

```tsx
import '@tanrei/web/tanrei.css';
import '@tanrei/web/words/en';
import { Button } from '@tanrei/react';

export function Toolbar({ onDeploy }: { onDeploy: () => void }) {
  return (
    <>
      <Button variant="filled" onClick={onDeploy}>
        Desplegar
      </Button>
      <Button variant="text" size="small" disabled>
        Revertir
      </Button>
    </>
  );
}
```

Las propiedades llevan los mismos nombres que los atributos del elemento (`variant`, `size`, `disabled`). Los eventos son controladores de eventos de React corrientes. Un evento propio del elemento se escucha con `on` y el nombre del evento en camel case, como React nombra los suyos (`onKeyDown`): un cajón de navegación emite `expandedchange`, y se escucha con `onExpandedChange`.

`@tanrei/web/words/en` da un texto en inglés llano para cada etiqueta y cada mensaje que los componentes dibujan o dicen, como el de un tag de obligatorio o el nombre de un botón de cerrar; prescinde de él y da los tuyos con `setWords()` de `@tanrei/react`. Consulta [Textos](/es/foundations/words/).

## Una entrada por sistema de diseño

El paquete tiene una entrada para cada sistema de diseño que Tanrei incluye, de modo que tu editor ofrece, y la comprobación de tipos acepta, solo lo que tiene tu sistema:

| Entrada | Lo que exporta |
|---|---|
| `@tanrei/react` | Los componentes del sistema predeterminado, Tanrei. El menú FAB, que vive en la capa m3-like, y el botón segmentado, que Tanrei deja fuera, no están en ella, y una variante que Tanrei deja fuera no es un valor de la prop: `<TextField variant="outlined">` no pasa la comprobación de tipos |
| `@tanrei/react/m3-like`, `@tanrei/react/m3-expressive-like`, `@tanrei/react/cupertino` | Los componentes de ese preset, con sus variantes |
| `@tanrei/react/advanced` | Los componentes avanzados, las piezas de las que se construyen otros: `TextInput`, `ModalLayer`, `Combobox` y los demás. Un producto suele escribir el componente construido a partir de uno: `TextField`, `Dialog`, `ComboboxField` |
| `@tanrei/react/all` | Todos los componentes, tenga cada uno el sistema que sea: para un sistema de diseño propio y para construir uno |

```tsx
import '@tanrei/web/tokens.css';
import '@tanrei/web/systems/m3-like.css';
import { FabMenu, FabMenuItem, TextField } from '@tanrei/react/m3-like';
```

Un componente es el mismo en todas las entradas, así que el empaquetador sigue conservando solo lo que importas. Todas las entradas exportan también `setWords`, `missingWords` y el tipo `TanreiEvent`. Las entradas se generan a partir del manifiesto de componentes de cada sistema, `@tanrei/web/systems/<id>.components.json`, que indica la entrada de cada componente (`react.import`); el manifiesto de tu propio sistema, que escribe `tanrei build`, indica `@tanrei/react/all`.

## Renderizado en el servidor

En un servidor, donde no hay `document`, un componente genera la etiqueta de su elemento y escribe como atributo cada prop que el elemento lee de un atributo, con el nombre de ese atributo. El primer HTML ya lleva la etiqueta, el valor y los estados:

```tsx
<TextField label="Correo electrónico" value="ada@example.com" required maxLength={80} readOnly={false} />
// <tanrei-text-field label="Correo electrónico" value="ada@example.com" required="" maxlength="80"></tanrei-text-field>
```

Una prop con su valor por defecto no escribe nada, así que un `false` nunca se escribe como presente. Un booleano que está activado por defecto y se desactiva escribe el atributo que el elemento lee como desactivado: `<CopyButton iconOnly={false} />` escribe `icon-only="false"` y `<BottomSheet handle={false} />` escribe `no-handle`. Los manejadores, los objetos y los arrays se asignan en el navegador, cuando el componente se monta. La raíz de sombra no se genera en el servidor: el elemento se dibuja cuando se carga su definición, y React hidrata la etiqueta sin discrepancias.

### Next.js (App Router)

Los componentes usan refs y efectos de layout, así que se usan desde un componente de cliente. Impórtalos en un módulo marcado con `'use client'`; un componente de servidor puede renderizar ese módulo, y Next.js lo sigue generando en el servidor en la primera carga.

```tsx
// app/sign-up.tsx
'use client';

import '@tanrei/web/words/en';
import { Button, TextField } from '@tanrei/react';

export function SignUp() {
  return (
    <form action="/sign-up" method="post">
      <TextField name="email" type="email" label="Correo electrónico" required />
      <Button type="submit">Registrarse</Button>
    </form>
  );
}
```

```tsx
// app/layout.tsx
import '@tanrei/web/tanrei.css';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="es">
      <body>{children}</body>
    </html>
  );
}
```

```tsx
// app/page.tsx (un componente de servidor)
import { SignUp } from './sign-up';

export default function Page() {
  return <SignUp />;
}
```

El renderizador de servidor de Lit (`@lit-labs/ssr-react`, `@lit-labs/nextjs`) no está soportado: genera la raíz de sombra en el servidor, y muchos de los elementos leen sus hijos y el documento mientras se renderizan, algo que ese renderizador no ofrece, así que fallan con él. No lo instales; lo que envía el servidor son los atributos de arriba.
