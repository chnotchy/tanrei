## 規則のありか

リポジトリのルートにある `AGENTS.md` が、人間であれ AI であれ、コントリビューターにとっての正式なガイドです。短い文書なので、最初に読んでおくと時間の節約になります。各パッケージやソースディレクトリには、ローカルな規則を書いた入れ子の `AGENTS.md` を置けます。最も近いファイルが適用されますが、どのファイルもルートの規則を弱めることはできません。詳しい版は、ルートの `CONTRIBUTING.md` です。

より長い資料は、リポジトリの `docs/` ディレクトリにあります。アーキテクチャの概要と、誰が何を決めるかを定めたガバナンスです。

## 変更の形

どの変更も、誰が行うかにかかわらず、次の手順に従います。

1. **信頼できる情報源から始める。** コンポーネントの公開インターフェースの変更は `specs/` から、デザイン値の変更は `tokens/` から始めます。プラットフォームのコードはその後です。
2. **チェックをローカルで実行する。** `pnpm validate`、`pnpm generate`、そして `pnpm check` です。ドリフトチェックが失敗したら、再生成してください。生成されたファイルを編集してはいけません。
3. **プラットフォームを正直に保つ。** あるプラットフォームを仕上げられないなら、そのステータスは実際のままにしておきます。ステータス表はリポジトリから生成されるもので、存在する以上のことを主張してはなりません。
4. **changeset を追加する。** 利用者に見える変更にはすべて追加し、Conventional Commits（`feat(web): …`、`fix(tokens): …`、`docs: …`）を使います。

## 受け入れられないもの

- コンポーネントの中にハードコードされた色、半径、タイポグラフィ、スペーシング、モーション、不透明度。
- テストを通すために更新されたスナップショットのベースライン。
- 緩められたコントラストやアクセシビリティのしきい値。
- ほかのデザインシステムから写したドキュメントの文章。Tanrei の文章は、すべてオリジナルです。

## ドキュメントの変更

このサイトは `apps/docs/` にあります。文章は手で書いた MDX です。英語が原文で、各ページをサイトのほかの言語に翻訳しています（言語の一覧と、翻訳がどの原文から作られたかを記録する方法は、`apps/docs/i18n/README.md` にあります）。仕様、トークンファイル、ステータス表から得られる表は、そのデータから描画し、手で入力することはありません。ローカルな規則は `apps/docs/AGENTS.md` を参照してください。
