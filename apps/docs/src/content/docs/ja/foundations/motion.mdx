Tanrei のモーションは、何が変わったかを示し、すぐに終わります。どのコンポーネントもはじめからモーションのトークンで動くので、コンポーネントを使うだけのプロダクトは何も設定しなくてかまいません。このページでは、トークンの中身、コンポーネントがそれで何をするか、そして何を当てにしてよいかを説明します。

## 役割ごとの時間

変化にかかる時間は、スケールから選んだ段ではなく、何が動くか、つまり**役割**で決まります。小さなコントロールの状態の変化、選択のしるし、大きさが変わる箱、現れるメニュー。どれも `tanrei.sys.motion.role` の下の役割で、同じ役割のコンポーネントは同じ速さで動きます。面は、現れるときより速く消えます。

<MotionTokens part="role" />

コンポーネント自身の時間のトークンは、自分の役割の別名です。たとえば `tanrei.comp.menu.motion.open-duration` は `tanrei.sys.motion.role.appear.anchored.enter` を指します。そのため、レイヤは 1 行で、同じ役割のコンポーネントすべての時間を変えられます。

```json
"tokens": {
  "tanrei.sys.motion.role.appear.anchored.enter": { "$value": "{tanrei.sys.motion.duration.medium1}", "reason": "Our menus open quickly." }
}
```

役割の時間はモーションのダイヤル `dial.motion.unit` に従い、このダイヤルを変えればすべての時間がまとめて変わります（[デザインシステムとカスタマイズ](/ja/foundations/design-systems/)）。どの役割にも当たらないものは、時間のスケールの段をそのまま使います。繰り返す動き（ローディングインジケーターの回転、スケルトンの明滅）、値まで伸びるプログレスバー、スクロール、そして遅延のような待ち時間です。

## イージング

役割ごとに 4 つの曲線があり、それぞれスケールの曲線のどれかを指しています。`enter` は現れる面、`exit` は消える面、`state` はその場での状態の変化、`spatial` はその場で動くものや大きさが変わるものに使います。既定のシステムでは `enter`、`state`、`spatial` が標準の曲線で、`exit` だけが加速する曲線です。消える面は速さを増しながら去ります。

## 自分の CSS でトークンを使う

どのトークンも `tokens.css` のカスタムプロパティです。自分で書くトランジションも、動くものの役割で時間を決めてください。そうすればコンポーネントと同じ速さで動き、レイヤやダイヤルの変更にも追従します。

```css
.result-row {
  transition: background-color var(--tanrei-sys-motion-role-state-large) var(--tanrei-sys-motion-easing-state);
}
```

## コンポーネントが自分で行うこと

- **どの面も同じように現れます。** メニュー、セレクトのリスト、ポップオーバー、ツールチップ、ダイアログ、スナックバーは、どれも同じ不透明度、拡大率、距離、ぼかし（`tanrei.sys.motion.appear.*`）から始まり、消えるときは同じ道を戻ります。既定のシステムでは、0.96 の拡大率からフェードインしながら、出てくる側から広がります。アンカーに向いた辺、モーダルな面なら中央、スナックバーならウィンドウの端です。シートは、現れ方の設定にかかわらず端から滑り込みます。これらは `sys.behavior.appearance` という 1 つの選択でまとめて決まります（[面がどこから現れるか](/ja/tokens/motion/#面がどこから現れるか)）。
- **途中で向きが変わった動きは、その位置から続きます。** 現れている途中のメニューを閉じると、いま描かれている値から消え始めます。値が飛ぶことも、別の状態が一瞬見えることもありません。
- **大きさが変わる箱は、レイアウトの中で動きます。** 1 行ぶん伸びるテキストフィールドや、フィールドの下に開くエラーの行は、フレームごとに大きさを変えるので、後ろにあるものも一緒に動きます。中身は箱の端に留まり、途中で中がスクロールすることはありません。
- **動きは最初のフレームから始まります。** 長いタスクの終わりに開いた面や変わった状態（開くときに多くの行を描くリストなど）は、そのタスクのあとに描かれる最初のフレームから動きを再生します。終わった姿でいきなり現れることはありません。マーキーテキストの流れやカルーセルの自動再生の進み具合のように、コンポーネントが止めてまた動かす動きは、止めた位置から続きます。
- **フォーカスリングはアニメーションしません。** すぐに現れるので、キーボードを使う人は自分がどこにいるかを待たずに確かめられます。
- **押下にはステートレイヤーで応えます。** 既定のシステムでは `sys.behavior.pressed-feedback` が `overlay` です。`ripple` を選んだシステムでは、リップルの時間は `tanrei.sys.motion.role.feedback` です。

## ページの読み込みでは何も動かない

コンポーネントは最初のフレームを、属性と内容が与える状態で描き、その状態へのトランジションを走らせません。`checked` と書いたチェックボックス、開いた状態で書いたアコーディオンの項目、最初の描画のあとで自分の大きさを測るフィールドは、ページが現れたときにはもうその姿でそこにあります。パッケージの要素はどれも、接続されてから最初の描画の 2 フレーム後まで `data-tanrei-settling` を持ち、その間は中で何もトランジションを始めません。

ページのマークアップに開いた状態で書いたオーバーレイ（`<tanrei-dialog open>` など）は、現れる動きなしに最初のフレームからそこにあります。ページが描かれたあとで開いた、あるいは開いた状態で追加されたオーバーレイは、いつもどおり現れる動きを再生します。

## モーションの低減

次の 2 つの設定のどちらかが求めると、動きが減ります。

- **利用者の設定**。OS かブラウザーの、動きを減らす設定です（`prefers-reduced-motion: reduce`）。
- **アプリ自身の設定**。ルート要素の `data-tanrei-motion="reduce"` 属性です。

どちらでも、すべてのコンポーネントへの効果は同じです。移動、拡大縮小、ぼかしは、`tanrei.sys.motion.role.reduced`（100 ms）の短い不透明度の変化に置き換わり、大きさの変化はすぐに済みます。マーキーテキストは流れなくなり、ローディングインジケーターは回る代わりに不透明度を変え、スケルトンは静止します。表示までの遅延は残ります。遅延は待ち時間を測るもので、動きではないからです。

プロダクトに独自の「動きを減らす」設定があるなら、`<html>` に属性を 1 つ付けます。

```html
<html data-tanrei-motion="reduce">
```

設定が変わったときに、スクリプトから付け外しすることもできます。

```js
function setReducedMotion(reduce) {
  if (reduce) document.documentElement.dataset.tanreiMotion = 'reduce';
  else delete document.documentElement.dataset.tanreiMotion;
}
```

コンポーネントは変更にすぐ従い、再読み込みは要りません。この属性は動きを減らすことしかできません。値は `reduce` だけで、利用者が動きを減らすよう求めているときに動きを戻す値はありません（WCAG 2.3.3）。属性はスタイルのコンテナクエリーで読まれます。コンテナクエリーのないブラウザーは `prefers-reduced-motion` にだけ従い、属性で減るのはコンポーネントがスクリプトで再生する動きだけになります。

`tokens.css` は、どちらの設定も 1 つの継承される値 `--tanrei-motion: reduce` として表します。自分の CSS で両方の設定に従って動きを減らすには、コンポーネントと同じように、メディアクエリーの下とその値のスタイルクエリーの下に同じルールを書きます。

```css
@media (prefers-reduced-motion: reduce) {
  .promo-banner { animation: none; }
}
@container style(--tanrei-motion: reduce) {
  .promo-banner { animation: none; }
}
```

このページは Web のパッケージについての説明です。ネイティブのパッケージは、プラットフォーム自身の設定に従います（SwiftUI の `accessibilityReduceMotion`、Android のアニメーター再生時間スケール、Flutter の `MediaQuery.disableAnimations`、React Native の `AccessibilityInfo.isReduceMotionEnabled()`）。Flutter では、アプリがウィジェットの上で `MediaQuery` を上書きすれば、自分で動きを減らせます。SwiftUI、Jetpack Compose、React Native には、アプリ全体に効く独自の設定はまだありません。

すべての値は、[モーションのトークンリファレンス](/ja/tokens/motion/)に掲載しています。
