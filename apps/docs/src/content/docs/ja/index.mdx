## ずれない仕組みを、最初から

<CardGrid>
  <Card title="信頼できる情報源は 2 つだけ" icon="description">
    人が書く契約は、デザイントークンとコンポーネント仕様の 2 つだけです。各プラットフォームのコード、このドキュメント、ステータス表はすべてそこから導かれ、食い違いが生じれば CI が失敗します。
  </Card>
  <Card title="同一ではなく、パリティ" icon="extension">
    どのプラットフォームでも、トークン・状態・アクセシビリティの意味は同じです。一方で API の形は各プラットフォームの慣習に従います。Compose なら `enabled`、Flutter なら `onPressed` に null、SwiftUI なら `.disabled(_:)` です。
  </Card>
  <Card title="実績のある構造" icon="menu_book">
    リファレンス・システム・コンポーネントの 3 層トークン、カラーロール、タイプスケール、テーマとコントラストごとに生成するトーナルパレット。見た目は抑制が効いていて、ほぼモノクロームです。
  </Card>
  <Card title="構造で守るアクセシビリティ" icon="verified">
    コントラストの組み合わせは、すべてのテーマとコントラストレベルについてビルド時に検証されます。見た目の大きさがヒット領域を決めることはなく、フォーカスリングはすべての操作可能なコンポーネントの仕様に含まれます。
  </Card>
</CardGrid>
