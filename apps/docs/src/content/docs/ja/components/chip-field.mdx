チップフィールドは、同じ種類の短いテキストをいくつも入力してもらう場面で使います。メッセージの宛先、ドキュメントの共有相手、通知を送る電話番号、記事のキーワードなどです。テキストは 1 件ずつチェックするので、12 件のうち 1 件のアドレスを打ち間違えても、残りの 11 件はそのまま残ります。入力済みの 1 件（以下、エントリ）は、それぞれ単独で取り除いたり、直したりできます。

**構成要素**は、[フィールド](/ja/components/field/)、[テキスト入力欄](/ja/components/text-input/)、[チップ](/ja/components/chip/)です。フィールドは枠で、ラベル、必須または任意の印、補足、エラーを受け持ちます。テキスト入力欄はボックスで、次のエントリを入力する場所でもあります。エントリは小さい入力チップで、ボックスの中、入力中のテキストの前に並びます。チップフィールドが自分で描くものはなく、トークンもありません。そのため、どのデザインシステムでも、隣のテキストフィールドと同じ見た目になります。

幅は置かれた場所に合わせて広がります。エントリと入力中のテキストは行に並び、収まらなければ折り返して、ボックスは 1 行分ずつ高くなります。エントリはすべて表示します。隠したり、「+3」のような件数にまとめたり、スクロールで見えなくしたりはしません。

Web では `<tanrei-chip-field>` です。ほかのプラットフォームはまだ実装していません。

### 使い方

`value` はエントリのリストで、テキストの配列です。`inputValue` は、入力中でまだエントリになっていないテキストです。

入力中のテキストは、次のときにエントリになります。

- Enter を押したとき。
- `separators` に挙げた区切り文字が入力されたとき。既定では 1 つもありません。カンマはメールアドレスの終わりにもなりますが、「Lovelace, Ada」のように名前の一部にもなるためです。
- フォーカスがフィールドの外へ移ったとき。
- 区切り文字や改行を含むテキストを貼り付けたとき。区切った 1 件ずつを、順番に受け付けるかどうか決めます。

Tanrei は、メールアドレスや電話番号が何であるかを知りません。`type` が選ぶのはキーボードだけで、何もチェックしません。エントリの候補は、1 件ずつ `check` で利用者側に渡します。受け付けないと答えた候補は、テキストのままボックスに残り、フィールドがエラーになります。すでにリストにあるテキストと、`maxEntries` を超えるテキストは、`check` を呼ばずに受け付けません。

受け付けない理由を、その 1 件のために自分の言葉で伝えるには、`check` のリスナーで `event.detail.reason` を設定します。設定しなければ、理由に応じて `invalidText`、`duplicateText`、`limitText` のいずれかを表示し、それも空なら `errorText` を表示します。`reject` は、受け付けなかったテキスト、理由、表示した言葉を 1 件ずつ知らせます。

エントリになったあとで誤りとわかったもの（サーバーが存在しないと返したアドレスなど）は、利用者側で伝えます。`error` と `errorText` を設定し、どのエントリのことかを言葉で示してください。ユーザーはそのエントリを取り除くか、入力部分に戻して直します。

### エントリを変える

| 目的 | 操作 |
| --- | --- |
| 入力部分からエントリへ移る | テキストの先頭で Backspace、または行の先頭の方向を指す矢印キー |
| エントリの間を移動する | 左右の矢印キー、Home、End |
| エントリを取り除く | エントリの上で Backspace か Delete、または取り除くアクション |
| エントリを直す | エントリの上で Enter か Space、またはチップを押す。テキストが入力部分に戻ります |
| 入力部分へ戻る | Escape、Tab、または文字の入力 |

最初の Backspace は、最後のエントリへ移るだけです。もう一度押すと取り除きます。キーを押し続けても 1 回分しか働かないので、入力中のテキストを消す操作が、そのままリストまで進むことはありません。

構成要素を自分で書いたものにないものが、チップフィールドが加えるものです。

| チップフィールドが加えるもの | 自分で書く場合 |
| --- | --- |
| エントリを作ること。Enter、区切り文字、フォーカスの移動、貼り付けたリスト | テキスト入力欄のイベントを受けて、テキストを区切ります |
| チェックと、エントリのエラー | フィールドに `error` と `errorText` を設定します |
| Tab で止まる場所が 1 つであること、エントリの間を移動するキー | チップと取り除くアクションの 1 つずつで Tab が止まります。チップを取り除き、フォーカスを移すのも利用者側です |
| エントリを 1 つのリストとして伝えること、3 つの読み上げ | 自分で用意します |
| リストを、フォームの 1 つの値として扱うこと | 隠した入力欄を使うか、自分で送信します |

チップフィールドにない並べ方が必要なときに、1 つ下の階層で書きます。エントリをチップ以外で描く場合や、ボックスにアイコンを入れる場合です。

### それぞれの構成要素が受け持つもの

| 観点 | フィールドから | テキスト入力欄から | チップフィールド自身 |
| --- | --- | --- | --- |
| プロパティ | `label`、`labelHidden`、`supportingText`、`errorText`、`error`、`disabled`、`requirement`、`requiredMark`、`requiredText`、`optionalText` | `variant`、`size`、`type`、`placeholder`、`readOnly`、`autocomplete`、`inputValue`（テキスト入力欄の `value`） | `value`、`separators`、`maxEntries`、`invalidText`、`duplicateText`、`limitText`、`removeLabel`、`addedText`、`addedCountText`、`removedText` |
| イベント | — | `input`、`action` | `change`、`check`、`reject` |
| スロット | `label-icon` | — | — |
| トークン | `comp.field.*` | ボックスは `comp.input-box.*`。エントリを置く場所は `comp.text-input.*` | なし。エントリは `comp.chip.*` を読みます |

- **エントリは小さいチップ**です。ボックスのサイズがどちらでも変わりません。長いエントリは 1 行を占め、チップが省略記号で切ります。切っても、テキスト全体が名前であり、値です。
- **プレースホルダー**は、リストが空の間だけ表示します。
- **読み取り専用**では、エントリへ移って読むことができ、リストは送信されます。エントリを作ること、取り除くこと、入力部分に戻すことはできません。チップは取り除くアクションなしで描きます。フィールドはチップの最後の行で終わり、入力のための場所を残しません。無効なフィールドはその場所を残し、もう一度有効になったときに同じ形になるようにします。
- **無効**では、フィールド、ボックス、すべてのチップが無効になり、何も送信しません。
- **`maxEntries`** は、上限を超える 1 件を受け付けず、`limitText` を表示します。前もって無効にしたり、印を付けたりはしません。上限は `supportingText` で伝えてください。
- **`type`** は `text`、`email`、`tel`、`url` です。それ以外は `text` として動きます。

### Web での描き方の違い

- 要素のシャドウルートにあるのは、`<tanrei-text-input>` を入れた `<tanrei-field>` と、テキスト入力欄の `entries` スロットに入る、エントリごとの `<tanrei-chip>` です。要素をインポートすると、3 つとも定義されます。
- `value` は配列のプロパティです。変えるときは、新しい配列を代入します。`value` 属性は、文字列の JSON 配列として 1 度だけ読み、フォームをリセットしたときに戻る値になります。`separators` も配列で、属性は JSON 配列です。
- 要素はフォームに関連付けられます。`name` のもとに、エントリごとに 1 つの値を順番に送信します。リストが空の間と、フィールドが無効の間は、何も送信しません。入力中のテキストを送信することはありません。無効な `<fieldset>` に従い、ページを移動して戻ると復元されます。`requirement` が `required` でリストが空の間は、値がないことを報告します。
- `change`、`check`、`reject` は、この要素が発生させる CustomEvent です。`detail` はそれぞれ `{ value, added, removed }`、`{ text, values }`、`{ text, reason, message }` です。`check` はキャンセルでき、イベントが返った時点で答えを読みます。あとから出した答えは読みません。
- `input` と `action` は、テキスト入力欄のイベントです。`action` が発生するのは、入力部分が空のときに Enter を押した場合だけで、続いてフォームの送信を求めます。テキストがあるときの Enter はエントリを作ります。このキーは、テキスト入力欄に届く前に止めるので、バブリングの段階で待つ `keydown` のリスナーには届きません。
- パーツ: `field`、`text-input`、`chip` が構成要素です。フィールドとテキスト入力欄のパーツは、同じ名前のままです（`label`、`supporting-text`、`container`、`input`、`entries` など）。チップのパーツは `entry-container`、`entry-label`、`entry-remove` です。
- 要素そのものはフォーカスを受け取らず、ロールもありません。`focus()` は入力部分に移ります。名前は `label` で付け、`aria-label` は使いません。
- 区切り文字は、テキストが変わったときにテキストの中から探します。押されたキーでは判断しません。そのため、タッチキーボードや音声入力でもエントリが作られます。IME で変換している間は、エントリを作りません。変換を確定するキーは変換を確定するだけで、テキストを読むのはそのあとです。
- 属性はケバブケースです。`input-value`、`max-entries`、`remove-label`、`added-count-text` などです。`readonly` と `autocomplete` は HTML の名前のままです。
- 要素が定義されるまでは大きさがなく、何も表示されません。ボックスの高さを確保してください。スクリプトなしでリストを受け取る必要があるページでは、通常の `<input>` か `<textarea>` を使い、サーバーでテキストを区切ります。

## ガイドライン

### チップフィールド、コンボボックス、タググループ

| 必要なもの | 使うもの |
| --- | --- |
| ユーザーが入力するテキストのリスト。1 件ずつチェックする | チップフィールド |
| プロダクトが持っているオプションからの選択 | [コンボボックス](/ja/components/combobox/)。チップフィールドに候補のリストはありません |
| 単独で置く、タグやチップの集まり。入力もフォームの値もない | [タググループ](/ja/components/tag-group/) |
| 1 件ずつラベルが必要な、少数の長いエントリ | テキストフィールドを並べた[フィールドグループ](/ja/components/field-group/) |
| 長さにかかわらず、1 つのテキスト | [テキストフィールド](/ja/components/text-field/) |

### 推奨

- エントリが何で、どうすれば作れるのかを、`supportingText` で伝える。例:「アドレスはカンマで区切ってください。」
- `separators` には、エントリの一部になりえない文字だけを挙げる。「Lovelace, Ada」のような名前を受け取るなら、何も挙げない。
- `removeLabel` には `{entry}` の場所を入れる。取り除くアクションが 2 つあっても、同じ名前になりません。
- `invalidText` には、正しいエントリがどういう形かを言葉で書く。
- 上限は `supportingText` で伝え、上限に達したときに起きることを `limitText` で伝える。

### 非推奨

- チップフィールドをフィールドの中に入れない。すでにフィールドです。
- アドレスのチェックを `type="email"` に任せない。選ぶのはキーボードだけです。
- `check` にあとから答えない。サーバーが受け付けなかったエントリは、`error` と `errorText` で伝えます。
- 入力中のテキストを値の一部として読まない。フォーカスが外へ移るとエントリになります。フィールドにフォーカスがあるままスクリプトで送信するプロダクトは、`inputValue` を読みます。

## アクセシビリティ

<ComponentAccessibility name="chip-field" />

### コンポーネントが担うこと

- 支援技術には、ラベルを名前とするリストが伝わり、エントリごとに 1 つの項目があります。項目には、エントリのテキスト全体を名前とするボタンと、エントリを含む `removeLabel` を名前とする、取り除くアクションのボタンが入ります。リストの次が入力部分です。ラベルを名前とし、補足またはエラーを説明とするテキストボックスです。
- エントリがいくつあっても、Tab で止まるのはフィールドで 1 か所です。エントリへは、矢印キーか Backspace で移ります。ポインター、タッチ、スクリーンリーダー自身の移動でも届きます。
- 受け付けなかったエントリは、キャレットのある入力部分に、テキストのまま残ります。理由はフィールドのエラーに言葉で示し、1 度だけ読み上げます。受け付けなかったエントリと受け付けたエントリを、色で見分けさせることはありません。
- エントリを 1 件作ったとき、まとめて何件か作ったとき、エントリを取り除いたときは、読み上げ中の内容に割り込まないライブリージョンで、利用者側の文を伝えます。
- 取り除く操作は、意図したときだけ起きます。Backspace は 2 回押す必要があり、押し続けても 1 回分しか働きません。
- 方向は、フィールドを置いた場所に従います。右から左のレイアウトでは、行は右から始まり、矢印キーは指す方向へ移動します。中のアドレスは、アドレス自身の方向のままです。
- 狭い場所で文字を 200% にしても、エントリはすべて表示されます。最後の行に残る幅が足りなければ、入力部分は次の行に移ります。

Web での既知の不足: スクリーンリーダーが何を読むかは、ブラウザーのアクセシビリティツリーから読み取ったもので、スクリーンリーダーで聞いて確かめてはいません。

### 利用者側で行うこと

- `label` を必ず指定する。
- `removeLabel`、`addedText`、`removedText` を、要素に指定するか、プロダクトの言葉として 1 度だけ用意する。ないと、取り除くアクションに名前が付かず、何も読み上げません。
- エントリの作り方を `supportingText` で伝える。エントリの上で Enter を押すと直せることを知らせる必要があれば、それも書く。
- エントリを受け付けなかった理由は、どう直せばよいかがわかる言葉で伝える。
