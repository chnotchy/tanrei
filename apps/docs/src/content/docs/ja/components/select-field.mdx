セレクトフィールドは、フォームの中で、あらかじめ決まっていて、ほかの値を受け付けないリストから 1 つの値を選ぶときに使います。国、タイムゾーン、プランなどです。ラベル、選ばれているオプションを表示してリストを開くボックス、補足の 1 行、値を受け付けなかったときの言葉という、いつもの組み合わせが、そのまま使える形でそろっています。

**構成要素**は、[フィールド](/ja/components/field/)と[セレクト](/ja/components/select/)です。フィールドは枠で、ラベル、必須または任意の印、補足、エラーを受け持ちます。セレクトはコントロールで、トリガーとリスト、その中でユーザーが行うすべてを受け持ちます。セレクトフィールドが自分で描くものはなく、トークンもありません。プロパティはどれも 2 つのどちらかのもので、そのまま渡されます。渡したオプションは、中のセレクトのオプションになります。

幅は置かれた場所に合わせて広がり、ボックスはその幅いっぱいに広がります。ボックスを狭くするには、置く場所を狭くします。

Web では、`<tanrei-option>` を子に持つ `<tanrei-select-field>` です。ほかのプラットフォームはまだ実装していません。

### 使い方

オプションはセレクトフィールドの子で、それぞれが値とラベルを持ちます。選ばれているオプションは `value` で指定します。`change` と `toggle` はセレクトのイベントで、どちらかを受け取った時点で、フィールドの `value` と `open` はすでに新しい値になっています。

### 1 つ下の階層

同じフィールドを 2 つの構成要素から自分で書いても、見た目は同じで、支援技術にとっても同じコントロールになります。

```html
<tanrei-field label="国" required required-text="必須"
  supporting-text="請求書の宛先になります。">
  <tanrei-select name="country" placeholder="国を選択">
    <tanrei-option value="jp">日本</tanrei-option>
    <tanrei-option value="ke">ケニア</tanrei-option>
  </tanrei-select>
</tanrei-field>
```

セレクトフィールドにない並べ方が必要なときに、1 つ下の階層で書きます。

| 必要なもの | 使うもの |
| --- | --- |
| ラベル、ボックス、補足、エラー | セレクトフィールド |
| 枠の中、ボックスの横や下に置く自分の要素 | [フィールド](/ja/components/field/)に、[セレクト](/ja/components/select/)と自分の要素を入れる |
| ボックスだけ。ラベルは別の場所にある（バーに置くテーマ、ツールバーに置く並び順、テーブルのセル） | [セレクト](/ja/components/select/)を単独で使い、セレクトの `label` で名前を付ける |
| スクロールするより入力したくなるほど長いリスト | [コンボボックス](/ja/components/combobox/) |

1 つ下の階層で変わるのは、何をどこに指定するかです。`name`、`value`、オプションはセレクトに指定し、フォームに加わるコントロールもイベントが届く先もセレクトになります。`label`、`error`、`disabled` はフィールドに指定したままにします。フィールドがコントロールに伝えるので、セレクトの側には指定しません。

### それぞれの構成要素が受け持つもの

| 観点 | フィールドから | セレクトから |
| --- | --- | --- |
| プロパティ | `label`、`labelHidden`、`supportingText`、`errorText`、`error`、`disabled`、`required`、`optional`、`requiredMark`、`requiredText`、`optionalText` | `variant`、`size`、`value`、`placeholder`、`readOnly`、`open`、`separation` |
| イベント | — | `change`、`toggle` |
| スロット | `label-icon` | `leading-icon` と、オプション |
| トークン | `comp.field.*` | ボックスは `comp.input-box.*`（すべての入力ボックスが読みます）。リストは `comp.select.*` |

セレクトは、自分の `label`、`labelHidden`、`error`、`disabled` を持っています。これらはセレクトフィールドのプロパティではありません。フィールドの `label` がコントロールに名前を付け、`error` がボックスをエラーの状態にし、`disabled` がボックスを無効にします。そのため、どれもセレクトフィールドに 1 回指定すればよく、ラベルもコントロールと一緒に変わります。

`stacked` では、ラベルはボックスの上にあるフィールドの行です。`filled` と `outlined` では、同じラベルをセレクトがボックスの中で浮き上がるラベルとして描き、フィールドはラベルの行を描きません。このとき必須のフィールドは、デザインシステムがどの印を指定していても、ラベルの後のアスタリスクで示されます。補足は、先頭のアイコンを過ぎた、値の始まる位置から始まります。リストが開いている間は、ボックスと同じように、ラベルと補足もフォーカスされた状態で描かれます。

トリガーとリストの動き（開く、矢印キー、文字の入力、選ぶ、グループ）は[セレクトのページ](/ja/components/select/)に、枠の動き（必須の印、補足、エラーとその読み上げ）は[フィールドのページ](/ja/components/field/)にあります。

### 1 つのフィールドだけを変える

セレクトフィールドに自分のトークンはありません。枠はフィールドのトークンを、ボックスとリストはセレクトのトークンを、どこで設定されていても読みます。1 つだけ変えるには、構成要素のトークンをその要素に設定します。

```html
<tanrei-select-field label="国"
  style="--tanrei-comp-field-label-gap: 12px"></tanrei-select-field>
```

### Web での描き方の違い

- 要素のシャドウルートにあるのは、`<tanrei-select>` を入れた `<tanrei-field>` だけです。要素をインポートすると、2 つとも定義されます。
- オプションは、`<tanrei-select-field>` の子のままです。移動も複製もされません。スロットを通して中のセレクトに届き、変わるたびにセレクトが読み直します。`replaceChildren()` で入れ替えても、セレクトのときと同じように動きます。
- 要素はフォームに関連付けられます。`name` と `form` を受け取り、値だけを送信します（無効の間は何も送信せず、読み取り専用の間は送信します）。リセットすると `value` 属性の値に戻り、無効な `<fieldset>` に従い、`required` が設定されていて値が空の間は、値がないことを報告します。2 つの構成要素がフォームに項目を加えることはありません。
- `change` は、composed でバブルする、セレクトのイベントです。`toggle` は、`detail.open` と `detail.reason` を持つ、セレクトの CustomEvent です。composed ですがバブルしないので、この要素では受け取れますが、`<details>` のような祖先には届きません。イベントのターゲットはこの要素で、どのリスナーでも `event.target.value` と `event.target.open` は新しい値です。
- パーツ: `field` と `select` が 2 つの構成要素です。構成要素のパーツは、1 つ下の階層と同じ名前です。`label-icon`、`supporting-text` と、`container`、`outline`、`active-indicator`、`value`、`placeholder`、`leading-icon`、`chevron`、`list`、`option`、`option-label`、`option-supporting-text`、`option-leading-icon`、`mark`、`group`、`group-title`、`divider` です。`label` と `requirement-label` は、2 つのうち描かれているほう（フィールドの行か、セレクトの浮き上がるラベル）を指します。`field-label`、`select-label`、`field-requirement-label`、`select-requirement-label` は、どちらか一方だけを指します。
- 要素そのものはフォーカスを受け取りません。`focus()` はトリガーに移り、ページの `<label for>` もフォーカスをトリガーに移します。ラベルの行を押すと、トリガーにフォーカスが移るだけで、何も開きません。トリガーを押すとリストが開き、補足を押しても何も起こりません。
- 要素にロールはありません。名前は `label` で付けます。ラベルが別の場所に描かれているときは `label-hidden` を併せて指定します。`aria-label` はここでは何にも名前を付けないので、使いません。
- 属性は構成要素のものと同じです。`label-hidden`、`supporting-text`、`error-text`、`required-mark`、`required-text`、`optional-text`、`readonly` です。
- オプションでも、オプションのグループでも、`label-icon` や `leading-icon` に入れるグリフでもない子は、描かれません。デバッグビルドはそのことを伝えます。
- 要素が定義されるまでの間、オプションはふつうのテキストとして表示されます。`tanrei-select-field:not(:defined) > *` を隠し、高さを確保しておいてください。スクリプトなしで動く必要があるページでは、`<label>` を付けた素の `<select>` を使います。

## ガイドライン

### 推奨

- ラベルには、何を選ぶのかを書き、フォームの中では見える状態にしておきます。
- オプションは、ユーザーが探す順に並べます。五十音順やアルファベット順、数の順、またはよく選ばれるものを先にした順です。
- 長いリストはグループに分け、それぞれに短いタイトルを付けます。
- あらかじめ値を選んでおくのは、ほとんどの人がその値を選ぶ場合だけにします。
- フィールドの幅は、置く場所（フォームの列）で決めます。ボックスはその幅いっぱいに広がります。

### 非推奨

- バーやツールバーで、`labelHidden` を付けたセレクトフィールドを使わない。それは、自身の `label` で名前を付けた単独の[セレクト](/ja/components/select/)です。
- プレースホルダーをラベルの代わりにしない。何かを選ぶと消えてしまいます。
- 断りなく、`change` でページの移動、送信、削除をしない。ユーザーは、読むためにリストの中を移動します。
- セレクトフィールドをフィールドの中に入れない。すでにフィールドです。デバッグビルドがそのことを伝えます。フィールドが囲むコントロールは、セレクトです。
- `aria-label` で名前を付けない。ラベルを描かないときは、`label` と `labelHidden` を指定します。

## アクセシビリティ

<ComponentAccessibility name="select-field" />

### コンポーネントが担うこと

- 1 つの、編集できないコンボボックスです。これはセレクトのものです。名前は `label` で、描かれていてもいなくても変わりません。説明は、表示している補足テキストまたはエラーテキストで、フィールドが任意の間は任意であることを伝えるテキストも加わります。
- `error` が true の間は invalid であることを、`required` が設定されている間は必須であることを、`disabled` が true の間は無効であることを、`readOnly` が true の間は読み取り専用であることを、リストが開いている間は展開されていることを伝えます。
- 名前、説明、状態は、フィールドが囲んだコントロールに結び付けるのとまったく同じ方法で結び付けられます。1 つ下の階層で自分で書いたフィールドも、同じコントロールになります。
- 描かれたラベル、必須・任意の印、グリフが、もう一度伝わることはありません。
- Tab キーで止まる位置は 1 つです。ラベルを押すとトリガーにフォーカスが移り、何も開きません。補足を押しても何も起こりません。
- セレクトフィールドの中にフォーカスがある間に現れたエラーは、構成要素のフィールドが 1 度だけ、控えめに読み上げます。
- リストの中のこと（アクティブなオプション、オプションの名前と説明と状態、グループ）は、すべてセレクトのものです。[セレクトのページ](/ja/components/select/#アクセシビリティ)にあります。
- 文字の方向、拡大したテキスト、強制カラーモードへの対応は、それぞれの構成要素が受け持ちます。
- 自分の言葉は持ちません。`requiredText` と `optionalText` が空のときは、フィールドがプロダクトの言葉から読みます。

Web での既知の制約は、構成要素のものです。グループの間の区切り線はセパレーターとしては伝わりません。入力した文字とラベルは JavaScript のやり方で比べます。要素が定義されるまでの間は、テキストとしてのオプションのほかに何も描かれません。

### 利用者側で行うこと

- すべてのセレクトフィールドに `label` を、すべてのオプションにラベルを付けます。
- 値は利用者側で検証して `error` を設定し、どう直せばよいかが分かる `errorText` を書きます。
- 必須・任意の言葉を渡します。`required-text` と `optional-text` をセレクトフィールドに書くか、`setWords({ requiredText, optionalText })` でプロダクト全体に一度だけ渡します。Tanrei は言葉を同梱しません。`requiredText` がなければタグの位置にアスタリスクを描き、`optionalText` がなければタグを描かず、何も伝えません。[プロダクトの言葉](/ja/foundations/words/)を参照してください。
- オプションの値は、1 つのセレクトフィールドの中で重複させません。
