印を線でつないで描くものは 3 つあります。違いは、読み手がそれで何をするかです。

| 種類 | 何であるか | マーカー | 状態について伝えること | 入力 |
| --- | --- | --- | --- | --- |
| **ステップ** | 順にこなしていく手順 | ステップの番号が入った輪 | なし | 受けない |
| **タイムライン** | 起きたことと、これから起きることの記録 | 点かグリフ。番号は入らない | 必要なら、各イベントがいまどの段階か | 受けない |
| **ステッパー** | プロダクトが進めるフローの中での現在地 | 番号かチェック | その人自身の現在地 | 受ける |

タイムラインは、イベントに番号を振らず、並べ替えず、隠しません。時刻を読み取ることもありません。順序は、渡したとおりです。

### 使い方

Web では、タイムラインは要素ではなく、プロダクト側の順序付きリストに付けるクラスです。リストは、スクリプトが動く前から `<time>` 要素を含む文書のリストとして働きます。スタイルシートがなければ、日付の付いた段落が並ぶ、ブラウザー標準の番号付きリストになります。

SwiftUI、Compose、Flutter、React Native は計画中です。このページの冒頭で各プラットフォームに添えた名前は仕様が定めたもので、まだ提供していません。React にもまだ `Timeline` コンポーネントはないので、クラスを付けたリストを使ってください。

| プロパティ | Web での書き方 |
| --- | --- |
| `label` | `aria-label`（またはリストの前の見出しを指す `aria-labelledby`） |
| `size: large` | `data-size="large"` |
| `density: compact` | `data-density="compact"` |
| イベント | `<li>` |
| `datetime` のある `time` | `<time class="tanrei-timeline-time" datetime="…">`。中身は、利用者側で書く言葉 |
| 時点ではない `time` | `<p class="tanrei-timeline-time">` |
| `title` | `class="tanrei-timeline-title"` を持つ要素（`<p>`） |
| タイトルのスロット | イベントの先頭か、時刻の直後に置く見出し（`h2` から `h6`） |
| `status` | `data-status="done"`、`"current"`、`"upcoming"` |
| `statusLabel` | `data-status-label` |
| `icon` | 項目の最初の子として置く `<span class="tanrei-timeline-marker tanrei-icon" aria-hidden="true">` |

リストには `role="list"` を書いてください。マーカーを消したリストを、リストとして伝えなくなるブラウザーエンジンが 1 つあるためです。

時刻は、プロダクト側で書くものです。読み手の言語、暦、書式で書き、同じ時点を機械向けに `datetime` に入れます。タイムラインは何も整形しません。「2 時間前」は、書き換えるまでそのままです。

- **マーカー**は、先頭側の端にあるボックスの中に置かれます。ボックスの差し渡しは medium で 24、large で 28 で、イベントの 1 行目の中央にそろいます。状態がなければ小さな点で、プロダクト側のグリフがあれば、細い線の輪にそのグリフを入れたものになります。
- **状態**が変えるのは、マーカーの形だけです。完了はチェックの入った輪、進行中は点の入った塗りつぶしの円、これからのイベントは空の輪です。時刻の色を除けば、タイムラインが持ち込む色は、この塗りつぶしの円だけです。
- **コネクター**は、マーカーのボックスから次のボックスへ伸びる線で、どちらにも届く手前で止まります。最後のイベントにはありません。どの状態のイベントの間でも、同じ線です。
- **時刻**はイベントの先頭に、控えめな色で置かれます。**タイトル**はその次に、本文と同じ大きさ、見出しの太さで置かれます。**本文**は、利用者側で用意するコンテンツです。ブロックどうしは 8 離れます。
- **密度**：regular ではイベントどうしが 16、compact では 8 離れます。compact は、1 行のイベントが長く続くログのためのものです。変わるのはこの間隔だけです。
- **サイズ**は、プローズと同じ 2 つです。コントロールの間に置くときは medium、文章を読むためのページでは large です。マーカーとコネクターはステップのものとそろえてあるので、同じページに並べても 1 つの仲間に見えます。

### プローズの中で

`.tanrei-prose` の中のタイムラインは、プローズから切り離されません。各本文の段落、リスト、リンク、インラインコードは、プローズのものとして描かれます。タイムラインはプローズの幅いっぱいに広がるので、本文の中のコードブロックはカラムの幅になり、本文の中の段落は行長の上限で止まります。`@tanrei/web/prose.css` にはタイムラインの規則も入っているので、プローズのページに 2 つ目のスタイルシートは要りません。

### Web での描き方の違い

- イベントのテキストは、要素（`<p>`）の中に書いてください。項目に直接書いたテキストには、時刻やタイトルとの間の余白を付けられません。
- 完了のイベントのチェックは、アイコンセットの `check` です。そのため `icons.css` とアイコンフォントが必要で、なければ輪は空になります。
- プローズの外では、長文の本文（リスト、引用）はプローズとしては組まれず、ページのほかの場所と同じように配置されます。
- デザインシステムが追加したサイズや密度は、そのシステムが規則を用意するまで、既定のものとして描かれます。
- パッケージのスクリプトがなければ、どの項目もリストの現在の項目として示されません。状態は、その場合も言葉で読み上げられます。

## ガイドライン

### 推奨

- イベントは、読み手が期待する順で渡します。変更履歴なら新しい順、計画なら古い順です。タイムラインはその順を保ちます。
- 状態のあるイベントには、読み手の言語で書いた言葉を `data-status-label` で必ず添えます。
- 状態がすべての読み手にとって重要なら、タイトルか本文のタグとして、見える言葉でも示します。
- 相対的な時刻（「2 時間前」）には、正確な時点を `datetime` で添えます。
- 1 行のイベントが長く続くログには compact を使い、古いイベントを表示するボタンをリストの後に置きます。

### 非推奨

- 手順にタイムラインを使わない。読み手がすることに番号を振るのは、ステップです。
- フローの中でのその人の現在地を示すために使わない。それはステッパーで、マーカーはコントロールではありません。
- すべてのタイトルを見出しにしない。40 件のイベントがある変更履歴では、ページのアウトラインが埋まってしまいます。見出しにするのは、各イベントがページのセクションになっている場合です。
- イベントの中にタイムラインを入れない。イベントの中のイベントは、本文の中のリストにします。
- 失敗したことを、マーカーだけで伝えない。イベントの言葉とタグで伝えます。

## アクセシビリティ

<ComponentAccessibility name="timeline" />

### コンポーネントが担うこと

- 文書の順序付きリストのままです。イベントと同じ数の項目があり、それぞれが状態の言葉、時刻、タイトル、本文の順に読み上げられます。
- 状態の言葉は時刻の前に読み上げられ、画面には描かれません。マーカーとコネクターは装飾で、支援技術からは隠されます。
- 3 つの状態は、3 つの色ではなく 3 つの形で、強制カラーモードでも変わりません。
- 進行中のイベントが 1 つだけのとき、パッケージのスクリプトがそれをリストの現在の項目として示します。
- `datetime` のある時刻は、文書の time 要素そのものです。
- テキストは読み手の設定に合わせて大きくなり、折り返します。切り詰めたり、折りたたんだり、ページに分けたりすることはありません。

### 利用者側で行うこと

- リストに `role="list"` を書き、その前の見出しか `aria-label` で名前を付けます。
- イベント自身のテキストがすでに状態を伝えている場合を除き、状態には必ず `data-status-label` を添えます。
- 状態の言葉は、3 つのブラウザーエンジンの現行版では、スタイルシートを通じてスクリーンリーダーに届きます。パッケージのスクリプトなしで古いブラウザーに対応するときは、`data-status-label` の代わりに、項目の先頭に `<span class="tanrei-timeline-status">完了、</span>` と利用者側で書いてください。
- 人が見ている間にイベントを追加するときは、プロダクト側のライブリージョンで読み上げさせてください。タイムラインは読み上げません。
