リスト行は、多くのリストを形づくる行です。名前、それについての 1〜2 行、そしてその前と後ろに置くもの。[リスト](/ja/components/list/)は項目を並べ、項目をアクション、リンク、選択肢にする箱であり、リスト行は 1 つの項目に表示する中身です。リスト項目の中に置くか、1 行だけが必要な場所では単独で使います。

行が描くのはテキストとグリフだけです。塗り、枠、ホバー、フォーカスを持たず、行自体が押せるものになることもありません。それを決めるのは行を入れたリスト項目です。

Web では `<tanrei-list-row>` です。ほかのプラットフォームはまだ実装していません。

### リスト項目の種類ごとの行

行は、自分が入っているリスト項目がどの種類かをその項目から知り、それに合わせて自分を描きます。

- **静的な項目、または単独の行。** 行は自分の余白と自分の色を描きます。先頭や末尾のスロットのコントロールは、それ自身のフォーカスと押下を保ちます。
- **インタラクティブな項目、リンク項目、選択肢。** 項目が中身に余白を付けるので、行は自分の余白を描かず、高さだけを保ちます。静的な項目と押せる項目が混ざった列でも高さはそろいます。項目は行の見出しで名前が付き、ほかのテキストで説明されます。選択された選択肢では、行のテキストとグリフが選択時のコンテンツ色で描かれます。
- **並べ替えられるリスト。** リストのハンドルが項目の先頭、行の前に立ち、行の先頭の余白の代わりになります。
- **グリフのある行とない行。** リストの `iconSpace` が求めるとき（既定では、リストのほかの行が先頭のグリフを描いている間）、先頭の部分のない行はグリフの幅を空けておき、見出しをほかの行と同じ位置から始めます。単独の行は幅を空けません。
- **横並びのリスト、折り返すリスト。** 1 行に並ぶときは行は中身の幅になり、切り詰められません。折り返すときはリストより広くならず、必要な分だけテキストが切り詰められます。

行は項目の直接の子にします。項目の中で別の要素に包まれた行には何も伝わらず、単独のときと同じように描かれます。

## ガイドライン

### 使う場面

人、場所、設定、メッセージ、ファイルなど、どの項目も同じ部品を示すリストの各項目にリスト行を使います。項目がタイル、カード、画像であれば、リスト項目にプロダクト自身のコンテンツを入れます。送信中のファイルには[ファイル項目](/ja/components/file-item/)を使います。

### 部品

| 部品 | 用途 |
| --- | --- |
| 見出し | 項目の名前。支援技術、並べ替えられるリストのハンドル、タイプアヘッドで、リスト項目はこの名前で呼ばれます。 |
| オーバーライン | 名前の上に置く短い分類、出どころ、時刻。 |
| 補足テキスト | 項目の内容、状態、メッセージの書き出し。1 行、または `supportingLines` で 2 行。 |
| 先頭のグリフまたはスロット | 項目の種類（`leadingIcon`）、またはそのアバターや画像（`leading` スロット）。 |
| 末尾テキスト | 短い値。件数、サイズ、時刻、設定の現在値。 |
| 末尾スロット | バッジ。静的な行ではスイッチ、チェックボックス、アイコンのみのボタン。 |
| 末尾のグリフ | 行が何かを開くことを示すシェブロン、または状態。 |

見出し、オーバーライン、補足テキストは収まらないところで省略記号付きで切り詰められます。切り詰められた見出しと補足テキストは、ホバーとキーボードフォーカスでツールチップに全文が表示されます。末尾テキストが行の半分を超えることはありません。

### 密度

`regular` の行は、デフォルトシステムで 1 行、2 行、3 行のときそれぞれ 56、72、88 の高さで、タッチとポインターの両方で使うプロダクト向けです。`compact` の行（40、56、72）は、ポインターで使うツール向けです。アクション、リンク、選択肢は、密度の指定にかかわらず、リスト自身の最小の高さとタッチターゲットより低くなりません。

### 推奨

- どの行にも見出しを付けます。オーバーラインは短い分類に、末尾テキストは短い値にとどめます。
- リストの中では、見せるグリフのない行にはグリフを付けずにおきます。リストがその幅を空けておくので、見出しはそろったままです。画像の幅は空けられないので、1 つの列の行には、すべてに画像を付けるか、どれにも付けないかにします。
- 何かを開く行は、インタラクティブな項目かリンク項目の中身にします。

### 非推奨

- インタラクティブな項目、リンク項目、選択肢の中身である行にコントロールを入れないでください。その項目は 1 つの要素なので、中のコントロールに支援技術は届きません。そうした行は静的なままにします。
- 行に自分でクリック処理を付けて押せるようにしないでください。フォーカス、状態、最小ターゲットを持つリスト項目を使います。
- 行が何をするかを末尾のグリフだけで伝えないでください。それを伝えるのは見出しと項目の役割です。

## アクセシビリティ

<ComponentAccessibility name="list-row" />

### コンポーネントが担うこと

- 行のテキストは、描かれる順（オーバーライン、見出し、補足テキスト、末尾テキスト）にテキストとして読まれます。グリフは隠されます。
- 行を入れたリスト項目は、項目にラベルがなければ行の見出しで名前が付き、アクション、リンク、選択肢は行のオーバーライン、補足テキスト、末尾テキストで説明されます。
- 切り詰められたテキストも、支援技術には常に全文が伝わります。ツールチップは支援技術から隠され、ホバーと項目のキーボードフォーカスで開き、ポインターが上にある間は残り、Escape で閉じます。
- 右から左のレイアウトでは行は左右反転し、各テキストはそれ自身の方向を保ちます。
- 強制カラーでは、テキストとグリフはシステムのテキスト色になり、無効な項目ではシステムの無効テキスト色になります。
- デバッグビルドでは、見出しのない行、1 でも 2 でもない `supportingLines`、先頭スロットに置き換えられた先頭グリフ、不明な密度を報告します。

### 利用者側で行うこと

- 行に `headline` を付けます。
- 静的な行のコントロールには、行の見出しで名前を付けます。スイッチなら「Bluetooth」、ボタンなら「brief.pdf を削除」のようにします。
- 先頭スロットのアバターや画像には代替テキストを付けるか、見出しがすでにその人を名指ししているなら隠します。
