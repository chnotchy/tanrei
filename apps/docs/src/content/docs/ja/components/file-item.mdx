ファイル項目は、1 つのファイルを見せるものです。名前の前には、ファイルの形式を表すグリフか、そのファイルの小さな画像があります。名前の下の 1 行には、プロダクトがそのファイルについて伝えることが入ります。形式、サイズ、送信がどこまで進んだか、何が問題だったかです。末尾には、ファイルに対する 2 つのアクションがあります。取り除くことと、もう一度試すことです。

形は 2 つあります。

- `row`（既定）。置かれた場所の幅いっぱいに広がる 1 行です。縦に並ぶファイルに使います。
- `tile`。利用者側が指定した幅と高さのボックスで、その下に名前があります。画像の並びに使います。

<Callout type="caution" title="見せるだけで、ほかには何もしません">
ファイル項目は、ファイルを 1 バイトも読まず、ファイルを保持せず、何も送りません。取り除くこともしません。取り除くアクションは、その人が求めたことを利用者側に伝えるだけで、項目を取り除くのは利用者側です。見せるものは、プロパティに指定されたとおりです。
</Callout>

**使われている場所**は、[ファイルアップロード](/ja/components/file-upload/)です。そこでは、選ばれたファイルの 1 つ 1 つがファイル項目です。単独では、プロダクトが持っているファイルを見せる場所ならどこでも使います。メッセージの添付ファイル、記録に付いた書類、すでに送信された申請のファイルなどです。

次の場合は、ほかのものを使います。

- ファイルを選んでもらい、それを一覧にする場合。それは[ファイルアップロード](/ja/components/file-upload/)です。ファイル項目を利用者側の代わりに持ちます。
- ファイルを並べ替えてもらう場合。それは、行でファイルを見せる[リスト](/ja/components/list/)です。[並べ替えられるファイル](#並べ替えられるファイル)を見てください。
- ファイルの中から選択してもらう場合。それは、選択のある[リスト](/ja/components/list/)です。ファイル項目に、選択の状態はありません。
- 画像そのものがコンテンツで、見てもらうためのものである場合。ファイル項目の画像は、グリフがあるはずの場所に置かれるもので、代替テキストを持ちません。

Web では `<tanrei-file-item>` です。ほかのプラットフォームはまだ実装していません。

### 使い方

`name` と、手元にあるテキストを指定します。`value` は、`click`、`remove`、`retry` が利用者側に返す値です。

<Tabs syncKey="platform">
  <TabItem label="Web">
    ```html
    <ul class="attachments" aria-label="添付ファイル">
      <li>
        <tanrei-file-item value="a" name="brief.pdf" format-text="PDF" size-text="820 KB"
                          href="/files/brief.pdf" remove-label="{name} を取り除く"></tanrei-file-item>
      </li>
      <li>
        <tanrei-file-item value="b" name="floor-plan.png" size-text="3.4 MB"
                          status="uploading" status-text="アップロード中" progress="0.4"
                          remove-label="{name} を取り除く" retry-label="{name} をもう一度試す"></tanrei-file-item>
      </li>
    </ul>

    <script type="module">
      import '@tanrei/web/components/file-item';

      const list = document.querySelector('.attachments');
      // ファイル項目が自分で消えることはありません。利用者側が項目を取り除き、ファイルの送信を止め、フォーカスを移します。
      list.addEventListener('remove', (event) => {
        cancel(event.detail.value);
        event.target.closest('li').remove();
      });
      list.addEventListener('retry', (event) => send(event.detail.value));
    </script>
    ```
  </TabItem>
  <TabItem label="React">
    ```tsx
    import { FileItem } from '@tanrei/react';

    <ul aria-label="添付ファイル">
      {files.map((file) => (
        <li key={file.id}>
          <FileItem value={file.id} name={file.name} sizeText={file.sizeText}
            status={file.status} statusText={file.statusText} progress={file.progress}
            errorText={file.errorText} retryable={file.retryable}
            removeLabel="{name} を取り除く" retryLabel="{name} をもう一度試す"
            onRemove={() => remove(file.id)} onRetry={() => retry(file.id)} />
        </li>
      ))}
    </ul>
    ```
  </TabItem>
</Tabs>

`removeLabel` と `retryLabel` は、`setWords()` でプロダクト全体に一度だけ指定できます。それ以外のテキストは、すべてインスタンスのものです。

| 観点 | `row`（既定） | `tile` |
| --- | --- | --- |
| 使う場面 | 種類を問わない、縦に並ぶファイル。 | 画像の並び。 |
| 幅 | 置かれた場所の幅。 | ボックスの幅である `width`。置かれた場所より広くはなりません。 |
| グリフまたは画像 | 名前の前。`preview` があれば、小さな正方形です。 | ボックス全体。`width` × `height` です。 |
| 名前 | 折り返され、切り詰められません。 | ボックスの下の 1 行。末尾が残るように、中ほどで切り詰められます。 |
| 2 行目 | 名前の下。 | ボックスの下。ボックスの幅の中で折り返されます。 |
| バー | テキストの下。 | ボックスの下端に沿って。 |
| アクション | 末尾。再試行、取り除くの順です。 | ボックスの中、上の末尾側の角。 |

`width` と `height` は数値で、読まれるのはタイルの形のときだけです。`height` がなければ、ボックスの高さはトークン `comp.file-item.tile.media.height` のとおりです。`width` がなければ、正方形になります。手元にある画像の縦横比に合わせて選びます。スクリーンショットなら `width="160" height="90"`、人物の写真なら正方形です。ボックスが、2 つのアクションに必要な幅より狭くなることはありません。

3 つ目の、小さくまとめた形はありません。1 行に収めたファイルは、2 行目に何もない行です。

### 見せるもの

それぞれのパーツは、利用者側が指定したときに見えます。見えるものを変えるのは、オンとオフを切り替える 2 つのプロパティ、`preview` と `nameHidden` です。見せるパーツの一覧を受け取るプロパティはありません。

| パーツ | 見える条件 |
| --- | --- |
| グリフ | 画像が描かれない場所では、常に。 |
| 画像 | `preview` が設定されていて、描く画像があるとき。 |
| 名前 | 行では常に。タイルでは、`nameHidden` が設定されて画像が描かれているときを除いて。 |
| 言葉で表した形式 | `formatText` を指定したとき。Tanrei は、形式を表す言葉を持ちません。 |
| サイズ | 読む人の言語に合わせて整形した `sizeText` を指定したとき。 |
| 言葉で表した状態 | `statusText` を指定したとき。 |
| エラー | `status` が `error` で、`errorText` を指定したとき。どの形でも、状態の場所に置かれ、切り詰められません。 |
| バー | `status` が `uploading` のとき。`progress` の値まで塗られます。`progress` が設定されていない間は不確定の表示です。 |

完了したファイルと失敗したファイルには、状態の言葉の前に印があります。チェックと、エラーの印です。名前の前のグリフは、状態によって変わりません。利用者は、それぞれについて場所を 1 つ覚えるだけで済みます。名前の前はそのファイルが何であるか、状態の前はそれがどうなっているかです。

`nameHidden` は、密に並んだ画像のためのものです。名前が隠れるのは、画像が描かれているときだけです。グリフを見せているタイルは、名前を保ちます。形式のグリフでは、同じ形式の 2 つのファイルを見分けられないためです。どの場合も、支援技術にとっての項目の名前は、その名前のままです。

### グリフは形式を表す

グリフの種類は 10 あります。種類ごとに、メディアタイプの一覧とファイルの拡張子の一覧があります。グリフは `mediaType` から選ばれます。メディアタイプが空であるか、`application/octet-stream` であるか、どの一覧にもない場合は、`name` の拡張子から選ばれます。種類は次の順に照合されます。一覧は固定で、どのプラットフォームでも同じです。そのため、1 つのファイルは、どこで見せても同じグリフになります。`video/mp2t` も種類を決めません。プラットフォームはこれを拡張子 `.ts` から推定しますが、この拡張子は TypeScript のファイルと動画のストリームが共有しています。そのため `index.ts` はコードのグリフになります。

- 形式を知るためにファイルを開くことはありません。
- プロダクト独自の形式には、`glyph` でアイコンセットのグリフを指定するか、`icon` スロットに自分のグリフを入れます。
- グリフはどれも同じ 1 色です。形式に固有の色はありません。色は、どこで使われても 1 つのことを意味します。そして形式は状態ではありません。
- 形式が大事な場面では、`formatText` を使って言葉で伝えます。グリフは、支援技術から隠されています。

### プレビューとそのコスト

`preview` は、グリフの場所にファイルの画像を描きます。画像の出どころは 2 つあります。

- `previewSrc`。サーバーが作った、そのファイルの小さな画像のアドレスです。どの形式のファイルにも描かれます。
- ファイルそのもの。`previewSrc` が空で、ファイルが画像である場合です。Web では、`file` プロパティに `File` を設定します。

`fit` は、画像がボックスをどう埋めるかを決めます。`cover`（既定）は、ボックスを埋め、収まらない部分を切り落とします。写真に使います。`contain` は、ボックスの地の上に画像の全体を見せます。スキャン、署名、図のように、端が大事なものに使います。

プレビューのコストは次のとおりです。

| 画像の出どころ | かかるコスト |
| --- | --- |
| `preview` がオフのとき（既定） | ありません。100 個のファイル項目のコストは、そのテキストのコストだけです。 |
| `previewSrc` があるとき | 項目ごとに画像のリクエストが 1 つ。プラットフォーム自身の画像の読み込みが行います。 |
| ファイルそのものを使うとき | ファイルのアドレスが 1 つ。項目が、初めて表示範囲かその近くに入ったときに作ります。項目がページを離れたとき、別のファイルを渡すかファイルをなくしたとき、プレビューが求められなくなったときに解放します。ファイルを読んで描くのは、プラットフォームの画像デコーダーです。項目自身は何も読みません。 |

- ファイルから描かれるのは、画像だけです。動画の 1 コマや書類の 1 ページを描くには、ファイルを開いて読む必要があり、Tanrei のコンポーネントはどれもそれをしません。そうしたファイルには `previewSrc` を指定します。
- 画像を描けるようになるまでの間と、描けなかった場合は、形式のグリフが描かれます。スピナーも、壊れた画像の印もなく、`status` も変わりません。サムネイルを読み込めなかったことは、ファイルの失敗ではありません。
- 画像に代替テキストはありません。画像はグリフがあった場所に置かれ、ファイルの名前は `name` が伝えます。

| `interactive` | ボタンです。`value` を持つ `click` を発火します。 | その人が今いる場所でファイルを開く場合。画像を自身のビューアーで、書類をパネルで開くときです。 |

本体は、グリフまたは画像と、テキストです。アクションは本体の横にあり、本体の中に入ることはありません。そのため、押せるファイル項目でも、フォーカスが止まる位置は多くて 3 つです。本体、再試行、取り除くです。

`readOnly` は、どちらのアクションも描かず、その場所も空けません。読むだけの記録に付いたファイルに使います。本体は、このときも押せます。

`disabled` は、アクションと本体を無効にします。項目が見せるものはそのまま残り、読めるままです。無効なアクションは待機時の地を保ちます。行では地がなく、タイルでは円の地があり、薄くなるのはグリフだけです。

### 言葉

ファイル項目は、自身の言葉を持ちません。2 つは `setWords()` でプロダクト全体に一度だけ指定でき、それ以外のテキストはすべてインスタンスのプロパティです。

| プロパティ | プロダクトの言葉のキー | ない場合 |
| --- | --- | --- |
| `removeLabel` | `removeLabel` | 取り除くアクションは描かれますが、名前がありません。デバッグビルドが報告します。 |
| `retryLabel` | `retryLabel` | 再試行のアクションは描かれますが、名前がありません。デバッグビルドが報告します。 |

それぞれのアクションの名前には、そのファイルの名前が入ります。`removeLabel` と `retryLabel` は場所 `{name}` を持つ文で、ファイル項目がファイルの名前を入れます（「`{name} を取り除く`」）。1 つの文ですべてのファイルに足り、利用者には言語の語順のまま「brief.pdf を取り除く、ボタン」と聞こえます。スクリーンリーダーがページのボタンを一覧にしたときも同じです。`{name}` のない文は、どのファイルのアクションも同じ名前にしてしまうので、デバッグビルドが報告します。

### 右から左

右から左のレイアウトでは、グリフまたは画像が右に、アクションが左に並び、取り除くアクションがいちばん外側になります。バーは右から伸び、タイルのアクションは左上の角に置かれます。画像が反転することはありません。ラテン文字のファイル名は、ドットと拡張子を含めて、自身の並びを保ちます。形式の 10 のグリフのうち、反転するのは `other` のグリフだけです。アイコンセットがそう指定しているためです。

### 推奨

- 完了したファイルには `statusText` を、失敗したファイルには `errorText` を指定します。状態を、印や色だけで伝えることはありません。
- `retryable` は、もう一度試せば直る可能性のある失敗にだけ指定します。大きすぎるファイルは、次も大きすぎます。
- サイズは利用者側で整形します。1 メガバイトを 1000 キロバイトとするか 1024 キロバイトとするかは、プロダクトが決めます。
- ひとまとまりのファイル項目は、名前を付けた `<ul>` のような利用者側のリストか、ファイルアップロードに入れます。
- 項目を取り除いた後は、利用者側でフォーカスを移します。単独のファイル項目は、自分の隣に何があるかを知ることができません。

### 非推奨

- 項目が自分で消えたり、状態を変えたり、バーを動かしたりすることを期待しない。項目は、設定された内容を描きます。
- 画像でないファイルに `nameHidden` を使わない。そのタイルは、どのみち名前を保ちます。
- メニュー、チェックボックス、キャプションを中に入れない。スロットはグリフの 1 つだけです。ファイルに対するほかのアクションは、項目の横に置きます。
- 選択したり並べ替えたりするリストの行として使わない。それはリストの行です。

## アクセシビリティ

### コンポーネントが担うこと

- 単独のファイル項目は、ファイルの名前が付いたグループです。ファイルアップロードの中では、そのリストの項目です。
- 押せる本体は、1 つのボタンまたは 1 つのリンクです。ファイルの名前が名前になり、2 行目が説明になります。フォーカス順では、アクションより前です。リンクは Enter で動作し、Space では動作しません。新しいタブで開くリンクは、名前の後に `targetLabel` を伝えます。
- アクションはボタンです。`removeLabel` と `retryLabel` が名前になり、その場所 `{name}` にファイルの名前が入ります。再試行が、取り除くより前です。
- バーは、そのファイルの名前が付いたプログレスバーです。エラーは 2 行目のテキストで、状態の場所で読まれます。
- グリフ、画像、状態の印は、支援技術から隠されています。それらが示すことは、言葉が伝えます。
- ファイル項目は、何も読み上げません。多くのファイル項目を持つ側が、全体のためのライブリージョンを 1 つ持ちます。ファイルアップロードがそうしています。
- 名前の全体が、常に支援技術に届きます。タイルが名前を切り詰めているときも、`nameHidden` が隠しているときも同じです。
- テキストが 200% のとき、行は折り返され、何も失われません。グリフとアクションが名前に行の半分の幅も残さないときは、アクションがテキストの下の独立した段に、行の末尾に揃えて移り、名前が行の幅いっぱいを使います。タイルのボックスは大きさを保ち、テキストがその下で大きくなります。
- 強制カラーモードでは、ボックスと、タイルのアクションの円形の地が縁を保ち、バーも見えたままです。画像はそのままです。
- 状態の間の色の変化は、短い時間をかけて動きます。動きを減らす設定では、すぐに変わります。

Web での既知の不足は次のとおりです。

- アニメーション GIF のような動く画像は、ブラウザーの画像要素が再生します。ファイル項目は、それを止めておくことができません。それが大事な場面では、`previewSrc` に静止画を指定します。
- 要素が定義されるまでは、何も描かれません。名前が属性であって、文書の中のテキストではないからです。スクリプトが動かない場所でファイルを一覧にする必要があるページは、自身のリンクを書きます。

### 利用者側で行うこと

- `name` を必ず指定します。
- `removeLabel` と `retryLabel` を、要素に、または `setWords()` で一度だけ指定します。
- 状態と失敗は、必ず言葉で伝えます。`statusText` と `errorText` です。
- `target="new"` を指定するときは、`targetLabel` も指定します。
- ひとまとまりのファイル項目には、利用者側のリストと名前を与えます。追加されたもの、完了したもの、失敗したものは、利用者側の 1 つのライブリージョンで伝えます。ファイルアップロードは、この両方を代わりに行います。
- 項目を取り除いた後は、フォーカスを次のファイルの取り除くアクションへ、またはファイルを追加したものへ移します。
