マーキーテキストは、プロダクトのテキスト 1 行を、それには狭すぎる場所に置くためのものです。止まっているあいだは、ほかの切れた行と同じように読めます。行の始まりから始まり、切れたところで省略記号で終わります。トリガーが続くあいだ（既定では、ポインターが重なっているあいだ、または置かれたコントロールにキーボードフォーカスがあるあいだ）は、ピクセル毎秒で決まる一定の速さで横にスクロールし、テキストのどの部分も一度は見える位置を通ります。そのあと始まりに戻って止まります。上の 1 行目にポインターを重ねてみてください。2 行目は収まっているので、決して動きません。テキストが収まっているマーキーテキストは、ただの 1 行のテキストです。

向いているのは、行の幅が決まっていて、テキストはたいてい短いけれどもときどき長くなる場所です。リスト行のタイトル、ナビゲーションバーやドロワーのラベル、チップ、再生中の曲名、テーブルのセルなどです。ほとんどの場合は切れた行のままで足りるなら、切れたままにして全文を[ツールチップ](/ja/components/tooltip/)で見せる方法もあります。ツールチップは全体を一度に見せ、何も動かしません。

### 使い方

Web と React の例は現在の仕様に沿っています。SwiftUI、Compose、Flutter、React Native は予定段階で、マーキーテキストはまだ提供されていません。

## ガイドライン

### 使う場面

行を 1 行のまま、レイアウトが決めた幅に保たなければならず、切れた部分がときどき必要になる場所で使います。プレイリストの行にある長い曲名、言語によって長くなる行き先のラベル、名前を入れたチップなどです。行は高さも位置も変えず、求められたときだけ残りを見せます。

行動するために全文を読む必要があるテキストには使いません。警告、エラー、選択の条件、金額、指示などです。動くテキストは読むのに時間がかかり、見落とされやすいからです。そうしたテキストには必要なだけ行を与え、折り返させます。

### トリガーの選び方

| トリガー | 用途 |
| --- | --- |
| `hover-or-focus` | 既定で、ほとんどどこでも適した選択です。ポインターを重ねたときにも、置かれたコントロールにキーボードで到達したときにも動くので、どちらの人にも同じものが見えます。 |
| `hover` | キーボードで素早く移動する長いリスト。フォーカスが通るたびに各行のタイトルが動き出すと、役に立つより気が散ります。 |
| `focus` | 主にキーボードやリモコンで操作するサーフェスの行。そこではホバーに意味がありません。 |
| `always` | 再生中の曲名や、ポインターを向けるより目をやるだけの行。表示されたときからひとりでに動くので、止める手段が必要です（アクセシビリティを参照）。 |

トリガーの範囲は、行だけでなく、行が置かれたコントロール（リスト行、チップ、行き先）です。リスト行のどこにポインターを重ねても、そのタイトルが動きます。ホバーとして数えるのはマウスやペンのような精密なポインターだけで、タッチでは動き始めません。

### repeat と bounce

- **`repeat`**（既定）は、テキストの終わりが通り過ぎるまで先頭側へ動かし、そのうしろに隙間を空けてコピーを続けます。行が空になることはなく、始めの状態に戻ります。電光掲示板のように読め、しばらく動く行に向いています。
- **`bounce`** は、テキストの終わりが見えるところまで動かして止め、元に戻します。コピーを描かないので、終わりと始まりが並んで見えることはありません。終わりを一度ちらりと見せるだけの行に向いています。

どちらも、テキストが書かれている方向に動かします。左から右のテキストなら左へ、右から左のテキストなら右へ動き、周りのページの方向には左右されません。

### 速さと止まる時間

- **`speed`** は 1 回の流れにかかる時間ではなく、ピクセル毎秒で表します。長い曲名も短い曲名も同じ速さで動きます。トークン `comp.marquee-text.speed` に任せ、プロダクトのどの動く行も同じ速さを保つようにします。文字サイズが大きくなると速さも文字とともに上がり、どの大きさでも 1 秒に通り過ぎる文字の数は同じです。
- **`startPause`** は、毎回の流れの前にテキストが始まりで止まる時間です。始まりを読めるようにするためのものです。`trigger="always"` では、最初の流れの前の待ち時間でもあります。
- **`endPause`** は、`bounce` のとき、テキストが終わりを見せたまま止まってから戻るまでの時間です。
- **`iterations`** は、1 回のトリガーで流れを何回繰り返してから始まりで止まるかです。null のままなら、ポインターが離れるかフォーカスが移るまで、`always` なら行が表示されているあいだずっと繰り返します。動きを短く収める回数を設定することが、ホバーやフォーカスのトリガーをアクセシブルにします（後述）。

止まる時間は読むための時間です。アニメーションを速めたり遅くしたりするプロダクトのモーション設定は、これを短くしません。

### 文言

テキストは、動くところを見る必要がめったにない長さにとどめます。マーキーはほかより長いときどきの曲名のためのもので、文をチップに収める手段ではありません。項目どうしを見分ける語は、動かなくても読める始まりに置きます。テキストには太字の部分のようなインラインの内容も入れられますが、常に 1 行です。

### 推奨

- 行は、人がポインターを重ねたりフォーカスしたりするコントロールの中に置き、トリガーの範囲がリスト行全体になるようにします。
- `iterations` を設定し、ホバーやフォーカスのたびに短く流れて止まるようにします。
- `trigger="always"` の行には止める手段を用意します。行自身の再生コントロールか、ページのあらゆる動きを止めるプロダクト側のコントロールです。

### 非推奨

- 行動するために全文を読む必要があるテキストに使わない。そのテキストには専用の行を与えます。
- 常に動く行を 1 つの画面にいくつも置かない。動く行は 1 本でも目を引きます。何本もあると、互いに、また画面のほかのすべてと競い合います。
- 動きを始めるために、行そのものをボタンやリンクにしない。行はテキストで、人が押すのは周りのコントロールです。
- 長いテキストを短い流れに収めるために止まる時間を縮めない。テキストを短くするか、別の方法で全体を見せます。

## アクセシビリティ

<ComponentAccessibility name="marquee-text" />

### 既定のままでは WCAG 2.2.2 に反することがある

[Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)（WCAG 2.2.2、レベル A）は、ひとりでに始まり、5 秒より長く続き、ほかのコンテンツと並んで表示される動きを、その人が一時停止、停止、または非表示にできることを求めています。Tanrei の既定はそれだけではこれを満たしません。次の 2 点で満たさず、どう満たすかはプロダクト側が決めます。

1. **`trigger="always"` は既定で再生コントロールを描きません**（`playbackControl` は false）。ほかのコンテンツと並んで 5 秒より長く動き続ける行には、止める手段が必要です。`playbackControl` を設定すると、行の末尾にアイコンだけの一時停止・再生ボタンが描かれ、`pauseLabel` と `playLabel`、またはプロダクトの言葉 `marqueePauseLabel` と `marqueePlayLabel` で名前が付きます。あるいは、ページのあらゆる動きを止めるプロダクト側のコントロールを `paused` に結び付けます。どちらもないまま動き続ける行は、デバッグビルドで報告されます。
2. **`hover`、`focus`、`hover-or-focus` では、`iterations` が null のとき、ポインターが離れるかフォーカスが移るまで流れを繰り返します。** WCAG の Understanding 文書は、ホバーやフォーカスで始まる動きをひとりでに始まる動きとして数え、フォーカスが離れたときにしか止まらない動きは止める手段にならないとしています。2.2.2 を満たすには、動きが 5 秒以内に終わるように `iterations` を設定します。長いテキストでは 1 回の流れだけで 5 秒を超えることがあります。その場合はテキストを短くするか速さを上げるか、別の方法で全文を見せます。

行は、ポインターが重なっているあいだやフォーカスが内側にあるあいだ、また画面の外にあるあいだやページが隠れているあいだ、動きをその場で保ちます。読みやすくはなりますが、止める手段ではありません。

### コンポーネントが担うこと

- テキストが収まらないときだけ動きます。テキストが収まる行はただのテキストを描き、何も始めません。
- 動きを減らす設定（WCAG 2.3.3）では決して動きません。ホバーやフォーカスでは、隠れた部分をビューポート 1 つ分ずつ、動きなしで見せ、それぞれで止まるので、テキストのどの部分も見られます。`trigger="always"` の行は切れたまま止まり、再生コントロールを描きません。
- 支援技術は、行が置かれた位置で、テキストを 1 回、全体を、テキストとして読みます。コピー、省略記号、フェードは支援技術から隠され、動きは読まれる内容を何も変えず、何も読み上げさせません。
- 行はフォーカスが止まる位置ではありません。Tab で到達するのは行が置かれたコントロールと、描かれているあいだの再生コントロールです。
- 再生コントロールは text バリアント、small サイズのボタンで、テキストが動いているあいだはアイコンセットの一時停止のグリフ、止まっているあいだは再生のグリフを表示します。Enter または Space で切り替わり、フォーカスはボタンにとどまり、`pausedChange` を発火します。ターゲットは最小ターゲットを満たします。
- 右から左のレイアウトでは、再生コントロールは行の左端に置かれます。テキストは自分の方向に従って動きます。
- 強制カラーモードでは、テキストはプラットフォームが周りの要素に与える色になり、端はフェードせずに切り取られます。
- コンポーネントは自分の言葉を持ちません。インスタンスからもプロダクトの言葉からも名前が得られない再生コントロールは、それでも描かれ、デバッグビルドで報告されます。未知の `trigger` や `loop`、範囲外の速さ、止まる時間、回数も同じく報告されます。

Web のコンポーネントは HTML の `<marquee>` 要素ではありません。この要素は[非推奨](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/marquee)で、動きを減らす設定を無視し、その人が一時停止できません。

### 利用者側で行うこと

- 上のとおり WCAG 2.2.2 を満たします。`trigger="always"` のすべての行に止める手段を用意し、ホバーやフォーカスで始まる動きが 5 秒以内に終わる `iterations` を設定します。
- 再生コントロールの 2 つの名前を、インスタンスで、またはプロダクトの言葉で一度だけ、ページの言語で与えます。「流れるテキストを一時停止」「流れるテキストを再生」のように、ボタンが何をするかを言います。
- 全文を読む必要があるテキストはマーキーに入れません。切れた行は、動きを起こさない人にはその部分を隠したままです。
- 常に動く行は 1 つの画面に 1 本までにし、人が読んでいる長いテキストの横には置きません。
