見た目は似ていても、別のものが 3 つあります。

| 種類 | 何であるか | 状態 | 伝えること |
| --- | --- | --- | --- |
| **順序付きリスト**（プローズ） | 順番のある項目。それぞれ語句か 1 文 | なし | 「これらを、この順で」 |
| **ステップ** | 読んで、別の場所で実行する手順 | なし | 「これをして、次にこれ」 |
| **ステッパー** | プロダクトが進めるフローの中での現在地 | あり | 「いまここです」 |

ステップには「現在」「完了」「失敗」といった状態がなく、マーカーはコントロールではありません。購入手続きやセットアップウィザードに必要なのはステッパーですが、Tanrei にはまだありません。

### 使い方

Web では、ステップは要素ではなく、プロダクト側の順序付きリストに付けるクラスです。リストはスクリプトが動く前から文書のリストとして働きます。Markdown レンダラーが書き出す `<ol>` にはクラスを 1 つ付けるだけでよく、ラッパーは要りません。スタイルシートがなければ、ブラウザーの番号付きリストになります。

SwiftUI、Compose、Flutter、React Native は計画中です。このページの冒頭で各プラットフォームに添えた名前は仕様が定めたもので、まだ提供していません。React にもまだ `Steps` コンポーネントはないので、クラスを付けたリストを使ってください。

| プロパティ | Web での書き方 |
| --- | --- |
| `label` | `aria-label`（またはリストの前の見出しを指す `aria-labelledby`） |
| `start` | リスト自身の `start` |
| `size: large` | `data-size="large"` |
| ステップ | `<li>` |
| ステップの `title` | 項目の最初の子で、`class="tanrei-steps-title"` を持つもの（`<p>`） |
| タイトルのスロット | 項目の最初の子として置く見出し（`h2` から `h6`） |

リストには `role="list"` を書いてください。マーカーを消したリストを、リストとして伝えなくなるブラウザーエンジンが 1 つあるためです。

- **マーカー**は、システムの細い線で描いた輪に、ステップの番号を入れたものです。差し渡しは medium で 24、large で 28 です。番号が 1 桁か 2 桁なら円のままで、それより長い番号では横に伸びてカプセル形になります。その場合も、どのステップの内容も同じ端から始まります。
- **コネクター**は、輪から次の輪へ伸びる線で、どちらの輪にも届く手前で止まります。最後のステップにはありません。
- **タイトル**は任意です。ステップのテキストであって、見出しではありません。ただし、項目の最初の子として見出しを置くと、ほかのタイトルと同じように描かれたうえで見出しのロールとレベルを保つので、そのステップはページのアウトラインに入ります。
- **本文**は、利用者側で用意するコンテンツです。ブロックどうしは 8、ステップどうしは 16 離れます。テキストでないブロック（コードブロック、テーブル、タブ、コールアウト）は、本文の幅いっぱいに広がります。
- **サイズ**は、プローズと同じ 2 つです。コントロールの間に置くときは medium、文章を読むためのページでは large です。プローズの中のステップは、そのプローズのサイズになります。
- **色**：番号、タイトル、本文は、ステップが置かれたサーフェスのコンテンツの色になります。輪とコネクターは、どちらもシステムにただ 1 つある細い線の色で描かれます。塗りはどこにもありません。

### プローズの中で

`.tanrei-prose` の中のステップは、プローズから切り離されません。各ステップの段落、リスト、リンク、インラインコードは、プローズのものとして描かれます。ステップはプローズの幅いっぱいを使うので、ステップの中のコードブロックはカラムの幅いっぱいに広がり、ステップの中の段落はこれまでどおり行長の上限で折り返します。ステップの中のリストには、順序付きなら英字、順序なしなら輪が付くので、サブステップがステップの番号を繰り返すことはありません。ステップのルールは `@tanrei/web/prose.css` に含まれているので、プローズのページに 2 つ目のスタイルシートは要りません。

### Web での描き方の違い

- タイトルがあるときは、本文を要素（`<p>`）の中に書いてください。タイトルの直後に直接書いたテキストには、タイトルとの間の余白を付けられません。
- 行長の上限があるプローズの中では、テキストだけのステップはその上限に収まります。ブロックも入っているステップに直接書いたテキストは収まらないので、`<p>` の中に書いてください。
- コードブロックや画像で始まるステップでは、マーカーの上端がそのブロックの上端にそろいます。そうしたブロックの前に直接書いたテキスト（Markdown のタイトなリスト項目）は、スタイルシートからは見えません。`<p>` の中に書いてください。
- 3 桁以上の番号では、マーカーが横に伸びてカプセル形になります。手順全体のマーカーの列がそれに合わせて広がるのは、幅を測るパッケージのスクリプトがある場合だけです。スクリプトがなければ、そのマーカーは隣の余白にはみ出します。
- パッケージのスクリプトがなければ、実行時に `start` を変えても、2 つのブラウザーエンジンでは描き直されません。

## ガイドライン

### 推奨

- 何の手順であるかを、手順の前の見出しか文で伝えます。どちらもないときは、リストに `label` を付けます。
- 1 つのステップに書くのは、1 つの操作と、それを行うのに必要なことだけにします。
- 注記やタブでの選択をはさんで手順を続けるときは、`start` を使います。
- 手順ではなく、語句を並べただけの項目には、クラスを付けないプローズの順序付きリストを使います。

### 非推奨

- フローの進み具合を示すためにステップを使わない。ステップには、現在のステップも完了したステップもありません。
- ステップの中にステップを入れない。サブステップは、本文の中の順序付きリストにします。
- すべてのタイトルを見出しにしない。あらゆる手順のあらゆるステップがアウトラインに並ぶページは、たどりにくくなります。

## アクセシビリティ

<ComponentAccessibility name="steps" />

### コンポーネントが担うこと

- 文書の順序付きリストのままです。ステップと同じ数の項目があり、それぞれが番号、タイトル、本文の順に読み上げられます。
- 読み上げられる番号は、見えている番号と同じです。`start` でほかの手順の続きにした場合も変わりません。
- 輪とコネクターは装飾で、支援技術からは隠されます。順序はリストが伝えるので、強制カラーモードでも、スタイルシートがなくても、何も失われません。
- テキストは読み手の設定に合わせて大きくなり、折り返します。横にスクロールするのは、コードブロックのように自身のボックスの中でスクロールするブロックだけです。

### 利用者側で行うこと

- リストに `role="list"` を書きます。
- 手順には、その前の見出しか `aria-label` で名前を付けます。
- タイトルを見出しにするのは、ステップがページのセクションになっている場合だけにします。
