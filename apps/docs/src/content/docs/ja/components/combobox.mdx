コンボボックスは、[コンボボックスフィールド](/ja/components/combobox-field/)のコントロールだけを取り出したものです。ボックス、その中で入力するテキスト、先頭のグリフ、消去ボタン、シェブロンと、オプション、グループ、状態の行の入ったリストがあります。上にラベルの行はなく、下に補足もエラーテキストもありません。

ユーザーが読むラベルがほかの場所にあるところで、単独で使います。

| 場所 | ユーザーが読むラベル | コンボボックスの `label` |
| --- | --- | --- |
| ツールバーの絞り込み | プレースホルダーとグリフが、何をする欄かを伝えます | 何を探すか。「トークンを検索」 |
| テーブルのセル | 列の見出し | 列と行。「担当者、リリースノート」 |
| ラベルを横に置いた行 | 横にあるテキスト | それと同じ言葉 |

単独で使うコンボボックスには、自身の `label` が必要です。これが、入力欄とリストのアクセシブルネームになります。Stacked のコンボボックスが `label` を描くことはありません。Filled と Outlined のコンボボックスは、ボックスの中で浮き上がるラベルとして描きます。

これは**上級者向け**のコンポーネントです。自分で組み立てるプロダクトのための、コントロールだけの部品です。ほとんどのフォームに合うのは、このコンボボックスをフィールドに入れてそのまま使える形にした[コンボボックスフィールド](/ja/components/combobox-field/)です。

**使われている場所**は、[コンボボックスフィールド](/ja/components/combobox-field/)です。自分で枠を付けるときは、[フィールド](/ja/components/field/)の中に入れます。フィールドが名前と説明を与え、必須であることを伝え、エラーの状態にします。

単独でもフィールドの中でも、置かれた場所の幅いっぱいに広がるブロックです。自分の幅は持たず、オプションや値に合わせて幅が変わることもありません。ボックスを狭くするには、置く場所を狭くします。

Web では、`<tanrei-option>` を子に持つ `<tanrei-combobox>` です。子の要素は、[セレクト](/ja/components/select/)が持つものと同じです。ほかのプラットフォームはまだ実装していません。

### フィールドの中に自分で入れる

フィールドでコンボボックスを囲むと、コンボボックスフィールドを自分で書いたものになります。コンボボックスの `label` は空のままにします。名前はフィールドが与えます。`label`、`error`、`disabled`、必須の指定はフィールドに、`name`、`value`、オプション、入力に関するすべてはコンボボックスに指定します。

```html
<tanrei-field label="都市" required required-text="必須"
  supporting-text="注文のお届け先です。">
  <tanrei-combobox name="city" value="tokyo">
    <tanrei-option value="kyoto">京都</tanrei-option>
    <tanrei-option value="tokyo">東京</tanrei-option>
  </tanrei-combobox>
</tanrei-field>
```

コンボボックスは、自分にしか分からないことをフィールドに伝えます。補足は、パディングと先頭のグリフを越えた、テキストが始まる位置から始まります。Filled と Outlined のコンボボックスは、フィールドのラベルをボックスの中で浮き上がるラベルとして自分で描くので、フィールドはラベルの行を描きません。リストが開いている間は、コンボボックスはフォーカスの状態で描かれるので、入力欄にフォーカスがあってもなくても、フィールドのラベルと補足も一緒にフォーカスの状態で描かれます。

フィールドのラベルを押すと、入力欄にフォーカスが移り、何も開きません。リストが開いている間は、ラベルはコンボボックスの外側にあります。押すとリストが閉じ、フォーカスは入力欄に残ります。

### コンボボックスが受け持つものと、フィールドが受け持つもの

| 観点 | コンボボックス | 囲んでいるフィールド |
| --- | --- | --- |
| 描くもの | ボックス、テキスト、プレースホルダー、先頭のグリフ、消去ボタンとシェブロン、オプション、グループ、状態の行の入ったリスト、Filled と Outlined のボックスの中で浮き上がるラベル | Stacked のコンボボックスの上のラベルの行、必須または任意の印、補足、エラーテキスト |
| 持つもの | 値、テキスト、リストが開いているかどうか、フォームの中での位置、イベント | なし |
| 支援技術に伝えるもの | リストを持つコンボボックスであること、展開されているかどうか、どのオプションがアクティブか | 名前、補足またはエラーテキスト、必須、invalid、無効 |

3 つのバリアントと、`small`（32）、`medium`（40）、`large`（56）の 3 つのサイズは、テキスト入力欄と同じです。コンボボックスとテキスト入力欄を横に並べると、すべての線がそろいます。既定のシステムが提供するのは `stacked` だけです。

### フィールドなしで、単独で使う

- **名前**は `label` です。`labelHidden` を付けると、Filled と Outlined のコンボボックスはラベルを描きません。
- **エラー**は `error` で、利用者側で設定します。ボックスがエラーの状態で描かれ、invalid として伝わります。コンボボックスにエラーテキストはありません。何が違うのかは、横に言葉で書くか、フィールドで囲んで伝えます。
- **必須**を伝えるのはフィールドです。単独のコンボボックスに必須の設定はありません。フォームが答えを求める箇所では、利用者側で検証します。
- **どのオプションの名前でもないテキスト**は、`allowCustomValue` を付けていなければ、ユーザーが離れるときに破棄されます。コンボボックス自身のエラーになることはありません。

### リストのグリフ

オプションのグリフは、ラベルの前の列に描きます。グリフのないオプションでその列の幅を空けておくかどうかは `iconSpace` が決めます。`auto`（既定）は、セクションの中にグリフのあるオプションがほかにあれば幅を空けておき、そのセクションのラベルを一直線にそろえます。グリフのないセクションでは空けません。セクションとは、グループか、グループの外にひと続きに並ぶオプションのことです。`always` はすべてのオプションで空けておき、`never` はグリフのあるオプションにだけ列を設けます。[メニュー](/ja/components/menu/)にも、同じ値と既定値の `iconSpace` があります。フィルターで隠れたオプションは数えません。

`density` は選択肢が取る広さを決めます。`regular`（既定。高さ 48）と、マウスで使い長いリストを扱うツール向けの `compact`（高さ 32、グリフ 20。[メニュー](/ja/components/menu/)の compact の行）です。文字の大きさは変わらず、コンテナーは密度にかかわらず `size` のとおりです。タッチでは選択肢がタッチターゲットより低くなることはありません。

### Web での描き方の違い

- `<tanrei-option>` と `<tanrei-option-group>` はデータで、自分では何も描きません。セレクトが持つ要素と同じものです。値が空文字列のオプションは、描かれますが、選べません。空の値は、何も選ばれていないことを表すからです。
- コンボボックスの子にある `<slot>` 要素は、そこに割り当てられた要素の代わりになります。シャドウルートにコンボボックスを持つ自前の要素は、こうして自分の子をオプションとして渡せます。オプションは、変わるたびに読み直されます。
- 要素はフォームに関連付けられます。`name` があれば `value` を送信し、編集しただけで確定していないテキストは送信しません。リセットすると `value` 属性の値に戻り、ページの移動で復元され、無効な `<fieldset>` に従い、フィールドが必須としている間は、値がないことを報告します。
- 要素はブロックです。`focus()` は入力欄に移り、ボックスの上の、ボタン以外の場所を押してもフォーカスが移ります。
- `chevron` は、逆の意味の属性 `no-chevron` で指定します。`readOnly` は、`readonly` 属性です。
- `input` は、テキストの要素のネイティブのイベントです。`change` と `action` は、`detail.value` と `detail.inputValue` を持つ composed な CustomEvent で、`action` をキャンセルすると Enter でフォームが送信されません。`toggle` は、`detail.open` と、閉じたときの `detail.reason` を持ちます。composed で、バブルはしません。
- リストは、トップレイヤーにある `popover="manual"` の要素です。外側を押すとリストは閉じ、押した位置にある要素にもその操作が届きます。
- パーツ: `container`、`outline`、`active-indicator`、`label`、`requirement-label`、`input`、`leading-icon`、`clear-button`、`chevron`、`list`、`option`、`option-label`、`option-supporting-text`、`option-leading-icon`、`mark`、`group`、`group-title`、`divider`、`status`。
- `empty-text` と `clear-label` を空のままにすると、プロダクトの言葉（`setWords()`）から読みます。
- 要素が定義されるまでの間、オプションはふつうのテキストとして表示されます。`tanrei-combobox:not(:defined) > *` を隠し、高さを確保しておいてください。

## ガイドライン

### コンボボックス、コンボボックスフィールド、自分で書くフィールド

| 必要なもの | 使うもの |
| --- | --- |
| ラベル、リストの付いたボックス、補足、エラー | [コンボボックスフィールド](/ja/components/combobox-field/) |
| ボックスだけ。ラベルは別の場所にある（ツールバーの絞り込み、テーブルのセル、ラベルを横に置いた行） | コンボボックスを単独で使い、コンボボックスの `label` で名前を付ける |
| 枠の中、ボックスの横か下に置く自分の要素 | [フィールド](/ja/components/field/)に、コンボボックスと自分の要素を入れる |
| 入力せずに選ぶ、決まったリスト | [セレクト](/ja/components/select/) |
| 入力した結果が、値ではなく行き先になるもの | [検索](/ja/components/search/) |

### 推奨

- 単独のコンボボックスには、見えるラベルと同じ言葉の `label` を付けます。見えるラベルとその場所が合わせて伝えていることを言葉にしても構いません。「担当者、リリースノート」のようにします。
- 単独のコンボボックスの幅は、置く場所で決めます。グリッドの列、セル、幅を持つツールバーの項目などです。
- 入力した内容に対する候補しかない場合は、シェブロンを付けません（`no-chevron`）。
- ボックスの上のラベル、補足、エラーがあれば足りるところでは、コンボボックスフィールドを使います。

### 非推奨

- ラベルの場所を節約するために、フォームで単独のコンボボックスを使わない。
- プレースホルダーをラベルの代わりにしない。入力を始めた途端に消え、名前にもなりません。
- フィールドの中のコンボボックスに `label`、`error`、`disabled` を指定しない。フィールドに指定すれば、ラベルと補足も一緒に変わります。
- コンボボックスフィールドをフィールドの中に入れない。すでにフィールドです。フィールドが囲むコントロールは、コンボボックスです。
- コンボボックスに `supporting-text`、`error-text`、`required`、`optional` を書かない。これらはフィールドのもので、コンボボックスはどれも描きません。

## アクセシビリティ

<ComponentAccessibility name="combobox" />

### コンポーネントが担うこと

- 入力欄は、リストボックスを持つ、編集できるコンボボックスです。名前は自身の `label` で、それがなければ、囲んでいるフィールドのラベルです。プレースホルダーが名前になることはありません。
- 説明は、フィールドが与えるものです。補足またはエラーテキストと、任意であることを伝えるテキストです。
- エラーの間は invalid として、フィールドが必須としている間は必須として伝えます。読み取り専用と無効の状態、リストが開いている間は展開されていることも伝えます。
- リストが開いている間も、フォーカスは入力欄にとどまります。アクティブなオプションは、入力欄のアクティブな子孫として伝わります。そのため、文字を入力すれば、いつでもテキストを編集できます。
- リストは、同じ名前のリストボックスです。それぞれのオプションは、名前、説明、選ばれているかどうか、無効かどうか、表示されているオプションの中での位置を伝えます。グループの名前は、そのタイトルです。
- 状態の行は、ライブリージョンです。テキストが変わると控えめに読み上げ、読み込みに失敗したときはすぐに読み上げます。
- シェブロンは、同じ名前のボタンで、フォーカスの順序には入りません。消去ボタンは、`clearLabel` を名前とするボタンで、入力欄の次にフォーカスが止まる位置です。
- フォーカスは、キーボードでもポインターでも、ボックス自身の縁で示します。ヒット領域は最小ターゲットを満たします。
- 浮き上がるラベルのあとのアスタリスクは、支援技術から隠します。必須の状態がすでに伝えているためです。
- 名前がない場合は、デバッグビルドで報告します。

### 利用者側で行うこと

- 単独のコンボボックスには、必ず `label` で名前を付けます。横に見えるテキストがあっても、それは名前になりません。
- 単独のコンボボックスの値が誤りになりうる場合は、何が違うのかを、支援技術に届く言葉で伝えます。ページに結び付けた自前のメッセージか、コンボボックスを囲むフィールドを使います。
- すべてのオプションにラベルと空でない値を付け、値は重複させません。
- 消去できるコンボボックスには `clearLabel` を付け、`emptyText` と `statusText` を書きます。
