表を引かなくても使える規則が 1 つあります。**アドレスがあればリンク、なければボタンです。** ページ上で何かを実行し、どこにも移動しないコントロールは[ボタン](../button/)で、テキストのように控えめに見せたいときは `text` バリアントを使います。ボタンのように見せたい行き先は、`href` を持つボタンです。

### 使い方

Web では、リンクは要素ではなく、プロダクト側の `<a>` に付けるクラスです。`<a>` は文書の中にあるので、スクリプトが動く前からリンクとして働き、クローラー、検索インデックス、ページ内の `<a>` を扱うルーターのどれからも見つけられます。ルーターのリンクコンポーネントにもこのクラスを付けられます。`.tanrei-prose` の中の `<a>` はクラスがなくても同じように描かれるので、Markdown から生成した HTML には何も足す必要がありません。

SwiftUI、Compose、Flutter、React Native は計画中です。このページの冒頭で各プラットフォームに添えた名前は仕様が定めたもので、まだ提供していません。React にもまだ `Link` コンポーネントはないので、クラスを付けた `<a>` を使ってください。

リンクは自分のテキストスタイルを持ちません。段落、見出し、キャプション、表のセルのどこでも、置かれたテキストの書体、サイズ、太さ、行の高さをそのまま使います。ホバー、フォーカス、押下は、リンクが通る各行のテキストの背後に描かれ、場所を取らないので、リンクの周りは動きません。グリフ、サイトのアイコン、印はテキストと同じ大きさで、隣の語と同じ行にとどまります。

**下線をいつ描くかは選択です。** 値は 3 つあります。`always` は、何もしていないときも、どの状態でも下線を描きます。`hover` は、リンクにホバーしている間、キーボードでフォーカスしている間、押している間に描きます。`never` は描きません。その場合も、ホバー、フォーカス、押下はステートレイヤー、ラベルの色、フォーカスリングで示されます。この選択は 3 つのレベルで設定します。デザインシステムのすべてのテキストリンクには `sys.behavior.link-underline`、リンクだけには `comp.link.underline.visibility`、1 つのリンクには `underline` プロパティです。既定のシステムの選択は `always` です。Web ではコンポーネントトークンがカスタムプロパティなので、フッターのような領域に独自の値を持たせられます。現在の項目のリンクとグリフだけのリンクには、どの選択でも下線がありません。強制カラーモードでは、どの選択でも下線を描きます。

**サイトの外へ出るリンクは、そのことを伝えます。** 外部リンクは、ラベルの後ろに `arrow_outward` のグリフを描き、アイコンを渡した場合はラベルの前にそのサイトのアイコンを描きます。`external` の値は `auto`、`on`、`off` です。`auto` では、ページとは別のオリジンの `http` または `https` のアドレスが外部になります。パス、フラグメント、メールアドレス、電話番号、ダウンロードは外部になりません。自分のサイトに含まれるほかのオリジンを 1 回宣言しておけば、それらも外部になりません。`comp.link.external.marks` は、プロダクト全体でアイコンを消す（`arrow`）か、両方の印を消します（`none`）。

サイトの外へ出ることと、新しいタブで開くことは、別々の事実です。ラベルの後ろの場所に入るグリフは 1 つです。`target="_blank"` のリンクには、外部かどうかにかかわらず `open_in_new` が入り、それ以外の外部リンクには `arrow_outward` が入ります。末尾側に自分でグリフを置いた場合はそれが代わりになり、グリフだけのリンクにはどちらもありません。

**リンクがアイコンを取りに行くことはありません。** `siteIcon` は利用者側で渡す画像です。自分のサイトが配信する画像を、サイトをビルドするときに用意します。コンポーネントが行き先のサイトやアイコンのサービスにそれを問い合わせると、読者がどのページを見ているかをその相手に知らせることになります。アイコンを渡さない場合、リンクは矢印だけを描きます。読み込めなかったアイコンは、場所を保ったまま何も描きません。

### Web での描き方の違い

- テキストの背後のコンテナは、行の高さ全体ではなく、テキスト自体の箱（フォントの高さ）です。
- グリフや印のあるリンクが折り返すと、行の端で切られた 1 つの箱として描かれます。どちらもないリンクは、すべての行で 4 つの角が丸くなります。
- グリフ、印、外部リンクの印のいずれかがある単独のリンクは、ラベルを、ラベル自身の最初の文字の方向ではなく、レイアウトの方向で配置します。
- スタイルシートはアドレスについて何も計算しません。`data-external` に対して印を描くだけです。この属性をページを作るときに書いておけば（Markdown から生成した HTML には、`@tanrei/web/links` のビルドステップ `markExternalLinks()` が書きます）、印は最初の描画に含まれます。
- パッケージのスクリプトがあれば、`data-external` のない `<a>` のうち、アドレスがサイトの外へ出るものにブラウザーで印が付きます。この印は最初の描画の後に現れ、1 つごとに、同じ行の後ろにあるものをテキストのサイズと間隔の分だけ動かします。属性もスクリプトもないページには、外部リンクの印は出ません。
- スタイルコンテナクエリのないブラウザーでは、スクリプトが 2 つの選択をページ全体について読み取ります。領域ごとの値は反映されません。スクリプトもなければ、どちらの選択も最初の値（`always` と、両方の印）になります。
- 押下への応え方がリップルのデザインシステムでも、複数行にわたるリンクはオーバーレイで応えます。
- パッケージのスクリプトがなくても、スタイルシートだけですべての状態を描きます。このとき、押下への応え方はオーバーレイです。

## ガイドライン

### リンクかボタンか

| 種類 | 何であるか | 使う場面 |
| --- | --- | --- |
| **リンク** | 行き先のあるテキスト。周りのテキストスタイルで描き、下線はデザインシステムの選択に従います | 文の中の語句、行き先である 1 行のテキスト、見出しの横のグリフ |
| **行き先のあるボタン** | ボタンとして描くリンク | 行き先が画面のアクションの 1 つであるとき。「はじめる」「ソースを見る」など |
| **テキストボタン** | ボタン | 何かを実行し、どこにも移動しないとき。どれほどテキストのように見せたくても同じです |

### 文の中か、単独か

`data-standalone` を付けても見た目は変わりません。リンクがテキストの行の一部ではないことを伝えるもので、上下の行に向けた押下を奪うことなく、ヒット領域を最小ターゲットまで広げられます。段落の下のリンク、表のセルの中のリンク、リンクの並びに使います。文の中では付けません。

`hover` と `never` は、単独で置かれるリンクのためのものです。ナビゲーションのリスト、フッター、関連ページの並びなどです。リストの中の位置が、それがリンクであることを伝えます。そうしたリンクに `data-underline` を付けるか、その領域にコンポーネントトークンの独自の値を持たせ、文の中のリンクには下線を残します。

### 推奨

- 周りの文がなくても行き先が分かるラベルにします。「こちら」ではなく「インストールガイド」と書きます。
- `data-variant="inverse"` は `sys.color.inverse-surface` の上だけで使います。控えめなコンテナ（ステータスのコンテナや `secondary-container`）の上では標準のリンクが適切です。
- ナビゲーションのまとまりの中で現在の項目にするリンクは 1 つまでとし、どれにするかはそのまとまりが決めます。
- 単独のリンクを 2 つ並べるときは `sys.target.spacing` を空けるか、行の高さをターゲットの高さにします。
- サイトのアイコンは、自分のサイトが配信するファイルとして渡します。`@tanrei/web/links` の `resolveSiteIcons()` がサイトのビルド時に用意するので、読者のブラウザーがほかの相手に問い合わせることはありません。
- 外部リンクの文言は、プロダクトの言語で 1 回だけ設定します（`setExternalLabel()`、またはビルドステップの `externalLabel`）。この文言は、[プロダクトの言葉](/ja/foundations/words/)のキー `externalLabel` です。`setWords({ externalLabel: '…' })` でも同じ文言を渡せ、`{ lang }` を付ければ言語ごとに渡せます。

### 非推奨

- リンクの色が本文の色と同じレイヤで、何もしていないときの下線を外さない。既定のシステムではリンクの色は本文の色そのもので、6 つのスキームすべてで本文に対して 1.00:1 です。リンクであることを伝えているのは下線だけです。選択が `hover` か `never` で、リンクの色と本文の色の差が 3:1 に満たない場合、ビルドは既定のシステムではエラーにし、プロダクトのレイヤでは警告します。
- タッチスクリーンで `hover` がリンクを見分けさせてくれると考えない。タッチスクリーンにホバーはないので、`hover` には `never` と同じ規則が適用されます。
- サイトのアイコンを、ブラウザーからそのサイトやアイコンのサービスに取りに行かない。読者がどのページを見ているかを、読者全員のブラウザーがその相手に知らせることになります。
- 行き先の代わりにクリックハンドラーを付けない。アドレスのない `<a>` はただのテキストとして描かれ、デバッグビルドで報告されます。
- 全体を押すコントロール（リンクカード、行き先のあるリストの項目）の中にリンクを置かない。リンクの中にコントロールを置くこともしません。
- 訪問済みのリンクに別のスタイルを付けない。「開いたことがある」ことを示したいプロダクトは、自分のデータをもとにタグやグリフで示します。

## アクセシビリティ

<ComponentAccessibility name="link" />

### コンポーネントが担うこと

- ブラウザー自身のリンクです。リンクのロール、Enter での移動、コンテキストメニュー、新しいタブで開く操作がそのまま働き、スクリプトがなくてもリンクとして動きます。
- 既定のシステムでは、周りのテキストとの違いを、色に頼らず下線で示します。どのスキームでも同じです。強制カラーモードでは、どの選択でも下線を描きます。
- 外部リンクの説明は 1 つで、名前の後に読み上げられます。新しいタブで開くリンクでは `aria-description`、それ以外では外部リンクの文言です。矢印とサイトのアイコンは支援技術から隠されます。
- キーボードフォーカスのフォーカスリングは、各行のリンクの部分を囲んで描かれます。
- 単独のリンクとグリフだけのリンクは、ヒット領域を最小ターゲットまで広げます。文の中のリンクは自分のテキストの範囲にとどまります。
- 印と、ラベルの横のグリフは、支援技術から隠されます。
- パッケージのスクリプトがあれば、新しいタブで開くリンクに `noopener` が付き、デバッグビルドでは、名前のないリンク、説明のないリンク、行き先でないアドレスが報告されます。あわせて、文の中にあって何もしていないときに下線がなく、本文との差が 3:1 に満たないリンク、文言のない外部リンク（ページに 1 回）、別のオリジンから読み込まれるサイトのアイコンも報告されます。

### 利用者側で行うこと

- グリフだけのリンクには `aria-label` で名前を付け、すべてのグリフに `aria-hidden="true"` を付けます。
- 新しいタブで開くことは、プロダクトの言語で `aria-description` に書きます。Tanrei は言葉を同梱しません。
- 無効なリンクは、`href` のない `<a>` に `role="link"` と `aria-disabled="true"` を付けて書きます。フォーカス順から外れるので、移動できない理由は横のテキストで伝えます。
- いまいるページやセクションを指すリンクに `aria-current` を付けます。
- 文の中で `hover` と `never` を使うのは、リンクの色が本文の色から 3:1 以上離れ、かつサーフェスに対して 4.5:1 を保つ場合だけにします。白に近いサーフェスに黒に近い本文を置く場合、これを満たすのは中間のトーンの狭い範囲です。
- サイトの外へ出ることは言葉で伝えます。リンクに `aria-description` を書くか、すべての外部リンクに向けて 1 回設定した文言を使います。Tanrei は言葉を同梱しません。外部で、かつ新しいタブで開くリンクでは、1 つの説明に両方の事実を書きます。
- サイトのアイコンは `alt=""` で書きます。これは装飾です。リンクの名前はラベルが伝え、印は矢印が担います。
