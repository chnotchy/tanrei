[タグ](/ja/components/tag/)も[チップ](/ja/components/chip/)も、1 つずつ置くものです。タググループは、それらをいくつかまとめて置くためのものです。記事のタグ、一覧の上の絞り込み、フィールドの下に出すいくつかの候補などに使います。メンバーを折り返す行に並べ、メンバーの間に適切な間隔を取り、全体が 1 つのリストであることを支援技術に伝えます。

グループ自身は何も描きません。コンテナも、縁も、パディングも、目に見えるラベルもありません。メンバーは、ほかの場所に置いたときとまったく同じように描かれ、フォーカスを受け、押されます。

Web では `<tanrei-tag-group>` です。ほかのプラットフォームはまだ実装していません。

## ガイドライン

### タググループの用途

| 集まり | 使うもの |
| --- | --- |
| 静的なタグ。記事のカテゴリー、設定が取りうる値、ステータスの並びなど | `spacing="tags"` のタググループ。 |
| それぞれのタグのページへ進むタグ | タググループに、`href` を持つチップを入れます。タグはテキストで、リンクにはなれません。 |
| 一覧の上の絞り込み、フィールドの下の候補、ユーザーが入力した項目 | チップを入れたタググループ。 |
| 1 つのコントロールとして働く絞り込み。一度に 1 つだけ、またはいくつでもオンにでき、Tab 1 回で通り過ぎられる | `selection` を指定し、絞り込みチップを入れたタググループ（後述）。 |
| 1 行に収めなければならないトグルボタンの並び | [ツールバー](/ja/components/toolbar/)。 |
| 2〜4 個の異なるアクション | [ボタングループ](/ja/components/button-group/)。 |
| いくつかの中から 1 つを選ぶ | [ラジオグループ](/ja/components/radio-group/)、[タブ](/ja/components/tabs/)、[セグメントボタン](/ja/components/segmented-button/)のいずれか。 |
| 目に見えるラベル、必須・任意の表示、エラーが必要なコントロール | [フィールドグループ](/ja/components/field-group/)。 |
| フィールドの中に入力された値 | フィールド自身が扱います。[コンボボックス](/ja/components/combobox/)は、自分でチップを並べます。 |

### 間隔

`spacing` は、集まりの中身を伝え、2 つの距離を決めます。1 行の中のメンバー同士の距離と、行と行の距離です。

- `chips`（既定値）は、チップのための値です。チップは、見えている縁の外側でも、タッチターゲットの大きさまで押下を受け取ります。行と行は、medium のチップがそのターゲットを丸ごと保てるだけ離れます。2 つのチップの領域が重なるところでは、領域は間隔の真ん中で接します。
- `tags` は、静的なタグのための値です。行と行は、1 行の中のタグ同士と同じ近さで並ぶので、折り返した集まりが 1 つのまとまりに見えます。

既定値は安全な側です。タグの集まりを `chips` のままにしても、少し離れて並ぶだけです。チップの集まりに `tags` を指定しても動作しますが、行と行がタッチターゲットの高さより近くなるので、デバッグビルドがそのことを報告します。

small のチップは、集まりが 1 行に収まる、密度の高い場所のためのものです。折り返した行では、タッチターゲットが本来の大きさになる前に、行の間で接します。タッチ画面で折り返す集まりには、medium のチップを使います。

デザインシステムは、`spacing` に値を追加できます。

### レイアウト

- メンバーは、指定した順に並びます。グループが並べ替えることも、選択されたチップを前へ出すこともありません。
- 行に収まらないメンバーは、丸ごと次の行へ進みます。切れることも、縮むことも、隠れることも、スクロールすることもなく、「ほか 3 件」のような表示もありません。表示を減らすには、グループに渡すメンバーを減らし、最後のメンバーを、残りを表示するアクションチップにします。
- 1 つのメンバーがグループより広い場合、そのメンバーはグループの幅になり、自身のラベルを省略記号で切ります。
- 集まりは、先頭側の端から始まります。行の末尾や中央に置くには、周りのレイアウトでグループを配置します。
- メンバーは、すべて同じサイズにします。サイズの違うメンバーは、行の中央にそろいます。
- メンバーのないグループは、何も描かず、場所も取りません。タグのない記事を特別に扱う必要はありません。

### ラベル

`label` は、支援技術に向けた集まりの名前です。「タグ」「絞り込み」のように付けます。描かれることはありません。目に見える名前が必要な場合は、利用者側の見出しやテキストを集まりの前に置き、そのうえで `label` も指定します。

### 選択

既定では、グループは値を持ちません。絞り込みチップは、それぞれが自身の `selected` を持ち、チップの 1 つずつが Tab で止まる位置になります。

絞り込みが 1 つのコントロールとして働く場合は、`selection` を指定します。それぞれの絞り込みチップに `value` を付けると、どのチップがオンかをグループが示します。

- `selection="single"`：オンにできるチップは多くても 1 つで、`value` がそれを示します。チップをオンにすると、ほかはオフになります。オンのチップをオフにすると、オンのチップはなくなり、`value` は `null` になります。それぞれのチップがトグルだからです。
- `selection="multiple"`：いくつでもオンにでき、`values` がそれらを示します。

ユーザーがチップを切り替えると、グループは `value` か `values` を設定し、`detail.value` か `detail.values` を持つ `change` を 1 回発火します。チップ自身の `change` は、グループで止まります。利用者側で `value` や `values` を設定すると、チップが切り替わり、何も発火しません。

選択がある場合、集まりで Tab が止まる位置は 1 つです。最後にフォーカスのあったチップ、それがなければ最初のオンのチップ、それもなければ最初のチップです。矢印キーは、右から左のレイアウトでも、指す向きのとおりにチップの間を移動し、Home と End で最初と最後のチップへ移ります。これらのキーは何も切り替えず、フォーカスは最後のチップから最初のチップへ折り返しません。Space で、フォーカスのあるチップを切り替えます。

選択が扱うのは、絞り込みチップだけです。集まりの中のほかのチップ（「追加」のチップや入力された項目など）にも同じ矢印キーで移り、いつもどおりに働きます。入力された項目は、これまでどおり Backspace か Delete で取り除け、そのときフォーカスを受けたチップが、集まりで Tab が止まる位置になります。

絞り込みチップを取り除いても、グループは `value` と `values` をそのままにします。その絞り込みもなくすべき場合は、利用者側で変更します。

答えが常にちょうど 1 つで、選択を解除する方法がない選択には、[セグメントボタン](/ja/components/segmented-button/)か[ラジオグループ](/ja/components/radio-group/)を使います。

### チップを取り除く

チップは取り除くことを求め、実際に取り除くのは利用者側です。フォーカスがそのチップか、その取り除くアクションにあった場合、グループは、後ろに続くチップへフォーカスを移します。後ろに続くチップがなければ、前のチップへ移します。いくつもの項目を続けて取り除く人は、いた場所からそのまま続けられます。

チップの取り除くアクションは、そのチップに `destructiveRemove` を付けない限り通常の見た目で、グループはそれを変えません。添付ファイルのように、取り除くと 1 回の操作では戻せないものが失われる場所にだけ付けます。適用中の絞り込みや検索語は、1 回の操作で戻せます。

次の 2 つは、利用者側の役割です。

- フォーカスを受けられるチップが残っていないときは、集まりが属するコントロールへフォーカスを移します。項目を追加するフィールドや、絞り込みを開くボタンなどです。そうしなければ、フォーカスはどこにもなくなります。
- グループは、何も読み上げません。取り除いたことを伝える必要がある場合は、ライブリージョンか[スナックバー](/ja/components/snackbar/)で伝えます。たとえば、絞り込まれる一覧から離れた場所で絞り込みを取り除いた場合です。

### 推奨

- 静的なタグの集まりには、`spacing="tags"` を指定します。
- 集まりには、ページの言語で `label` を付けます。
- 1 つの集まりには、1 種類のメンバーを入れます。入力された項目の後ろに「追加」のチップを 1 つ置く場合は例外です。

### 非推奨

- ダイアログやフォームのアクションにタググループを使わない。ボタングループを使います。
- タグとチップ以外のものを入れない。ほかの内容も並べられますが、デバッグビルドで報告されます。
- グループからメンバーの見た目を変えない。代わりに、レイヤでグループのトークンを変えます。

## アクセシビリティ

<ComponentAccessibility name="tag-group" />

### コンポーネントが担うこと

- 集まりは、`label` を名前とする 1 つのリストとして伝わります。メンバーは、それぞれがリストの 1 項目です。タグはそのテキストとして、チップは状態を持つボタンまたはリンクとして、入力チップは取り除くアクションを横に伴って読み上げられます。
- リストは、メンバーがいくつあり、いまその何番目にいるかを伝えます。「リスト、4 項目」のように読み上げられます。
- メンバーは、指定した順に読み上げられ、その順にフォーカスを受けます。右から左のレイアウトでも同じです。
- 選択がない場合、チップは 1 つずつがフォーカスが止まる位置です。入力チップも 1 か所で、Tab は取り除くアクションを飛ばし、チップ本体での Backspace か Delete で取り除きます。グループ自身はフォーカスを受けず、キーも処理しません。
- 選択がある場合、集まりでフォーカスが止まる位置は 1 つです。矢印キー、Home、End でチップの間を移動し、それぞれの絞り込みチップは、押されているかどうかをこれまでどおり伝えます。グループはリストのままなので、スクリーンリーダーは、チップがいくつあるかをこれまでどおり伝えます。
- フォーカスのあったチップが取り除かれると、フォーカスは次のチップへ移ります。取り除くアクションへ移ることはありません。選択がある場合は、そのチップが集まりでフォーカスが止まる位置になります。
- 空のグループは、何も伝えません。空のリストも、名前もありません。
- テキストを 200% にすると、メンバーが大きくなり、より多くの行に折り返します。切れるものはなく、横にスクロールすることもありません。
- 強制カラーモードでも、グループは何も描きません。メンバーが、自身の縁を描きます。
- 右から左のレイアウトでは、すべての行が右から始まります。

Web での作り：リストは、グループのシャドウルートにある 1 つの要素で、スロットを囲みます。グループは、メンバーがグループの中にある間、それぞれに `role="listitem"` を書き込み、メンバーが出ていくときに取り除きます。自身の `role` を持つメンバーや、それ自体に意味のあるネイティブ要素（リンク、ボタン）は、そのロールを保ち、リストの項目にはなりません。そのような要素は `span` で包みます。

Web での既知の制約：

- 要素が定義されるまでの間、メンバーは、間の空白で区切られて順にページに置かれ、間隔もリストもありません。最初の描画からレイアウトをそろえたいページは、次の規則を加えます。

  ```css
  tanrei-tag-group:not(:defined) {
    display: flex;
    flex-wrap: wrap;
    align-items: center;
    gap: var(--tanrei-comp-tag-group-row-gap-chips) var(--tanrei-comp-tag-group-gap-chips);
  }
  ```

### 利用者側で行うこと

- グループに `label` を指定します。Tanrei は言葉を同梱しません。
- 入力チップには、その項目の名前を含む `removeLabel` を付けます。
- 選択がある場合は、それぞれの絞り込みチップに、集まりの中で重複しない `value` を付けます。`value` のない絞り込みチップは選択から外れ、デバッグビルドで報告されます。
- チップが `remove` を発火したら取り除き、最後の 1 つがなくなったら、利用者側でフォーカスを移します。
- ステータスは、それぞれのタグの言葉で伝えます。色だけでは伝わりません。
