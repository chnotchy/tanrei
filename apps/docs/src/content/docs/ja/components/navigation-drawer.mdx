## 概要

<ComponentAvailability name="navigation-drawer" />

:::note[仕様は改訂済み、各プラットフォームは追従待ち]
このページは、仕様の現在の形のナビゲーションドロワーを説明しています。`collapsible` のドロワーはアイコンの列まで狭まり、これがナビゲーションレールの代わりになります。折りたたんだドロワーは、展開したドロワーからラベルがなくなっただけのもので、各項目をアイコンの後ろで切った形です。メニューボタンでまた広がり、どのアイコンも位置を変えません。行き先の `badge` のテキストは `trailingText` になって控えめに描かれ、`trailing` スロットにはグリフを置けます。`badge` は、アイコンに付けるバッジになりました。`group` の項目で、入れ子の行き先を開閉できます。項目の高さは 48 で、メニューの項目と同じです。`responsive` を付けると、ウィンドウの幅がドロワーの表示のしかたを選びます。`href` を持つ行き先はリンクで、`revealSelected` と `scrollOffset` によってドロワーはサイトのサイドバーになります。Web コンポーネントはすでにこのすべてに対応しており、デモもそれを示しています。SwiftUI、Compose、Flutter、React Native は上の表で「追従待ち」です。追従するまでは以前の版（項目の高さ 44、`badge` は項目の末尾のテキスト、折りたたんだ形、グループ、リンクの行き先、幅に応じた表示はなく、ナビゲーションレールは別のコンポーネント）を提供しており、これらの例もその版のものです。 コンパクトな `density`、行き先にもなるグループ（`selectableGroups`）、絞り込みの入力欄（`filterable`）はさらに新しく、今のところ Web だけです。
:::

### 使い方

ナビゲーションドロワーが持つ項目は 5 種類です。`destination`（行き先）は、アイコン（省略可）、ラベル、末尾の内容（省略可）でできた 1 行の項目で、`href` を持つとリンクになります。`group`（グループ）は、中の行き先やグループを開閉する行です。`section`（セクション）は行き先やグループをまとめるもので、`title`（Web では `headline`）（見出し）と、前に引く `divider`（区切り線）を持てます。セクションは入れ子にできず、グループはセクションを持てません。`header-button`（最初のものがメニューボタン）と `main-action` はヘッダーに置きます。Web では子要素の `<tanrei-navigation-drawer-item>`、`<tanrei-navigation-drawer-group>`、`<tanrei-navigation-drawer-section>` と、`header-button` と `main-action` のスロットに入れるアイコンだけの `<tanrei-button>` と `<tanrei-main-action-button>` です。追従待ちのプラットフォームは、行き先とセクションをそれぞれの流儀で受け取ります。SwiftUI では `TanreiNavigationDrawerItem` と `TanreiNavigationDrawerSection` のビュー、Compose では同じ名前の呼び出し、Flutter では `children:` に並べた `TanreiNavigationDrawerDestination` と `TanreiNavigationDrawerSection`、React Native では配列 `items` の中の行き先とセクションの要素です。React Native のセクションは、自分の `items` を持つことで行き先と見分けられます。

選択は、行き先の値によってドロワーが持ちます。行き先がどのセクションにあってもかまいません。`change` と `reselect` はナビゲーションバーと同じです。Compose にはドロワー全体の値がなく、今の項目に利用者側で `selected` を付け、その `onClick` が change と reselect を兼ねます。Flutter は番号で選び、番号はセクションをまたいで読み上げ順に数えます。

`href` を持つ行き先はリンクであり、ボタンではありません。ブラウザーはほかのリンクと同じようにたどり、ドロワーは押されただけではそれを選択しません。どの行き先が今の場所かは、移った先のページが伝えます。ドロワーの `value` に、その行き先の値を、値がなければ書かれたとおりの `href` を設定します。リンクをふつうに実行したときにも `change` と `reselect` は発火します。どちらも `href` を持ち、キャンセルできるので、クライアントサイドのルーターはここで遷移を引き取れます。リンクの行き先は、今のところ Web で使えます。

グループの行はグループを開閉するだけで、何も選びません。グループがそれ自体ひとつの場所でもあるとき（サイトでセクションの概要ページがある、選ぶとフォルダーの中身を表示する、など）は、ドロワーに `selectableGroups` を付け、グループに `value` か `href` を与えます。するとグループの行は行き先の行と同じようにそれを選び、シェブロンはグループを開閉する独立した操作部品になります。どちらも持たないグループは、これまでどおり開閉するだけです。行き先にもなるグループは、今のところ Web で使えます。

`density` は既定の `regular` か `compact` です。`compact` は項目の高さ 32、グリフ 16 で、アイコンの列も狭く、行き先の多いドロワーをポインターで使うツール向けです。コンパクトな密度は、今のところ Web で使えます。

`filterable` を設定すると、項目の上に絞り込みの入力欄を描きます。入力した文字をラベルに含む行だけにドロワーが絞り込まれ、それを含むグループは絞り込みの間だけ開きます。入力欄を空にすると、ドロワーは元に戻ります。`filterValue` はそのテキストで、ユーザーが入力するとドロワーが自分で設定してから `filterChange` を発火します。ページを描き直すときに絞り込みを戻すため、利用者側で設定することもできます。入力欄の文言は利用者側のものです。`filterLabel` が入力欄の名前になり、`filterPlaceholder`、`filterCountText`（「一致: \{count} 件」）、`filterEmptyText`、`filterClearLabel` は、空にしておくとプロダクトの文言から読みます。絞り込みは、今のところ Web で使えます。

ドロワーには 2 つのバリアントがあり、1 つのプロダクトでたいてい両方を使います。ウィンドウの幅が足りればスタンダード、足りなければモーダルです。

- **スタンダード**はレイアウト領域で、オーバーレイではありません。開いている間はコンテンツの横に自分の幅を確保し、閉じている間は幅を持ちません。スクリムを描かず、フォーカスを中に閉じ込めることもありません。
- **モーダル**は操作するオーバーレイで、しかもモーダルなものです。スクリムとともにコンテンツの上に滑り込み、閉じるまでフォーカスを中にとどめ、行き先が選ばれると自分で閉じます。

`responsive` を付けると、この選択をドロワーがウィンドウの幅から自分で行います（後述の「ウィンドウの幅に合わせる」を参照）。

どちらのバリアントも `open` で表示と非表示を切り替えます。モーダルのドロワーは、スクリムや Escape を押したとき、プラットフォームの「戻る」を使ったとき、端の方へドラッグしたときにも閉じ、`close` を発火します。Web では、ダイアログと同じくドロワー自身が `open` を false に戻します。ほかのプラットフォームでは、閉じたことを受けて利用者側で状態を合わせます。Flutter と React Native では `onClose`、SwiftUI では `isPresented` のバインディング、Compose ではドロワーの状態で、その `confirmValueChange` が閉じるたびに呼ばれます。

## ガイドライン

### 使う場面

ナビゲーションバーに収まらないほど行き先が多いとき、または行き先がグループに分かれるときに使います。メールアプリのフォルダーとラベル、プロジェクトの各セクション、管理画面などです。大きいウィンドウでは、スタンダードのドロワーをサイドバーとしてコンテンツの横に置きます。コンパクトなウィンドウでは、モーダルのドロワーをメニューボタンからコンテンツの上に滑り込ませ、行き先が選ばれたら閉じます。

### バーとドロワーの選び方

| 観点 | [ナビゲーションバー](/ja/components/navigation-bar/) | [ナビゲーションドロワー](/ja/components/navigation-drawer/)（折りたたみ） | [ナビゲーションドロワー](/ja/components/navigation-drawer/)（展開） |
| --- | --- | --- | --- |
| 置き場所 | 下端に沿って | 先頭側の端に沿ったアイコンの列 | 先頭側の端のパネルの中 |
| ウィンドウ | Compact | Medium 以上 | Expanded 以上（スタンダード）、または Compact（モーダル） |
| 行き先の数 | 3〜5 個 | 最上位の行き先とグループ。1 つにつき 1 セル | プロダクトにある分だけ。セクションとグループにまとめます |
| 行き先の形 | アイコンと、その下の 1 行のラベル。アイコンにバッジ | 項目をアイコンの後ろで切った形。アイコンだけで、バッジを付け、名前はツールチップで示します | 1 行の項目。アイコン（省略可）、折り返すラベル、末尾のテキストや内容 |
| ほかに持つもの | なし | ヘッダー：メニューボタンと、アイコンだけに折りたたんだメインアクション | ヘッダー：メニューボタン、タイトルやアカウントの切り替え、メインアクション |
| ネイティブのプラットフォームでの行き先 | タブバーのタブ | 選択状態を持つボタン | 選択状態を持つボタン |
| 位置づけ | レイアウト領域 | レイアウト領域。またはモーダルのドロワーが広がる元になるレイアウト内の列 | スタンダードはレイアウト領域、モーダルはモーダルなオーバーレイ |

- **折りたたんだドロワーがナビゲーションレールです。** 折りたためるドロワーは、コンテンツに幅が要るときにアイコンの列まで狭まり、メニューボタンでまた広がります。どのアイコンも位置を変えません。Tanrei の独立したナビゲーションレールは、この形に統合されて廃止されました。
- **バーとドロワーは、同じ行き先を置く場所が違うだけです。** 同じ行き先と同じ選択を受け取るので、ウィンドウの大きさに合わせて変わるプロダクトは、行き先に手を加えずにブレークポイントでバーとドロワーを切り替えられます。同時に表示するのはどちらか一方だけです。
- **ドロワーはもっと多くを持てます。** バーに収まらないほど行き先が多いとき、メールアプリのフォルダーとラベルのように行き先がグループに分かれるときは、展開したドロワーを使います。大きいウィンドウではスタンダードのドロワーをコンテンツの横に置き、コンパクトなウィンドウではモーダルのドロワーをメニューボタンから重ねて開きます。
- **モーダルの折りたためるドロワー**は、アイコンの列をレイアウトに残したまま、メニューボタンで開くとスクリムの上でコンテンツに重なって広がります。
- どのプラットフォームでも、どちらも行き先の値で選び（Compose は項目ごとのフラグ、Flutter は番号）、`change` と `reselect` を発火します。

### ナビゲーションレールの移り先

Tanrei には独立したナビゲーションレールはありません。レールは、折りたためるドロワーを折りたたんだ形です。

| 以前 | 現在 |
| --- | --- |
| ナビゲーションレール | `collapsible` を付け、`expanded` を false にしたナビゲーションドロワー |
| レールの行き先（アイコンとその下のラベル） | 行き先。折りたたんだときは、項目をアイコンの後ろで切った形で描きます。アイコンだけで、名前はツールチップで示します |
| レールのラベルの表示 | `collapsedLabels`：`never`（既定）、`selected`、`always`。後の 2 つは、アイコンの下に `shortLabel` を描きます |
| レールのアイコンのバッジ | 行き先の `badge`、`badgeCount`、`badgeLabel`。どちらの形でも描きます |
| レールのメニューボタンと FAB | ドロワーの最初の `header-button`（メニューボタン）と `main-action`。メインアクションは折りたたむとアイコンだけになります |
| ドロワーの項目末尾の `badge` のテキスト | `trailingText`、または `trailing` スロット |
| レールのトークン | `comp.navigation-drawer.collapsed.*` と、折りたたんだときの状態 |

Web は実装済みです。SwiftUI、Compose、Flutter、React Native は、追いつくまで独立したナビゲーションレールを提供しますが、これらのページではそれを説明していません。

### Material 3 での名前

| Material 3 | Tanrei |
| --- | --- |
| Navigation rail | 折りたためるナビゲーションドロワーを折りたたんだ形 |
| Expanded navigation rail | 折りたためるナビゲーションドロワーを展開した形 |
| Modal expanded navigation rail | モーダルの折りたためるナビゲーションドロワー |
| Navigation drawer | 折りたためないナビゲーションドロワー |

### バリアントの選び方

| バリアント | どういうものか | 用途 |
| --- | --- | --- |
| スタンダード（既定） | レイアウトの中のパネルで、末尾側の端に細い線を引きます。開閉に合わせて横のコンテンツの幅が変わります。スクリムを描かず、横のコンテンツで作業している間も開いたままです。 | ドロワーをサイドバーとして開いたままにできる、幅の広いウィンドウ。 |
| モーダル | 末尾側の角が丸い、浮き上がったパネルです。スクリムの上に重なってコンテンツの上へ滑り込みます。閉じるまでフォーカスをとどめ、行き先が選ばれると自分で閉じます。 | コンパクトなウィンドウ。アプリバーや、折りたたんだドロワーのヘッダーにあるメニューボタンから開きます。 |

デザインシステムはバリアントを追加できます。追加したバリアントは、スタンダードと同じように振る舞います。

### 開く、フォーカス、閉じる

- **スタンダードを開く。** ドロワーが滑り込み、横のコンテンツが場所を空けます。メニューボタンなどで人の求めに応じて開いたときは、今の行き先へ、なければドロワーの最初のフォーカスできる要素へフォーカスが移ります。最初から開いた状態で表示したドロワーは、フォーカスを動かしません。
- **スタンダードの横で作業する。** Tab でドロワーからコンテンツへ進んでも、ドロワーは開いたままです。フォーカスが中にある状態で閉じると、開く前にフォーカスがあった場所へ戻ります。
- **モーダルを開く。** ドロワーが先頭側の端から滑り込み、ウィンドウの残りの部分にスクリムがフェードインします。フォーカスは今の行き先へ、なければ最初のフォーカスできる要素へ移り、ドロワーの中にとどまります。背後のものはすべて、ポインター、タッチ、キーボード、支援技術のどれからも操作できなくなります。
- **モーダルを閉じる。** スクリムを押す、Escape を押す、プラットフォームの「戻る」を使う、先頭側の端の方へ幅の半分を超えてドラッグするかその向きにフリングする、行き先を選ぶ。どれでも 1 回だけ閉じます。ドロワーは滑り出てスクリムが消え、開いたときにフォーカスを持っていた要素へフォーカスが戻ります。
- **端からのスワイプでは開かない。** iOS では画面の先頭側の端は「戻る」のジェスチャーなので、そこからドロワーを開くことはしません。目に見えるメニューボタンから開きます。
- 動きを減らす設定では、瞬時に開閉します。

### 折りたたむ

- **`collapsible`** を付けると、ドロワーは幅 72 の折りたたんだ形を持ちます。展開したドロワーからラベルがなくなっただけの形です。最上位の行き先とグループは、それぞれの項目をアイコンの後ろで切った 48 × 48 のセルになり、角の丸みは項目と同じで、選択中のものは項目とまったく同じように塗ります。ヘッダーのボタンは列に縦に並び、メインアクションはアイコンだけに縮みます。セクションの見出しは文字なしで行を保ち、ヘッダーのスロットと末尾の内容は描きません。
- **折りたたんだセルは、名前をツールチップで示します。** ツールチップはコンテンツの側に出ます。ポインターをセルに置いたままにするとツールチップの待ち時間の後に、キーボードフォーカスではすぐに表示し、タッチでは表示しません。ラベルはもともとセルのアクセシブルネームなので、ツールチップが読み上げに加えるものはありません。
- **`expanded`** は、スタンダードの折りたためるドロワーの形を選びます。モーダルの折りたためるドロワーは、閉じている間も列をレイアウトに残し、`open` でコンテンツの上へスクリム付きで広がります。
- **メニューボタン** は最初の `header-button` です。ドロワーが折りたためる間は、展開しているか折りたたんでいるかを伝え、ドロワーを制御するボタンとして扱われます。押すと、求めた形を付けて `expandedChange` を発火します。Web はそれを自分で反映し、ほかのプラットフォームでは利用者側で `expanded` か `open` を設定します。グリフと名前は利用者側で決めます。
- **`collapsedLabels`** は、どのセルがアイコンの下に短いラベルを描くかを選びます。既定の `never`（描かない）、`selected`（選択中のものだけ）、`always`（すべて）です。ラベル付きの列は、それを求めるプロダクトやデザインシステムのためのものです。そのときセルは `shortLabel`（なければラベル）を描き、ツールチップは出しません。どれでも、ラベルはアクセシブルネームのままです。
- **どのアイコンも位置を変えません。** アイコンはどちらの形でも同じ列と同じ高さに並び、どのセルも高さを保つので、形が変わるときに動くのは末尾側の端だけです。端が通り過ぎるとラベルが消え、ラベル付きの列では短いラベルが現れます。唯一の例外は開いているグループで、折りたたんだドロワーはその中身を描かないため、その下のセルが上に詰まります。 メインアクションのグリフも、どちらの形でも、ボタンのどのサイズでも、どちらの密度でも、行き先のアイコンと同じ線の上に立ちます。ドロワーはボタン自身のトークンから位置を決めます。列より幅の広い折りたたみ時の正方形（既定のシステムの大きいメインアクション）は列の端からはみ出し、デバッグビルドで報告します。small か medium を使い、コンパクトなドロワーでは、medium の正方形が列いっぱいになるので small を使います。
- **選択は、その場で色が変わります。** 新しく選ばれると、展開していても折りたたんでいても、項目はその場で色を変えます。選択を示すために何かが伸びたり、縮んだり、滑ったりすることはありません。

### 密度

- **`regular`**（既定）は、高さ 48 の項目に 24 のグリフで、[メニュー](/ja/components/menu/)の項目と同じ高さです。タッチでもポインターでも使うプロダクト向けです。
- **`compact`** は[ツリービュー](/ja/components/tree-view/)のコンパクトな行と同じです。高さ 32、グリフ 16、行の内側の余白 8、行の間 2、見出しの高さ 28 で、折りたたむとアイコンの列の幅は 56 です。ファイルブラウザーやエディターのサイドバーのように、行き先の多いドロワーをポインターで使うツールに使います。
- **どちらの密度でも、入れ子のアイコンがそろいます。** 階層が 1 つ深くなるごとに中身を 1 段字下げし、その幅はその密度のアイコンと間隔の和なので、入れ子の行き先のアイコンはグループのラベルの始まる位置に立ち、同じ階層のアイコンは 1 列に並びます。
- **タッチのターゲットは保ちます。** タッチでは、コンパクトな項目も少なくともタッチターゲットの高さで描きます。ポインターでは、ヒット領域は項目とその上下の間隔の半分です。ポインターターゲットより小さくなりますが、WCAG 2.5.8 の 24 は上回ります。
- デザインシステムは、ドロワーの `.compact` のトークン（`comp.navigation-drawer.item.container.height.compact` など）で、コンパクトの中身を変えたり、密度を加えたりできます。

### ツリービューと共有する行

- **[ツリービュー](/ja/components/tree-view/)と同じパラメーター**を、同じ名前と意味で持ちます。`chevron`、`guides`、`indent`、`highlight`、`iconSpace`、`expandable`、`labelWrap` と `supportingWrap`、行の `supportingText` と `supportingPosition`、そして `stickyParents` と `stickyMax` です。
- **`chevron`**：既定の `start` は、グループのシェブロンをアイコンの前に描き、すべての行でその場所を空けるので、同じ階層のアイコンがそろいます。`end` は行の最後、末尾の内容の後に描きます。`none` は描かず、グループのアイコンを押すと開閉し、開いている間は `openIcon` を表示します。折りたためるドロワーは `start` を `end` として描くので、どちらの形でもアイコンの位置は変わりません。グループのないドロワーはその場所を空けません。
- **`indent`**：`auto` は、行の最初の部分をグループのラベルが始まる位置にそろえ、グループがラベルの前に何も描かないときはその階層のインデントだけ字下げします。数値はその px だけ、0 は字下げしません。行のラベルがドロワーの幅の半分より先から始まることはありません。
- **`highlight`**：既定の `indented` は、入れ子の行の塗りとステートレイヤーを行の始まる位置から描き、`full` はどの階層でも幅いっぱいに描きます。
- **`iconSpace`** は、アイコンのない行にもアイコンの場所を空け、同じ階層のラベルをそろえます。`auto`（同じ階層のほかの行にアイコンがあるとき）、`always`、`never` です。
- **`expandable`** を false にすると、すべてのグループを開いた状態で、シェブロンなしで表示します。グループの行はその中身の名前になり、操作できるものではなくなります。
- **`guides`**：`shown` は、開いたグループの中身の横に、シェブロン、なければアイコン、なければラベルの始まりの下に線を描きます。`hover` は、ポインターがドロワーの上にある間か、フォーカスが中にある間だけ描きます。
- **1 行**：ラベルと補足テキストは 1 行で、入りきらなければ省略記号で切り、切れている行は、ホバーとキーボードフォーカスで全文をツールチップに表示します。`labelWrap` と `supportingWrap` で折り返せます。アクセシブルネームは常にラベル全文です。
- **補足テキスト**は、ラベルの下（`below`）か後ろ（`inline`）に置き、行の説明として読み上げます。
- **グループ**は、末尾のシェブロンの前に末尾のテキストや内容を、また `openIcon` と `loading` を持てます。`loading` は中身の下に読み込み中の行を描き、その名前はドロワーの `loadingLabel` です。
- **`stickyParents`**（ドロワーでは既定でオフ、ツリービューではオン）は、上に見えている行が属する開いたグループの行を、エディターのスティッキースクロールのように、内側のものから最大 `stickyMax`（2）個まで上端に固定します。折りたたんでいる間は働きません。

### ウィンドウの幅に合わせる

`responsive` を付けると、デザインシステムの 2 つのブレークポイント（既定のシステムでは 1024 と 600）をもとに、ウィンドウの幅がドロワーの表示のしかたを選びます。このとき `variant` は無視します。

| ウィンドウ | 表示 | ドロワーのあり方 |
| --- | --- | --- |
| 広い方のブレークポイント以上 | `standard` | コンテンツの横のスタンダードのドロワー。`open` が何であっても表示し、折りたためるなら `expanded` が選ぶ形になります |
| 狭い方のブレークポイント以上で、`collapsible` のとき | `column` | モーダルの折りたためるドロワー。アイコンの列をレイアウトに残し、`open` の間はコンテンツの上に広がります |
| それより狭い | `modal` | 折りたためない、モーダルのドロワー |

- **表示は導き出すもので、保存しません。** 幅だけに従い、ドロワーがそれを `variant`、`open`、`expanded` に書き込むことはありません。今の表示は、最初に決まったときと、幅によって変わるたびに、`presentationChange` が伝えます。
- **新しい表示には、閉じた状態で入ります。** 動きを付けず、すぐに描きます。開いていたオーバーレイは下ろし、`close` を 1 回発火します。`expanded`、`value`、各グループの `open` は保つので、スタンダードの表示に戻ると、離れたときの形のままです。
- **`modal` の表示では、メニューボタンは利用者側で用意します。** 表示が `modal` の間は、アプリバーなどに自前のメニューボタンを表示し、そこから `open` を設定します。このときドロワー自身のメニューボタンは、閉じることしかしません。
- **ドロワーは、訪問をまたいで何も覚えません。** 展開か折りたたみかという人の選択を残したいときは、`expandedChange` が運ぶ値を保存し、そこから `expanded` を設定します。

### サイトのサイドバーとして

すべての行き先に `href` を付け、ドロワーの `value` にそのページ自身のアドレスを渡すと、ドロワーは文書でできたサイトのサイドバーになります。

- **今の場所はページが伝えます。** リンクは、押されただけでは選択されません。各ページが、自分の行き先を `value` に設定します。その行き先の `value` を、なければ書かれたとおりの `href` を渡します。
- **`revealSelected`** は、ドロワーが最初に現れたときに、選択中の行き先を含むグループを開きます。最初のフレームで、動きを付けずに開き、その後も `value` が変わるたびに開きます。その後で人が閉じたグループは、`value` が変わるまで閉じたままです。
- **選択は、着いたときに見えています。** ドロワーが現れたとき、そして `value` が変わるたびに、選択を示す項目が全部は見えていなければ、スクロールする領域の中央へ運びます。見えていれば、まったく動かしません。そのため、今のページがすでに見えているサイドバーは、ページを移っても位置が変わりません。フォーカスは動かしません。
- **`scrollOffset`** は、項目がどれだけスクロールしているかを読み書きします。ドロワーは何も保存しません。長いツリーを読者が離れたときの位置に保ちたいサイトは、スクロール量と各グループの `open` を自分で（たとえばセッションのストレージに）保存し、最初のフレームの前に戻します。それでも、今のページを含むグループは開き、選択が見えなくなるスクロール量よりも選択の方を優先します。
- **サイトの外へ出るリンク**には `target` に `new` を指定します。新しいタブで開き、末尾の内容を置いていなければ、展開した項目の末尾にアイコンセットの `open_in_new` を描き、名前の後に `targetLabel` を読み上げます。この言葉（「新しいタブで開きます」など）は利用者側で用意します。Tanrei は言葉を同梱しません。
- **ルーターは `change` を聞きます。** `change` は、ブラウザーがリンクをたどる前に発火します。ただし、ふつうの実行のときだけです。`target` が `same` のリンクを、修飾キーなしの主ボタン、タッチ、Enter のいずれかで実行したときです。これをキャンセルし、運ばれてきた `href` へ移ります。別のタブで開いたリンクは何も発火せず、モーダルのドロワーも開いたままにします。

### 絞り込み

絞り込みは、ドロワーをその場で狭めるもので、検索ではありません。[検索](/ja/components/search/)はすべてのページの内容を探し、見つけたものを専用のビューに表示します。絞り込みは、ドロワーがすでに並べている場所のラベルだけを見て、それをその場に残します。そのため、ページの名前を知っている読み手は、「/」と最初の数文字の 2 つのキーでそこに着き、周りの項目の中でその位置を見られます。それぞれに専用のキーを割り当てます。サイドバーに絞り込みを持つドキュメントサイトにならって、絞り込みには「/」、検索には ⌘K か Ctrl+K です。

- **一致するもの。** 入力したすべての語を、それぞれラベルのどこかに、順不同で含む行が一致します。大文字と小文字、文字の幅（全角と半角）、文字に付く記号（アクセントなど）は区別しません。「nav dr」は「Navigation drawer」に、「resume」は「Résumé」に一致します。比べるのはラベルだけで、補足テキスト、末尾テキスト、アドレスは比べません。取得も、順位付けも、並べ替えもしません。サーバーで探す、順位を付ける、ラベル以外も比べるプロダクトは、`filterable` を設定せず、これまでどおり一致した行をドロワーに渡します。
- **`filterMode`** の既定は `filter` です。一致しない行は隠し、一致を持つグループは残し、名前で一致したグループは中身ごと残します。`highlight` は何も隠さず、一致に印を付けるだけです。前後のつながりの中で読む構造に使います。
- **グループは一時的に開きます。** 一致を持つ閉じたグループは、絞り込みのために開いて描きます。`open` は変わらず、`toggle` も発火しないので、入力欄を空にすると、また閉じます。絞り込み中にユーザーが開閉したグループはユーザーのもので、置いたままの状態を保ちます。
- **最初の一致はすぐに選べます。** 入力欄にフォーカスがある間、一致する最初の行をフォーカスのある行として描きます。Enter はその行で Enter を押したときと同じくそれを実行し、下矢印はその行にフォーカスを移します。入力は入力欄で続けられます。Escape は入力欄を空にし、もう一度押すと、「/」を押す前の場所にフォーカスを戻します。
- **「/」は、ページのどこからでも入力欄に移ります。** ただし、テキストの入力欄にフォーカスがあるときは、そこにスラッシュを入力します。折りたたんだドロワーは、先に展開します。キーは `filterShortcut` で変えられ、空のリストにするとキーを割り当てません。すでに「/」を使っているプロダクト向けです。狭いウィンドウでは、[アプリシェル](/ja/components/app-shell/)が閉じたドロワーをこのキーで開き、入力欄にフォーカスを移します。
- **件数。** 絞り込み中は、結果の先頭に控えめな 1 行で、一致した行の数（`filterCountText`）を、何も一致しなければ `filterEmptyText` を表示します。`filterCountHidden` を設定すると件数は描きませんが、支援技術には伝えます。
- **一致には、検索と同じ印を付けます。** 一致した文字を濃い文字色と太い文字にし、後ろに薄い塗りを描きます。
- **何も保存しません。** ドロワーがなくなると、テキストも忘れます。絞り込みを読み手について回らせたいときは、`filterChange` から `filterValue` を取っておき、次のページで戻します。

### 行き先、グループ、セクション

- 項目の高さは最小 48 で、[メニュー](/ja/components/menu/)の項目と同じ高さ、同じ角の丸みです。ラベルは 1 行で切り詰め、`labelWrap` を付けると折り返して項目も高くなります。
- ラベルの位置がそろうように、アイコンはすべての行き先に付けるか、どれにも付けないかのどちらかにします。折りたためるドロワーは、折りたたんだときに最上位の行き先とグループをアイコンで描くので、それぞれにアイコンを付けます。
- `trailingText` は、項目の末尾にラベルより控えめに描く短いテキストです。「24」のような件数か、「新着」のような言葉を書きます。件数はバッジではなく、ここにテキストとして書きます。バッジはアンカーに付ける印で、項目の末尾には付ける先がありません。印を付けるなら、`badge` でアイコンに付けます。そのほかのもの、たとえばグリフは `trailing` スロットに入れます。スロットは `trailingText` より優先され、操作はできません。`target` が `new` のリンクは、自分で項目の末尾に `open_in_new` を描くので、このグリフを利用者側で置くことはありません。末尾の内容はラベルの後に読み上げ、折りたたんでいる間は描きません。
- `badge` は、どちらの形でもアイコンにバッジを描きます。点か `badgeCount` の数字で、名前は `badgeLabel` です。
- グループの行は、`chevron` が置く位置のシェブロン（上記）で、中の行き先やグループを開閉します。選択中の行き先を含む閉じたグループは選択中として描き、折りたたんでいる間は最上位のグループも同じです。折りたたんでいる間にグループを押すと、ドロワーが展開してグループが開きます。階層は 3 つまでにします。
- **行き先にもなるグループ**（`selectableGroups` を付け、グループに `value` か `href` を与えたもの）は、[ツリービュー](/ja/components/tree-view/)と同じように行を 2 つに分けます。シェブロンが開閉し、行の残りがそれを選び、1 回押して両方が起きることはありません。シェブロンは行の次にフォーカスが移る独立した操作部品で、ヒット領域の幅は少なくともポインターターゲットです。折りたたんでいる間は、ほかのグループと違い、セルを押すとそれを選び、ドロワーは折りたたんだままです。中の行き先には、ドロワーを展開してたどります。`revealSelected` は、そのようなグループが今のページのときにもそれを開くので、サイトのサイドバーは表示中のセクションのページを示します。
- セクションの見出しは、その下の行き先をまとめて名付けるものです。見出しであって、操作できるものではありません。見出しのないセクションも作れます。タイトルのない、区切っただけのグループです。
- セクションの `divider` は、上にあるものと区切るために、セクションの前に区切り線を描きます。区切り線を利用者側で置くことはありません。
- ヘッダーには、アイコンの列に縦に並ぶヘッダーボタンと、その下のメインアクションがあります。ヘッダーのスロットは展開している間メニューボタンの横に置かれ、タイトルやアカウントの切り替えに使います。折りたたんでいる間は描きません。そこに置いたただのテキストは、ドロワーのタイトルのスタイル（`comp.navigation-drawer.header.typescale` と `comp.navigation-drawer.header.color`）で描きます。自分でスタイルを指定した要素は、そのスタイルのままです。
- 項目がヘッダーの下の空きより高くなると、項目がスクロールし、ヘッダーはその場にとどまります。スクロールがどちらかの端に達しても、ドロワーの背後のページまでスクロールすることはありません。

### 推奨

- よく使う行き先を先頭に、セクションの外か最初のセクションに置きます。
- 自分のアドレスを持つ行き先には `href` を付け、本物のリンクにします。新しいタブで開け、アドレスをコピーでき、クローラーもたどれます。
- セクションには「ラベル」「管理」のように、中の行き先に共通するものを名前にします。
- スタンダードとモーダルで同じ行き先と値を使い、ウィンドウの幅だけで切り替えられるようにします。

### 非推奨

- 「サインアウト」や「新規作成」のようなアクションをドロワーに置かない。ドロワーの項目は場所です。
- セクションを入れ子にしたり、グループにセクションを入れたりしない。デバッグビルドで報告し、内側のセクションの行き先をその場所に描きます。
- `selectableGroups` を付けずにグループに `value` や `href` を与えて、行で選べるようにしようとしない。開閉するだけで、デバッグビルドで報告します。
- スタンダードが収まる幅のウィンドウでモーダルを使わない。
- 絞り込みを、サイトの検索の代わりにしない。絞り込みは場所を名前で見つけるものです。内容の中の語を探す読み手には、検索が必要です。

### コンポーネントが担うこと

- Web では、ドロワーは `label` を名前とするナビゲーションのランドマークです。各行き先はリンク（`href` があるとき）かボタンで、今の行き先には `aria-current="page"` が付きます。モーダルのドロワーは、`label` を名前とするモーダルな `<dialog>` でもあります。
- iOS、Android、Flutter、React Native では、各行き先は、選択状態と行き先の中での位置を持つボタンです。それぞれのプラットフォームでサイドバーやドロワーの項目が読み上げられるのと同じです。モーダルのドロワーは、`label` を名前とするモーダルなコンテナ（モーダルのトレイト、またはペインのタイトル）です。
- 行き先は、どちらの形でもラベルを名前とする 1 つの要素です。アイコンは隠し、アイコンのバッジの説明と末尾の内容を、名前と状態の後に読み上げます。
- リンクの行き先は、どの状態でもボタンの行き先とまったく同じように描き、訪問済みの見た目はありません。コンテキストメニュー、新しいタブで開くこと、ドラッグ、ホバーで出るアドレスなど、ブラウザーがリンクに与えるものはすべて残ります。新しいタブで開くリンクは、説明の最後に `targetLabel` を読み上げます。
- 折りたたんだセルのツールチップは、ポインターやキーボードを目で見て使う人のためのものです。支援技術からは隠します。支援技術は、もともとラベルをセルの名前として読み上げます。
- グループの行は、展開状態を持ち、入れ子のリストを制御するボタンです。閉じたグループでは右（左から右に書くレイアウトの場合）で開き、開いたグループでは左で閉じ、グループの中では左でその行へ移ります。Tab は表示中のすべての行をたどります。
- 行き先にもなるグループは、WAI-ARIA Authoring Practices の「トップレベルのリンクを持つ開閉式ナビゲーションメニュー」です。行はリンクかボタンで、今のページのときは `aria-current="page"` を持ち、シェブロンはグループのラベルを名前とする別のボタンで、展開状態を持ち、入れ子のリストを制御します。どちらも Tab で止まり、行の上では右と左でこれまでどおりグループを開閉できます。
- ドロワーが折りたためる間、メニューボタンは展開しているか折りたたんでいるかを伝え、ドロワーを制御するボタンとして扱われます。形が変わっても、フォーカスはそれまでのセルにとどまります。
- セクションの見出しは見出しとして伝え、フォーカスは受け取りません。
- Tab はヘッダーの中身と、無効でないすべての行き先を順にたどります。Enter と Space でフォーカス中の行き先を実行します（Web のリンクでは Enter だけ）。無効な行き先はフォーカスを受け取らず、無効であることを伝えます。
- スタンダードでは、開くとフォーカスが中に入り、閉じると戻ります。Tab でコンテンツへ進んでも閉じません。モーダルでは、Tab と Shift+Tab はドロワーの中で折り返し、Escape とプラットフォームの「戻る」で閉じてフォーカスを戻します。
- フォーカスリングは項目の周りに、キーボードフォーカスのときだけ描きます。全部は見えていない項目にキーボードフォーカスが移ると、見えるところまで最小限だけスクロールします。
- ヒット領域は、どちらの形でもセル全体で、最小ターゲットを下回ることはありません。
- 文字を大きくしても、どちらの形の幅も変わらず、項目と見出しが高くなります。ラベルは折り返し、短いラベルは切り詰め、アイコンは拡大しません。
- 絞り込みの入力欄は、`filterLabel` を名前とする検索フィールドで、項目の前にあり、ドロワーのリストを操作することを伝えます。クリアボタンの名前は `filterClearLabel` です。「/」は入力欄のキーボードショートカット（Web では `aria-keyshortcuts`）として伝え、キーのヒントは支援技術から隠します。
- 絞り込みで隠した行は、支援技術からも消えます。そのため、聞こえる位置と数はどれも絞り込み後のものです。入力が 1 秒止まると、ドロワー自身のステータスが、一致した行の数、または何も一致しないことを、フォーカスを動かさずに polite に伝えます。結果の先頭に描く件数は支援技術から隠し、代わりにステータスが伝えます。
- 一致には、色だけでなく太さと塗りでも印を付けるので、色だけに頼ることはありません。強制カラーモードでは、プラットフォームの、印を付けたテキストの色で描きます。行の名前はラベル全体のままで、印のところで区切って読み上げることはありません。
- ラベルのない行き先、`label` のないモーダルのドロワー、どの行き先も指していない値、重複した値、入れ子のセクション、グループの中のセクション、3 つより深い階層、デザインシステムにないバリアント、メニューボタンのない折りたためるドロワー、`trailing` スロットの中のフォーカスできる要素、`javascript:` のアドレスや読み取れない `href`、定義にない `target`、`target` が `new` なのに `targetLabel` のないリンクは、デバッグビルドで報告します。 デザインシステムにない密度と、`selectableGroups` を付けていないのに `value` か `href` を持つグループも報告します。絞り込みでは、`filterLabel` のない入力欄、名前のないクリアボタン、未知の `filterMode`、2 つ以上の組み合わせを持つ `filterShortcut`、ほかのドロワーや検索がすでに使っている組み合わせを報告します。

プラットフォームごとの既知の制約：

- Web：Firefox はトップレイヤーから出ていく要素をアニメーションできないので、そこではモーダルのドロワーがスライドして出ていかず、すぐに消えます。
- Web：すべての寸法が `rem` に従うので、ブラウザーの文字サイズを大きくすると、アイコンも大きくなります。ドロワーの幅は変わりません。Tanrei の文字の大きさだけを変えたときは大きくなりません。
- Web：開いたスタンダードのドロワーから Tab でフォーカスが出ていくことはテストしていますが、コンテンツのどこに着くかは、負荷がかかると安定しなかったため、まだ確かめていません。
- SwiftUI は、どのビューがフォーカスを持っていたかを知ることができません。そのためドロワーを閉じても、キーボードフォーカスはどの要素にも戻らず、プラットフォームの既定の場所へ移ります。開いたときは現在の行き先か、なければ最初の有効な行き先にフォーカスが移り、ヘッダーのコントロールには移りません。Mac では、モーダルのドロワーが覆って無効にするのは、付けたビューだけです。ウィンドウのルートに付けてください。
- SwiftUI：Escape、アクセシビリティの「戻る」ジェスチャー、開いたときのフォーカスの移動は、まだ端から端までテストしていません。行き先は位置を値のテキスト（「2 of 6」）として持ち、英語だけです。
- Compose は、モーダルのドロワーを、Material のドロワーのようにアプリのウィンドウの中ではなく、`TanreiDialog` と同じく専用の `Dialog` ウィンドウで表示します。見た目は同じで、そのウィンドウがフォーカスを中にとどめ、「戻る」に応え、背後を支援技術から隠します。
- Compose にはドロワー全体の値がないので、どの行き先も指していない値を報告する手段がありません。
- Flutter のモーダルのドロワーは `Scaffold.drawer` ではありません。ウィンドウいっぱいの `Stack` の最後の子として置き、`open` で制御します。行き先は集合の中の位置を持ちません。
- Flutter：短い行を持つデザインシステムのように、行とその間隔を合わせてもタッチターゲットに届かないとき、ヒット領域だけを広げるのではなく、行同士の間が広がります。
- React Native は、どの要素がフォーカスを持っていたかを知ることができません。そのためドロワーを閉じても、開いた要素へはフォーカスを戻せません。モーダルのドロワーではプラットフォームが決めた場所へ移り、スタンダードのドロワーでは何もしません。
- React Native のドロワーには、まだ自分の `insets` プロパティがなく、`TanreiProvider` のインセットだけを読みます。行き先は位置を値のテキストとして持ち、`positionText` を渡さなければ英語です。
- React Native：モーダルのドロワーのドラッグとフリング、フォーカスの移動、アクセシビリティの「戻る」ジェスチャーは、実機ではまだ確かめていません。
- 以前の版を提供している SwiftUI、Compose、Flutter、React Native：最初の項目はドロワーの余白から間隔の半分だけ下に置かれ、ラベルが折り返した行の高さの伸び方もそろっていません（SwiftUI と Compose は、文字が収まらなくなるまで行の最小の高さを保ちます）。追従するときに、余白を最初のセルまでで測り、行の高さを最小値として扱うようになります。
- Web：入力欄ですぐに選べる最初の一致はフォーカスのある行として描きますが、入力欄のアクティブな子孫ではありません。行き先はリンクかボタンで、入力欄のアクティブな子孫にはなれないためです。スクリーンリーダーの利用者は、下矢印でその行に着きます。
- SwiftUI、Compose、Flutter、React Native には、まだ絞り込みがありません。
- Web：モーダルの折りたためるドロワーは、列の幅まで狭まってからでないとフォーカスを戻さず、ドラッグするとパネル全体が動き、ダイアログは開いたときに測った列の位置に置かれます。

### 利用者側で行うこと

- すべての行き先にラベルを付けます。折りたたんだ列にラベルを描くとき（`collapsedLabels`）は、列には長すぎるラベルに `shortLabel` も付けます。
- `target` が `new` のリンクには、プロダクトの言語で `targetLabel` を付けます。
- サイトでは、各ページで `value` をそのページ自身の行き先に設定します。
- `responsive` のドロワーの表示が `modal` の間は、ドロワーを開く自前のメニューボタンを表示します。
- メニューボタンには「メニュー」のような名前を付けます。Web 以外のプラットフォームでは、`expandedChange` から `expanded` か `open` を設定します。
- `label` で「メール」のようにドロワーに名前を付けます。モーダルのドロワーはダイアログなので、これがその名前になります。
- モーダルのドロワーは、「メニュー」のようなラベルを持つ、目に見えるメニューボタンから開きます。
- `open` を合わせておきます。モーダルのドロワーが閉じたら、プラットフォームに応じて `onClose`、バインディング、ドロワーの状態から false にします。
- SwiftUI では、ドロワーが閉じた後に、キーボードフォーカスをメニューボタンへ利用者側で戻します。
- React Native では、ドロワーが閉じた後にメニューボタンへのフォーカスの戻しを利用者側で行い、プロダクトの言語で `positionText` を渡し、ウィンドウのインセットを `TanreiProvider` に渡します。
- 各行き先の値は重複させず、スタンダードとモーダルのどちらでも変えないでおきます。
- `filterable` のときは、何を絞り込むかを伝える `filterLabel`（「ナビゲーションを絞り込む」）を入力欄に付け、`filterCountText`、`filterEmptyText`、`filterClearLabel`、`filterPlaceholder` の文言を、ドロワーに、またはプロダクトの文言として一度だけ渡します。
