## 概要

<ComponentAvailability name="app-shell" />

アプリシェルは、ウィンドウの枠組みです。領域を配置するだけで、その中身は描きません。ヘッダーに置くのは利用者側のアプリバー、ナビゲーションに置くのは利用者側のナビゲーションドロワー、フッターに置くのは利用者側のレイアウトです。シェルが加えるのは、自作の枠組みでは忘れられがちなものです。ランドマーク、ひとそろいのウィンドウ幅の区切り、固定されたヘッダーがリンク先を隠さないための余白、そしてキーボードで枠組みを飛び越える手段です。

枠組みはウィンドウ全体を占めるものなので、このページには動く例がありません。ページの中にシェルを描いても、そのシェルは、ページが置かれたウィンドウのウィンドウクラスになってしまいます。[仕様](#仕様)には、フィクスチャをプロパティとともに一覧で示します。テストでは、それぞれを専用のウィンドウに単独で描いています。

Web では、利用者側の領域を `<tanrei-app-shell>` で囲みます。この要素はシャドウルートを持たないので、`<header>` はページのバナーに、ただ 1 つの `<main>` はメインのランドマークになり、スクリプトがなくても、クローラーにも読めます。ほかのプラットフォームはまだ実装していません。

`@tanrei/web/app-shell.css` は、スクリプトが動く前に枠組み全体をレイアウトします。そのため、サーバーでレンダリングしたページは、スクリプトが届いてもレイアウトが動かず、スキップリンクは、スクリプトが無効でも働きます。要素自身も、同じスタイルシートをページに加えます。

### 書くもの

領域は、`slot` 属性を持つ子です。メインの領域は、`slot` を持たない、ただ 1 つの `<main>` です。

| 領域 | Web での書き方 | シェルが与えるもの |
| --- | --- | --- |
| スキップリンク | `<a class="tanrei-link" data-standalone slot="skip-link" href="#main">` | キーボードで最初にフォーカスが止まる位置。キーボードフォーカスがある間だけ描かれます。 |
| お知らせ | コールアウトを囲む `<div slot="announcement">` | ヘッダーの上、枠組みの幅いっぱい。 |
| ヘッダー | アプリバーを囲む `<header slot="header">` | 幅いっぱい。ページをスクロールしても上端に残ります。 |
| ナビゲーション | `<tanrei-navigation-drawer slot="navigation" responsive>` | 先頭側の端。3 つの見せ方のいずれかになります。 |
| メイン | `<main id="main" tabindex="-1">` | ガター、幅の上限、スキップリンクの行き先。 |
| アサイド | `<aside slot="aside">`、またはサイドシート | 広いウィンドウでは末尾側の端。それ以外ではメインコンテンツの上か下。 |
| フッター | `<footer slot="footer">` | ページの終わり、ガター、余白。 |
| ナビゲーションバー | `<tanrei-navigation-bar slot="navigation-bar">` | 下端。狭いウィンドウのときだけ。 |

領域は、キーボードでたどる順に書きます。スキップリンク、お知らせ、ヘッダー、ナビゲーション、アサイド（メインコンテンツの前に来る場合）、メイン、アサイド（後に来る場合）、フッター、ナビゲーションバーの順です。スタイルシートは領域を名前で配置し、フォーカスの順序を入れ替えることはありません。書かなかった領域は、場所を取らず、ランドマークも増やしません。

## ガイドライン

### 3 つのウィンドウクラス

シェルは、ウィンドウの幅だけをもとに、ウィンドウを 3 つのクラスのいずれかに分類します。

| クラス | 幅 | ナビゲーション | アサイド | メニューボタン | ナビゲーションバー | ガター |
| --- | --- | --- | --- | --- | --- | --- |
| `compact` | 600 未満 | 開いたとき、コンテンツの上に重なる | メインコンテンツの上か下 | 表示 | 表示 | 16 |
| `medium` | 600 から 1023 | ドロワーが `collapsible` ならアイコンの列。そうでなければ compact と同じ | 上か下 | 列がなければ表示 | 非表示 | 24 |
| `expanded` | 1024 以上 | コンテンツの横 | コンテンツの横、末尾側の端 | 非表示 | 非表示 | 32 |

- 幅の境目は、トークン `sys.breakpoint.medium` と `sys.breakpoint.expanded` です。`responsive` を付けたナビゲーションドロワーも同じ 2 つを読むので、枠組みとドロワーは同時に切り替わります。
- Web では、幅を `rem` で比べます。そのため、ページを拡大している読み手には、列が読めないほど狭くなる前に、より狭いクラスの配置が使われます。
- クラスは `windowclasschange` で知らされ、`windowClass` に入っています。検索の見せ方、サイドシートのバリアント、アウトラインの形など、シェルが切り替えないものは、これをもとに利用者側で切り替えます。
- Web では、枠組みの中のすべてが `--tanrei-app-shell-window-class` も継承します。そのため、スタイルシートは、スクリプトなしで、スタイルのコンテナクエリを使ってクラスに合わせられます。

### メニューボタン

ヘッダーにアイコンだけのボタンを 1 つ置き、`data-app-shell-menu` を付けます。シェルは、ナビゲーションがレイアウトの中に場所を持たない間だけ、このボタンを表示します。押すと、ドロワーがコンテンツの上に開き、フォーカスがその中へ移ります。ドロワーを閉じると、フォーカスはボタンに戻ります。ボタンは、ナビゲーションが展開されているかどうかを伝えます。

その状態は `navigationOpen`（`navigation-open`）に入っていて、利用者が変えたときは `navigationopenchange` で知らされます。ウィンドウクラスが変わると、ナビゲーションは閉じます。

### スクロールするもの

| `scroll` | スクロールするもの | 用途 |
| --- | --- | --- |
| `page`（既定） | ウィンドウがページをスクロールします。ヘッダーは上端に固定され、ナビゲーションとアサイドは、コンテンツの横で見えたままです。 | 読むためのページ：ドキュメント、記事、設定。 |
| `main` | 枠組みはウィンドウとちょうど同じ大きさで、メインの領域だけがスクロールします。 | ペインが別々にスクロールするアプリ：メールクライアント、エディター。 |

- ふつうは `page` を使います。ページ内検索、見出しへのリンク、読んでいた位置への復帰、スマートフォンのブラウザーで折りたたまれるバーが、どれもシェルのないページと同じように働きます。
- `headerPosition: static` にすると、ヘッダーはページと一緒にスクロールして見えなくなります。
- Web で `scroll: main` を使うときは、アプリバーの `scroll-target` に、メインの要素の id を指定します。
- Web で `scroll: main` を使うとき、（compact か medium のウィンドウで）メインコンテンツの上か下に描くアサイドは、メインの領域がスクロールしても動きません。いまはまだ一緒にスクロールしません。ページと一緒にスクロールさせたい内容は `<main>` の中に置きます。
- Web では、JavaScript のプロパティは `scrolls` です。どの要素にも、すでに `scroll()` メソッドがあるためです。属性は `scroll` です。

### 見出しへのリンクはヘッダーの下で止まる

シェルは、固定されたヘッダーの高さを測り、ページのスクロールするビューに、その分のパディングを付けます。そのため、リンクで移動した先の見出しも、キーボードフォーカスを受けた要素も、ヘッダーの下に隠れず、ヘッダーのすぐ下で止まります。Web では、同じ距離がルートの `--tanrei-app-shell-scroll-offset` に入るので、テーブルのヘッダー行のような、利用者側で固定しているパーツに使えます。シェルの中では、`--tanrei-prose-scroll-offset` は 0 のままにします。

### 何が何の上に重なるか

- ヘッダーとナビゲーションバーは、その下をスクロールしていくもの（フッターを含む）すべての上に重なります。メインの領域、アサイド、フッターにあるものは、`z-index` をいくつにしても、その上には出ません。どの領域も、中にあるものの重なりをその領域の中で閉じるからです。
- メニュー、ポップオーバー、ツールチップ、スナックバー、ダイアログ、シートは、枠組み全体の上に重なります。Tanrei のものは自分でそこに描かれます（Web ではブラウザーのトップレイヤー）。利用者側で作るオーバーレイも同じように、`popover` か、`showModal()` で開く `<dialog>` で描いてください。大きな `z-index` で持ち上げてはいけません。
- Web では、枠組みそのものが 1 つのスタッキングコンテキストになっています。そのため、枠組みの中の重なりの段が、ページが枠組みの外に描くものと競り合うことはありません。

### メインの領域の幅

- `mainWidth: contained`（既定）は、コンテンツの幅を 768 までにし、使える幅の中央に置きます。読むためのページに使います。
- `mainWidth: full` は、ガターの内側の幅をすべて使います。テーブル、ボード、エディターに使います。
- 幅の広いテーブルや 1 行のコードのように、縮められないコンテンツは、自身のボックスの中でスクロールします。枠組みを広げることはありません。

### アサイド

- expanded のウィンドウでは、アサイドはメインコンテンツの横に 240 の幅で置かれ、ページをスクロールしても見えたままです。
- それより狭いウィンドウでは、メインコンテンツと同じ列に入ります。`asideOrder: before` はメインコンテンツの上に描き、ページのアウトラインに向いています。`after`（既定）は下に描き、関連リンクに向いています。
- `asideOrder` は、読む順序でもあります。Web では、マークアップでも `<aside>` を `<main>` の同じ側に書きます。
- アサイドには、`asideLabel` でプロダクトの言語の名前を付けます。
- アサイドに置いたサイドシートは、自身の幅と縁を保ちます。そのバリアントは、`windowclasschange` をもとに設定します。

### フッター

- フッターは、フッターの領域を埋めているあいだ表示されます。埋めなければ、フッターもランドマークもありません。
- `footerHidden`（`footer-hidden`）は、埋めたフッターを、マークアップから外さずに隠します。サイトのページではなく、作業のための画面に使います。決済、サインイン、エディターなどです。このときフッターは場所を取らず、線を描かず、ランドマークにならず、キーボードのフォーカスも止まりません。ナビゲーションとアサイドは、ページの終わりまで見えたままです。
- フォーカスがフッターの中にあるときに隠すと、フォーカスはメインの領域に移ります。

### 領域の間の線

| `separation` | 描き方 |
| --- | --- |
| `auto`（既定） | デザインシステムが選んだもの。既定のシステムでは線です。 |
| `divider` | フッターの上、コンテンツの横にあるアサイドの先頭側の端、メインコンテンツとその上か下に置かれたアサイドの間に、細い線を描きます。 |
| `gap` | 線は描きません。余白は同じです。 |

線は場所を取りません。ヘッダー、ナビゲーション、お知らせ、ナビゲーションバーの周りには、シェルは線を描きません。これらのコンポーネントは、自身の縁を自分で描くからです。ヘッダーのアプリバーは、位置の変わらない領域の縁として下端の線を静止時から引き、ページがその下をスクロールしても保ちます。コンテンツが下に潜り込んだときだけ表示したいときは、バーの `dividerVisibility` を `scroll` にします。

### 推奨

- どのページにも `<main>` を 1 つ置き、スキップリンクが指す id を付けます。
- スキップリンクの文言は、プロダクトの言語で書きます。Tanrei は言葉を同梱しません。
- ナビゲーションの領域には、`responsive` を付けたナビゲーションドロワーを使います。

### 非推奨

- ページのタイトル、説明、アクションをシェルに入れない。それらは[ページヘッダー](/ja/components/page-header/)で、メインの領域の先頭に置きます。
- 記事のフッター（前と次のページ、編集リンク）をフッターの領域に入れない。それはメインコンテンツの終わりに置くものです。フッターの領域は、サイト全体に属するもののためにあります。
- CSS で領域の順序を入れ替えない。マークアップの順序が、フォーカスの順序です。

## アクセシビリティ

<ComponentAccessibility name="app-shell" />

### コンポーネントが担うこと

- 中身のある領域は、それぞれのランドマークになります。バナー、ナビゲーション、メイン、補足、コンテンツ情報です。要素自身がランドマークにならない領域には、ロールを付けます。
- スキップリンクは、キーボードで最初にフォーカスが止まる位置です。たどると、フォーカスはメインの領域そのものに移り、その上端がヘッダーのすぐ下に見えます。次に Tab を押すと、コンテンツの最初のコントロールに届きます。
- Tab は、読む順序で領域をたどります。この順序は、どのウィンドウクラスでも、レイアウトの方向が左から右でも右から左でも変わりません。表示されていない領域に、フォーカスが止まる位置はありません。
- リンクで移動した先や、フォーカスを受けた要素が、固定されたヘッダーやナビゲーションバーの下に隠れたままになることはありません。
- ウィンドウクラスが変わったときに、メニューボタンのように表示されなくなったものにフォーカスがあれば、フォーカスはメインの領域に移ります。
- 隠したフッター（`footerHidden`）は、アクセシビリティツリーに現れず、キーボードのフォーカスも止まりません。
- 幅 320 のウィンドウでテキストを 200% にすると、枠組みは 1 列になり、横にスクロールするものはありません。
- 強制カラーモードでは、線とスキップリンクのボックスを、システムのテキストの色で描きます。
- 右から左のレイアウトでは、ナビゲーションが右に、アサイドが左に置かれます。フォーカスの順序は変わりません。

### 利用者側で行うこと

- ページごとに `<main>` をちょうど 1 つ置きます。1 つもない場合や 2 つ以上ある場合は、デバッグビルドで報告します。
- アサイドの名前（`asideLabel`）と、ナビゲーションドロワーとナビゲーションバーの `label` を用意します。1 つのページにナビゲーションのランドマークが 2 つあれば、名前も 2 つ必要です。
- スキップリンクの文言と、メニューボタンのラベルを用意します。
- ページごとに、レベル 1 の見出しを 1 つ、メインの領域に置きます。[ページヘッダー](/ja/components/page-header/)のタイトルがそれにあたります。
