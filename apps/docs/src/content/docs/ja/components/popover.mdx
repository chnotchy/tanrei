ポップオーバーは、それを開いたコントロールの横でユーザーが操作するコンテンツに使います。いくつかの設定、短いフォーム、共有のパネル、リンクやボタンが必要な説明などです。開いている間も、ページのほかの部分はそのまま使えます。コンパクトなウィンドウでは、代わりにウィンドウの下端にボトムシートの見た目で表示します。Tanrei のポップオーバーとダイアログは、コンパクトなウィンドウではすべてそうなります。

### 使い方

コントロールは利用者側で用意します。Web では、ポップオーバーを横に置く要素の id を `anchor` に指定します。この要素は、ポップオーバーを開く要素（オープナー）でもあります。ポップオーバーは、この要素がダイアログを開くことと、そのダイアログが開いているかどうかを支援技術に伝え、閉じるときにはこの要素にフォーカスを戻します。フィールドがサーフェスのアンカーで、それを開くのがフィールドの中のボタンである場合は、そのボタンを `opener` に指定します。

ポップオーバーは、メニューと同じく制御コンポーネントです。オープナーが押されたら `open` を設定し、ポップオーバーが `close` を発火したら false に戻します。ホバーやフォーカス、時間の経過で、ひとりでに開くことはありません。`close` は理由を伝えます。`escape`、`outside`、`focus-out`、`close`（閉じるボタン）、`anchor-hidden` のいずれかです。アクションを押してもポップオーバーは閉じません。閉じるのは、利用者側のハンドラーです。コンパクトなウィンドウでシートとして表示されているときは、スクリムを押すと `outside` を伝え、`focus-out` と `anchor-hidden` は伝えません。

ポップオーバーには名前を付けます。見出しを描くなら `headline`、描かないなら `label` です。

SwiftUI、Compose、Flutter、React Native は計画中です。このページの冒頭で各プラットフォームに添えた名前は仕様が定めたもので、まだ提供していません。

### 配置

`placement` は、ポップオーバーをアンカーのどの側に置くかと、その辺に沿ってどうそろえるかを指定します。13 個の値はツールチップと同じで、意味も同じです。

| 値 | 位置 |
| --- | --- |
| `bottom-start`（既定）、`bottom`、`bottom-end` | アンカーの下。先頭側の端をそろえる、中央にそろえる、末尾側の端をそろえる |
| `top-start`、`top`、`top-end` | アンカーの上。そろえ方は同じ 3 通り |
| `start`、`start-top`、`start-bottom` | アンカーの先頭側の横。中央にそろえる、上端をそろえる、下端をそろえる |
| `end`、`end-top`、`end-bottom` | アンカーの末尾側の横。そろえ方は同じ 3 通り |
| `auto` | 下、上、末尾側、先頭側の順に見て、最初に余裕のある側 |

先頭側と末尾側は、レイアウトの方向に従います。`offset` は、アンカーまでの距離をプラットフォームのレイアウト単位で指定します。省略すると `comp.popover.offset` になります。`crossOffset` は、置かれた辺に沿ってポップオーバーを動かします。アンカーのその辺から外れるところまでは動きません。

ポップオーバーは、ウィンドウの端から `comp.popover.window-margin` だけ内側に収まるように、次のことをこの順に行います。

1. 指定された側に余裕がなければ、そろえ方を保ったまま反対側に回ります。
2. どちらの側にも余裕がなければ、余裕の大きいほうの側に置かれ、その余裕に収まる大きさになります。このとき、コンテンツはスクロールします。
3. 余白を保つのに必要なだけ、置かれた辺に沿ってずれます。
4. ウィンドウがポップオーバーの最小の大きさより小さいときは、ウィンドウの外に出る代わりに、アンカーに重なります。

アンカーが動くと、ポップオーバーも付いていきます。いまの側に余裕がある間は、その側にとどまります。アンカーがまったく見えなくなると、理由 `anchor-hidden` で `close` を発火します。

### 大きさ

ポップオーバーの幅はコンテンツの幅で、`comp.popover.container.min-width`（160）から `container.max-width`（400）の間に収まります。`width="anchor"` を指定すると、アンカーと同じ幅になります。フィールドの下に開くサーフェスに使います。どの場合も、ウィンドウの幅から余白を引いた幅を超えることはありません。

高さはパーツの高さの合計で、`container.max-height`（480）と、置かれた側の余裕が上限です。それを超えると、ヘッダーとアクションはその場に残り、その間でコンテンツがスクロールします。コンテンツがスクロールする間は、ヘッダーの下とアクションの上に区切り線を引きます。`dividerVisibility` を `scroll`（Web では `divider-visibility`）にすると、ヘッダーの下の線はコンテンツがスクロールされてから、アクションの上の線は下にまだ続きがある間だけ引かれます。`cupertino` と `m3-like` は、すべてのポップオーバーでこちらを選んでいます。SwiftUI、Compose、Flutter、React Native は、追従するまでこの描き方です。

コンテンツが自分で余白を持つ場合や、端まで届く場合（リストなど）は、`inset` を false にします（Web では `no-inset`）。

### パーツ

| パーツ | 内容 |
| --- | --- |
| ヘッダー | 見出しと、`closable` が true のときの閉じるボタン。コンテンツがスクロールしても動きません |
| コンテンツ | 既定のスロット。リンク、フィールド、ほかのコントロールなど、何でも入ります |
| アクション | `actions` スロットに入れる Tanrei のボタン。確定のアクションには `confirming`、取り消しのアクションには `dismissive` を付けます。ボタングループと同じ並べ方で配置し、ラベルが収まらなくなると縦に積みます |
| 矢印 | アンカーを指す三角形。任意です。`arrow` は 1 つのポップオーバーに、`comp.popover.arrow.visible` はデザインシステム全体に矢印を付けます |

`variant` のないアクションは、`comp.popover.actions.variant`（既定のシステムでは Tonal）になります。閉じるボタンは、アイコンだけの小さいボタンで、バリアントは `comp.popover.close-button.variant` です。既定のシステムでは、Tanrei のほかの閉じるボタンと同じく Tonal で、どんなコンテンツの上でもコントロールとして読めます。m3-like と cupertino のプリセットは、グリフだけの見た目（Text）のままです。

### モーション

ポップオーバーは、Tanrei で現れるほかのすべての面と同じように現れます。アンカーに面した辺の中央から、フェードインしながら少し（デフォルトのシステムでは 96 % から）拡大し、閉じるときは同じ道を少し速く戻ります。モーションの途中で開閉が切り替わると、その時点の状態から折り返します。動きを減らす設定では、フェードだけになります。m3-like プリセットでは、Material のメニューと同じく、その辺から展開します。ページのマークアップに open で書かれたポップオーバーは、最初のフレームからモーションなしで表示されます。

### コンパクトなウィンドウ

`comp.popover.compact.window-width`（既定のシステムでは 600）より狭いウィンドウでは、ポップオーバーはボトムシートの見た目になります。これは、コンパクトなウィンドウでのすべてのポップオーバーとダイアログに対する Tanrei の規則です。開くのは同じポップオーバーで、props とイベントも同じです。変わるのは描き方だけです。

- ウィンドウの下端に付き、`comp.bottom-sheet.container.max-width` までウィンドウの幅いっぱいに広がり、ボトムシートの色とエレベーションで描かれます。上の角は `comp.bottom-sheet.container.shape`、下の角は直角です。画面キーボードが出ているときは、その上に載ります。
- 高さは中身に合わせますが、上に `comp.bottom-sheet.container.margin-block-start` を残した高さを超えません。超えた分は、ヘッダーとアクションの間でコンテンツがスクロールします。
- 矢印もドラッグハンドルもなく、ドラッグにも追従しません。`placement`、`offset`、`crossOffset`、`width` は使われません。
- モーダルです。ボトムシートのスクリムがページを暗くし、後ろのものはすべて操作不能になり、フォーカスは中にとどまります。Escape、戻る、スクリムを押すこと、閉じるボタンで閉じます。
- ボトムシートのモーションで下端からせり上がり、閉じるときは下へ戻ります。動きを減らす設定では、その場でフェードします。
- 開いている間にウィンドウの幅がこの値をまたぐと、モーションなしでその場で形を変え、フォーカスはそのままです。

`compactPresentation` を `own`（Web では `compact-presentation="own"`）にすると、そのポップオーバーはどのウィンドウでもアンカーの横にとどまります。属するものの隣にいなければならないサーフェスに使います。`initialFocus="anchor"` のポップオーバーは、入力中のフィールドを使える状態に保つため、常にアンカーの横にとどまります。シートをまったく使わないデザインシステムは、`comp.popover.compact.window-width` を 0 にします。

ここでいうポップオーバーにメニューは含まれません。メニュー、セレクトやコンボボックスのリスト、ボタンのメニューは、どのウィンドウでもコントロールの横にとどまります。

### Web での描き方の違い

- ポップオーバーは、トップレイヤーにある `popover="manual"` の要素です。モーダルの `<dialog>` の中で操作できるようにするには、その dialog の子孫に置きます。
- コンパクトなウィンドウのシートは、`showModal()` で開くネイティブの `<dialog>` で、スクリムはその `::backdrop` です。
- 外側を押すとポップオーバーは閉じ、押した位置にある要素にもその操作が届きます。
- Web には固有の戻る操作がないので、`close` が理由 `back` を伝えることはありません。
- `anchorElement` と `openerElement` は、id で届かない要素（別のシャドウルートの中の要素など）を指定するプロパティです。
- `arrow` は未設定、true、false のいずれかです。属性は、なし、`arrow`、`arrow="false"` で表します。
- 開いたときにフォーカスを受け取る要素には、`autofocus` を付けます。
- 強制カラーモードでは、コンテナと矢印にテキストの色の輪郭線が付きます。

### ツールチップ、ポップオーバー、メニュー、ダイアログ

| 観点 | ツールチップ | ポップオーバー | メニュー | ダイアログ |
| --- | --- | --- | --- | --- |
| 開くきっかけ | ホバー、キーボードフォーカス、長押し | オープナーを押す | アンカーを押す | プロダクト |
| 入るもの | アンカーの説明 | ユーザーが操作するコンテンツ | 項目だけ | 判断 |
| フォーカス | 受け取りません | 受け取り、戻します | 受け取り、戻します | 受け取り、保ちます |
| ページをふさぐか | いいえ | いいえ（コンパクトなウィンドウのシートでは、はい） | いいえ | はい |

1. コントロールが何であるかを伝えるだけで、押せるものが中にないなら、ツールチップです。
2. コマンドや選択肢のリストなら、メニューです。
3. 答えなければ先に進めないなら、ダイアログです。
4. それ以外は、ポップオーバーです。

### トグルチップ

トグルチップは、説明する対象の隣にある小さな情報ボタンの奥に置く、短い注記です。独立したコンポーネントではなく、ポップオーバーを開くボタンです。注記にリンクがある、タッチでも届かなければならないなど、ツールチップでは足りないところで使い、1〜2 文に収めます。

- **ボタン。** アイコンだけのボタン（`variant="text"`、`size="small"`）にし、`label` には「情報」ではなく、注記が何についてのものか（「ストレージについて」）を書きます。押すとポップオーバーが開き、もう一度押すと閉じます。ポップオーバーはこのボタンを `anchor` に指定します。
- **ポップオーバー。** `label` で名前を付けます。タイトルを描くなら `headline` で。ほかのポップオーバーと同じく、開くとフォーカスを受け取り、閉じるとボタンに返します。Escape と外側の押下でも閉じます。
- **ページの代わりにしない。** 先へ進む前に読まなければならないことは、フィールドの補助テキストやページそのものに書きます。尋ねなくても読めるように。

### 推奨

- コントロールを押して開き、同じコントロールをもう一度押したら閉じます。
- コンテンツは短くします。1 つの作業で、フィールドは多くても数個です。
- ポップオーバーが大きく、外側の押せる場所を覆ってしまうときは、`closable` を付けます。Escape のないタッチのためにも付けます。
- ユーザーが入力しているフィールドの下に出すサーフェスには、`width="anchor"` と `initialFocus="anchor"` を使います。
- `compactPresentation` を `own` にするのは、コンパクトなウィンドウでも属するものの横にいなければならないポップオーバー（説明する語のすぐ横に出す注など）だけにします。
- アクションのラベルは短くします。ポップオーバーより幅の広いラベルは折り返しません。

### 非推奨

- ホバーやフォーカスでポップオーバーを開かない。タッチでは届きません。ポインターが通っただけでフォーカスを奪うサーフェスは、抜け出せない罠になります。
- 外側をうっかり 1 回押しただけで失われて困るものを、ポップオーバーに入れない。長いフォームは、ダイアログかシートに入れます。
- ポップオーバーの中に、ポップオーバーを 2 つ以上重ねない。1 段増えるごとに、Escape を押す回数が 1 回増えます。
- 先に進む前に答えが必要なものに、ポップオーバーを使わない。それはダイアログです。

## アクセシビリティ

### コンポーネントが担うこと

- コンテナは、モーダルではないダイアログです。`headline` または `label` が名前になります。外側のものを隠したり、操作不能にしたりしません。
- コンパクトなウィンドウでシートとして表示されているときは、コンテナはモーダルなダイアログです。外側はすべて操作不能になり、Tab と Shift+Tab は中で循環します。閉じると、フォーカスはオープナーに戻ります。
- オープナーは、ダイアログを開くことと、そのダイアログが開いているかどうかを伝えます。オープナー自身の名前とロールは変わりません。
- 開くと、利用者側で印を付けた要素に、なければコンテナにフォーカスを移します。そのため、ポップオーバーの名前が最初に読み上げられます。コンテナのフォーカスインジケーターは、キーボードで開いたときだけ表示します。
- ポップオーバーは、文書のどこに書かれていても、Tab の順序ではオープナーのすぐ後に来ます。最後の要素で Tab を押すと、フォーカスはオープナーの次の要素に進み、ポップオーバーは閉じます。フォーカスを閉じ込めることはありません。
- Escape は、いちばん上のオーバーレイだけを閉じ、それより先には届きません。ポップオーバーが置かれているダイアログは、開いたままです。
- 閉じるとき、フォーカスがポップオーバーの中にあれば、オープナーに戻します。ユーザーがフォーカスをほかへ動かしていた場合は、そのままにします。
- メニューやツールチップなど、ポップオーバーの中から開いたオーバーレイは、ポップオーバーの一部です。その中を押したり、その中にフォーカスを移したりしても、ポップオーバーは閉じません。
- テキストを 200% にすると、ポップオーバーの中のテキストは折り返し、ポップオーバーは上限まで大きくなり、それを超えるとスクロールします。コンパクトなウィンドウでは、ウィンドウの幅いっぱいのシートになります。自分の表示を保つポップオーバーは、幅 320 のウィンドウでは、ウィンドウの幅から余白を引いた幅になります。

### 利用者側で行うこと

- ポップオーバーに `headline` または `label` を付けます。`closable` のときは `closeLabel` も付けます。
- オープナーが押されたら `open` を設定し、`close` を受け取ったら false にします。
- Web では、できるだけポップオーバーの要素を文書の中でオープナーのすぐ後に置きます。スクリーンリーダーの読み上げ順が、Tab の順序と同じになります。
- 短いフォームでは、最初のフィールドに、開いたときにフォーカスを受け取る印を付けます。テキストだけのポップオーバーには付けません。
