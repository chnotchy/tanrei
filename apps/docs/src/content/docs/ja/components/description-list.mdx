## 概要

説明リストは、注文、ファイル、アカウント、コンポーネントなど、ひとつのものについての情報を示します。それぞれの項目は、項目名と、それに答える値の組です。項目名は控えめなラベルで、利用者が知りたいのは値のほうです。

同じ項目を、3 つのレイアウトで描けます。

| `layout` | 描き方 | 用途 |
| --- | --- | --- |
| `inline`（既定） | 項目名を値の横に置きます。項目名はすべて 1 つの列に並び、列の幅は最も長い項目名に合わせます。 | 利用者が調べものに使う、ひとまとまりの項目。 |
| `stacked` | 項目名を値の上に置きます。 | 長い値や長い項目名、複数列に並べる項目。 |
| `stat` | 値を先に大きな数値として描き、項目名をその下にラベルとして置きます。 | 画面の最初に見せる、少数の数値。 |

Web では、プロダクト側のネイティブの `<dl>` を `<tanrei-description-list>` で囲みます。この要素はシャドウルートを持たず、リストにロールも付けません。そのため、スクリーンリーダーにも、クローラーにも、スクリプトのないページでも、通常の HTML の説明リストのままです。ほかのプラットフォームはまだ実装していません。

`@tanrei/web/description-list.css` は、スクリプトが動く前にリスト全体を描きます。要素自身も同じスタイルシートをページに加えるので、スクリプトだけを読み込んだページでも、少し遅れてリストが描かれます。

### 書くもの

| パーツ | Web での書き方 |
| --- | --- |
| 項目 | `<dl>` の中の `<div>`。1 つの `<dt>` と、その `<dd>` を囲みます。 |
| 項目名 | `<dt>`。テキストか、値が説明する対象のコンポーネント（凡例の中のタグなど）です。コロンは書きません。 |
| 値 | `<dd>`。テキストかコンポーネントで、空でもかまいません。 |
| 複数の値 | 1 つの項目に書いた複数の `<dd>`。それぞれを別の行に描きます。 |

一部の Markdown レンダラーが書き出すような、`<div>` でまとめていない `<dl>` も、`inline` または `stacked` の 1 列で描かれます。`columns` と `stat` のレイアウトには、`<div>` でのまとまりが必要です。

## ガイドライン

### 説明リストを使う場面

- **ひとつ**のものについての情報に使います。同じ項目名を持つものが複数あるなら、それは[テーブル](/ja/components/table/)です。テーブルでは、見出しが列に名前を付けます。
- 段落の間で順に読む、言葉の説明はプローズです。コンテンツの中の `<dl>` には何も付けずにおきます。プローズはそれを、項目名を目立たせた本文として組みます。このコンポーネントは同じリストをレイアウトした形で、目立つのは値のほうです。
- 利用者が選んだり押したりするリストは、[リスト](/ja/components/list/)です。

### 収まり方

リストは、ウィンドウの幅ではなく、自身の幅からすべてを決めます。同じリストが、ページでも、カードでも、サイドパネルでも、ダイアログでも正しく収まります。

- **`inline` は自分で縦に並びます。** 最も長い項目名の横で値に残る幅が 144 を下回ると、すべての項目がそろって、項目名を値の上に置いた形になります。幅に余裕ができると 2 列に戻ります。幅が変わるたびに決め直します。まだ表示されていないパネルやタブの中で、幅のないまま最初にレイアウトされたリストも同じです。小さいウィンドウのために、利用者側でレイアウトを切り替えないでください。
- **列は自分で減ります。** `columns` は、`stacked` と `stat` のレイアウトが描く列の最大数です。各列の幅は 144 以上です。そのため 4 つの数値は、広いページでは 4 列、狭いページでは 2 列ずつ、スマートフォンでは 1 列になります。項目の数より多い列を描くことはありません。
- **`inline` のリストは 1 列です。** `columns` を指定しても変わりません。
- **何も途中で切りません。** 値は折り返します。途中で改行できない識別子やアドレスは、列の端で改行します。リストが横にスクロールすることはありません。

### 密度

| `density` | 項目名と値 | 項目の間 | 用途 |
| --- | --- | --- | --- |
| `regular`（既定） | 文字サイズ 14 / 行の高さ 20 と、14 / 22 | 12。線があるときは線の両側に 12 | 利用者が読む項目：ページ、カード、ダイアログ。 |
| `compact` | 12 / 16 と 13 / 20 | 6。線があるときは線の両側に 6 | 利用者がざっと目を通す項目：サイドパネル、インスペクター。 |

`stat` の数値は、`regular` で 32 / 40、`compact` で 20 / 28 です。

### 項目の区切り方

| `separation` | 描き方 |
| --- | --- |
| `auto`（既定） | デザインシステムが選んだもの。既定のシステムでは細い線です。 |
| `divider` | 項目とその下の項目の間に、細い線を 1 本描きます。 |
| `gap` | 余白だけで、線は描きません。 |

最初の行の上、最後の行の下、列と列の間、項目名と値の間には線を描きません。枠で囲んだリストにしたいときは、Outlined の[カード](/ja/components/card/)の中にリストを置きます。

### 推奨

- 項目名はできるだけ短くします。「この注文のお届け先住所」ではなく「お届け先」です。
- 値がないことが情報になる場合は、言葉で書きます。「なし」「未設定」「無制限」などです。
- 変化は言葉で伝えます。「先週より 12% 増」のように、数値の下の 2 つ目の値として書きます。
- 値の中でステータスを示すときは、小さいタグ（`size="small"`）を使います。行が高くなりません。

### 非推奨

- 項目名の後ろにコロンを付けない。句読点は言語ごとに決まるもので、項目名と値はスタイルと位置ですでに見分けられます。
- 空の値にダッシュを入れない。空のままにするか、ないことを言葉で書きます。
- 良し悪しを伝えるために数値に色を付けない。増減は、言葉か、ラベルでそれを伝えるタグで示します。
- 関係のないものを横に並べるためにリストを使わない。それはレイアウトです。

## アクセシビリティ

<ComponentAccessibility name="description-list" />

### コンポーネントが担うこと

- ネイティブのリストは説明リストのままです。どのレイアウトでも、どちらの密度でも、線があってもなくても、項目名とその説明はブラウザー自身のものです。
- 読み上げの順序は変わりません。`stat` のレイアウトは数値をラベルの上に描きますが、支援技術には項目名を先に伝えます。
- リストの中に、フォーカスや入力を受け取るものはありません。値の中のリンクやボタンは、自身のターゲットと、フォーカスの順序での位置を保ちます。
- テキストを 200% にしたときも、幅 320 のウィンドウでも、同じ幅の規則によってリストが縦に並び、列が減ります。最小の幅は、テキストとともに大きくなります。
- 右から左のレイアウトでは、項目名の列が右に置かれ、列は右から埋まります。項目名と値はそれぞれ自身の方向を保つので、バージョン、アドレス、金額の並びが逆になることはありません。
- 強制カラーモードでは、線とテキストがテキストの色になります。リストには、失われる塗りがありません。
- 項目名のない値、`inline` のリストへの `columns`、整数でない列数、`<div>` でまとめていないリストでの `stat` のレイアウトや複数列、未知のレイアウト・密度・区切り方は、デバッグビルドで報告します。

### 利用者側で行うこと

- リストの上に、何についての情報かを伝える見出しを置きます。リスト自身は名前を持たず、項目名が見出しになることもありません。
- すべての値に項目名を付けます。
- 利用者が見ている間に数値が変わり、その変化を読み上げさせる必要があるときは、リストかその項目を、プロダクト側のライブリージョンの中に置きます。リストは変化を読み上げません。
