ワンタイムコード入力欄は、プロダクトがユーザーに送り、1 回だけ入力してもらう短いコードに使います。サインイン、メールアドレスや電話番号の確認、支払いの承認などです。マス目は、コードの長さと、まだ足りない分を示します。

これはコード全体のための 1 つの入力欄で、1 文字ごとの入力欄の集まりではありません。テキストの値は 1 つ、Tab で止まる位置は 1 つ、支援技術にとってのテキストボックスも 1 つで、マス目はその値を描いたものです。そのため、プラットフォームのコードの自動入力が 1 回の操作で入り、貼り付けたコードが丸ごと入り、スクリーンリーダーは名前の付いた 1 つのテキストボックスとして読みます。

これは**上級者向け**のコンポーネントです。自分で組み立てるプロダクトのための、コントロールだけの部品で、ラベル、補足、エラーテキストは自分では持ちません。ほとんどのプロダクトに合うのは、この入力欄をフィールドに入れてそのまま使える形にした[ワンタイムコードフィールド](/ja/components/one-time-code-field/)です。

**使われている場所**は、[ワンタイムコードフィールド](/ja/components/one-time-code-field/)です。自分で組み立てるときは、[フィールド](/ja/components/field/)の中に入れます。フィールドが名前と説明を与え、必須であることを伝え、エラーの状態にします。このページの例はその書き方で、ワンタイムコードフィールドの 1 つ下の階層にあたります。見えるラベルがほかの場所にあるとき（ダイアログの見出しなど）は、単独で使って `label` を指定します。`label` が描かれることはありません。

Web では `<tanrei-one-time-code-input>` です。ほかのプラットフォームはまだ実装していません。

### 使い方

`value` は、そこまでに入力されたコードです。最大で `length` 文字の、数字か、`alphanumeric` では数字と大文字の英字で、グループをどう描いていても区切りは含みません。

### マス目

| パーツ | 内容 |
| --- | --- |
| マス | コードの 1 文字につき 1 つのボックス。空か、1 文字を持ちます。空のマスと埋まったマスは同じボックスです |
| 文字 | 埋まったマスの文字。テキストフィールドの入力のテキストスタイルで、等幅の数字で描きます。`mask` を付けると、パスワードの入力欄が描く印に置き換わります |
| アクティブなマス | 入力欄にフォーカスがある間、次の文字が入るマス。最初の空のマスか、すべて埋まっていれば最後のマスです。縁の内側にフォーカスの線を描きます。これが入力欄のフォーカスインジケーターで、入力位置の目印でもあります |
| キャレット | 空のアクティブなマスに描きます。埋まったアクティブなマスには描きません。次の文字は、そのマスの文字を置き換えるためです |
| グループの印 | `groupSize` を指定したとき、決まった数のマスごとに入る短い線。描くだけのもので、値にも、コピーされるものにも、フォームが送信するものにも含まれません |

マスの高さは medium のテキストフィールドと同じなので、1 つのフォームの中でワンタイムコード入力欄とテキストフィールドの高さがそろいます。サイズも見た目も 1 つだけです。マスの高さ、角、塗りは、デザインシステムがレイヤーで決めます。

マスの並びは先頭側の端から始まり、幅はマスに必要な分だけです。2 グループの 6 マスは、既定のシステムで幅 284 になり、幅 320 の画面に収まります。場所が足りないときは、マスが幅を分け合って細くなります。細くなるのは、1 文字とその両側の小さなパディングの幅までです。それでも足りなければ並びを折り返します。まずグループの間で折り返し（折り返した位置の印は描きません）、グループがないときはマスの間で折り返します。マスが切れることはなく、収めるためにコードを小さく描くこともありません。

### 入力と読み取り

| いつ | 起きること |
| --- | --- |
| 入力できる文字を打つ | アクティブなマスに入り、そのマスの文字を置き換えて、次のマスがアクティブになります。最後のマスではアクティブなマスは動かないので、続けて打った文字は最後の文字を置き換えます |
| それ以外の文字を打つ | 何も起きません。マスが持てるのは、コードに使える文字だけです |
| Backspace | 埋まったアクティブなマスはその文字を、空のアクティブなマスは 1 つ前の文字を失います。後ろの文字は前に詰まり、値に空きはできません |
| 左右の矢印キー、Home、End | 埋まったマスと最初の空のマスの間で、アクティブなマスを動かします。上下の矢印キーは何もしません |
| すべて選択してから文字を打つ | コード全体を置き換えます。一部のマスだけを選ぶことはできません |
| 貼り付け、ドロップ、自動入力、音声入力 | アクティブなマスがどこにあっても、テキスト全体を 1 つのコードとして読みます |

入力や貼り付けは、寛容に読みます。ほかの文字体系の数字や、全角の数字と英字は ASCII の文字として、小文字は大文字として読みます。値は常に ASCII なので、送ったコードとそのまま比べられます。

貼り付けたテキストからは、空白、ハイフン、ダッシュを取り除きます。`123 456` も `123-456` も `123456` になります。数字のコードでは、長いテキストの中から、ちょうど `length` 桁の数字の並びが 1 つだけあるときにそれを探し出すので、「確認コードは 123456 です。」のようなメッセージを丸ごと貼り付けられます。どれがコードか決まらないときは、何も変えません。

入力メソッドがまだ確定していないテキストは、下線付きでマスに描きます。確定するまで、値は変わりません。

### イベント

| イベント | いつ |
| --- | --- |
| `input` | ユーザーが値を変えるたび。新しい値を伝えます |
| `complete` | ユーザーによる変更で、値が `length` 文字になったとき。その変更の `input` の後に、1 回だけ |
| `change` | フォーカスが離れたとき、または Enter が押されたときに、値が最後に確定した値と違っている場合 |
| `action` | Enter。Web のフォームの中では、続けて、通常のテキスト入力と同じようにフォームが送信されます |

プロダクトが `value` を設定したときは、どれも発火しません。また、コードがそろっても、ほかには何も起きません。入力欄が送信することも、フォーカスを動かすことも、自身を無効にすることも、何かを読み上げることもありません。そろったコードをどう扱うかは、プロダクトが決めます。

### Web での描き方の違い

- 要素はフォームに関連付けられます。`name` を受け取り、コードだけを、またはコードがなければ空文字列を送信します。リセットすると `value` 属性の値に戻り、フィールドが必須としていて値が空の間は、値がないことを報告します。`length` より短いコードについては何も報告しません。入力途中のコードを受け付けないかどうかは、利用者側で決めます。
- シャドウルートにある `<input>` は 1 つだけです。`autocomplete="one-time-code"` と `inputmode="numeric"`（`alphanumeric` では、大文字にする `text`）を持ち、`mask` を付けるとパスワードの入力欄になります。`maxlength` と `pattern` はありません。あると、空白を含めて貼り付けたコードを、読む前にブラウザーが切ってしまうためです。
- `input`、`change`、`complete`、`action` は、`detail.value` を持つ CustomEvent です。`action` をキャンセルすると、フォームは送信されません。
- `readOnly` の属性は `readonly`、`groupSize` の属性は `group-size` です。
- キャレットは、要素が自分で描いたものです。入力メソッドが変換候補のウィンドウを出すとき、ブラウザーはそれを、アクティブなマスではなく、ネイティブの入力欄のテキストの位置（並びの先頭）に置きます。
- 要素がユーザーのメッセージを読むことはありません。プロダクトが、メッセージのコードをブラウザーに求め、`value` に設定することはできます。
- 要素が定義されるまでは、大きさがありません。マスの高さを確保してください。スクリプトなしで動く必要があるページでは、素の `<input autocomplete="one-time-code" inputmode="numeric">` を使います。この要素は、それを描いたものです。

## ガイドライン

### ワンタイムコード入力欄とテキストフィールド

| 観点 | ワンタイムコード入力欄 | テキストフィールド |
| --- | --- | --- |
| 持つもの | ユーザーに送り、1 回だけ入力してもらう、長さの決まった短いコード | 任意のテキスト |
| 見せるもの | 1 文字ごとのマス。コードの長さと、足りない分 | テキスト |
| 受け取るもの | 数字、または数字と大文字の英字 | すべて |

`autocomplete="one-time-code"` を付けたテキストフィールドでも、コードは正しく入力できます。マス目が要らない場所では、そちらが適しています。パスワード、ユーザーが自分で決めた暗証番号、リカバリーキーやライセンスキー、カード番号、郵便番号は[テキストフィールド](/ja/components/text-field/)です。描くほど短い決まった長さがないか、マス目で見せるべきではないためです。プロダクトが数として読む値は[数値フィールド](/ja/components/number-field/)です。

### 推奨

- ラベル、マス目、補足、エラーがあれば足りるときは、[ワンタイムコードフィールド](/ja/components/one-time-code-field/)を使います。フィールドにこの入力欄を入れて自分で書くのは、ワンタイムコードフィールドにない並べ方が必要なときだけです。
- [フィールド](/ja/components/field/)の中に入れ、何文字のコードか、どこに送ったかを `supportingText` に書きます。
- グループは、メッセージの書き方に合わせて描きます。「123 456」と送るコードには `groupSize="3"` を指定します。
- コードが違うことは、フィールドの `error` と `errorText` を使って言葉で伝えます。違っていたコードを消すかどうかは、利用者側で決めます。1 桁だけ違うことがよくあります。
- そろったコードを確かめている間は、`disabled` ではなく `readOnly` を使います。無効にするとフォーカスが外れ、コードを直すことになったユーザーが位置を見失います。
- 新しいコードを求める手段と、時間の制限があればその説明を、入力欄の近くに置きます。これらはプロダクト側のボタンとテキストです。
- `complete` で確認や送信をする場合は、入力欄の前でそれを伝えます。

### 非推奨

- 1 文字ごとの入力欄を並べてコードの入力を作らない。スクリーンリーダーには名前のないテキストボックスが並び、自動入力も貼り付けもできません。
- 貼り付けを禁じない。`mask` を付けていても同じです。目で写すしかないコードは、記憶力の試験になります。
- ユーザーに先に伝えずに、フォーカスを動かしたり、フォームを送信したりしない。
- 習慣で `mask` を付けない。1 回しか使えず期限のあるコードを隠す必要はほとんどなく、隠すと間違いに気づきにくくなります。
- フィールドの中で `label` を使わない。コントロールの名前はフィールドが与えます。

## アクセシビリティ

<ComponentAccessibility name="one-time-code-input" />

### コンポーネントが担うこと

- 1 つのテキストボックスです。名前は、囲んでいるフィールドのラベルか、フィールドがないときは自身の `label` です。説明は、フィールドが表示している補足テキストまたはエラーテキストです。値は、コード全体を 1 つの文字列にしたものです。
- エラーの間は invalid として、フィールドが必須としている間は必須として、`readOnly` が true の間は読み取り専用として、`mask` が true の間はパスワードの入力欄として伝えます。
- マス、キャレット、グループの印は支援技術から隠し、フォーカスも受け取りません。
- ネイティブの挿入位置は、アクティブなマスにあります。マスが埋まっていれば、その文字の前です。挿入位置の文字を読むスクリーンリーダーは、アクティブとして描かれているマスを読みます。
- マスがいくつあっても、Tab で止まる位置は 1 つです。
- 入力欄自身は何も読み上げません。値の変更も、コードがそろったことも読み上げません。現れたエラーは、囲んでいるフィールドが読み上げます。
- 入力メソッドのテキストを確定または取り消すキーは、アクションのキーとして扱わず、フォームも送信しません。
- 押せる範囲は最小ターゲットを満たします。押すと入力欄にフォーカスが移り、押したマスが埋まっていれば、そのマスがアクティブになります。
- テキストを 200% にすると、マスは文字に合わせて大きくなり、細くなり、折り返します。何も切れず、横にスクロールすることもありません。
- 強制カラーモードでは、すべてのマスに縁が付き、アクティブなマスの縁はハイライトの色になります。エラーを、入力欄自身の色で示すことはありません。
- 右から左のレイアウトでも、マスは左から右に並びます。数字の並びが逆になることはありません。マスの並びは右端に、フィールドのラベルの下に置かれます。
- どの言語でも、自身の言葉は持ちません。

Web での既知の不足：

- コードを入力し、置き換え、貼り付ける間にスクリーンリーダーが何を伝えるかは、ブラウザーのアクセシビリティツリーで確かめたもので、スクリーンリーダーで聞いて確かめてはいません。
- 入力メソッドは、Chromium では実際に動かし、Firefox と Safari ではそのイベントだけで確かめています。
- 要素が定義されるまでは、何も描かれません。

### 利用者側で行うこと

- コントロールに名前を付けます。囲んでいるフィールドのラベルか、見えるラベルがほかの場所にあるときは、それと同じ言葉の `label` です。
- 何を入力するのかを言葉で伝えます。何文字か、どこに送ったかです。マス目で長さが分かるのは、マス目が見えるユーザーだけです。
- コードが違う、期限が切れている、必須である、といったことは、フィールドの `errorText`、`supportingText`、`required` で伝えます。色だけで示してはいけません。
- コードを入力できる時間に制限がある場合は、それを伝え、時間の延長か新しいコードを求められるようにします。
