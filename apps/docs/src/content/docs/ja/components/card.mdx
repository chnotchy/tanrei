カードには 3 つの形があります。ふつうのカードはコンテナで、中身は自分のセマンティクスを保ち、ボタンやリンクを置けます。操作できるカードは 1 つのボタンです。リンクカード（`href` のあるカード）は 1 つのリンクです。押すと別のページやアドレスへ移動するならリンクカードを、その場で何かが起こるなら操作できるカードを使います。

### 使い方

Web と React の例は現在の仕様に沿っています。SwiftUI、Compose、Flutter、React Native は追従待ちで、ふつうのカードと操作できるカードは提供していますが、リンクカードはまだありません。これらの例は、いま提供しているものを示しています。

## ガイドライン

### 使う場面

レポート、人物、商品、設定項目など、1 つの対象についての情報をまとめ、周りから区切りたいときに使います。カードがするのは、中身に余白を取り、角で切り抜き、色を渡すことだけです。中身のレイアウトは、Tanrei のテキストスタイル（カードのタイトルには `heading-5`）やコンポーネントを使って組み立てます。

カードが「中身を開く」という 1 つのアクションなら、カード全体を操作できるようにします。アクションが複数あるなら、カードは操作できないままにして、中にボタンを置きます。

### 移動先のあるカードはリンク

移動先のあるコントロールはリンクです。カードも同じです。押すと別のページへ移動するだけなら、操作できるカードの click で移動させるのではなく、`href` を指定します。カードは本物のリンクになり、Web では中身を包むアンカーになります。新しいタブで開く、アドレスをコピーする、移動する前に行き先を確かめる、といったことができ、支援技術はボタンではなくリンクとして読み上げます。このサイトでページからページへ案内しているカードも、リンクカードです。

- リンクカードの見た目は、どの状態でも操作できるカードとまったく同じです。リンク専用の見た目も、訪問済みの状態もありません。
- `href` は `interactive` より優先されます。両方を指定したカードはリンクです。
- リンクカードは Enter で移動します。Space では移動しません。Space はふつうのリンクと同じ働きをし、Web ではページをスクロールします。
- 先に `click` が発火し、そのあとで移動先が開きます。クライアントサイドのルーターのように移動を自分で扱うなら、その click をキャンセルします。
- `target` は `same`（既定）か `new` です。新しいタブやウィンドウで開くリンクには `targetLabel` が必要です。名前のあとに読まれる言葉で、「新しいタブで開きます」などと書きます。Tanrei はこの文言を用意していません。中身は利用者側のものなので、カードは印を描きません。示したい場合は、中身に `open_in_new` のグリフを置きます。
- 無効なリンクカードは、どの方法でも移動できず、フォーカスの順序からも外れます。
- 空白だけの `href` は移動先になりません。`javascript:` のアドレスや、アドレスとして読めない値は受け付けず、デバッグビルドで報告します。カードは `href` がないときと同じになります。

移動先と独自のアクションの両方が必要なカードは、ふつうのカードのままにして、見出しをリンクにするか、`href` を指定した[ボタン](/ja/components/button/)を中に置きます。

### バリアントの選び方

重要度ではなく、置く背景で選びます。

| バリアント | 区切り方 | 用途 |
| --- | --- | --- |
| Outlined（既定） | 輪郭線 | ほとんどのカード。Filled のカードと同じ色調のサーフェスに置くとき。 |
| Filled | 色調 | 無地のサーフェスの上で、色調の違いだけでまとまりを示せるとき。同じ色調のサーフェスに置くと見えなくなります。 |
| Elevated | 奥行き | ピン留めした項目やドラッグできる項目など、ページより手前にあるもの。 |

### 推奨

- 操作できるカードとリンクカードには `label` で名前を付けます。ふつうは見出しのテキストです。
- 一緒に並べるカードは、バリアントをそろえます。
- 端まで広げたい画像には `inset` を false（Web では `flush`）にし、その下のテキストにはカードの余白トークンで自分で余白を取ります。

### 非推奨

- 操作できるカードやリンクカードの中に、ボタン、リンク、入力欄、トグルなど、フォーカスを受ける要素を置かない。支援技術から届かず、押すとカードまで反応します。
- 操作できるカードの click ハンドラーからページを移動しない。移動するカードには `href` を指定します。
- ふつうのカードを無効にしない。無効にするアクションもリンクもないので、`disabled` は無視されます。
- カードの重要度を奥行きで表さない。

## アクセシビリティ

<ComponentAccessibility name="card" />

### コンポーネントが担うこと

- 操作できないカードはロールを持たず、中身のセマンティクスに手を加えません。`label` があれば、それを名前とするグループになります。
- 操作できるカードは、ボタンのロールを持つフォーカス可能な 1 つの要素になり、無効状態も伝えます。名前は `label` です。ない場合は中身全体が 1 つの文字列として読まれ、デバッグビルドで報告されます。
- リンクカードは、リンクのロールを持つフォーカス可能な 1 つの要素になり、名前の決まり方は同じです。`target` が `new` のあいだは、`targetLabel` が説明として、名前とロールのあとに読まれます。無効なリンクカードはリンクのロールのまま無効状態を伝え、移動先を持ちません。
- 操作できるカードは Enter と Space で、リンクカードは Enter だけで実行します。ヒット領域は最小ターゲットを満たし、フォーカスインジケーターはキーボードフォーカスのときだけ表示します。
- 中身に合わせて伸びるので、文字を大きくしても切れません。
- Web では、操作できるカードやリンクカードの中に操作できる要素があると、スロットが変わるたびにデバッグビルドで報告します。新しいタブで開くリンクカードに `targetLabel` がない場合も報告します。

プラットフォームごとの既知の制約：

- SwiftUI、Compose、Flutter、React Native には、まだリンクカードがありません。これらでは、移動するカードも、アクションの中で移動する操作できるカードのままです。
- Web：カードに入れた要素の内側へ、後から操作できる要素を加えた場合は報告されません。
- Web：操作できないカードが自分から click を出すことはありませんが、中身をクリックすると通常の DOM の click が発生し、カードを通ってバブリングします。
- SwiftUI、Compose、Flutter、React Native は、入れ子になった操作できる要素を検出できないため、確認しません。このルールは利用者側で守ってください。
- React Native では、`label` のある操作できないカードは group のロールになりますが、iOS はこのロールをどのトレイトにも対応付けません。VoiceOver がグループの名前を読み上げるかは、実機でまだ確かめていません。
- Compose：プラットフォームのキー処理を通した Enter と Space での実行は Robolectric 上でしか確かめておらず、実機ではまだ試していません。
- React Native には文字色の継承がありません。文字列はカードがコンテンツ色で描きますが、自前のテキストは `useContentColor()` で色を読み取ります。
- SwiftUI：最小ターゲットより小さい操作できるカードは、見た目の大きさはそのままで、レイアウト上はターゲットの大きさを占めます。

### 利用者側で行うこと

- 操作できるカードとリンクカードには `label` を付けます。付けないと、中身全体が長い 1 つの名前として読まれます。
- 新しいタブやウィンドウで開くリンクカードには、プロダクトの言語で `targetLabel` を付けます。
- 操作できるカードとリンクカードに、ほかのコントロールを入れないでください。ボタンやリンクが必要なカードはふつうのカードにして、そのうちの 1 つを主なアクションや移動先にします。
- 操作できないカードの中身には、代替テキストや見出しレベルなど、それぞれにセマンティクスを付けます。カードは何も補いません。
