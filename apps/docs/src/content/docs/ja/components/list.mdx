### 使い方

リストの項目の種類は `list-item` の 1 つだけです。項目の渡し方は、各プラットフォームで繰り返しの子要素を渡すときの流儀に従います。Web では子要素、SwiftUI ではビュービルダーの中のビュー、Compose ではコンテンツラムダの中の呼び出し、Flutter では `children` のウィジェットです。React Native だけは、プレーンなオブジェクトの配列を `items` に渡します。選択状態はリストが持ちます。1 つを選ぶリストでは `value` が、複数を選ぶリストでは `values` が、選ばれている選択肢を値で指します。

ページへ移る行には `href` を付けます。その行はリンクであり、ボタンではありません。見た目は操作できる行とまったく同じで、ブラウザーはほかのリンクと同じように扱います。新しいタブで開け、アドレスをコピーでき、クローラーもたどれます。`target` に `new` を指定すると新しいタブで開き、行にアイコンセットの `open_in_new` を描きます。このとき、行の名前の後に `targetLabel` を読み上げます。リンクの行は、今のところ Web で使えます。SwiftUI、Compose、Flutter、React Native は追従待ちで、これらの例は行き先のない行を示しています。

`reorder` に `buttons` を指定すると、項目の順番を並べ替えられるようになります。どの行にも 2 つのアイコンボタンを描きます。1 つは行を 1 つ上へ、もう 1 つは 1 つ下へ移します。どちらも Tanrei のボタンなので、キーボード、ポインター、タッチ、スイッチ、音声コントロール、スクリーンリーダーのどれでも同じように使え、ドラッグは要りません。

順番は利用者側のデータなので、リストが順番を変えることはありません。ボタンを押すと `move` が発生し、`from` に項目のインデックス、`to` に移動後のインデックスが入ります。どちらも 0 から数えます。これを受けて、利用者側で項目を並べ替えます。するとリストは、2 つの行が入れ替わる様子を描き、動かした行の同じボタンにフォーカスを保ち、行が今どこにあるかを支援技術に伝えます。何も変えなければ、何も起きません。プロダクトが移動を断るときは、そうします。

並べ替えは `comp.list.motion.reorder-duration` の時間内に行います。それより遅れて届いた順番も描きますが、リストはすでに移動が断られたものとして扱っているので、読み上げはしません。

3 つの文言は利用者側で用意します。`moveUpLabel` と `moveDownLabel` はボタンの名前で、リストが行の見出しを入れる場所 `{headline}` を持ちます（「`{headline}を上へ移動`」）。`movedText` は移動の後に読み上げる文です。文全体をプロダクトの言語で書き、リストが埋める 3 つの場所に印を付けます。`{headline}`、`{position}`（1 から数えます）、`{count}` です。文言はリストに付けるか、`setWords()` でプロダクト全体に一度だけ渡します。

並べ替えられるリストに入るのは静的な行だけで、リストボックスにはなりません。行の末尾のスロットには、移動ボタンの後に、自前のコントロールを 1 つ置けます。多くの場合、項目を削除するボタンです。

`reorder` の `drag` は、ポインターや指でドラッグするハンドルを加える値で、仕様にはありますが、まだ実装されていません。Web では 2 つのボタンを描き、ハンドルは描きません。並べ替えは現在 Web で使えます。SwiftUI、Compose、Flutter、React Native は、まだ追いついていません。

## ガイドライン

### 使う場面

メッセージ、人、ファイル、設定項目、ピッカーの選択肢など、同じ種類のものを縦に並べるときに使います。どの行も同じ種類の要素で始まり、同じ種類の値で終わるので、上から下へ目で追えます。1 つのものについて多くを伝えるならカード、列をまたいで値を比べるなら表、ボタンから開く短いアクションの一覧ならメニューを使います。

リストは自分では何も描きません。背景も、項目の周りの余白も、スクロールもありません。サーフェスの上に置くか、カードに入れるか（iOS の設定画面のようなグループ化されたリストは、`inset` をオフにしたカードに入れます）、画面のスクロールビューの中に置きます。

### 4 種類の行

行はいつも `list-item` です。どの種類の行になるかは、リストの `selection` と、項目の `interactive` と `href` で決まります。

| 種類 | 条件 | 何か | 用途 |
| --- | --- | --- | --- |
| 静的 | `selection` が none で、`interactive` が false | 内容を見せるリスト項目。フォーカスを受けず、ホバーや押下にも反応しません。 | 読むだけの行や、スイッチなどのコントロールを末尾のスロットに持つ行。 |
| 操作できる行 | `interactive` が true | リスト項目の中にある 1 つのボタン。見出しが名前になります。 | 設定、ペインに開くメッセージ、ダイアログなど、行ごとに何かを変える場合や、その場で開く場合。 |
| リンクの行 | `href` を指定 | リスト項目の中にある 1 つのリンク。見出しが名前になり、操作できる行とまったく同じように描きます。Enter で実行し、Space では実行しません。`href` は `interactive` より優先されます。 | ページの索引、検索結果、関連する文書など、行ごとに自分のアドレスを持つページへ移る場合。 |
| 選択肢 | `selection` が single か multiple | リストボックスの選択肢。選択状態を持ちます。 | テーマ、言語、課題のラベルなど、行の中から選ぶ場合。 |

1 つのリストに、静的な行、操作できる行、リンクの行を混ぜられます。選べるリストに入るのは選択肢だけで、`interactive` と `href` は無視されます。並べ替えられるリストに入るのは静的な行だけで、ここでも `interactive` と `href` は無視されます。行そのものが 1 つのボタンや 1 つのリンクだと、その行を動かすボタンを中に持てないからです。

### 並べ替えられるリスト

- `reorder` は、順番に意味があり、その順番を使う人が決める短いリストに使います。フォントスタックのファミリー、ホーム画面のセクション、キューなどです。長いリストには、並べ替えの代わりにソートの手段を用意します。1 回押すと、行は 1 つ分だけ動きます。
- 項目の並べ替えは、`move` のハンドラーの中か、その後フレームワークが描画し次第すぐに行います。今ある要素を動かしても、新しい要素を描画してもかまいません。リストは、動かした行を位置と見出しで見つけます。
- 移動ボタンの文言には、行の見出しの場所を入れます（「`{headline}を上へ移動`」「`{headline}を下へ移動`」）。見出しがそれぞれのボタンの名前に入るので、ページのボタンの一覧でも音声での操作でも、行ごとのボタンを区別できます。
- `movedText` は、3 つの場所を含む 1 つの完結した文として書きます。リストは自分で語句を組み立てないので、語順はプロダクトの言語のものになります。
- 末尾のスロットに置くコントロールは 1 つまでにし、名前には項目を入れます（「Inter を削除」）。2 つの行の削除ボタンを聞き分けられるようにするためです。
- リストが読み上げるのは移動だけです。項目を削除したり追加したりしたときに何を伝えるかは、利用者側で決めます。最後の項目を削除したときは、項目を追加する場所へ、利用者側でフォーカスを移します。
- 行には幅の余裕を持たせます。移動ボタンと末尾のコントロールを並べるとテキストが行の半分より狭くなる場合、リストはすべての行で、これらをテキストの下の独立した行に置きます。既定のシステムでは、削除ボタンがあり、アイコンもアバターも画像もない行は、行の幅がおよそ 400 px を下回るとこの配置になります。

### 選択の種類

| `selection` | リストの役割 | 選択肢を選ぶと |
| --- | --- | --- |
| None（既定） | リスト | 何も選ばれません。操作できる行は、それぞれ自分のクリックを発火します。 |
| Single | リストボックス | その選択肢が選ばれ、それまで選ばれていたものは外れます。ラジオボタンと同じく、選ばれている選択肢をもう一度選んでも外れません。「なし」も答えになるなら、そのための選択肢を加えます。 |
| Multiple | 複数選択のリストボックス | その選択肢のオンとオフを切り替えます。 |

矢印キーはフォーカスを動かすだけです。選択が変わるのは、Space か Enter を押すか、行をタップしたときです。これは意図した動きです。リストでは行を選ぶと重い処理が始まることがあり、50 行を矢印キーで通り過ぎるたびに 50 回読み込みが走っては困ります。

選ばれた選択肢は、選択時の塗りと、末尾のチェックで示します。チェックの場所はどの選択肢でも空けておくので、テキストの位置がそろいます。状態を示すのに必要な 3:1 のコントラストを満たすのはチェックのほうで、塗りだけでは満たしません。

### 行と構成要素

- 見出しだけなら 1 行の行、オーバーラインか 1 行の補足テキストが加われば 2 行の行、補足テキストが 2 行以上なら 3 行の行になります。内容や文字の拡大に合わせて、これらの高さより伸びます。
- `supportingMaxLines` を指定すると、長い補足テキストを省略記号で切ります。プレビューの列に向いています。切っても、支援技術には全文が伝わります。
- 行の先頭には、先頭アイコンか、先頭メディアを置きます。メディアは、人を表すアバター（丸い枠）か、ものを表す画像（ひと回り大きい角丸の四角）です。メディアを置くとアイコンは描かれません。
- 行の末尾には、短いテキスト（件数、時刻）、末尾アイコン（何かを開く行ならシェブロン）、静的な行なら自前のコントロールを置きます。`target` の値が `new` のリンクの行は、ほかのアイコンを指定していなければ、自分で末尾アイコンとして `open_in_new` を描きます。
- アイコンは、デザインシステムのアイコンセットにあるグリフの名前（`wifi`、`chevron_right`）で指定します。行に沿った向きを示すグリフは、右から左のレイアウトでは反転します。
- `divider` は、テキストの開始位置から行の下に細い線を引きます。色は、すべてのコンポーネントが使う 1 つの細い線の色です。最後の行以外すべてに付けるか、まとまりの区切りに付けます。行の間に、自前の[区切り線](/ja/components/divider/)を足すことはありません。

### 推奨

- 見出しは短くし、詳しいことは補足テキストに書きます。見出しがその行の名前です。
- 選べるリストには、何を選ぶのかが分かる `label` を付けます。「テーマ」などです。
- 設定を切り替える行は、末尾のスロットにスイッチを持つ静的な行にします。スイッチの名前は見出しと同じにし、見えるラベルは隠します。
- セクションに分けたいときは、2 つのリストの間に見出しを置きます。リスト自体にはセクション見出しの機能がありません。
- ページへ移る行には `href` を付け、`interactive` はその場で何かをする行に使います。クリックのハンドラーから遷移する行はリンクではありません。新しいタブで開けず、アドレスもコピーできません。

### 非推奨

- 操作できる行、リンクの行、選択肢の中に、ボタン、リンク、スイッチなどのコントロールを入れない。行は 1 つの要素なので支援技術は中のコントロールに届かず、コントロールを押すと行も反応してしまいます。
- その場で何かを実行するものを選択肢にしない。リストボックスは値を選ぶものです。アクションには操作できる行を使います。
- 静的な行を無効にしない。無効にするアクションがないので、`disabled` は無視されます。
- 選択を示すために行の中にチェックボックスやラジオボタンを描かない。`selection` を使えば、チェックが描かれ、状態も支援技術に伝わります。

### コンポーネントが担うこと

- 選択のないリストはリストとして、各行はリスト項目として、位置とリスト全体の件数とともに伝えます。操作できる行は、リスト項目の中の 1 つのボタンで、リンクの行は、そこにある 1 つのリンクです。
- リンクの行は、操作できる行と同じく、リストの矢印キーの順番に入ります。Enter でリンクをたどります。Space は、ほかのリンクの上と同じ働きをし、押下の状態は表示しません。新しいタブで開く行は、名前と説明の後に `targetLabel` を読み上げます。無効なリンクの行には、たどるものもコピーするものもありませんが、矢印キーでは届きます。
- 選べるリストは、`label` を名前とするリストボックスとして伝えます。`selection` が multiple のときは複数選択できることも伝えます。各行は、選択状態、位置、件数を持つ選択肢です。
- 操作できる行、リンクの行、選択肢は、見出しを名前とし、オーバーライン、補足テキスト、末尾のテキストを、この読み順で説明として伝えます。アイコン、チェック、区切り線、先頭メディアは支援技術から隠します。
- 操作できる行か選択肢を含むリストは、Tab で止まる位置が 1 つです。最後にフォーカスがあった行、なければ最初に選ばれている選択肢、それもなければ最初の有効な行に止まります。上下の矢印キーで行の間を移動し、端で折り返しません。Home と End で最初と最後の行へ、文字を打つと見出しがその文字で始まる次の行へ移ります。Space と Enter で実行します。静的な行はフォーカスを受けませんが、静的な行の中のコントロールは自分の Tab で止まる位置を持ったままです。
- 並べ替えられるリストでは、移動ボタンはそれぞれ、`moveUpLabel` か `moveDownLabel` を名前とし、その場所 `{headline}` に行の見出しが入るボタンです。どのボタンも、読み順のとおりに、行の末尾のコントロールより前で、自分の Tab で止まる位置を持ちます。このときリストは Tab で止まる位置が 1 つではなく、矢印キーは何もしません。最初の行の上へ移動するボタンと、最後の行の下へ移動するボタンは無効になりますが、描いたままにします。どの行にも同じ部品が同じ場所に並びます。
- 移動の後、フォーカスは動かした行の同じボタンに残るので、もう一度キーを押せば、行はもう一度動きます。行が最初か最後になったときは、その行のもう一方の移動ボタンへフォーカスが移ります。
- 並べ替えられるリストは、読み上げ中の内容に割り込まないライブリージョンを 1 つ持ちます。移動の後、そこに `movedText` が、行の見出し、新しい位置、行の件数を埋めた形で入ります。次の移動があると、内容は置き換わります。数字は、リストの言語の書き方で書きます。移動を読み上げるものは、ほかにありません。
- 2 つの行は短い動きで入れ替わります。動きを減らす設定では、すぐに入れ替わります。
- フォーカスのある行を利用者側で削除すると、フォーカスは、その場所に来た行の同じコントロールへ移ります。そこに行がなければ、1 つ前の行の同じコントロールへ移ります。
- コントロールがテキストを圧迫する幅では、コントロールはテキストの下の独立した行へ移ります。どのコントロールも、ターゲットより小さくなることはありません。
- 無効な行にも矢印キーで届くので、そこに行があることは分かります。実行はできません。
- フォーカスリングは行の内側に描くので、リストを囲むスクロールビューに切られません。キーボードフォーカスのときだけ表示します。
- 操作できる行と選択肢の高さは最小ターゲット以上で、行全体がヒット領域です。行同士のヒット領域は重なりません。
- 文字を大きくすると行は伸びます。見出しは折り返し、切れることはありません。
- 見出しのない行、ラベルのない選べるリスト、値が空または重複している選択肢、どの選択肢も指していない選択値、`href` を持つ選択肢、`javascript:` のアドレスや読み取れない `href`、定義にない `target`、`target` の値が `new` なのに `targetLabel` のないリンクの行は、デバッグビルドで報告します。並べ替えられるリストについては、誰も渡していない移動の文言（文言ごとに 1 回）、`movedText` の中の波かっこで囲まれたテキストのうち 3 つの場所のどれでもないもの、`interactive` や `href` を持つ行、選べるリストに指定した `reorder` を報告します。

プラットフォームごとの既知の制約：

- すべてのプラットフォーム（既定のシステム）：選ばれた選択肢の塗りは、ライトテーマではホバーした行の塗りに近く、ダークテーマでは浮き上がったサーフェスの上でかすかにしか見えません。選択を示しているのはチェックです。
- Web：`reorder` の `drag` は実装されていません。2 つの移動ボタンを描き、ハンドルは描かず、ドラッグはできません。
- SwiftUI、Compose、Flutter、React Native には、まだ並べ替えられるリストがありません。`reorder` も、`move` も、3 つの文言もありません。
- SwiftUI、Compose、Flutter、React Native には、まだリンクの行がありません。`href`、`target`、`targetLabel` はありません。
- SwiftUI には、リストやリストボックスのロールも、複数選択のプロパティもありません。リストは `label` を名前とするコンテナで、操作できる行と選択肢はボタンです（選択肢は選ばれている間、選択済みのトレイトを持ちます）。それぞれ位置を値（「2 of 3」）として持ちますが、英語でしか読み上げられません。
- SwiftUI は無効なボタンにキーボードフォーカスを渡さないため、矢印キーは無効な行に止まらず、飛ばして進みます。
- SwiftUI は先頭メディアを常に支援技術から隠すため、名前を付けた写真も読み上げられません。
- SwiftUI は、選択肢の値を、ほかのモディファイアーより先に `TanreiListItem` そのものに付けた `.tag(_:)` からしか読めません。別のビューに付けたタグは届きません。
- SwiftUI：矢印キー、Home、End、先頭文字での移動、Tab で止まる位置は、規則としてテストしているだけで、実際のキーボードではまだ確かめていません。
- React Native にはリストボックスのロールも、複数選択のプロパティもありません。選べるリストもロールはリストのままで、各選択肢が選択肢のロールと選択状態を持ちます。リスト自体を VoiceOver と TalkBack がどう読み上げるかは、プラットフォームしだいです。
- React Native には、集合の中の位置を表すプロパティがありません。操作できる行と選択肢は、位置を値のテキスト（「2 of 3」）として持ちます。静的な行はそれ自体が要素ではないため、位置は読み上げられません。位置のテキストは、`positionText` を渡さない限り英語です。
- React Native：矢印キー、Home、End、先頭文字での移動はキーイベントで受け取っていますが、ハードウェアキーボードをつないだ実機ではまだ確かめていません。
- Flutter には、リストボックスや選択肢のロールも、複数選択のフラグも、位置と件数のプロパティもありません。選べるリストは、選択できるリスト項目を並べたリストとして伝わります。
- Flutter は先頭メディアを常に支援技術から隠すため、名前を付けた写真も読み上げられません。
- Compose には、リスト、リストボックス、選択肢のロールも、複数選択のフラグもありません。リストはコレクションとして伝わり、TalkBack は各選択肢が選ばれているかどうかを読み上げます。
- Compose：リストの中に `LazyColumn` を置くと、位置、件数、矢印キーの対象になるのは、コンポーズ済みの行だけです。
- Compose も先頭メディアを常に支援技術から隠すため、名前を付けた写真は読み上げられません。
- Compose：フォーカスの要求を受け付けるのは、リストの Tab で止まる位置になっている行だけです。コードやユーザー補助サービスがほかの行にフォーカスを移そうとしても、何も起きません。
- Compose：プラットフォーム本来のキー処理を通したキーボード操作と、リストボックスでの TalkBack は、Robolectric でしか確かめておらず、実機ではまだです。
- SwiftUI、Compose、Flutter、React Native は行のスロットの中身を調べられないため、操作できる行や選択肢の中にコントロールがあっても報告しません。このルールは利用者側で守ってください。

### 利用者側で行うこと

- 選べるリストには `label` を付けます。付けないと、リストボックスに名前がありません。
- 行どうしを見分けられる見出しを書きます。スクリーンリーダーが最初に読むのも、先頭文字での移動が照らし合わせるのも見出しです。
- `target` の値が `new` のリンクの行には、「新しいタブで開きます」のように、プロダクトの言語で `targetLabel` を付けます。Tanrei は言葉を同梱しません。
- 並べ替えられるリストには、3 つの文言をプロダクトの言語で付けます。`moveUpLabel`、`moveDownLabel`、`movedText` です。最初の 2 つがないと、ボタンは動きますが名前がありません。3 つ目がないと、移動は読み上げられません。
- `move` が発生したら、項目を並べ替えます。リストは何も変えていません。並べ替えの動きの時間より後に渡した順番は描きますが、読み上げはしません。
- 削除や追加は利用者側で伝え、最後の項目を削除したときは、利用者側でフォーカスを移します。
- 操作できる行、リンクの行、選択肢にはコントロールを入れません。自前のコントロールが必要な行は静的な行にして、末尾のスロットに置き、コントロールの名前を見出しと同じにします。
- アバターや画像に見出しにない意味があるなら、それを補足テキストに書きます。メディアは名前を付けない限り支援技術から隠され、SwiftUI、Compose、Flutter では名前を付けても読み上げられません。
- 件数の多いデータは、各プラットフォームの遅延リストで自分で組み、必要なら件数を伝えます。リストはスクロールも仮想化もしません。
- React Native では、プロダクトの言語で `positionText` を渡します。SwiftUI では位置は英語で読み上げられ、今のところ変える方法はありません。
