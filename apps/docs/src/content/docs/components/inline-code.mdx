Inline code names a thing from code inside a sentence: a command, a prop, a file, a value. Lines of code to read and copy are a [Code block](../code-block/). Keys to press are a [Keyboard shortcut](../keyboard-shortcut/), which reads the modifier names aloud.

### Usage

On the web, inline code is a class on your own `code` element, not an element. The text is in the document, so search, find-in-page and copy work before any script runs. Every `code` inside `.tanrei-prose` that is not in a `pre` is drawn the same way without the class, so rendered Markdown needs nothing.

SwiftUI, Compose, Flutter and React Native are planned: the names beside each platform at the top of this page are the ones the spec gives them, and nothing ships there yet.

Inline code has no size of its own. Its font size is the size of the text it sits in, multiplied by one ratio (`comp.inline-code.label.scale`), which evens out the code face and the text face. In body text that is 13 beside 14. In a heading it is the heading's own size.

It never makes its line taller. The fill is as tall as the code face's own text box and has no padding above or below.

A run wraps with its line. It breaks at its spaces first. A part with no space that is longer than the line breaks between characters, and no hyphen is added, because a hyphen would change the code. It is never cut and never scrolls.

Inside a link it takes the link's color and the link's underline runs under it. Inside strong text it is one weight step heavier. It is never slanted.

It is always laid out left to right, as a run of its own, in a right-to-left sentence too.

### What the web draws differently

- `translate="no"` and `spellcheck="false"` are your attributes, or your Markdown renderer's. A stylesheet cannot set them.
- A hyphen in the code is a place where a line may end, before the run is broken between characters.
- WebKit draws the fill and the corners of every piece of a run that wraps, and not the room at each end: the pieces after the first begin at the fill's edge.
- A line break inside the run is drawn as one space only in browsers that support `white-space-collapse: preserve-spaces`. Write a run on one line.
- An unknown `data-variant` is drawn as `auto`, and nothing is reported in debug builds.

## Guidelines

### Tonal or plain

| Variant | Draws | Use it when |
| --- | --- | --- |
| **Tonal** | The code face on a faint fill | A name in running text |
| **Plain** | The code face alone, in the color of the text around it | A column or a list whose every entry is code, and text on a colored container |

### Do

- Write the sentence so that it reads when the code is spoken as words. Screen readers do not announce the code role by default.
- Use plain on a colored container such as a status container or an inverse surface. The tonal fill is a surface role and is paired with surfaces only.
- Set the form once on the ancestor (`data-tanrei-code="plain"`) for a table or a list of names.

### Don't

- Don't use inline code for emphasis. It says "this is code".
- Don't put keys to press in inline code. Use a Keyboard shortcut.
- Don't put more than a line in it. Use a Code block.

## Accessibility

<ComponentAccessibility name="inline-code" />

### What the component handles

- It is the `code` element, so it has the code role, and its text is read where it sits in the sentence.
- It is told from the words around it by its face, not by color. In forced colors the fill goes and nothing is lost.
- It takes no focus and no input. Inside a link or a button, a press over it reaches that element.
- A long name breaks instead of scrolling the page, at any text size.
- Selecting and copying a sentence copies the code's characters exactly.

### What you need to do

- Write a name out in the sentence where its spelling matters, because symbols are read as the person's settings say.
- Mark the run `translate="no"` so that a browser's translation leaves it alone.
