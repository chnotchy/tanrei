A tree view shows a structure a person looks through or chooses in: the files of a project, the tokens of a design system, the folders of a product. A row that holds others has a chevron and opens and closes. With `selection` one item or several are chosen, and the tree tells you which.

It is not navigation. The places of a product are a navigation drawer, the headings of a page are a table of contents, and folded content is an accordion. Those keep links and buttons, each its own stop in the focus order. A tree is one stop, moved through with the arrow keys, because it may hold thousands of rows.

On the web it is `<tanrei-tree-view>` around your own nested lists. The lists stay in the document, so where no script runs the page shows the whole hierarchy as a nested list. The other platforms have not implemented it yet.

`@tanrei/web/tree-view.css` draws the tree before any script runs, and nothing moves when the script loads. The chevron is a glyph of the icon set and needs the icon font.

### What you write

| Part | On the web |
| --- | --- |
| The tree's name | The `label` attribute, in your product's language. |
| An item | An `<li>`. Its first child element is its row: a `<span>` or a `<div>`. |
| The label | The row's text, in one element: `<bdi>`. It may hold inline content such as a code span. |
| The supporting text | An element with `data-supporting-text`, inside the label's element, after the label. |
| The icon | A `.tanrei-icon` in the row, holding the glyph's name. The tree has no glyph of its own for a folder or a file. |
| The open icon | `data-open-icon` on a parent's `.tanrei-icon`: the glyph drawn while it is open, such as `folder_open` beside `folder`. |
| The trailing content | An element with `data-trailing` in the row: a tag, a swatch. It is placed and not styled. |
| The trailing text | An element with `data-trailing-text` in the row: a count, a size, a value. One line. |
| An item's own items | A `<ul>` after the row, inside the same `<li>`. |

A row may also hold its label as plain text, with no `<bdi>` around it. Use the `<bdi>` where the row has a supporting text, and where a name's direction can differ from the page's, such as a file name on an Arabic page.

| On the `<li>` | Meaning |
| --- | --- |
| `data-value` | What identifies the item. Without one it cannot be chosen. Unique within the tree. |
| `data-open` | A parent shows its items. The tree sets and removes it when the user opens or closes the parent. |
| `data-expandable` | The item will hold items you have not given yet. It gets a chevron; give its items when `toggle` says it opened. |
| `data-loading` | You are fetching its items. While it is open a loading row is drawn under it, with the tree's `loading-label`. |
| `data-disabled` | It cannot be chosen, opened or closed by the user. The arrow keys still reach it. |
| `data-supporting-position` | `inline` puts its supporting text after its label, on its line. Without it the note stands below the label. |

| Event | When | `detail` |
| --- | --- | --- |
| `change` | The user changed the selection. On the tree. | `value` (single) or `values` (multiple), after the change |
| `toggle` | The user, or the browser's find-in-page, opened or closed a parent. On the `<li>`; it bubbles. | `open` |
| `rename` | The user gave an item a new name in place. On the `<li>`; it bubbles. | `label` (the new name, trimmed) and `previous` |
| `create` | The user named the new item `create()` asked for. On the tree. | `label`, `parent`, `within` and `after` (the `<li>` it goes under and follows, or `null`) |

None of these fires for a change you make yourself.

| Method | What it does |
| --- | --- |
| `edit(li)` | Opens the field on an item's name, as F2 does. Only while the tree is `editable`. |
| `create({ parent, icon })` | Adds a new row beside the selected item, with an empty field to name it in. Returns whether it did. |

## Guidelines

### Is it a tree view

| You have | Use |
| --- | --- |
| A structure to look through or choose in | Tree view |
| The places of a product, as links | Navigation drawer |
| The headings of one page | Table of contents |
| Content folded under a few headers | Accordion |
| Items of one level | List |

### What a press does

| The item | A press on its row | A press on its chevron |
| --- | --- | --- |
| Can be chosen, a parent | Chooses it | Opens or closes it |
| Can be chosen, a leaf | Chooses it | — |
| Cannot be chosen, a parent | Opens or closes it | Opens or closes it |
| Cannot be chosen, a leaf | Nothing | — |

One press never does two things. A person who chooses a folder does not lose their place because it also closed.

An item can be chosen when `selection` is `single` or `multiple`, it has a `data-value` and it is not disabled. In a single selection, pressing the chosen item again changes nothing. In a multiple selection each item is chosen by itself: choosing a parent does not choose what it holds.

What a choice does is yours. Answer `change` to show the chosen file or the chosen token's editor in a pane beside the tree. A row holds no control: put the action beside the tree.

### Selection and parents that are closed

The tree draws the selected fill on the item's own row. It does not mark a parent because an item under it is selected, and it does not open a closed parent to show a selection. If the chosen item should be in view, set `data-open` on the parents above it: you know the path.

### Density

| `density` | A row of one line | Use for |
| --- | --- | --- |
| `regular` (default) | 48 | A product used by touch as well as by pointer. |
| `compact` | 32 | A tool looked through with a pointer, and a small tree inside a page of text. |

A compact row is lower than the pointer target. That is accepted because it is asked for by name and is never the default. For touch a row is the touch target high in both densities.

| `none` | Nowhere | Folders that show their state by their own glyph. |

With `chevron="none"`, a parent whose icon names an open glyph (`data-open-icon="folder_open"`) shows open and closed by its glyph, and a press on the glyph opens and closes it. A parent without an icon opens by a press on its row, unless its row chooses: then selection wins, and the arrow keys open it. The arrow keys always open and close.

`expandable="false"` turns opening and closing off: every parent is shown open, with no chevron and no toggle, and no row says that it is expanded or collapsed. Use it for a structure that is always shown whole.

### Guides

`guides="shown"` (or the bare attribute) draws a hairline down from each open parent beside the rows it holds. `guides="hover"` draws them only while the pointer is over the tree or focus is in it. Use them in a deep tree, where the indent alone no longer shows which rows belong together. A line stands under the parent's first leading thing: the chevron at the start, else its icon, else the start of its label. It takes no space, and no line is drawn while the indent is 0.

### Indent

| `indent` | Where a child begins |
| --- | --- |
| `auto` (default) | Where its parent's label begins: the step follows what the parent's row holds before its label — the chevron at the start, the icon. A row with nothing before its label steps its items in by the level's indent token. |
| a number | That many pixels further in than its parent. `0` sets no level in, and draws no guides. |

### Icons and their room

`icon-space="auto"` (the default) keeps an icon's room on a row without an icon while another row of its level has one, so that the labels of a level stand in one column. `always` keeps it on every row, and `never` only where there is an icon. `icon-gap` sets the room between the icon and the label in pixels; left `auto` it is the token `comp.tree-view.icon.gap`, the same in both densities.

### Highlight

`highlight="indented"` (the default) draws a row's fill, its hover and press and its focus ring from where its level begins, so that the fill shows the level. `highlight="full"` draws them across the whole tree, as file browsers do. The hit area is the whole width either way.

### One line

A label and its note are one line each, cut with an ellipsis where they do not fit. A cut one is shown whole in a tooltip on hover and on keyboard focus, which Escape hides; the accessible name is always the whole label. `label-wrap` and `supporting-wrap` let them wrap instead. The note stands below its label; `data-supporting-position="inline"` on the `<li>` puts it after the label, on its line. Give the label its element (`<bdi>`): a label written as the row's own text wraps.

### Pinned parents

In a scrolling box, the rows of the open parents above what is shown stay pinned at its top while their items scroll under them, as an editor's sticky scroll does. At most `sticky-max` rows (2) are pinned, the innermost parents. They are the rows themselves: a press on a pinned parent closes it, and a row the keyboard reaches under them is scrolled below them. `sticky-parents="false"` turns it off. A tree that is not in a scrolling box of its own pins nothing.

### Choosing several

| Key or press | In a multiple selection |
| --- | --- |
| Space, Enter, a press | Chooses or unchooses the item, and makes it the anchor. |
| Shift+Down, Shift+Up | Moves focus and selects from the anchor to the focused row; going back shrinks the range. |
| Shift+Space, a Shift-press | Selects from the anchor to the row. |
| Ctrl+Shift+Home, Ctrl+Shift+End | Selects from the focused row to the first or the last row shown. |
| Ctrl+A | Selects every row shown that can be chosen. |

On Apple platforms Command takes the place of Ctrl. Each gesture fires one `change`.


### Renaming and new items

With `editable`, a double-click on a row's label or F2 on a focused row puts the name into a text field, with the name before its extension selected. Enter, or leaving the field, gives the new name; Escape gives it up. The tree changes no label itself: it fires `rename`, and you set the label if you accept the name.

```js
tree.addEventListener('rename', (event) => {
  const li = event.target;
  if (renameFile(li.dataset.value, event.detail.label)) li.querySelector('bdi').textContent = event.detail.label;
});

newFileButton.addEventListener('click', () => tree.create({ icon: 'draft' }));
newFolderButton.addEventListener('click', () => tree.create({ parent: true, icon: 'folder' }));
tree.addEventListener('create', (event) => {
  const li = makeItem(event.detail.label, event.detail.parent);
  event.detail.after ? event.detail.after.after(li) : tree.querySelector('ul').append(li);
});
```

`create()` adds a row of the tree's own beside the selected item, at its level, with an empty field. Nothing is added to your data until a name is given: `create` carries the name, and the item you add in answer takes the focus. Escape, or an empty name, leaves nothing behind. Give the field its name with `edit-label` ("Name") or `setWords({ editLabel })`.

### Large trees

The tree shows what it is given, does not scroll and does not draw only the rows in view. Place it in your own scrolling box.

- Give a large parent's items when it opens: mark it `data-expandable`, and add its `<ul>` when `toggle` says it opened. Set `data-loading` while you fetch.
- Only the rows that are shown cost anything. A closed parent's items are not styled, laid out or read until it opens.
- A change of one row restyles that row alone, whatever the size of the tree.

Filtering is yours too. Give the tree the items that match, set `data-open` on the parents that hold them, and say how many matched in a status of your own.

### Deep trees and narrow windows

Each level begins further in. Where that would put a row's label past half of the tree's width, the row begins no further in than puts its label at half of the width, so names keep half of the width. Assistive technology is still told the true level.

### Rendering on a server

Everything is drawn before the script loads except the selected fill, which appears when the element is defined. To have it in the first frame, write `aria-selected="true"` on the selected item's row yourself.

### Do

- Write `label`, `loading-label` where any item may be loading, and `edit-label` where names are edited or new items named, in your product's language. `loading-label` and `edit-label` can also be given once for the whole product, with `setWords({ loadingLabel, editLabel })`.
- Name the glyphs yourself: a folder and a file are your product's kinds, not the tree's.
- Keep names whole. A label wraps and is never cut.

### Don't

- Don't put a link, a button or a field in a row. No key of the tree reaches it.
- Don't use a tree for the pages of a site. Links are found by the ways a browser and a screen reader list links.
- Don't select by moving focus. The arrow keys move; Enter and Space choose.

## Accessibility

<ComponentAccessibility name="tree-view" />

### What the component handles

- The element is a `tree` named by `label`. Each row is a `treeitem` and each nested list a `group`, so the level comes from the nesting.
- A parent's row carries `aria-expanded`. A row that can be chosen carries `aria-selected`, true or false. A disabled row carries `aria-disabled`, and a loading parent `aria-busy`.
- The label is the row's name. The supporting text, the text of the trailing content and the trailing text are its description, in that order.
- The tree is one stop. Tab enters it at the row focused last, or the first selected row that is shown, or the first row.
- Down and Up move through the rows that are shown. Right opens a parent, then steps in. Left closes it, then steps out. In a right-to-left layout Left and Right swap.
- Home and End go to the first and the last row. Typing letters moves to the next row whose label begins with them. `*` opens every closed parent among the focused row and its siblings.
- Enter and Space do what a press on the row does. Selection never follows focus.
- With `editable`, F2 opens a text field on the focused row's name. Enter gives the name and Escape gives it up, and focus goes back to the row. While an input method is composing, both keys are the input method's. The field is named by `edit-label`, and a new row is a tree item at its level holding the field.
- With `chevron="none"` open and closed are told by the glyph and by `aria-expanded`, never by color, and the arrow keys always open and close. With `expandable="false"` no row carries `aria-expanded`; the groups still tell the level.
- In a multiple selection Shift with the arrows or Space selects a range from the anchor, Ctrl (Command) with Shift and Home or End selects to the first or last row, and Ctrl (Command) with A selects everything shown.
- Pinned parent rows are the rows themselves, so assistive technology meets each once, in its place.
- Opening, closing and choosing are told by the row's own state. Nothing is announced and focus does not move.
- A parent that closes around the focused row takes the focus. A focused row that is removed gives focus to the row after it.
- The focus ring is drawn inside the row, so a scrolling box does not clip it. On a disabled row it is drawn at full strength: the row is faded, its ring is not.
- The chevron, the icons and the guides are hidden from assistive technology. The loading row is hidden too: the parent says that it is busy.
- A label and a note are one line each; a cut one is shown whole in a tooltip on hover and on keyboard focus, which Escape hides and the pointer can move onto, and the accessible name is always whole. With `label-wrap` and `supporting-wrap`, at 200% text they wrap and the rows grow.
- In forced colors a selected row takes the system's selection colors and an edge.
- An empty `label`, an item without a label, a label written as the row's own text, a control in a row, a value that names no item, two items with one value, an unknown `density`, `selection`, `chevron`, `guides`, `icon-space` or `highlight`, an `indent` or `icon-gap` that is not a number, a parent with no icon under `chevron="none"` and a field without `edit-label` are reported in debug builds.

### What you need to do

- Give every item that can be chosen a `data-value` that is unique in the tree.
- Say what a failed fetch is yourself, beside the tree or as an item whose label says it. The tree announces nothing when items arrive.
- Give a mark of your own in the trailing content where each chosen item of a multiple selection must be told apart by more than its fill.
- Place a long tree in a scrolling box with a name or a heading, so that people know what the box holds.
