When the content inside it changes size, the box moves from the size it shows to the new one in a single motion. Whatever comes after it in the layout moves along with it instead of jumping in one frame. It draws nothing of its own: no background, border, corner or padding.

### Usage

The Web and React samples show the current spec. SwiftUI, Compose, Flutter and React Native are planned: they do not ship a size transition yet.

## Guidelines

### When to use

Use a size transition around content of your own whose size changes while a person is looking at it: a reply draft that wraps onto a second line, a summary that you replace with its full text, an error line that appears below a field you built yourself, a status label whose word gets longer. Without it, everything below jumps in one frame, and the person loses their place.

Tanrei's own components already move their own size changes — a text input that grows, a snackbar that expands, an accordion that opens. Don't wrap them in a size transition to get that.

To show or hide a whole section on request, use an [accordion](/components/accordion/): opening and closing is its job. A size transition does not open or close anything. It follows whatever is inside it.

### How long a change takes

The time grows with the distance. In the default system, a change of up to 64 pixels takes 300 ms. Each further 64 pixels, or part of them, adds 50 ms, up to 400 ms at most. A large change then does not look rushed next to a small one, and a far one never makes people wait. Set `duration` only where one place needs a different tempo from every other size transition in your product. `0` makes the change instant.

### Choosing an axis and an anchor

| Axis | Use for |
| --- | --- |
| Block (default) | Content whose height changes: paragraphs, lists, a section that gains a row. Its width is the layout's. |
| Inline | A label whose width changes: a status word, a count, a button's text. It is as wide as its content. |
| Both | A small box whose width and height change together, such as a badge that wraps onto a second line. Both move as one motion. |

| Anchor | Use for |
| --- | --- |
| Start (default) | Most content. The first line never moves, and what is new appears after it. |
| End | Content docked at the end of its container, such as a message composer above the keyboard. Its last line stays where it is, and the box grows toward the start. |
| Center | Something centered in its space, such as a notice in the middle of an empty panel. |

### Do

- Wrap the content that changes, and only that. A size transition around a whole page moves everything at once.
- Use `disabled` while content changes at every frame — while a person drags something inside it, for example — and for a change that people should not watch, such as a list replaced by search results.
- Listen for `settle` when you need to measure or scroll after the change: it arrives once, after the last frame.

### Don't

- Don't use it to make things appear or disappear with a fade. It moves only the size. A fade belongs to the content.
- Don't put a size transition around a Tanrei component that already moves its own size.
- Don't rely on it to remove layout shift from your metrics. Browsers still count an element moved by a change of layout. It removes the jump a person sees.

## Accessibility

<ComponentAccessibility name="size-transition" />

### What the component handles

- It exposes nothing of its own to assistive technology: no role, no name, no state. It is never a focus stop. Its content is read and reached as if the box were not there.
- Content that the box clips during a motion stays in the reading and focus order. A person who tabs into it during the motion reaches it, and the motion ends within 400 ms in the default system.
- While it moves, nothing scrolls: not the box, not its content and not the page. Focus, the caret and a selection stay where they are.
- When reduced motion is requested, every change of size is instant. `settle` still arrives once per change.
- A change of the space the layout gives it — the window is resized, the text size or the direction changes — is instant, so the box never lags behind a person resizing the window.
- An unknown `axis` or `anchor`, and a `duration` that is negative or not a number, are reported in debug builds.

### What you need to do

- Announce a change that matters yourself, in a live region or a notice the person will meet. A size transition only moves its size, and says nothing.
- Keep the content's own names, roles and order correct. The size transition adds none.
