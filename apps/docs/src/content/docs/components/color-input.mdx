A color input is the box of a [color field](/components/color-field/), alone: the container, the swatch, the value as text and the picker button. It has no label row above it and no help or error text below it.

Use it bare where the label a person reads stands somewhere else:

| Where | The label a person reads | The input's `label` |
| --- | --- | --- |
| A row of a list of colors, or of a palette's tones | The row's own text | The list and the row: "Primary, tone 40" |
| A cell of a table | The column's header | The column and the row: "Background, dark theme" |
| A toolbar | A text or a glyph beside it | What the color is for: "Highlight color" |

Bare, the input needs a `label` of its own. It is the accessible name. A stacked input never draws it; a filled or an outlined one draws it as the label that floats in the box.

It is an **advanced** component: the bare control, for a product that composes its own. Most forms want the [color field](/components/color-field/), which is this input inside a field, ready to use.

**Used in** the [color field](/components/color-field/). To frame it yourself, put it in a [field](/components/field/), which names it, describes it, marks it required and puts it in its error condition.

It is a block as wide as the place it is put in, bare and framed alike. It has no width of its own: for a narrower box, give it a narrower place.

On the web it is `<tanrei-color-input>`. The other platforms have not implemented it yet.

### Usage

`value` is a number sign and six hexadecimal digits in lowercase (`#0f766e`), or an empty string for no color. It is never a half-typed text: while the input holds something that is not a color, `value` is empty.

      tone.addEventListener('change', () => save(tone.value));

### In a field, by hand

A field around a color input is a color field written out. Leave the input's own `label` empty: the field names it. `label`, `error`, `disabled` and the requirement are said on the field; `name`, `value`, `invalidText` and the picker on the input.

```html
<tanrei-field label="Brand color" requirement="required" required-text="Required"
  supporting-text="Six hexadecimal digits, like #0f766e.">
  <tanrei-color-input name="brand" value="#0f766e"
    invalid-text="Enter six hexadecimal digits, like #0f766e."
    picker picker-label="Choose color"></tanrei-color-input>
</tanrei-field>
```

The input tells its field what only it knows. The field's help starts where the value's text starts, after the swatch. A filled or an outlined input draws the field's label itself, floating in the box, so the field draws no label row. A committed text that is not a color puts the field in error with the input's `invalidText`.

### What is the input's, and what is the field's

| Aspect | The color input | The field around it |
| --- | --- | --- |
| Draws | The box, the swatch, the value as text, the picker button, and the label that floats in a filled or an outlined box | The label row above a stacked input, the required or optional mark, the help, the error text |
| Holds | The value, its place in a form, the events, the picker it presents | Nothing |
| Says to assistive technology | The value as text; the picker button, as a separate button | The name, the help or the error text, required, invalid, disabled |

The box itself is the same bare, framed and in a color field, and is described once, on the color field's page: [the parts of the box](/components/color-field/#the-field), [the value and the text](/components/color-field/#the-value-and-the-text), and [the picker](/components/color-field/#the-picker).

The three variants and the three sizes, `small` (40), `medium` (48) and `large` (56), are the text input's. The default system ships `stacked` only. The swatch stands where a text input's leading icon stands, at that icon's size, so a color input under a text input with a leading icon shares its start edges.

### Bare, without a field

- **The name** is `label`. `labelHidden` stops a filled or an outlined input from drawing it.
- **An error** is `error`, which you set: the box is drawn in its error condition and exposed as invalid. The input has no error text. Say what is wrong in words beside it, or frame it.
- **A committed text that is not a color** draws the box in error and emits `entryError`. `invalidText` is added to the input's description; nothing draws it.
- **Required** is a field's to say. A bare input has no requirement setting: where the form needs an answer, validate it yourself.

### What the web draws differently

- The element is form-associated. With a `name` it submits `value` — the color, or an empty string —, resets to its `value` attribute, is restored on navigation, follows a disabled `<fieldset>`, and reports a missing value while its field says it is required, and a bad input while an entry error lasts.
- The element is a block. `focus()` goes to the native text element, never to the picker button; a press anywhere on the box outside that button focuses the text, except that a press on the swatch opens the picker while the button is shown.
- `input` and `change` are plain events: read `value` from the element. `pickerrequest` is a cancelable CustomEvent with `detail.value`; `entryerror` is a CustomEvent with `detail.text` and `detail.message`, which is `invalidText`. Their types are `TanreiColorInputPickerRequestDetail` and `TanreiColorInputEntryErrorDetail`.
- Parts: `container`, `outline`, `active-indicator`, `label`, `requirement-label`, `swatch`, `input`, `picker-button`. It has no slot.
- The element has no words of its own and reads none of the product's: `label`, `invalidText` and `pickerLabel` are empty until you give them.
- The browser's picker differs by browser: a popup of the page in Chromium, the system's color window in Firefox and Safari. Its look, placement and keys are the browser's.
- A text in full-width characters (`＃０ｆ７６６ｅ`) is not read as a color.
- Before the element is defined it has no size. Reserve the height of the box.

## Guidelines

### Color input, color field, or a field by hand

| You need | Use |
| --- | --- |
| A label, the box, help and an error | A [color field](/components/color-field/) |
| The box alone, in a row or a column that already names the color | A color input, named by its own `label` |
| Something of your own inside the frame, beside or below the box | A [field](/components/field/) with a color input and your own element in it |
| A color that is shown and not edited | A sample with its value or its name in text beside it |

### Do

- Give a bare input a `label` that says what the row and its place say together: "Primary, tone 40".
- Name the picker button for its row too: "Choose the color of Primary, tone 40". A page of rows otherwise has many buttons of one name.
- Give a bare input its width by its place: a column of a grid, a cell, a toolbar's item with a width.
- Use the color field wherever a label above the box, help and an error are what you need.

### Don't

- Don't use a bare input in a form to save the room of a label. An input with no visible label anywhere is a guess for everyone who sees it.
- Don't tell a color by the swatch alone. The value is text; a person who cannot tell two samples apart reads two different values.
- Don't set `label`, `error` or `disabled` on an input inside a field. Say them on the field, so that the label and the help follow.
- Don't put a color field inside a field. It is a field already; the control a field frames is the color input.

## Accessibility

<ComponentAccessibility name="color-input" />

### What the component handles

- It is one text box whose value is the text it shows, and — with `picker` — one separate button, named by `pickerLabel`, that is exposed as opening a dialog.
- Its name is its own `label`, or the label of the field around it where it has none.
- Its description is what its field gives: the help or the error text. Where no field frames it, `invalidText` is its description while an entry error lasts.
- It is exposed as invalid while in error, as required while its field says so, and as disabled.
- The swatch is decorative and hidden from assistive technology: the value's text says the color.
- Nothing is announced when the value changes, and it adds no name of the color.
- Focus is shown by the box's own edge, from the keyboard and from a pointer alike. The hit area meets the minimum target.
- In forced colors the box gains an edge and takes the person's colors. The swatch alone keeps the value's color; its edge is the text color.
- In a right-to-left layout the box is mirrored: the swatch at the right, the picker button at the left. The value itself stays left to right.
- A missing name is reported in debug builds.

### What you need to do

- Name every bare input with `label`. A visible text beside it does not name it.
- Give `pickerLabel` whenever `picker` is set.
- Where a bare input can be wrong, say what is wrong in words that reach assistive technology: write `invalidText`, and put a message of your own on the page — or frame the input with a field, which draws the words.
