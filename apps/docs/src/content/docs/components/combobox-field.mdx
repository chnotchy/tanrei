Use a combobox field wherever a form asks for one value that people would rather type than scroll to: a city out of hundreds, a person, a token. It also serves a field that suggests values and takes one of the person's own, such as a font family. It is the ordinary case, ready to use: a label, the box with its list, a line of help and the words for a wrong value. The box is drawn and measured as the text field's of the same variant and size, and the list is drawn as a select's.

**Built from** a [field](/components/field/) and a [combobox](/components/combobox/). The field is the frame: the label, the required or optional mark, the help and the error. The combobox is the control: the box, the text typed in it, and the list with its options. The combobox field draws nothing of its own and has no token: every property it has is a property of one of the two, given to it unchanged, and the options you give it are its combobox's.

It is a block as wide as the place it is put in, and its box fills it. It has no width of its own: for a narrower field, give it a narrower place. Its width never follows its options or its value, because a person types into it before any option is known.

On the web it is `<tanrei-combobox-field>` with `<tanrei-option>` children, the elements a [select](/components/select/) holds. The other platforms have not implemented it yet.

### Usage

A combobox field holds what its combobox holds, which is two things. `value` is the committed choice: the chosen option's value, or a custom text. `inputValue` is the text in the input. The value changes only when the person chooses an option, commits the text (Enter with no option active, or leaving the field) or presses the clear button; typing and moving through the list never change it.

### One level down

A combobox field is a [field](/components/field/) with a [combobox](/components/combobox/) in it. Write the two yourself where you need something the field does not offer — something of your own between the label and the box, or below the help. The picture, the name, the description and the states are the same.

### The field

| Part | What it is |
| --- | --- |
| Label | The field's row above the container (`stacked`), or the combobox's own label floating inside it (`filled`, `outlined`). It is the accessible name, drawn or hidden with `labelHidden` |
| Requirement mark | After the label: the requirement tag in its required form, an asterisk or nothing for `requirement="required"`; the requirement tag in its optional form for `optional`. A floating label takes the asterisk |
| Input | The text: what the person types to find an option and, while they are not typing, the chosen option's label or the custom value. One line, which scrolls |
| Placeholder | A hint shown while the input is empty. Never a label, and never a value |
| Leading icon | The glyph in the `leading-icon` slot, or else the chosen option's own |
| Clear button | With `clearable`, while the text is not empty: empties the text and the value |
| Chevron | Says that the field has a list to look through, and opens and closes it. It does not turn. Leave it out (`chevron` false) where suggestions exist only for what was typed |
| Supporting text | The field's row: a line of help. It stays while `error` is true, with `errorText` below it. Both start where the input's text starts |

The label row, the mark and the supporting row are the [field](/components/field/)'s, drawn from the field's tokens; everything else is the [combobox](/components/combobox/)'s. The three variants and the two sizes, `medium` (48) and `large` (56), are the text field's. The default system ships `stacked` only.

While the list is open, the label and the help are drawn focused with the box, whether or not the input has focus.

### The list

The list opens `comp.combobox.list.offset` below the container, exactly as wide as it, and above it where there is no room below. It is as tall as its rows up to `list.max-height` (320), and scrolls beyond that.

| Part | What it is |
| --- | --- |
| Option | A row with a label, and optionally a supporting line and a glyph. The chosen one has a quiet fill and a check |
| Match | With `filter="contains"`, the part of each label that matched the text is drawn heavier |
| Group | A run of options under an optional title. A group the filter leaves empty is not drawn |
| Status row | After the options: `statusText`, a loading indicator while `status` is `loading`, the failure while it is `error`, or `emptyText` where nothing matched |

`filter="contains"` shows the options whose label contains the text, whatever the case, the width of a character or the marks on a letter. With `filter="none"` the combobox shows every option you give it and you filter, on `input`. The combobox never fetches, waits, sorts or ranks.

### Typing, moving and choosing

| Input | What happens |
| --- | --- |
| Typing | Edits the text and opens the list, filtered. The first match is the active option; with `allowCustomValue` none is |
| Down Arrow, Up Arrow, list closed; the chevron | Opens the list with every option. The chosen option is the active one, or the first enabled one |
| Down Arrow, Up Arrow, list open | The next or previous option, across groups, stopping at the ends |
| Page Down, Page Up | Ten options down or up |
| Home, End, Left Arrow, Right Arrow | Move the caret in the text |
| Enter, an option active; a press on an option | Chooses it and closes the list. It does not submit a form |
| Enter, no option active | Commits the text, emits `action`, and submits the form unless `action` is cancelled |
| Escape | Closes an open list and keeps the text. Pressed again, restores the committed value's text. It never clears a value |
| Tab; a press outside | Leaves the field: the text is resolved and the list closes. The active option is not chosen |
| A press on the label | Moves focus to the input and opens nothing. While the list is open it is a press outside the combobox: the list closes, and focus stays in the input |

Leaving the field resolves the text: the combobox decides which value the text stands for. An empty text empties the value. The whole label of an option chooses that option. Any other text becomes the value with `allowCustomValue`, and is given up without it.

The list does not open on focus. Set `open` yourself if you want that.

While an input method is composing, every key belongs to it. The Enter that confirms a conversion chooses nothing and submits nothing.

`toggle` carries the reason for a close: `select`, `commit`, `escape`, `outside`, `press`, `tab`, `focus-out`, `anchor-hidden` or `empty`.

### What the web draws differently

- `<tanrei-option>` and `<tanrei-option-group>` are data: they draw nothing. They are the elements a select holds. An option whose value is the empty string is drawn and cannot be chosen, because the empty value means that nothing is chosen.
- The element's shadow root holds a `<tanrei-field>` around a `<tanrei-combobox>`. Your `<tanrei-option>` children stay its own children and reach the combobox through a slot; nothing is moved or copied.
- The combobox field is a form-associated element: the one control the form sees. It takes `name`, submits `value` and never the text of an edit that was not committed, resets to the `value` attribute, and reports a missing value to the form while `requirement="required"` and `value` is empty. Enter with no option active submits its form.
- `value`, `inputValue` and `open` are the combobox's at every moment: each is already the new one in every listener.
- `chevron` is the inverse attribute `no-chevron`, and `readOnly` is `readonly`.
- `input` is the native event of the text element. `change` and `action` carry `detail.value` and `detail.inputValue`. The four events are the combobox's own, with the combobox field as their target; `toggle` does not bubble.
- `focus()` goes to the input. The element itself is not focusable and has no role: name it with `label`, never with `aria-label`.
- Parts: `field` and `combobox` are the two members; each member's parts are exported under their own names, and `label` and `requirement-label` also as `field-label`, `combobox-label`, `field-requirement-label` and `combobox-requirement-label`.
- One field is set apart by a custom property on it: `--tanrei-comp-field-*` for the rows, `--tanrei-comp-input-box-*` for the box, `--tanrei-comp-combobox-*` for the list.
- The list is a `popover="manual"` element in the top layer. A press outside closes it and also reaches the element under it.
- The status row stands under the options and does not scroll with them, so a count or a failure stays in view.
- Before the element is defined, its options are running text. Hide `tanrei-combobox-field:not(:defined) > *` and reserve the height.
- The web has no back gesture of its own, so `toggle` never carries the reason `back`.

## Guidelines

### Combobox field, select, search or a text field

| Aspect | Combobox field | Select | Search | Text field |
| --- | --- | --- | --- | --- |
| Holds | One value found by typing | One value of a closed list | A query | Any text |
| Shows choices | As the person types | After a press | Suggestions and results | No |
| Takes a value that is not listed | With `allowCustomValue` | No | Yes | Yes |
| Part of a form | Yes | Yes | No | Yes |

1. With up to about five short options, show them all: radio buttons.
2. If the list is short enough to scan, and closed, it is a select.
3. If people would rather type than scroll, or the field takes a value that is not listed, it is a combobox field.
4. If typing leads to places to go rather than to a value, it is a search.
5. Several values are another component: a combobox holds one.
6. If the label stands elsewhere — a filter in a toolbar, a cell of a table — it is the bare [combobox](/components/combobox/), named by its own `label`.

### Do

- Write a label that names what is chosen, and keep it visible in a form.
- Use `allowCustomValue` only where a value that is not listed is a real answer.
- Give `clearable` to a combobox field whose value may be none, and name the button with `clearLabel`.
- When you load options, set `status` and `statusText` so the list says that it is waiting, how many it shows, or that it failed.
- Give `emptyText`, on the combobox field or once for the whole product with `setWords({ emptyText })`. Tanrei ships no words: without it a text that matches nothing draws no row, and the list has nothing to show.

### Don't

- Don't use the placeholder as the label. It goes away as soon as the person types.
- Don't save, navigate or submit on `input`. It fires at every keystroke; `change` is the committed value.
- Don't treat a text that names no option as an error of the field. It is given up when the person leaves. If you want to say "choose one from the list", set `error` and `errorText` yourself.
- Don't put a combobox field inside a field. It is a field already; the control a field frames is the [combobox](/components/combobox/).
- Don't open the list on focus in a form of many fields: it covers the fields below at every stop.

## Accessibility

<ComponentAccessibility name="combobox-field" />

### What the component handles

- The input is an editable combobox with a list box. Its name is `label`, drawn or hidden, and never the placeholder. The field gives it to the combobox, which carries it on its own input.
- The shown supporting or error text is its description, with `optionalText` while the field is optional.
- An error that appears while focus is in the field is announced once, politely.
- It is exposed as invalid while `error` is true, as required while `requirement` is `required`, as read-only, and as expanded while its list is open.
- Focus stays in the input while the list is open. The active option is its active descendant, so typing never stops editing the text.
- The list is a list box named by the label. Each option has its name, its description, whether it is the chosen one, whether it is disabled, and its position among the options shown. A group is named by its title.
- A match is marked by weight, never by color alone. The label is read as one text.
- The status row is a live region: its text is read politely when it changes, and at once when the source failed. While loading, the list is marked busy and nothing is announced.
- While an input method is composing, the combobox handles no key.
- The chevron is a button for a pointer and for touch exploration, outside the focus order. The keyboard opens the list with Down Arrow.
- The clear button is a button named by `clearLabel`, and the next focus stop after the input.
- Escape closes the list and goes no further, so a dialog around the combobox stays open.
- The field's hit area meets the minimum target, and options are at least the minimum target tall.
- At 200% text the label, the help, the options, the titles and the status row wrap. Only the text in the input stays on one line, and scrolls.
- In forced colors the field and the list gain an edge, the active option takes the highlight colors, and the chosen option is shown by its check.
- In a right-to-left layout the field and each row are mirrored, and each text keeps its own direction. The chevron, the clear button's glyph and the check are not mirrored.

Known gaps on the web:

- The divider between two groups is not exposed as a separator: a list box holds options and groups only.
- The filter folds case, width and marks for every script alike. It does not match Hangul by its first consonant or kana by its reading.
- Before the element is defined, the options are text on the page without a control.

### What you need to do

- Give every combobox field a `label`, and every option a label and a value that is not empty.
- Give a clearable combobox field a `clearLabel`.
- Write `statusText` on the combobox field. Give `emptyText`, `requiredText`, `optionalText` and `clearLabel` on the combobox field, or once for the whole product with `setWords()`. Tanrei ships no words; a missing one is reported in development. See [The product's words](/foundations/words/).
- Validate the value yourself, set `error`, and write `errorText` so that it says how to put the answer right.
- Keep option values unique within a combobox field.
