The Web and React samples show the current spec. SwiftUI, Compose, Flutter and React Native are lagging: they do not have `separation` yet, and their samples show what they ship.

## Guidelines

### When to use

Use a progress indicator for a task that takes long enough to notice: an upload, an import, a deploy, a long save. Show how far it has come when you can measure it, even roughly; people wait more patiently for a bar that moves. When you cannot measure it yet, show it indeterminate, and switch to a value as soon as you have one.

For a short wait whose length you cannot measure, such as a list fetching its next page, use a [loading indicator](/components/loading-indicator/) instead. It has no track, because it never promises a value.

### Choosing a variant

| Variant | Use for |
| --- | --- |
| Linear | Tasks that belong to a page or a section: at the top of a page, inside a card, under a file in an upload list. The bar fills the width its layout gives it. |
| Circular | Tight places and progress next to text: in a button, in a list row, in a small panel. The ring has a fixed size. |

### Choosing a size

| Size | Bar thickness / ring size in the default system | Use for |
| --- | --- | --- |
| Small | 2 / 16 | Dense rows, inside controls, next to small text. |
| Medium | 4 / 24 | Most places. The default. |
| Large | 8 / 40 | The one task a view is about, or an empty section waiting for its content. |

### Divider or gap

A determinate indicator is told from the rest of its track in one of two ways. Under `divider` it is drawn on the track with no space between them. Under `gap` a little empty space is left after it, on a ring at both ends of its arc. An indeterminate indicator looks the same under both. Whether a bar marks the end of its track with a dot is a separate choice, the size of its stop indicator: a design system that gives it a size draws the dot under either separation, and the default system draws none.

The design system chooses once for every component that has this choice, and the default system chooses divider. Leave `separation` at `auto` to follow that choice, so the indicator agrees with the button groups and menus around it. Set `divider` or `gap` on one indicator only when that one has a reason to differ.

### Do

- Give it a label that says what is in progress: "Uploading report.pdf", not "Progress". If a caption is shown next to it, use the same words.
- Use a value text when a percentage is not the natural reading: "3 of 10 files", "Step 2 of 4".
- Tell people when the task ends, in words: a message that it is done, or what went wrong and what to do next.

### Don't

- Don't use color to report a failure. A red bar says nothing to someone who cannot see the color; stop the indicator and show a message next to it.
- Don't use it as a gauge of a level, such as storage used or password strength. That is a meter, which is a different component.
- Don't let the value go backwards or jump to the end before the task is done. The bar is a promise about the remaining wait.
- Don't show several indicators for one task. Show one for the whole, or one for each item the person cares about.

## Accessibility

<ComponentAccessibility name="progress-indicator" />

### What the component handles

- It exposes the progress bar role with the label as its name. Determinate, it exposes the range, the current value (clamped to the range) and the value text when there is one; indeterminate, it exposes no value and the platform's busy state. Flutter has no progress bar role or busy state yet, so there it exposes the label and the value.
- It is never focusable, and it does not announce its changes. Assistive technology reads the current value when the person reaches it.
- When reduced motion is requested, a value change shows at once, and the indeterminate form stops moving and gently pulses its opacity instead, at most once a second.
- Its looping animation stops while it cannot be seen — in an app in the background everywhere, and scrolled out of view or on a hidden screen where the platform can tell — and resumes when it can.
- An empty label, a value outside the range and an unknown `separation` are reported in debug builds.

### What you need to do

- Announce the end of the task yourself: a message in a live region, or focus moved to the result. The indicator will not say that the task is done or has failed.
- Keep the indicator color at least 3:1 against the track and the surface behind it if you change them, with a divider and with a gap alike. The value is read from where the indicator meets the track.
- If the task holds up a region of the page, mark that region busy while it runs (`aria-busy` on the web).
