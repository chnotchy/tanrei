A text input is the box of a [text field](/components/text-field/), alone: the container, the text, the icons, the prefix and the suffix, the segments of a date, the picker button and the resize handle. It has no label row above it, no help and no error text below it, and it draws no count.

Use it bare where the label a person reads stands somewhere else:

| Where | The label a person reads | The input's `label` |
| --- | --- | --- |
| A filter in a toolbar or over a list | The placeholder and the glyph say what it does | What it filters: "Filter tokens" |
| A cell of a table | The column's header | The column and the row: "Quantity, oak desk" |
| A row whose label stands beside the input | The text beside it | The same words |

Bare, the input needs a `label` of its own. It is the accessible name. A stacked input never draws it; a filled or an outlined one draws it as the label that floats in the box.

It is an **advanced** component: the bare control, for a product that composes its own. Most forms want the [text field](/components/text-field/), which is this input inside a field, ready to use.

**Used in** the [text field](/components/text-field/) and the [chip field](/components/chip-field/). To frame it yourself, put it in a [field](/components/field/), which names it, describes it, marks it required and puts it in its error condition.

It is a block as wide as the place it is put in, bare and framed alike. It has no width of its own: for a narrower box, give it a narrower place.

On the web it is `<tanrei-text-input>`. The other platforms have not implemented it yet.

### In a field, by hand

A field around a text input is a text field written out. Leave the input's own `label` empty: the field names it. `label`, `error`, `disabled` and the requirement are said on the field; `name`, `value` and everything about typing on the input.

```html
<tanrei-field label="Email" required required-text="Required"
  supporting-text="We only use it to sign you in.">
  <tanrei-text-input name="email" type="email" autocomplete="email"></tanrei-text-input>
</tanrei-field>
```

<Example label="A field with a text input in it: the same picture as a text field" column>
  <tanrei-field class="not-content" style="inline-size: 20rem; max-inline-size: 100%" label="Email" required required-text="Required" supporting-text="We only use it to sign you in.">
    <tanrei-text-input type="email"></tanrei-text-input>
  </tanrei-field>
</Example>

The input tells its field what only it knows. Its help starts where the text starts, past the padding and a leading icon. A filled or an outlined input draws the field's label itself, floating in the box, so the field draws no label row. A date or a time left half-filled puts the field in error with the input's `invalidText` or `unavailableText`.

One thing is yours by hand: the count. With `counter` the input keeps the count, and a field draws what it is given as `count-text`. Give it at every change:

```html
<tanrei-field label="Display name">
  <tanrei-text-input name="display-name" maxlength="40" counter></tanrei-text-input>
</tanrei-field>

<script type="module">
  const field = document.querySelector('tanrei-field');
  const input = field.querySelector('tanrei-text-input');
  field.countText = input.countText;
  input.addEventListener('input', () => (field.countText = input.countText));
</script>
```

The text field does this itself. It is the only thing the text field does that a field and a text input written by hand do not do.

### What is the input's, and what is the field's

| Aspect | The text input | The field around it |
| --- | --- | --- |
| Draws | The box, the text, the placeholder, the prefix and the suffix, the icons, the segments of a date or a time, the picker button, the resize handle, and the label that floats in a filled or an outlined box | The label row above a stacked input, the required or optional mark, the help, the error text, the count |
| Holds | The value, its place in a form, the events | Nothing |
| Says to assistive technology | Its own description: the prefix and the suffix, the count | The name, the help or the error text, required, invalid, disabled |

What happens in the box is the same bare, framed and in a text field, and is described once, on the text field's page: the [input types](/components/text-field/#input-types), [several lines](/components/text-field/#several-lines) and the resize handle, [code](/components/text-field/#code), and [dates and times](/components/text-field/#dates-and-times) with the picker button.

### Bare, without a field

- **The name** is `label`. `labelHidden` stops a filled or an outlined input from drawing it.
- **An error** is `error`, which you set: the box is drawn in its error condition and exposed as invalid. The input has no error text. Say what is wrong in words beside it, or frame it.
- **A date or a time left half-filled**, or with a value that is not available, draws the box in error and emits `entryError`. `invalidText` or `unavailableText` is added to the input's description; nothing draws it.
- **The count** is kept, described and announced, and not drawn. `countText` is the count as text ("12/40"), for you to draw.
- **Required** is a field's to say. A bare input has no requirement setting: where the form needs an answer, validate it yourself.
- **Small** (32, its text 14) is for an input in an app bar, a toolbar or a dense row of controls: it stands beside a small [select](/components/select/) or a small button at one height. `medium` (40) and `large` (56) are for forms. Its hit area meets the minimum target at every size.
- **A prefix in a right-to-left page.** The value of an email, URL, phone, number or password input is written left to right. Beside a prefix it stands against it, so `https://` and the address read as one string in a right-to-left page too; without a prefix it stands at the input's start edge.

### What was entered already

The `entries` slot is a place inside the box, before the typed text, for what a person entered already: the chips of a list of addresses, for example. The input lays its content and the typing part out in lines that wrap, and the box grows by whole lines. While the slot holds content, a floating label floats and the placeholder is not shown.

```html
<tanrei-text-input label="Recipients" type="email">
  <tanrei-chip slot="entries" kind="input" size="small" label="ada@example.com"
    remove-label="Remove ada@example.com"></tanrei-chip>
</tanrei-text-input>
```

The input gives these items no role, no place in the focus order and no key: they are yours. A press in the box outside every item focuses the typing part. For a list of entries with its keys, its checks and its form value, use the [chip field](/components/chip-field/), which is built on this place.

### Clearing

With `clearable`, a single-line input draws a clear button at its end while it holds a value: for a filter, a search or a query that a person empties whole. A press on it empties the value, emits `input` and, where the value changed since the input took focus, `change`, and leaves focus in the input. A press never takes focus from the input, so typing goes on where it was and a touch keyboard stays up. Its room is kept while the input is empty, so the text and the icons do not move as the button comes and goes. A multi-line input, a date and a time draw none.

The clear button comes after the input and after a button of yours in the `trailing-icon` slot, and is the next stop in the focus order. Name it with `clearLabel` ("Clear filter"), or once for the product with `setWords({ clearLabel })`.

<Example label="Clearable: a filter emptied at one press" column>

    <span slot="leading-icon">search</span>
  </tanrei-text-input>
</Example>

### Showing a password

With `revealable`, a password input draws a reveal button at its end, after the clear button where there is one. A press shows the value as plain text, so a person can check what they typed instead of typing it twice, and a second press hides it again. The value, the caret and the selection stay as they are, no `input` or `change` is emitted, and focus does not move: a press leaves it in the input, and Enter or Space leaves it on the button. It is a toggle button, never a submit button. `revealed` says whether the value is shown, and `revealChange` tells you when the person changed it. A shown value is hidden again when its form is submitted or reset, when the type changes and when the input is disabled.

Name the button with `revealLabel` ("Show password"), or once for the product with `setWords({ revealLabel })`. It keeps one name in both states: its pressed state says whether the value is shown.

<Example label="A password that can be checked" column>
  <tanrei-text-input class="not-content" type="password" label="Password" value="correct horse" revealable reveal-label="Show password" autocomplete="current-password"></tanrei-text-input>
</Example>

### What the web draws differently

- The element is form-associated. With a `name` it submits `value`, resets to its `value` attribute, is restored on navigation, follows a disabled `<fieldset>`, and reports a missing value while its field says it is required. A date or a time in an entry error is reported as well.
- The text is edited in a native `<input>` in the shadow root, or a `<textarea>` while `multiline`. A date or a time is a group of spin buttons.
- The element is a block. `focus()` goes to the native element, and a press anywhere on the box outside a button focuses it.
- `input` and `change` are composed events. `action` is a cancelable CustomEvent: cancel it to keep Enter from submitting the form. `pickerrequest` and `entryerror` are CustomEvents whose `detail` holds `{ value, type, min, max }` and `{ reason, text }`. Their types are `TanreiTextInputActionDetail`, `TanreiTextInputPickerRequestDetail` and `TanreiTextInputEntryErrorDetail`.
- `countText` is a read-only property, new after each change of the value. It has no attribute.
- Attributes are kebab-case, such as `label-hidden`, `min-rows`, `prefix-text` and `no-wrap`, which is `wrap` set to false. `readonly`, `maxlength`, `autocomplete`, `min` and `max` keep HTML's names.
- Parts: `container`, `outline`, `active-indicator`, `label`, `requirement-label`, `input`, `entries`, `segment`, `prefix`, `suffix`, `leading-icon`, `trailing-icon`, `clear-button`, `reveal-button`, `picker-button`, `resize-handle`.
- The reveal button is a toggle `<tanrei-button>`. While the value is shown the native `<input>` is `type="text"` and keeps the password field's other attributes. `revealchange` is a CustomEvent whose `detail` holds `{ revealed }`; its type is `TanreiTextInputRevealChangeDetail`. `reveal-label` left empty is read from the product's words (`setWords({ revealLabel })`).
- `clear-label` left empty is read from the product's words (`setWords({ clearLabel })`).
- Slots: `leading-icon`, `trailing-icon` and `entries`. A trailing icon may be your own icon-only Button. The `entries` part has no box of its own: its items stand in the box's own lines.
- `resize-label` and `segment-empty-text` left empty are read from the product's words (`setWords()`).
- Before the element is defined it has no size. Reserve the height of the box.

## Guidelines

### Text input, text field, or a field by hand

| You need | Use |
| --- | --- |
| A label, the box, help, an error and a count | A [text field](/components/text-field/) |
| The box alone, under a label that stands elsewhere: a toolbar's filter, a table's cell, a row with its label beside it | A text input, named by its own `label` |
| Something of your own inside the frame, beside or below the box | A [field](/components/field/) with a text input and your own element in it |
| A search with suggestions or results that open from it | A [search](/components/search/) |
| A number that is stepped and kept within limits | A [number field](/components/number-field/) |

### Do

- Give a bare input a `label` in the words of the visible label, or in words that say what the visible label and its place say together: "Quantity, oak desk".
- Give a bare input its width by its place: a column of a grid, a cell, a toolbar's item with a width.
- Keep the visible label close enough that a person who sees the page reads the two as one.
- Use the text field wherever a label above the box, help and an error are what you need.

### Don't

- Don't use a bare input in a form to save the room of a label. Apart from a filter or a search marked by its glyph, an input with no visible label anywhere is a guess for everyone who sees it.
- Don't use the placeholder as the label. It goes as soon as someone types, and it is never the name.
- Don't set `label`, `error` or `disabled` on an input inside a field. Say them on the field, so that the label and the help follow.
- Don't put a text field inside a field. It is a field already; the control a field frames is the text input.
- Don't draw the count, the help or an error inside the box with a style of your own. They are a field's rows.

## Accessibility

<ComponentAccessibility name="text-input" />

### What the component handles

- It is one text box, a multi-line one with `multiline`; a search box for `type` search where the platform has that role; a group of spin buttons for a date or a time.
- Its name is its own `label`, or the label of the field around it where it has none. The placeholder is never the name.
- Its description is the prefix and the suffix while they are shown, then the count, then what its field gives: the help or the error text.
- It is exposed as invalid while in error, as required while its field says so, and as read-only and disabled.
- The count is announced once typing pauses for a second, never on every keystroke, whether or not anything draws it. It is said as it stands ("12/40") or, where you give one, as your sentence: `counterText` while there is a `maxLength`, with the places `{count}`, `{limit}` and `{remaining}` (`{remaining} characters left`), and `counterNoLimitText` while there is none, with `{count}`. Give them on the element or once with `setWords({ characterCountText, characterCountNoLimitText })`. A value longer than the limit, which only you can set, is said as digits. The same sentence is the input's description; what is drawn stays the digits.
- Focus is shown by the box's own edge, from the keyboard and from a pointer alike. The hit area meets the minimum target.
- The asterisk after a floating label is hidden from assistive technology: the required state already says it.
- A missing name is reported in debug builds.

### What you need to do

- Name every bare input with `label`. A visible text beside it does not name it.
- Where a bare input can be wrong, say what is wrong in words that reach assistive technology: a message of your own tied to the page, or a field around the input.
- For a date or a time, give `segmentEmptyText`, and write `invalidText` and `unavailableText` even where no field shows them: they are read with the input.
- Name the resize handle with `resizeLabel` and the picker button with `pickerLabel`.
- Give a clearable input a `clearLabel` that says what it clears ("Clear filter").
- Give a revealable password input a `revealLabel` ("Show password"), and keep its `autocomplete` hint (`current-password`, `new-password`).
