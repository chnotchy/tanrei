`@tanrei/react` wraps each custom element from `@tanrei/web` in a real React component with typed props and event handlers. The wrappers are generated from the custom elements manifest, so they always match the elements they wrap.

<ReleaseNotice platform="web" registry="npm" pkg={["@tanrei/react", "@tanrei/web"]} />

## Install

React 18 or later is required.

### From npm

```sh
npm install @tanrei/react @tanrei/web
```

### From source

To use the source as it stands on `main`, do as for the [Web package](/getting-started/web/) (Git, Node 22.22 or later, pnpm 12): build both packages in a clone of the repository and pack them,

```sh
git clone https://github.com/chnotchy/tanrei.git
cd tanrei
pnpm install
pnpm --filter @tanrei/web --filter @tanrei/react build
pnpm --filter @tanrei/web --filter @tanrei/react pack --pack-destination ../tanrei-packages
```

then install both packed files in your project with one command, so that the React package finds the Web package beside it:

```sh
npm install path/to/tanrei-packages/tanrei-web-*.tgz path/to/tanrei-packages/tanrei-react-*.tgz
```

## Use

Load the stylesheets once, before the components render: `tanrei.css` is the base of the page, the tokens and every other stylesheet of the package in one file. To load them one by one, see the [Web guide](/getting-started/web/).

```tsx
import '@tanrei/web/tanrei.css';
import '@tanrei/web/words/en';
import { Button } from '@tanrei/react';

export function Toolbar({ onDeploy }: { onDeploy: () => void }) {
  return (
    <>
      <Button variant="filled" onClick={onDeploy}>
        Deploy
      </Button>
      <Button variant="text" size="small" disabled>
        Roll back
      </Button>
    </>
  );
}
```

Props carry the same names as the element's attributes (`variant`, `size`, `disabled`). Events are ordinary React handlers. An element's own event is `on` and the event's name in camel case, as React names its own (`onKeyDown`): a navigation drawer fires `expandedchange`, and you listen with `onExpandedChange`.

`@tanrei/web/words/en` gives a word in plain English for every label and message the components draw or say, such as a required tag's or a close button's; leave it out and give your own with `setWords()` from `@tanrei/react`. See [Words](/foundations/words/).

## One entry per design system

The package has an entry for each design system Tanrei ships, so that your editor offers, and the type check accepts, only what your system has:

| Entry | What it exports |
|---|---|
| `@tanrei/react` | The components of the default system, Tanrei. The FAB menu, which lives in the m3-like layer, and the segmented button, which Tanrei leaves out, are not in it, and a variant Tanrei leaves out is not a value of the prop: `<TextField variant="outlined">` does not type-check |
| `@tanrei/react/m3-like`, `@tanrei/react/m3-expressive-like`, `@tanrei/react/cupertino` | The components of that preset, with its variants |
| `@tanrei/react/advanced` | The advanced components, the building blocks of others: `TextInput`, `ModalLayer`, `Combobox` and the rest. A product usually writes the component built from one — `TextField`, `Dialog`, `ComboboxField` |
| `@tanrei/react/all` | Every component, whichever system has it: for a design system of your own, and for building one |

```tsx
import '@tanrei/web/tokens.css';
import '@tanrei/web/systems/m3-like.css';
import { FabMenu, FabMenuItem, TextField } from '@tanrei/react/m3-like';
```

A component is the same in every entry, so a bundler still keeps only what you import. Every entry also exports `setWords`, `missingWords` and the `TanreiEvent` type. The entries are generated from each system's components manifest, `@tanrei/web/systems/<id>.components.json`, which names the entry of each component (`react.import`); the manifest of your own system, which `tanrei build` writes, names `@tanrei/react/all`.

## Server rendering

On a server, where there is no `document`, a component renders its element's tag with each prop the element reads from an attribute written as that attribute, under the attribute's own name. The first HTML already carries the label, the value and the states:

```tsx
<TextField label="Email" value="ada@example.com" required maxLength={80} readOnly={false} />
// <tanrei-text-field label="Email" value="ada@example.com" required="" maxlength="80"></tanrei-text-field>
```

A prop at its default writes nothing, so a `false` is never written as present. A boolean that is on by default and turned off writes the attribute the element reads as off: `<CopyButton iconOnly={false} />` writes `icon-only="false"`, `<BottomSheet handle={false} />` writes `no-handle`. Handlers, objects and arrays are set in the browser, once the component mounts. The shadow root is not rendered on the server: the element draws itself when its definition loads, and React hydrates the tag without a mismatch.

### Next.js (App Router)

The components use refs and layout effects, so they are used from a client component. Import them in a module marked `'use client'`; a server component can render that module, and Next.js still renders it on the server for the first load.

```tsx
// app/sign-up.tsx
'use client';

import '@tanrei/web/words/en';
import { Button, TextField } from '@tanrei/react';

export function SignUp() {
  return (
    <form action="/sign-up" method="post">
      <TextField name="email" type="email" label="Email" required />
      <Button type="submit">Sign up</Button>
    </form>
  );
}
```

```tsx
// app/layout.tsx
import '@tanrei/web/tanrei.css';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

```tsx
// app/page.tsx (a server component)
import { SignUp } from './sign-up';

export default function Page() {
  return <SignUp />;
}
```

Lit's server renderer (`@lit-labs/ssr-react`, `@lit-labs/nextjs`) is not supported: it renders the shadow root on the server, and many of the elements read their children and the document while they render, which it does not provide, so they fail under it. Leave it out; the attributes above are what the server sends.
