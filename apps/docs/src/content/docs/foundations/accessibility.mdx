Accessibility in Tanrei is a set of constraints on the system itself. The token build refuses to produce a scheme that fails contrast, and a component spec is not valid without its role, keyboard table and target guarantee.

## Contrast

The token build measures every scheme, light and dark at standard, medium and high contrast, against these thresholds, and fails when a pair falls short:

| Content | Standard and medium contrast | High contrast |
| --- | --- | --- |
| Text, and icons drawn in a content color | {contrast.text} | {contrast.highContrastText} |
| A status's mark on its own tonal container | {contrast.nonText} | {contrast.nonText} |
| Boundaries and graphics needed to identify or operate a control | {contrast.nonText} | {contrast.nonText} |
| The focus ring against adjacent surfaces | {contrast.nonText} | {contrast.nonText} |

Large text has no lower threshold. WCAG accepts less contrast for text of about 24px regular, or 19px bold, and up, but the build holds every text role at {contrast.text}, and at {contrast.highContrastText} at high contrast: a color role does not know the size it will be set in.

Disabled elements and pure decoration are exempt, and so is the `outline-variant` hairline at standard contrast. That exemption is why a border which is the only sign of a control must use `outline`, not `outline-variant`.

### Enforced invariants

These hold for every theme at every contrast level, six permutations in all, and the build fails otherwise:

- each `(X, on-X)` role pair, and each text role (`on-surface`, `on-surface-variant`, `link`, an intent's color) on every surface role, is at least {contrast.text}, and at least {contrast.highContrastText} in the two high-contrast schemes;
- each status color is at least {contrast.nonText} against its own tonal container;
- `outline` is at least {contrast.nonText} against every surface role;
- in the default system at medium and high contrast, `outline-variant` is at least {contrast.hairlineMedium} and {contrast.hairlineHigh} against every surface role, and `outline` stays stronger;
- `focus-ring` is at least {contrast.nonText} against surfaces.

Project rules forbid loosening a threshold to make a check pass.

## Target size

<DimensionScale group="target" source="tokens/sys/measure.tokens.json" />

**Nothing a person presses is drawn smaller than the minimum.** `sys.target.minimum` is 36 in the default system: a button, an input box, a tab or a row is drawn at least that high whatever the density and the size, and an icon-only button at least that wide, so a small button, which the size ladder draws at 32, is drawn 36 high. A mark drawn smaller than the target, such as a checkbox's box or a small chip, keeps its size and extends its hit area to `sys.target.touch` for touch and `sys.target.pointer` for a fine pointer. Both equal the minimum in the default system; a system that sets them higher takes a press from that larger area. Every spec declares this guarantee. [Size and density](/foundations/size-and-density/) shows the heights, and how a product sets the minimum.

## Focus

Every interactive component shows the gap-then-ring focus indicator for keyboard and assistive-technology focus, immediately and without animation. Focus order follows reading order. Disabled components leave the focus order.

## Keyboard

Each component spec contains a table of keys and actions, shown on its documentation page under **Accessibility**. Platforms with hardware keyboard support implement the table exactly.

## Text scaling

Interfaces must remain usable with text at **200%**. Containers grow with their text, labels wrap before they truncate, and nothing relies on a fixed height to fit a line of text. Native implementations use each platform's scalable text mechanism.

## Reduced motion

Motion is reduced when the person's system setting asks for it, or when the product sets `data-tanrei-motion="reduce"` on the root element for a setting of its own. Spatial animation is then removed or replaced by a brief fade, and what shows work under way — a loading indicator, an indeterminate progress indicator, a busy button — stops turning or sliding and fades its opacity out and back once per cycle instead. See [Motion](/foundations/motion/).

## Semantics

A spec names the component's WAI-ARIA role and how its accessible name is formed. Each platform maps the role to its native equivalent: accessibility traits in SwiftUI, semantics properties in Compose and Flutter, `accessibilityRole` in React Native. On the web, Tanrei prefers native elements inside the shadow root, so that browsers and testing tools see real semantics.

## How it is tested

| Platform | Automated check |
| --- | --- |
| Web | axe-core in Playwright |
| SwiftUI | XCTest accessibility audit |
| Compose | Accessibility Test Framework checks |
| Flutter | `meetsGuideline` matchers |
| React Native | role and label assertions, plus native audits through the gallery app |

<Callout>
  Automated checks catch a minority of real problems. They are a floor. Use a screen reader and a keyboard on anything you build with these components.
</Callout>
