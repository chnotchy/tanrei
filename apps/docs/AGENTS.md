## Component pages

- Prose lives in `src/content/docs/components/<name>.mdx` and `src/content/docs/ja/components/<name>.mdx`. The parity checker requires **both** files at exactly these paths.
- Keep the four sections, in order: Overview, Specs, Guidelines, Accessibility. Place `<ComponentAvailability>`, `<ComponentSpecs>` and `<ComponentAccessibility>` under the matching heading; write only when-to-use, do/don't, content and guidance prose yourself.
- Per-platform samples use `<Tabs syncKey="platform">` with the tabs Web, React, SwiftUI, Compose, Flutter, React Native, in that order, using the idiomatic names from `spec.platforms.*`. `Tabs` and `TabItem` are the docs' own (`import { Tabs, TabItem } from '…/components/tabs'`), drawn by Tanrei's Tab view: sets with one `syncKey` share a choice and remember it (`components/tabs/keys.mjs`); a tab whose label is not ASCII needs a `value`, the same in both languages.
- The page is in the sidebar once the status file lists it (`pnpm generate`): the `Components` group of `astro.config.mjs` is made from `docs/status/status.json` (`src/lib/listing.mjs`), in groups by category. Do not write a component's slug there by hand.
- What a list of components shows follows the design system the reader chose — the default system until they choose another (the header's menu beside the brand, `src/components/frame/Header.astro`, and the index's `src/components/SystemSelect.astro`, kept under the docs' key for the shared choice `system`, as a set of `<Tabs syncKey="system">` keeps its own): a component the chosen system's components manifest lists among what it does not have is not drawn in the sidebar or the index, except its own page in the sidebar while it is read. Code reads the systems from the manifests (`manifests`, `src/lib/repo.ts`) and never writes a system's name or a component's.
- What a list of components shows follows the spec's `listing`: the sidebar and the index show a component marked to be shown on request only to a reader who turned on "All components" (`src/components/ListingSwitch.astro`), its page is always built, found by the search and shown in the sidebar while it is open, and the head of its page says what it is a part of (`src/lib/page-head.ts`, `listingFacts`). Code asks `listings.listed` and `listings.onRequest` (`src/lib/repo.ts`) and never writes a listing's name.

A generated block that writes headings (`StatusMatrix`, `Roadmap`, `Backlog`, `ComponentIndex`) takes `headingLevel` from the page that places it: 2 directly under the page's title, one more than the heading it stands under otherwise. A Markdown table's first header cell says what its column holds; it is never left empty.

## The fixtures' gallery

The Specs tab draws every fixture of the spec, each on a stage of its own (`src/components/fixtures/FixtureGallery.astro`): Tanrei's Figure with the fixture's id as its title, the props that make it as its caption, and two actions in its header — the stage's scheme and the copy of the fixture's markup as a product writes it. The stages stand in groups by the first token axis of the spec that tells its fixtures apart, and in one column: one stage to a row, each as wide as the column, never side by side. Which stage a fixture takes is `src/lib/fixture-gallery.ts`'s, from the spec alone:

- **In the page**: a fixture that is not presented is drawn in the page's document, at its own size in the middle of its stage. One that is as wide as its layout (the renderer gives it the width of the web harness's stage) starts its stage at that width, fills it, and has a width handle on the stage's end edge.
- **In a window**: a presented fixture is drawn alone, presented, in an `iframe` of the component's fixture document (`/fixtures/<name>/?id=<fixture>`), at the size of the stage its baseline was taken of (else of the window the web harness draws it in), scaled down where the column is narrower. Every fixture of a spec the site's own renderer cannot draw (`drawsLive` in `src/lib/fixtures.ts`: a class on the product's own elements, items that are native elements or nest two deep, a frame of a whole window) is drawn the same way. What it puts in the top layer or places against the window stays in that window, and what reads the window's width reads the stage's. A window is `inert` until what it draws has opened, so that it never takes the focus from the page as it loads. The host lets this site, and no other, frame a fixture document (`/fixtures/*` in `public/_headers`: `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`); every other document is framed by no page (`DENY`, `'none'`), and a page frames only the site's own documents (`frame-src 'self'`). A window the browser refused to draw is let go of `inert` at once.

The fixture document is the windows' only, and no reader's page: it stands outside the site's frame, draws one fixture (`?id=`) and nothing without one, and is linked from nowhere — no stage's action and no link of a page opens it, the site's search does not index it, it says `noindex`, and the sitemap leaves out every page under `/fixtures/` (`astro.config.mjs`). It is the web package's own document of a component's fixtures — the one its tests draw every fixture in and take each baseline from (`fixturesDocument` in `packages/web/test/harness.ts`) — with the site's tokens, faces and components: what a window shows is what every platform's baseline is compared with. The harness reads the repository relative to its own file, so the site's build cannot run it; `scripts/fixture-documents.mjs` runs it with Node before `dev`, `build`, `validate` and `test:node`, takes each document apart (its stylesheets, its stages, its step in script) and reads each stage's size from its baseline (a picture at a device pixel ratio of 2), into `src/fixture-documents.generated.json`, which git ignores. Never draw a fixture's staging a second time in the site: where the site needs it, ask the document.

Nothing is drawn before it is near the view. A window loads when it comes near it, in a box that takes the window's proportions before anything loads. A fixture of the page and a stage's actions are written in templates and drawn — with `document.importNode`, so that a component's children are defined before it is connected, as when the page is parsed — once their stage is within half a window of the view; until then the canvas holds the room the fixture's baseline shows (its stage in the web package's snapshots, less the stage's padding) and the header the room of its actions. Drawn half a window early, a fixture that takes more room than its baseline grows away from the view. Do not use `content-visibility: auto` on a stage instead: a stage not laid out has no size, and a component that measures its place once keeps what it chose in no room (the description list's terms stacked above values that fit beside them). The width handle is a window splitter (`src/components/fixtures/ResizeHandle.astro`, `src/lib/resize-handle.ts`) that resizes nothing itself: it reports each width as a `docs-resize` event, so that Tanrei's own splitter can take its place by sending the same event.

## Figures drawn from the repository

A figure the site draws from the repository — the parts of a component, its lengths, its states, its motions, its color roles, its controls — stands in `VisualFrame` (`src/components/visuals/`), and what it shows is made by `src/lib/visuals/` from the spec and the resolved tokens, never written into a page: a page writes the figure's one line, and the six languages share it. What the frame does for every figure:

- **It holds its room before anything is defined.** `reserve` gives the canvas its size as tokens (`{ block: 'comp.button.container.height.medium' }`; a list is a sum), and what the figure shows stands in one row at that size, scrolling sideways inside the stage where the column is narrower, never wrapping into rows the reserve does not hold. What a figure lays over its stage (numbers, lines, labels) goes into the overlay, absolutely placed, drawn by script once the elements are defined and the figure's time has come (`whenDrawn` in `src/lib/visuals/frame.ts`: near the view, when the browser is idle, or at once). Do not use `content-visibility: auto` on it, for the reason the fixtures' stages do not.
- **It is drawn under the default system.** A preset is behind the switch in the header (`controls="system"` or `"both"`): its stylesheet is loaded when its tab is pressed, once for the page, and the choice is the figure's alone — not shared with another figure, not remembered, and not the header's choice of system, which decides what the lists show.
- **Its words are the page's.** The title is the page's or the dictionary's (`visuals` in `src/lib/i18n.ts`, the same keys in the six languages); what comes from a spec — a part's description, a requirement — is shown as written, in English (`i18n/README.md`). A figure's text alternative is made from the dictionary's sentence for its count (`anatomyAlt`, one for each plural form the language has).

`test/browser/visuals.test.mjs`, a file of `test:browser`, opens the first page that draws a figure in `VisualFrame` (the button's) at 390 and at 1440 wide and asks that the figure's stage and its header take the same room before its elements are defined (its scripts held back until the page is parsed and drawn) as once they are, and that what it shows stands in one row; and that it is drawn under the default system, no preset's stylesheet is asked for with the page, and choosing a preset loads its stylesheet once and draws the stage, and nothing outside it, with that system's tokens.

### The state matrix

A component's states are drawn by `<StateMatrix name="…" />` (`src/components/visuals/StateMatrix.astro`, `src/lib/visuals/states.ts`): Tanrei's Table in the figure frame, a row for each value of one choice (`variant` where the component has one; twice, off and on, for a component that is selected or not), a column for each state the docs can show, and the states it cannot show named under it. Every cell is the live component, made from the web package's own fixture document of the spec's first fixture with the row's and the column's props set on its web element, holding the room of that fixture's baseline before it is defined. A component whose first fixture's document does not hold its web element (a class on a native element, a stage that wraps it) has no matrix, and the build says so.

- **The browser's states are restyled on the docs' side; the component gets no attribute for them.** Hovered, focused and pressed are the browser's own conditions (`:hover`, `:focus-visible`, `:focus-within`, the `data-pressed` a press controller writes), which nothing of a component's public surface can set. `src/lib/visuals/pseudo-states.ts` copies each rule of the element's shadow root that names one, with the condition taken out and `[data-docs-state~="<state>"]` required of the host instead, at the same specificity, right after the rule it copies (out of `@media (hover: hover)`, so a touch screen shows hover too), and sets that attribute on the cell's element only. A condition inside `:not()`, `:is()`, `:where()` or `:has()` is left as it is. A press is drawn as the figure's system answers one (`sys.behavior.pressed-feedback`): a ripple as the overlay it ends as, nothing where the system answers with nothing. Nothing in a held cell moves: its transitions are off.
- **A cell is a picture.** What it draws is `inert` and `aria-hidden`, so Tab does not pass through it, and the cell says in words what it shows, read with the table's headers.

`test/browser/state-matrix.test.mjs` opens the button's page and asks that every cell's container and label compute to what the default system resolves that variant's state tokens to (and, under a preset chosen in the header, that system's), that the table takes the same room with its scripts held back as once drawn, at 390 and 1440, and that nothing in it takes the focus or is exposed.

## Adding a page in both locales

1. Create `src/content/docs/<path>.mdx` (English is the root locale) and add its slug to the sidebar in `astro.config.mjs`.
2. For Japanese, create `src/content/docs/ja/<path>.mdx` with the same path. Relative imports need one more `../`. Internal links start with `/ja/`.
3. A page without a Japanese file falls back to English with Starlight's notice. That is preferred over a partial or machine-quality translation: translate a page completely and naturally, or not at all.
4. A page may carry a `date` in frontmatter; the page's head then shows it. Release notes are the packages' `CHANGELOG.md`, not pages of the site.

## Writing

- All prose is original. Never copy or closely paraphrase text from m3.material.io or any other design system's documentation.
- Tanrei is independent, and is described by what it is. Another design system is named only for a preset, a fidelity note, a dependency or a data source.
- Be honest about availability, and write install pages as they read once a version is released. A published package's page gives the registry install first ("From npm") and building from the source second ("From source"); a paused platform's page gives the steps from the source first and the registry steps under "Once it is published". Every install page carries `<ReleaseNotice>` (`src/lib/release-notice.ts`), which says what differs today — a prerelease and its dist-tag, a paused platform not yet published — from `tanrei.config.json`'s version and `packages/tools/paused-platforms.json`, and draws nothing once nothing does. No page states the version, the tag or what is published in its prose. The home hero's eyebrow says "prerelease" from the same version (`heroEyebrow`), and an example's content never reads as a statement of Tanrei's own release.

## Look and feel

`src/styles/tanrei-theme.css` maps Starlight's `--sl-*` variables onto `--tanrei-*` tokens. Use tokens for every color, radius and type value; do not introduce literals. The file is unlayered on purpose so it overrides Starlight's layers. Starlight's `data-theme` drives `color-scheme`, which is all the `light-dark()` tokens need. The contrast switch sets `data-tanrei-contrast` on `<html>`.

Every stylesheet `@tanrei/web` ships is loaded once, for every page, by `src/styles/prose.css` (the frame's by `frame.css`), into a layer of the docs' own: each is written in `tanrei.components`, which on this site comes before Starlight's layers, so a copy that arrives as written — through another package's bundle (Theme Studio carries the Tree view's and the Accordion's) or a component's `<style>` — loses to Starlight's reset. No component of the site loads one (`test/stylesheets.test.mjs`). Whether every live example and spec fixture is then drawn as the package draws it is asked of the built site in a browser (`test/browser/previews.mjs`).

The faces are registered by `src/styles/fonts.generated.css`, written before every `dev`, `build` and test by `packages/tools/src/font-faces.js` (gitignored, as are the font files it cuts). The icon families come from files cut down to the glyph names the site draws. Noto Sans JP, which comes in about 120 files by Unicode range, each taken whole for any one of its characters, is also cut down to the Japanese characters that the specs and the pages not in Japanese or Chinese hold (`--text-cut`, `--text-from` in `package.json`), as "Noto Sans JP Cut": on a page whose language is not Japanese each stack names it before Noto Sans JP, so the Japanese that page quotes is drawn with the same glyphs from a few small files; a character the cut does not hold falls through to the family's own files. A font file is never inlined into a stylesheet (`assetsInlineLimit` in `astro.config.mjs`): every page would carry it. Japanese written into a component's code rather than its spec or its page is not in the cut — it is still drawn, from the family's files (`test/browser/icon-font.test.mjs` checks the Button page).

Tables and notices are Tanrei's Table and Callout. A Markdown table and a `:::note[Title]` directive (`tip`, `caution`, `danger`) are written as Markdown and converted at build time (`src/lib/markdown.mjs`); in MDX a notice is `<Callout type="caution" title="…">` from `src/components/Callout.astro`, and a table one of the docs' components writes goes inside `src/components/Table.astro` with a `label`. Do not style a table, a cell or a callout in the theme file: say it with the component's attributes (`data-align`, `data-wrap="false"`, `rowHeaders`, `stickyFirstColumn`, `density`). A column's `data-align` and `data-wrap="false"` go on its header cell and on each of its cells (the page is drawn before the element is defined, and without script); what the header cell says is the whole column's, so the header of a column whose cells wrap does not say `data-wrap="false"`.

A tree of files is Tanrei's Tree view inside Tanrei's Figure: `<FileTree>` from `src/components/FileTree.astro` around a Markdown list. An item's first word is its name and the rest is a note in the page's language; a name that ends with a slash, or an item that holds a list, is a folder. Nothing in it can be chosen (`selection` is `none`), every folder is written open, and the list stays in the document, readable with scripting off. Pass `label` where "Files and folders" does not say what the tree is. Do not import the framework's `FileTree`.

The page that was not found is the docs' own: `src/pages/404.astro` and `src/pages/[locale]/404.astro` draw `src/components/NotFound.astro` — Tanrei's Empty state at the large size, whose title is the page's `h1` — inside the page frame, with words from `src/lib/i18n.ts` (`notFound`). The framework's own is off (`disable404Route`). A language's page is built as `<language>/404/index.html` and copied to `<language>/404.html` (`src/lib/not-found-files.mjs`), which is what a host that answers with the nearest `404.html` serves.
A frame around something to look at — a live example, a specimen, a row of systems — is Tanrei's Figure, written as its native parts (`<tanrei-figure><figure><div data-part="frame">…`), so `@tanrei/web/figure.css` draws it before the element is defined; a list of facts is Tanrei's Description list around the page's own `dl`. Do not draw a frame, a caption or a `dl` by hand: what a component of the docs adds is the arrangement inside the stage and, where the look must differ, a component token set on the element (the hero's larger corner). Every figure has a name before any script runs: `aria-labelledby` names its title, or its caption where it has no title, with an id from `src/lib/figure-id.ts`, and a figure that draws neither takes `aria-label` from `src/lib/i18n.ts`.

Code is Tanrei's Code block and Inline code; the framework's code component and its highlighter are off (`expressiveCode: false`, `markdown.syntaxHighlight: false`).

- **A fenced block** is written as Markdown and becomes `<tanrei-code-block>` at build time (`src/lib/markdown.mjs`), highlighted there by `@tanrei/web/highlight`, so its colors are in the first paint and the browser loads no highlighter. The fence's first word is the language (`html`, `css`, `js`, `jsx`, `ts`, `tsx`, `json`, `sh`/`bash`, `swift`, `kotlin`, `dart`; `text` for none — a language without a grammar is drawn plain and the build warns). Every block gets a copy button and a name for assistive technology (the heading above it and the language); a shell block gets the prompt `$`.
- **The rest of the fence's first line is the element's attributes**, written as HTML: ```` ```ts title="sizes.ts" line-numbers highlighted-lines="3, 7-9" ````. There is no other fence vocabulary (no `{2}` marks, no `ins=`/`del=`, no frames); an attribute the step does not know fails the build. `copy="false"` and `prompt=""` remove what the step adds. The words of the copy button and of a marked line come from `src/lib/i18n.ts` (`code`), in the page's language.
- **A block written by hand** in MDX — a demo, a block built from a string — is `<tanrei-code-block><pre><code>{source}</code></pre></tanrei-code-block>` and is left as written. Do not import a `Code` component from the framework.
- **Inline code** is any `code` outside a `pre`: `MarkdownContent.astro` gives each one the class `tanrei-code` with `translate="no"` and `spellcheck="false"`. Its variant comes from the nearest ancestor's `data-tanrei-code`: the docs' own tables (`Table.astro`) and fact blocks say `plain`; running text says nothing (tonal). Do not style `code` or `pre` in the theme file.

A control, a row of names and a measure the site draws are Tanrei's too; no component of the site and no page writes a native `input`, `select`, `button`, `details`, `fieldset`, `progress` or `meter` of its own (`test/adoption.test.mjs` names the places still owed — a key written as `kbd`, the icons page's example — each with what it waits for). A choice of one that switches what is drawn is the Tabs (`ContrastSwitch.astro`: the page's contrast, three secondary tabs after the word «Contrast», its help Tanrei's Tooltip around the row and each tab's description; its rows are the group `page-contrast` and keep the choice under the key the head's script reads), a choice of one that only sets a value the Radio group, a setting that is on or off the Switch (the typescale's flip), a measure the Progress indicator (the roadmap's bar), a row of names the Tag group of `NameTag.astro` (a component's states, the values of a choice of kind), a list of facts by platform the Description list. Three rules come with every such element, because its words are attributes and its box is drawn by script:

- **It holds its room before it is defined.** A rule written with `:not(:defined)` on the element's own class gives it the box it will take, from the component's own tokens, with its words drawn from its attributes (`content: attr(label)`) where they decide the size — measured equal to the drawn box in the six languages at 1440 and 390 before it lands.
- **Without script it is either readable or gone.** A name stays a word (the same `attr()` text); a control that can do nothing without script is not drawn (`@media (scripting: none)`, on the same `:not(:defined)` selector — a rule of the class alone loses to the one that holds the room).
- **Its words come from `src/lib/i18n.ts`**, in the six languages, and a word that is only an attribute and should be found is given to the search index (`data-pagefind-index-attrs`).

The search is Tanrei's Search (`src/components/frame/Search.astro`, in the app bar). The component searches nothing: the page's script loads the search index the framework's build writes (`/pagefind/`, one for each language, on the first use and never before), asks it, and gives the element a page as a result group, a section as a result, the excerpt as runs of text and the count as its status text; nothing found is Tanrei's Empty state in the view. What turns the index's answer into those values is `src/lib/search.mjs`, without a browser in it; every word is in `src/lib/i18n.ts` (`search`). Do not import the framework's `Search` component or the index's own interface, and never insert the index's excerpt as markup. The index answers a word it does not have with the pages of a shorter beginning of it and does not say so: the script shows them only where a marked word begins with a typed one, or the index has the word when asked for it alone, between quotation marks (`answersAsTyped`, `exactQuestions`); otherwise nothing was found. The element itself is defined on its first use, not with the page: until then the stylesheet draws the trigger and the script makes that drawing a button with the search's name (Tab, a press, Enter, Space, both chords); a pointer over it or focus on it defines the element, and what is typed after a chord before the field is there goes into it. `data-define-on-use` keeps `src/lib/define-on-demand.ts` from defining it with the page; `test/browser/search-on-use.test.mjs` opens it each way, cold and warm, and prints how long the view took to take focus (`DOCS_ENGINES=chromium,firefox,webkit` for the three engines).

What the index reads is the built page's main region (`data-pagefind-body` on the framework's `<main>`), less what stands under `data-pagefind-ignore`. Three rules follow, for every component of the docs:

- **A live example is not text of the page.** Its stage — `DemoFrame`'s, a stage of the fixtures' gallery and its actions, a row of systems — carries `data-pagefind-ignore`: «Save» in a sample button is not what the page says. A figure's title and caption are, and are read.
- **A glyph's name is not a word.** A `span` that holds a ligature's name (`slot="icon"`, `slot="media"`, `class="tanrei-icon"`) carries `data-pagefind-ignore`; `test/search.test.mjs` reads the sources for it. A word that is only an attribute and should be found (a status tag's `label`) is given to the index with `data-pagefind-index-attrs`.
- **Words that stand side by side need white space in the markup.** The build removes it between tags, and the index then reads one word. Terms, descriptions, cells and tab panels are parted for every page by `src/lib/index-text.mjs` (in `frame/TwoColumnContent.astro`); anything else a component writes side by side — the items of a flex row or a grid — gets `{' '}` between them, which is drawn nowhere. Not between inline boxes of one line: a space there is drawn. Two inline boxes that must be two words and stand with no space (a file's name and its note in a tree, which the Tree view sets apart by its own gap) get a hidden line break between them, `<br hidden>`: the index reads a break as the end of a word, and a hidden element makes no box. What the index reads is asked of the index itself in a test (`test/index-reads.mjs`), not of a model of it.

## Running

```
pnpm --filter @tanrei/web build    # the docs load the built web package
pnpm --filter @tanrei/docs dev
pnpm --filter @tanrei/docs validate   # astro check: type errors and warnings in .astro / .ts fail
pnpm --filter @tanrei/docs build      # astro check, then the site (`test` builds it again)
pnpm --filter @tanrei/docs test:node  # Node's runner, no browser and no build of the site (about 3 s): test/*.test.mjs
pnpm --filter @tanrei/docs test:browser  # the built site (`build` first) in Chromium, a few minutes: test/browser/*.test.mjs
TEST_SHARD=2/3 pnpm --filter @tanrei/docs test:browser  # every third file of them, as the second of CI's three docs browser jobs runs
```

`test:browser` holds one thing: `test/browser/previews.mjs` (run by `previews-light.test.mjs` and `previews-dark.test.mjs`, a scheme each) opens every page of the root language that draws a live example, a spec fixture or a file tree, in both schemes, and compares each with a copy of its markup drawn beside it by the page's own rules under every stylesheet of `@tanrei/web` (`compare-previews.mjs` says how). A box, a margin, a color or a pseudo-element's glyph that differs is the page doing to a component what its stylesheet does not allow: a stylesheet in a layer Starlight's beat or not loaded, a page rule that reaches into a component, fixtures that share one document's state (a radio group's `name`). What it leaves out is said there: the fixtures drawn in a window of their own (an `iframe` of the component's fixture document), those the page stages files into, and the parts placed against a box outside the preview.

It holds a second: `test/browser/fixture-gallery.test.mjs` opens every component page at 1440 and at 390 wide and asks that the Specs tab has a gallery with one stage for each fixture of the spec, that every stage stands inside the column and the window, that what each fixture draws stands inside its stage and has both its lengths, and that the page never scrolls sideways; for every component, that its fixture document draws a fixture alone, whole, in a window of its baseline's size; and that no page links to a fixture document and the sitemap lists none.

And a third: `test/browser/fixture-windows.test.mjs` opens a page of presented fixtures (the Dialog's) and one whose windows grow to hold their documents (the Scroll area's), scrolls to each window, and asks that a fixture is drawn in it with every element defined, that the browser refuses no frame and the page throws nothing, and that every window is let go of `inert`.

Every file of `test:browser` serves `dist/` through `test/browser/host.mjs`, with the headers `dist/_headers` gives each path, read as Cloudflare Pages reads them (every matching rule in the file's order, a header two rules set joined, `! Name` detaching one): a header that refuses something on the site refuses it in the tests too. `test/headers.test.mjs` (in `test:node`) reads `public/_headers` the same way and asks that each document is sent one `X-Frame-Options` and the framing policy above.

And a fourth: `test/browser/seo.test.mjs` reads every built page's head — one image of a shared link that the site serves as a PNG of 1200 × 630, `og:locale` and its alternates, structured data that parses with what its type needs, a title no other page of its language has, no author but the repository's owner — and opens a few pages to load the image they name.
