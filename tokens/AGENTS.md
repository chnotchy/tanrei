# tokens/ — local rules

- Format: DTCG 2025.10. `$type` on groups, object values for `dimension`/`duration`/`color`, aliases in braces. The resolver is `tanrei.resolver.json`; pin `$schema` to `/schemas/2025.10/`.
- Tiers, in reference order: `dial` (the few numbers everything is derived from) < `ref` (raw options) < `sys` (decisions; names are public API) < `comp` (a component's bindings). A token may reference its own tier or a lower one.
- **Every token's value is one of three kinds**: an **alias** (`"{tanrei.sys…}"`, re-pointable); **derived** — a rule in `$extensions["dev.tanrei.derive"]` such as `{ "fn": "mul", "of": "{tanrei.dial.space.unit}", "by": 1.75 }`, written next to the literal `$value` it produces at the dial defaults (the build fails if they disagree); or **fixed** — `{ "fixed": "<why no dial should move this>" }`. A bare literal is rejected.
- **Every token needs a one-product rationale** in `$extensions["dev.tanrei.vocabulary"].rationale`, on the token or inherited from its group: why might *one product* need this distinction? "Material has it" and "Button uses it" are not reasons.
- `vocabulary.lock.json` is generated. If it changes, the vocabulary changed — say so in the PR and the changeset.
- `generated/` is produced from `systems/<id>.system.json` by `@tanrei/token-engine`. Never edit it. To change colors, change that system's palette declarations or role rules (and bump `specVersion` for meaningful role-table changes).
- `systems/` holds design-system layers. A layer changes values; it cannot add token ids except through its `vocabulary` extensions. New vocabulary must pass the one-product test.
- **A component lives in the layer every system that ships it descends from.** Most live in the root, their documents in `comp/`. One that a single line of systems ships lives in that line's root: the FAB menu, in `m3-like` (and so in `m3-expressive-like`). That layer declares the component's whole vocabulary under `vocabulary` — `"tanrei.comp.<component>": { "document": "comp/<component>.tokens.json", "rationale": "…", "rules": [ … ] }` — and keeps the document next to it (`systems/<layer>/comp/<component>.tokens.json`, a component document like those in `comp/`, its ids still `tanrei.comp.<component>.*`); `rules` are the rules that value the component's own states. Only the systems that descend from the layer have the component; the others neither ship nor leave it out, and their stylesheets say where it lives (`--tanrei-unavailable-layer`). A product on another line takes it with `components.include: [{ "name": "<component>", "from": "<layer>" }]`: the document and its rules come, valued with the product's own tokens, and none of the holding layer's values. The component's spec and its row in `specs/inventory.json` say `"layer": "<layer>"`; `pnpm validate` holds that they agree with the layer, that one layer at most declares a component, and that a component that lives in a layer has no document in `comp/`. `vocabulary.lock.json` lists its ids under `layers.<layer>`, so moving a component into a layer is a move, not a removal.
- **The root layer is `systems/core.system.json`**: the one layer without `extends`, the first of every chain. The default system (`systems/tanrei.system.json`) extends it, and so do the presets `m3-like` and `cupertino` (`m3-expressive-like` extends `m3-like`): a preset inherits nothing of the default system's own layer. The root has no output of its own and is not offered where a system is chosen.
- **The default system's layers — the root and `tanrei.system.json` — set generated values only**: palettes, color roles, per-state component tokens, and component colors valued by a color rule — what lands in `generated/`. The default system is the documents here as they are written, so every other default is changed in its own document (`dial/`, `ref/`, `sys/`, `comp/`), and a new core token is written there too, with its rationale. A line for such a token under either layer's `tokens`, or a declaration under its `vocabulary` that is not a color role, would reach every system that extends it and never the default system: `pnpm validate` and `pnpm generate` refuse it and name the document. Vocabulary extensions (a layer's `vocabulary`, each with a rationale, additive only) belong to the layers above them.
- **A system's components are a change to its parent's**: `components.omit` (with a `reason`, and `insteadUse` naming what the system ships for the same job), `components.include` (brings back what an ancestor left out by its name; takes a component that lives in a layer the system does not extend with `{ "name", "from" }`), `components.variants.<component>.omit|include`. The root leaves nothing out; an ancestor's choice stays unless a layer undoes it by name. `pnpm validate` holds that every name is in `specs/inventory.json`, that a layer leaves out only what its parent ships and brings back only what an ancestor left out, that `insteadUse` names a component the system ships, and that a component's default variant stays.
- `icon-sets/<id>.icon-set.json` holds what an icon set's font cannot tell: the glyph names mirrored in right-to-left, validated by `schema/icon-set.schema.json`. It is data, not a token; a system gets the file whose `families` holds its icon family. The list is regenerated from its `source`, never edited by hand.
- Units are px (= dp = pt = logical px) and ms. Letter spacing is px at the style's own size; emitters convert (em on the web).
- A new component token file must be added to the `comp` set in the resolver, or it does not exist.
- **A group of `comp/` is a component of `specs/inventory.json`, or a set several components read** (such as `comp.input-box`, the box of the text input, the select, the combobox, the number input and the color input). Such a set names its readers (`dev.tanrei.shared.readers`, two or more) and is no component; no reader's own group may repeat one of its names, but those the set lists under `alsoIn` for a part of the reader's own. `validate` holds both (`validateSharedSets`). A value of the set is written once — in the document and in a layer — and a prop bound to one of its axes lists the values its component offers.
- After any edit: `pnpm validate && pnpm generate`, then build the platform packages — the generated Swift/Kotlin/Dart must compile.
