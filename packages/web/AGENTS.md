# packages/web — local rules

- Lit 3, no decorators (`static properties`), one folder per component: `src/components/<name>/<name>.ts`, `<name>.styles.ts`, `<name>.test.ts`. Tag `tanrei-<name>`, class `Tanrei<Name>`.
- Styles use only `--tanrei-comp-*` / `--tanrei-sys-*` custom properties. Private switches are `--_*`. Never a literal color, size, radius, duration or opacity. Beware CSS list values: `none` inside a `box-shadow` list invalidates the whole declaration — use a transparent zero shadow.
- Prefer a native element inside the shadow root (`<button>`, `<input>`) for semantics and keyboard behavior; axe-core cannot see `ElementInternals` roles. Public styling API = `::part()` + documented custom properties; document slots/parts/events in JSDoc so they reach `custom-elements.json`.
- States: each state paints from that state's tokens (no overlay element of the component's own; the only layer is the on-demand `.ripple`); focus is `outline` + `outline-offset` (gap-then-ring), never transitioned; minimum target via a centered `::before`; honor `prefers-reduced-motion`, `forced-colors`, RTL.
- **Compose the primitives, never copy them** (`src/primitives/`, README "Building a component"): `stateRules(on, paints)` (precedence), `PressController` + `pressHold()` (data-pressed, press-hold, ripple lifecycle), `rippleStyles({ color, inset, grow, fade, easing })` (custom property names), `focusRing(on)` + `syncFocusStyle()`, `minimumTarget(selector)`, and `cornerRadius(token)` from `src/styles/shape.ts`. Each takes the component's own selectors and comp tokens. A behaviour two components need goes into a primitive first, with Button moved onto it and every baseline unchanged.
- Choices of kind (`--tanrei-sys-behavior-*`) arrive as the choice's NAME. Read them from the cascade, never from a system id and never cached: static looks with `@container style(--tanrei-sys-behavior-…: <name>)` (add a script fallback only where the look can be drawn without style-query support), interaction-time behaviour with `getComputedStyle(this)` at the moment of the interaction. An unknown name means the first value. What a browser cannot draw falls back to the first value and is stated in `README.md`.
- Corner smoothing (`--tanrei-sys-shape-corner-smoothing`) is an amount, drawn by ONE shared rule (`src/styles/shape.ts`): a component's rounded box carries `data-tanrei-shape` and names its shape token with `cornerRadius(token)` — `--tanrei-corner-radius` plus `--tanrei-corner-pill`, the emitter's `<token>-pill` mark for the `corner.full` step, which draws round caps whatever the smoothing — once per state shape token (never `border-radius` directly); anything concentric with it (a focus ring, a ripple) multiplies its radius by `--_corner-scale` and inherits the curve with `corner-shape: inherit`. The mapping (exponent `2 + s`, radius `× (1 + 0.4 s)`) is the nearest superellipse to Figma's construction (what the amount means), measured against it and against CoreGraphics — do not retune it without re-measuring (`README.md` has the numbers).
- **Motion follows its role** (`docs/architecture/motion.md`, MOT-1 to MOT-6). A duration or an easing a component adds or changes reads its own `--tanrei-comp-<name>-motion-*` token, and that token aliases a role — `sys.motion.role.*` for how long, `sys.motion.easing.enter` / `exit` / `state` / `spatial` for the curve — never a step of the duration scale or a curve of the scale. A surface that appears starts from `--tanrei-sys-motion-appear-{opacity,scale,distance,blur}` (set by `sys.behavior.appearance`; under `unfold` the scale applies along the one axis that leaves the anchor), grows from its anchor or its centre (`appear-origin`), and leaves on the same path backwards, faster, on the exit curve. Never parse a duration from the custom property: compute it through a real property, as the press-hold does. The motion of a surface that appears, of a box that follows its content and of the first frames is composed from `src/primitives/motion.ts` (`appearStyles()` + `AppearController`, `AnimatedSize`; README "Building a component"), not written again in a component. Every element extends `TanreiElement` (shadow root) or `TanreiLightElement` (light DOM) from `src/primitives/element.ts`, never `LitElement` or `ReactiveElement` itself: the base settles it (MOT-3), so its first frames start no transition; the element that a surface's entrance moves carries `data-tanrei-appear`, which settling leaves alone.
- Text is a role of `sys.typescale` (16, by level), used whole (`--…-<role>-font` + `-letter-spacing`); emphasized text takes `--…-<role>-font-weight-emphasized`, never a literal weight. `src/styles/text.css` and `prose.css` are the light-DOM utilities; keep them in step with the roles (the test counts them).
- Controls that stand close in a row (a search bar's action buttons, a floating toolbar's items) keep a touch target's length each: compose `KeptLengths` + `keptLength()` (`src/primitives/kept-length.ts`, SRC-34, TBR-16) — the space is `max(gap, what the two lack)`, never a widened control. Between the product's slotted elements use `keptSpaces()` and give `KeptLengths` the box: the space is a spacer of the box's own.
- **A `z-index` orders the component's own parts, never the page.** A shadow root makes no stacking context, so a part's `z-index` is otherwise ordered against the page's own levels (it rose over a product's sticky header at 1 and took its clicks). A stylesheet that gives a part a `z-index` above 0 puts `isolation: isolate` on its outermost box (the host, or a light-DOM class's root); the levels are `-2` to `4`; what must stand over the page is in the top layer (`popover`, a `<dialog>` opened with `showModal()`), never lifted by a number. The container of repeated items is the outermost box (a drawer, not its groups: a pinned row stands over the other groups' rows). `test/stacking-guards.test.mjs` refuses a level outside the range and an unsealed stylesheet; `src/stacking.test.ts` mounts every fixture and refuses any part ordered in the page's stacking context. Both allowlists only shrink.
- **Never space or place a slotted element with a margin or a padding from `::slotted()`**: a page's rules beat a shadow root's rules for what it slots, whatever their layer, so a reset such as `* { margin: 0; padding: 0 }` (Starlight, Tailwind's preflight) takes them away. The parent makes the spacing (its own `gap`, grid tracks or spacers, its own padding); a negative spacing (an avatar group's overlap) is a grid track shorter than the item. `src/page-reset.test.ts` mounts each such component under that reset. A rule on `::slotted()` reads the SLOTTED element's cascade: never a private `--_*` name of yours there (the item defines its own), and `:host(...)` takes its conditions inside the parentheses (`:host([a]:not([b]))`).
- Pressed is `data-pressed="<feedback>"` on the native element, set on pointer down / Enter / Space without a transition in and held for at least `sys.motion.duration.press-hold` (BTN-8) — not `:active`, which a key press or a tap ends within a frame. A duration token is an expression: compute it through a real property (`.label`'s inert `transition-delay`), never parse the custom property.
- `--tanrei-sys-elevation-level0` is `0 0 0 0 transparent` (an empty layer list), so it stays valid inside a `box-shadow` list.
- Tests are Playwright (`pnpm --filter @tanrei/web test`), driven by the spec's fixtures through `test/harness.ts` (`acmeSystemCss()` mounts the `acme` fixture system: three different state strengths for BTN-3, glow focus, a static icon set). Cite every behavior id. Baselines live in `snapshots/<name>/<fixture>.png`, and under each preset in `snapshots/systems/<system>/<name>/<fixture>.png` (add the component to `SUBJECTS` in `src/systems.test.ts`; `fixtureHost()` finds a fixture's element by the spec's tag); a missing baseline fails. Record with `TANREI_SNAPSHOT_REASON="…" pnpm --filter @tanrei/web test:update`, then look at the images. Baselines are recorded and verified on Linux in the Playwright container CI runs — one recorded on macOS will not match; use the record-baselines workflow (`CONTRIBUTING.md#recording-baselines`).
- Four Playwright projects (`playwright.config.ts`): `chromium` runs everything and owns the baselines (tests titled `snapshot: …`); `firefox` and `webkit` run everything else; `firefox-no-style-queries` runs the BTN-10 tests as a browser without style container queries. A behaviour test must pass in all of them: move focus with `tab()` / `tabTo()` from the harness, never count Tab presses after a click, never compare a serialized `font-family` with its quotes, and measure a press from the input event, not from an observer.
- A test sets or takes off a custom property on the root with `rootTokens(page, { name: value })` from the harness (`''` takes it off), never with a write of its own: a single root token written alone has WebKit restyle the page for seconds (`test/root-tokens.test.mjs` looks). A `snapshot:` loop mounts its one fixture with `mountFixtureAsInAll()`, not every fixture for each picture.
- CSS that turns a length into a number (`calc(<length> / 1px)`) is missing in Firefox, and inside a list value (`font-variation-settings`) it drops the WHOLE declaration. Do not use it.
- **No words**: a product gives every word in its own language. A string prop's initialiser is `''`, and no file under `src/` holds a word a person reads or hears, in any language — not as a fallback either (`src/primitives/words.test.ts` looks). The one exception is the English word pack, `src/generated/words-en.ts` (generated from `specs/words/en.json`, a word for every key), which only `src/words/en.ts` imports: a product applies it by importing `@tanrei/web/words/en`, and nothing imports it on a product's behalf — no entry, component, harness, fixture or test but the pack's own. A word a component draws or exposes is `this.words.get('<key>', this.<prop>)` (`WordsController`, `src/primitives/words.ts`): the instance's prop, else the product's words, else nothing. Where nothing was given and the part is drawn: draw the mark the spec names in its place or nothing, keep the control working, and call `this.words.missing(key, { id, effect })` — once per key and page, never a `report()` of your own for it. The keys are generated from the specs (`src/generated/words.ts`); never write one into a list. Locale data (month, weekday, period and field names, digits, today) comes from `Intl` through `primitives/locale-date.ts`, and where `Intl` has none there is none. A test is a product: it gives its words by a fixture's props or by `setWords(page, …)` from the harness; the harness and the gallery set none, and never import the pack.
- **A test must not depend on the machine's speed.** A runner shard is slower and busier than a Mac, so a race that never shows locally fails CI once in fifty runs. `mountFixtures()` returns once the document is painted as the components count it (MOT-4: a surface opened before then appears at once), so a surface the test opens plays its entrance; `beforePaint: true` returns before that, for a test of what is placed before the first paint and for a page whose clock the test holds while it mounts. Read a motion in the task that starts it or wait for its end (`transitions.ts`, `at-rest.ts`), hold the page clock for a timer or a press-hold (`page-clock.ts`, `watched-press.ts`), aim a press where a box rests, and install a listener before its event. Before opening a pull request, run the tests you touched in **harsh mode** (`TANREI_HARSH=1`, `test/harsh.ts`): it waits 300 ms around every input action in every engine and plays Chromium's motion at a fifth of its speed, so a read that lands mid-motion or after a 100 ms state has ended fails every time. A correct test passes in it; only a test that legitimately measures real time is exempted, by name and with a reason (`HARSH_OPT_OUTS`). Then run them as CI does, in the Linux container (`pnpm --filter @tanrei/web test:ci-like <files> --project=<engine>`, `scripts/ci-like.sh`). `test/timing-guards.test.mjs` refuses the patterns that are always wrong — `document.getAnimations()` as a wait (it sees no shadow root), any other wait for motions or count of them outside `test/motions.ts`, `waitForTimeout(<number>)` without a reason, `goto('about:blank')` where the pointer hovers or leaves — and its allowlists only shrink.
- `custom-elements.json` and `packages/react/src/generated/` are generated (`pnpm generate`). Export new components from `src/index.ts`.
