# packages/swiftui — local rules

The root `AGENTS.md` applies. These rules add to it.

## Rules

- **Every token flows through the system instance in the environment.** Read `@Environment(\.tanreiSystem) private var system` (or `theme.system`) and use `system.button…`, `system.shape…`, `system.measure…`. **Never reference a system statically** in `Sources/` outside `Generated/` — not `TanreiSystem.tanrei`, not as a default argument, not in a `static let`. The only exception is the default of `TanreiTheme.init(system:)`. Things that cannot read the environment take the value as a parameter (`TanreiHitTarget.minimum(in:)`, `TanreiFocusRingMetrics(containerCornerRadius:measure:)`); Dynamic Type never goes through `@ScaledMetric` (a constant `1` scaled by it is rounded to a pixel — 1.0 from `xSmall` to `xLarge` — and its initial value cannot be a token): read `@Environment(\.dynamicTypeSize)` and multiply the token by `TanreiDynamicType.scale(forSize:at:)`, the factor of the text it belongs to.
- **No literal design values in `Components/` or `Primitives/`.** Colors, radii, sizes, spacing, type, opacity and durations come from the system instance. If a value is missing, the fix is in `tokens/` (and then the emitter), not a literal here. The one allowed constant is an identity for a token the vocabulary does not have (`TanreiIdentity.opacity` for the rest state).
- **Colors are paints.** A component color token is a `TanreiPaint` (`role` / `mix` / `alpha` / `none` / `literal`); draw it with `colors[paint]` from `@TanreiPalette`. Never `Color(...)`, never `.primary`/`.secondary`, and never combine colors yourself (no overlays, no `.opacity()` on a role to fake a state) — if a look needs a mix, it is a token value.
- **Roles are open-ended.** `TanreiColorRole` is a `RawRepresentable` string key because other systems declare other palettes. Do not switch exhaustively over roles or assume the set. `ir.intents` lists what a future `palette` prop may name; that prop is not in the spec yet — do not add it.
- **Sizes and variants are open-ended too (BTN-7): a layer may add a size or a variant.** `Tanrei<Name><Axis>` (`TanreiButtonSize`, `TanreiButtonVariant`) are generated `RawRepresentable` keys like `TanreiColorRole`; their tokens live in generated holders (`system.button.sizes`, `system.button.variants`: named core fields + `extra` + a total `subscript`). A component reads `tokens.sizes[size]` and `tokens.variants[variant]` and **never switches over sizes or variants** or assumes the set. The lookup falls back to the axis default and reports through `TanreiDiagnostics.report` (debug builds only) — never call `assertionFailure`/`precondition` for an unknown key yourself. Interaction **states** are closed: that switch stays.
- **One shape for everything a layer can extend**: named fields for core values, `extra`, a keyed lookup — series structs (`TanreiSpace`, `TanreiShape`, `TanreiTypescale`, `TanreiElevation`, `TanreiState`, `TanreiMeasure`, `TanreiDuration`, `TanreiEasing`) included. The emitter reads placement from the IR (`axis` / `key` / `member` / `state`, `ir.axes`, `ir.extensions`); do not go back to parsing token names.
- **A state is drawn from that state's tokens** (BTN-3 / BTN-6). Resolve one `TanreiInteraction` (`enabled` / `hovered` / `focused` / `pressed` / `disabled`), then read container, label, outline, elevation, opacity and shape from the tokens of that state — through the GENERATED lookups `tokens.variants[variant][state: state]` and `tokens[state: state]` (optional: `nil` at rest). Never write that switch by hand. The component never computes how a state looks: no state layer, no disabled-opacity logic.
- The vocabulary structs have exactly one public memberwise initializer with every label required, so a product's stale generated system file fails to compile. Do not add convenience initializers or default arguments to generated types (the emitter must not either). The single exception is `extra: … = [:]`, so that the values file of a system without extensions carries no trace of the feature (a test guards this).
- Naming: public symbols are prefixed `Tanrei`. A spec enum prop bound to an `axis` becomes the generated open key `Tanrei<Name><Prop>` whose constants are the spec values verbatim (`filled`, `small` …); a key that is not a Swift identifier is prefixed with its axis (`3x` → `size3x`). A closed enum prop (no `axis`) stays a Swift enum. Events become an `action:` closure (`@MainActor`). `disabled` is always SwiftUI's `.disabled(_:)` environment, never an init parameter.
- Keep the mapping from props to tokens in a pure, internal `Tanrei<Name>Appearance` value so it can be tested without rendering.
- Interaction: show exactly one state via `TanreiInteraction.resolve` (disabled, else pressed > focused > hovered, else enabled). The focus indicator comes from `system.measure` (signed `focusOffset`, optional inner stroke `focusInnerWidth` in `focusRingInner`, outer stroke `focusOuterWidth` in `focusRing`), is shown for keyboard focus only, is never animated and is not dimmed by a state's opacity. Every animation goes through `TanreiMotion`, which returns `nil` under Reduce Motion.
- **Icons are drawn by the icon style tokens** (`system.icon`: `families` — a `TanreiFontStack` per selection state — `weight`, `fillUnselected`, `fillSelected`; sizes in `system.measure.icon…` or the component's `iconSize`). Anything that draws an icon glyph goes through `system.icon.drawing(size:selected:)` / `.family(selected:)` / `.axes(size:selected:)` / `.font(size:selected:)` — the family AND the fill follow the selection state, everywhere; never write a family name, a `FILL` or a `wght` value. The font is not bundled and `font(…)` is `nil` without it. A component's icon slot stays a slot: a component whose icon follows a selection state (the icon button) hands its slot `tanreiIconContext(size:selected:)` — the icon font of that state as the slot's font, or the platform font at the box size under `fontFamilyPolicy: .system` / without the font — and `TanreiIconGlyph("name")` draws a glyph with it (nothing, never the name, without the font). An icon is not text: it does not follow Dynamic Type unless the spec says it belongs to a label (Button's does).
- **Font stacks arrive read** (`TanreiFontStack`: `families`, `generic`, `system`). `generic` is the IR's `genericClass` — its reading of the generic keyword for a platform with three font classes; the emitter reads `font.genericClass ?? font.generic`, decides nothing, and refuses anything outside the three (`scripts/check-emitter.mjs`). Never parse a CSS keyword (`system-ui`, `sans-serif`…) here; if the reading is wrong, the fix is in `ir.js` (`fontStack()`), not in this package.
- **Choices of kind are read, never inferred** (`system.behavior.pressedFeedback` / `.focusStyle`). Switch over the enum; never branch on a system's id, and never guess a choice from values (a pressed opacity below 1 does not mean `dim`).
- **Corner smoothing is an amount** (`system.shape.cornerSmoothing`, 0–1). SwiftUI has only the OS's curve, so every rounded shape a component or primitive draws takes `system.shape.roundedCornerStyle` (`.circular` at 0, `.continuous` above) — never compare the amount to 0.6 or branch on a system's id.
- **Text styles are the sixteen type roles** (`display`, `heading1`…`heading6` = h1…h6, `bodyLarge`/`body`/`bodySmall` = lead/p/small, `label`/`labelSmall`/`caption`, `code`/`codeSmall`, `eyebrow`). **Emphasis is a weight step, not a role**: `tanreiTextStyle(_:emphasized:)` adds `system.typescale.emphasis[style.family]` to the weight and nothing else; never build an "emphasized" text style by hand, and never scale the weight with Dynamic Type. `TanreiTextStyle.family` is generated from the role's name (first segment; `caption`, `code*`, `eyebrow` → `label`) — it is not parsed here.
- **A blur is a CSS blur.** Convert only through `TanreiShadowBlur` (σ = blur / 2 = SwiftUI's shadow radius). `View.blur(radius:)` is a different quantity; do not use it for a token blur.
- **A press is held** (BTN-8): pressed = `isPressed || hold.isHeld` (`TanreiPressHold`, `system.motion.duration.pressHold`). New pressable components wrap their chrome in `TanreiPressTracking` (never a second copy of the hold, the contact point or the key-press route), activate by key with `tanreiKeyActivation`, map `TanreiPressLayers` onto their own state tokens in their `…Appearance`, and draw a container with `TanreiContainerLayers` and an icon with `TanreiIconSlot`.
- **Do not attach a SwiftUI gesture inside a control's label to watch touches**: it takes the tap from `Button` (macOS) and breaks tap and scroll (iOS). Use `TanreiContactPoint`.
- A button's `containerGap` and `outlineWidth` are members of the **size** axis (`tokens.sizes[size].containerGap` / `.outlineWidth`), like its height and paddings.
- **Dynamic Type has one scaling.** Glyphs, tracking, line box and icon are multiplied by ONE factor: the size `UIFontMetrics(.body)` scales the token size to ÷ the token size (`TanreiDynamicType`), and fonts are built AT that size (`Font.custom(_:fixedSize:)`, `Font.system(size:)`). Do not use `Font.custom(_:size:relativeTo:)` or a text-style font: SwiftUI then scales the glyphs itself, and its size differs from `UIFontMetrics` by a point from 47pt up (`TanreiDynamicTypeTests` found it) — the token line height is lost. A change here is not done until `TanreiDynamicTypeTests` has run on an iOS simulator too (`xcodebuild test -scheme Tanrei -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:TanreiTests/TanreiDynamicTypeTests`, from the repo root; macOS has no Dynamic Type, so `swift test` only proves that nothing scales there) and the Gallery's audit has passed.
- Text: `tanreiTextStyle(_:)` makes a line exactly the token line height (`TanreiLineBox`), so `padding-block` + line height adds up to the container height as on the web. Do not add vertical padding to compensate for font metrics. **The line box is for text only**: apply it to the `Text`, never to a row that also holds an icon; a container hands the font down with `tanreiFont(_:)`, and an icon takes width but no height in the row (it is centered and never grows the container).
- Minimum hit target: SwiftUI only hit-tests a control inside its layout frame, so a larger `contentShape` alone does **not** work. Wrap the control in `TanreiMinimumHitTarget(sizing:control:)` and end the style body with `.tanreiHitTargetExpansion()`. `TanreiButtonTests` has an end-to-end click test for this; copy it for new controls.
- Do not use `@State` + preferences for layout that must be right on the first pass: `ImageRenderer` (snapshots) does not apply those updates.
- Swift 6 mode, no `@unchecked Sendable` without a lock, no new dependencies without the maintainers' approval.
- Public surface follows the spec. Change `specs/` first, never only this package. Do not change a spec's platform status from here — report it.

## Tests

Run from the repo root: `swift build`, `swift test --no-parallel` (what `pnpm --filter @tanrei/swiftui test` and CI run). Suites that host a window (`HostedView`) share the key window and the main actor with every other suite, so the whole package runs serially; a `.serialized` suite serializes only its own tests.

- Every behavior id of the spec (`BTN-1` …) must appear in the test file next to the test that covers it; the parity checker greps for them.
- Snapshot tests iterate a fixture list that mirrors the spec; a test asserts the two lists are identical.
- Tests that pass an unknown key on purpose wrap the code in `Reports.collecting { … }` (`Support/Reports.swift`): it installs the task-local `TanreiDiagnostics.handler`, so the debug assertion does not trap and the report can be asserted.
- **Prove that values drive rendering.** For every token a component reads, some test builds a modified copy of `TanreiSystem.tanrei` (`var system = …; system.button.variants.filled.pressed.containerColor = .role(.error)`), renders or resolves with `TanreiTheme(system:)`, and asserts the result changed accordingly. Tests may reference `TanreiSystem.tanrei`; sources may not.
- Paint math is tested in `TanreiPaintTests.swift` (mix / alpha / none / literal, light and dark). It must stay identical to `mixColors` in `packages/token-engine/src/states.js`.
- Record baselines only deliberately: `TANREI_RECORD_SNAPSHOTS=1 TANREI_SNAPSHOT_REASON="…" swift test` (rewrites only baselines whose pixels changed; refuses without a reason). Never record to make a failing comparison pass — a diff is a finding.
- **Two renders.** `Snapshot.render` (`ImageRenderer.cgImage`) is what baselines, sampled colors and sizes use; it is NOT bit-stable — the OS renderer returns one of two rasterizations (±1/255 on a few antialiased pixels) depending on its cache state, so never compare two of them at zero tolerance. A test that asserts two views draw identically uses `Snapshot.renderExact` (bit-stable; never compared with a baseline or with `render`). Do not widen a tolerance instead.
- **`ImageRenderer` draws a view that carries `.accessibilityFocused(_:equals:)` as nothing** (macOS 26, found by `TanreiCarouselTests`): bind assistive-technology focus only on the live path, never under `\.tanreiScrollsInPlace` (`TanreiCarouselSpokenFocus`).
- A state that only exists during an interaction (a held press) is read from the hosted window: `HostedView.color(at:)`. The end of a hold is scheduled on the main actor, so such a test is `async` and suspends (`Task.sleep`) — spinning the run loop alone never lets it run.
- **The gallery is spec-driven.** It reads every `specs/*.spec.json` from its bundle; a component joins it with ONE entry in `GalleryRegistry.components` (`"<spec name>": .<name>`) and a `GalleryComponent` in `App/Components/<Name>Gallery.swift` that draws a `GalleryFixture` from its props (`fixture.key("variant", default: …)`, `fixture.bool("disabled")`, `fixture.content`, for a component with item kinds `fixture.items` — `GalleryItem`s with their kind, props and nested items — and for a slot a fixture fills `fixture.slot("actions")`, drawn as the slot's `fixture` kind says; `SpecFixture.slot(_:)` is the same in the unit tests) and calls `fire` from its event. No pbxproj edit. Rows are keyed `<component>.<fixture-id>`: identifiers `fixture.<key>` / `count.<key>`, `-focus <key>`. A spec whose SwiftUI status is not `planned` and that has no entry is shown as `unregistered.<name>` and fails `testEveryFixtureOfEveryImplementedSpecIsShown`.
- **A looping animation goes through `TanreiCycle`** (never a `TimelineView` or a `repeatForever` of its own): it pauses while the view is not visible and snapshots freeze it with `\.tanreiCyclePhase`. Record such a fixture as the spec's `verify` says (Reduce Motion, `_accessibilityReduceMotion`, at phase 0). **SwiftUI mirrors a shape in a right-to-left layout**: something that must not mirror (a ring, a turning arc) pins `.environment(\.layoutDirection, .leftToRight)`, and a test proves it (`renderExact` in both directions).
- `Gallery/` is the XCUITest host (keyboard, the full accessibility audit — Dynamic Type included —, Dynamic Type growth, tap/scroll under `ripple`): `xcodebuild test -project packages/swiftui/Gallery/TanreiGallery.xcodeproj -scheme TanreiGallery -destination 'platform=iOS Simulator,name=iPhone 17'`. A change to press handling or focus is not done until it has run.
- Baselines render with `Snapshot.theme` (light, standard contrast, system font) so an installed Inter (or any other family a type token names) does not change them. The same policy keeps the icon font out of them: a fixture whose content is a glyph name draws the SF Symbol a product would pass for it (TanreiIconButtonTests: `favorite` → `heart`, `heart.fill` when on); the glyph path is tested apart, and against the real font only where the machine has it.
- The macOS accessibility tree of a SwiftUI view is not available to unit tests (it is built only when an assistive client attaches). Accessibility semantics come from building on SwiftUI's `Button`; do not replace it with a gesture.

## Adding a component

1. The spec and `tokens/comp/<name>.tokens.json` exist and `node packages/tools/src/cli.js validate` passes.
2. Regenerate tokens; confirm `Tanrei<Name>Tokens` (with, per axis the component declares, the key `Tanrei<Name><Axis>`, `…<Axis>Tokens` (+ `…<Axis>StateTokens` when the axis has states) and the holder `…<Axis>s`; plus `…StateTokens` for per-component state values) appears in `Generated/TanreiTokens.swift`, the `TanreiSystem` struct has the new property, and `Generated/TanreiSystem+Tanrei.swift` has its values. The emitter places tokens by the IR's `axis` / `key` / `member` / `state`. Regenerate the Acme fixture as well.
3. Add `Components/Tanrei<Name>.swift`: prop enums, the public view, the internal `…Appearance(tokens:…state:)` that maps props + state to token values, the style/chrome built from the primitives.
4. Add `Tests/TanreiTests/Tanrei<Name>Tests.swift`: behavior tests by id, token-binding tests per state (light and dark), modified-system tests, hit-target tests, snapshot fixtures.
5. Record baselines once, look at them, commit them.
5a. Register it in the gallery (`GalleryRegistry.components` + `App/Components/<Name>Gallery.swift`) and run the gallery UI tests.
6. Update `README.md` if the public API grew. Report the new status to whoever owns the spec.
