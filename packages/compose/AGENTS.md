# packages/compose — local rules

Adds to the root `AGENTS.md`; never weakens it.

## Naming idioms

- **Explicit API mode is on.** Every declaration states its visibility, in generated files too. Public is exactly what the spec's `platforms.compose` block names and the README's "Public API" table lists; a new building block starts `internal`. Making something public means adding it to that table in the same change.
- Everything public is prefixed `Tanrei`. A prop bound to a token axis (spec `axis`) is NOT an enum: its type is the generated open key `Tanrei<Component><Axis>` (a value class over the token key, PascalCase constants for core values: `TanreiButtonVariant.Filled`). Closed props stay enums, `Tanrei<Component><Prop>` with PascalCase values.
- Follow the spec's `platforms.compose` block. Boolean `disabled` becomes `enabled = true`; events become `on<Event>` lambdas.
- Parameter order: required lambdas/values, `modifier`, spec props, optional slots, `interactionSource`, trailing `content` slot.
- Modifier factories are `Modifier.tanrei<Thing>()`.

## Rules

- No Material dependency (`androidx.compose.material*`). Only `runtime`, `ui`, `foundation`, `animation`.
- **Every token flows through the system instance.** Read `TanreiTheme.tokens` (a `TanreiSystem`) in composition and pass values down. Outside generated code there is no static token object: never write `TanreiSystem.Tanrei.…` in `components/` or `primitives/` (the only references are the default of `TanreiTheme(system = …)` and of `LocalTanreiSystem`). Defaults of composition locals and modifier parameters derive from the current system, not from a fixed token.
- **No literal design values** in `components/`: colors, sizes, radii, type, opacity and motion come from `TanreiTheme.tokens.<name>` (or the system tiers inside primitives). If a token is missing, stop and raise it against `tokens/` — do not inline a number.
- **A state renders from that state's tokens.** Resolve one `TanreiInteractionState` with `collectTanreiInteraction(enabled)` (disabled, else pressed > keyboard-focused > hovered; the pure rule is `tanreiInteractionStateOf`; `pressed` is HELD for `motion.duration.pressHold`, spec `XXX-n` "keep it visible for at least press-hold") and draw container / label / outline / elevation / opacity / shape from `tokens.<variant>[state]`, `tokens.opacity(state)`, `tokens.containerShape(state)`. The component never computes how a state looks: no overlays, no opacity math, no "disabled = on-surface at 38%". Animate between state values with the component's `motion` tokens — elevation too (`animateTanreiElevation`, same spec as the container color); entering pressed is immediate (`snap()`).
- **Choices of kind come from `TanreiTheme.tokens.behavior`**, never from a system's id: `pressedFeedback` decides which state's container color is drawn under a press and whether the pressed color arrives as a ripple (grow: the component's `motion.feedback-duration` + its state easing; fade: its state duration, once the press has ended and press-hold has passed — one rule on every platform; under `ripple` and `dim` only the container color stays with the state under the press, under `none` every part does); `focusStyle` is read inside `tanreiFocusRing`. The pressed-feedback rules live in primitives (`drawnStates`, `rememberTanreiRipple`); a component calls them, it does not restate them. **Corner smoothing is an amount, not a choice**: `TanreiTheme.tokens.shape.cornerSmoothing` (0–1) goes through `tanreiContainerShape` — 0 is `RoundedCornerShape`, above 0 Figma's construction (`smoothedRoundRectPath`, three cubics per corner, the smoothing budgeted per CORNER as Figma does — a pill is the circular capsule —, the same path Flutter draws; the web draws the nearest superellipse) — and every outline (container, border, elevation ring and shadow, ripple clip, focus ring) reads it; never draw a corner any other way. Compose draws every choice; if a future one cannot be drawn, fall back to the enum's first value and say so in the README.
- **Shadow tokens have CSS `box-shadow` semantics.** The only conversion to Android's blur radius is `cssBlurToAndroidBlurRadius` in `primitives/TanreiElevation.kt` (the focus glow uses it too); never pass a `blur` to a platform API directly. An empty level draws nothing. **Never use `Modifier.dropShadow`**: it cuts the Gaussian's tail at ≈ 1.7σ and drifts by a fraction of a pixel; `tanreiElevation` draws the whole shadow (3σ) itself, and `List<TanreiShadowLayer>.extent` is how far that reaches.
- **Colors are paints.** Component colors are `TanreiPaint`; evaluate with `paint.color` (composition) or `paint.resolve(colors)`. A paint may differ per scheme (`TanreiPaint.Scheme`); that works because a `TanreiColors` knows its `scheme` — never build a `TanreiColors` for one scheme out of another's, and never match on a paint's kind in a component. `TanreiPaint.None` resolves to transparent and draws nothing. Do not resolve a paint at build time or cache it across schemes. Animate resolved colors with the premultiplied converter (`PremultipliedColor`) so fading in from `None` matches a CSS transition.
- **Sizes and variants are open-ended**: a design system may add values. Never `when` over a size or a variant and never build per-size tables by hand: read `tokens.<axis>s[key]` (`tokens.sizes[size]`, `tokens.variants[variant][state]`). The lookup is total — an unknown key reads the default value — and the component reports it in debuggable apps only: `if (key !in tokens.sizes) TanreiReportUnknownValue(…)` (spec behaviour `XXX-n` "names a value that the active design system does not have"). Interaction STATES are closed; `when (state)` stays.
- **Everything a layer can extend has one shape**: named members for core values, `extra: Map<…> = emptyMap()` for added ones, a keyed lookup. `extra` is the only constructor parameter with a default. Holders containing a `Map` must be `@Immutable` (the Compose compiler treats `Map` as unstable).
- **Generated product code lives in another module and package**: whatever a generated values file uses from this library must be public.
- **Roles are open-ended** (`TanreiColorRole` is a value class over the key). Do not `when` over roles or assume the default system's set. `ir.intents` / `TanreiSystem.intents` is what a future `palette` parameter may name; that parameter is not in the spec yet.
- **Text styles are by level.** `typescale` has sixteen roles (`display`, `heading1`…`heading6`, `bodyLarge` / `body` / `bodySmall`, `label` / `labelSmall` / `caption`, `code` / `codeSmall`, `eyebrow`); the theme's default text style is `body`. Emphasis is not a role: `TanreiTextStyle.emphasized(emphasis)` adds the family's step of `typescale.emphasis` (`TanreiTypeEmphasis`) to the weight, and the composable `emphasized()` reads the current system's. A style's `family` (`TanreiTypeFamily`) is decided by the emitter from the role's key (first segment; `caption`, `code`, `eyebrow` → label) — never guess it in Kotlin.
- **Fonts are named, never bundled, and a font stack is read once — by the token build.** Text styles, typefaces and icon families arrive as `TanreiFontStack(families, generic, system)`; never parse a CSS keyword (`system-ui`, `monospace` …) in Kotlin. `TanreiFontStack.toFontFamily` is the one rule (named families, then the platform font of `generic`; `system` = the platform font first). The default typefaces are Inter / Noto Sans JP / Noto Sans (text) and Roboto Mono (code); the icon font is Material Symbols Rounded. Tests and snapshots render with the platform's fonts, so a family NAME change moves no baseline. Do not add font files or a font dependency.
- **Icon style is tokens, read through one helper.** `TanreiSystem.icon` (`TanreiIconStyle`: a family per selection state — `unselected`, `selected` —, `weight`, `fillUnselected`, `fillSelected`; generated, required like every core token) says how icons are drawn. `TanreiIconStyle.glyph(size, selected)` returns the family of that state, `FILL`, `wght`, `opsz` (icon box clamped to `opticalSizeMin`–`opticalSizeMax`, `sys.icon.optical-size.*`: the font's range is a token, never a literal) and `GRAD` 0; a static set changes the family and ignores the axes. Never write a family, fill, weight or optical size by hand. There is no icon component: an icon is a slot. **A component with an icon slot** lays it out in a box of its icon-size token, clears its semantics (an icon is decorative; the name is the component's) and provides `LocalTanreiContentColor` (the icon color of the state and look), `LocalTanreiIconGlyph` (`tokens.icon.glyph(iconSize, selected)`) and `LocalTanreiTextStyle` = `glyph.toTextStyle(iconSize)` (the app's icon font via `TanreiFontFamilies.resolveIcon`, sized in dp so text scaling never grows it) — as `TanreiIconButton` does. Button's `icon` slot does not do this yet.
- **Everything that varies with a Button size is on the size axis**, including `containerGap` and `outlineWidth`: read `tokens.sizes[size].…`, never a flat member.
- **Typed accessors are top-level declarations: one package, one declaration.** Shipped systems share the library's package, so a shipped system's file declares accessors only for what IT added (`declaredBy`), an ancestor's being in the ancestor's file; a product's file (own package) declares everything.
- Always pass `indication = null`: an `Indication` draws in the bounds of `clickable` (the 48dp target). Press feedback — including the ripple — is drawn by the component inside its container, from the pressed tokens. Never add `androidx.compose.material:material-ripple`.
- **No generated accessor throws.** A step accessor under a system without the step answers with the declaring system's value through `TanreiDiagnostics.missingStep` (reported once in debuggable apps); spring sets are a series like the others (`extra`, keyed lookup, plus their `scheme`).
- The focus indicator (`tanreiFocusRing`) is for keyboard focus only and is never animated. From the control outwards: signed `focus.offset` (negative = inside), optional inner stroke (`focus.inner-width`, role `focus-ring-inner`; 0 = none), outer stroke (`focus.outer-width`, role `focus-ring`).
- Modifier order for interactive components is load-bearing: input (`clickable`…) → `tanreiMinimumTouchTarget()` → `tanreiGroupOpacity` → `tanreiFocusRing` → `tanreiElevation` → container / border → size/padding. Input before the touch target makes the hit area and a11y bounds 48dp; visuals after it keep the visual size. Heights are minimums; vertical padding is the `padding-block` token.
- The generator emits only current vocabulary: deprecated tokens never reach Kotlin. Generated constructors take required parameters for every core token (only `extra` defaults, to empty) — adding a core token is a compile error for stale generated systems, by design. The values file of a system WITHOUT extensions must not mention `extra` or accessors at all (`TanreiAxesTest` guards it).
- **A condition with prefixed parts** (`selected.container.color` inside a variant) is chosen ONCE from the spec's props into a closed private enum (`TanreiIconButtonLook`: plain / unselected / selected) and read from every state's tokens through one mapping function; the ripple is the pressed container color of that look. Never branch per state or per variant on it.
- **A required accessible name** (`contentDescription` for a label-less control) is a non-null `String` parameter; when it is blank the component still renders, sets no `contentDescription`, and calls `TanreiReportMissingName` (debuggable apps only).
- **A toggle** is `Modifier.toggleable(role = Role.Button)` (an on / off state), never `Role.Checkbox` / `Role.Switch` unless the spec says so; it emits the click, then the change (ICB-11, as a native checkbox).
- Do not change a component's status in `specs/`; report and let the maintainer flip it after verification.

## Adding a component

1. The spec (`specs/<name>.spec.json`) and its `comp.<name>` tokens exist first; run the token generator so `Tanrei<Name>Tokens` and `TanreiSystem.<name>` exist. The emitter takes the class shape from the IR, never from names: a token on an axis (`axis` / `key` / `member` / `state`) becomes `tokens.<axis>s[key].<member>` (`sizes[size].containerHeight`) or, for an axis with states, `tokens.<axis>s[key][state].<member>` (`variants[variant][state].containerColor`); a shared per-state token becomes `tokens.<part>(state)`; everything else is a flat member.
2. Implement `components/Tanrei<Name>.kt` from `TanreiTheme.tokens.<name>` and primitives. The parity checker greps this file for the component name, each prop's Compose name, each enum value and each event name.
3. Write `Tanrei<Name>Test.kt`: every behaviour id (`XXX-n`) must appear literally next to the test that covers it. Tests run on Robolectric (`@GraphicsMode(NATIVE)`, SDK pinned in `src/test/resources/robolectric.properties`); pixel probes via `captureToImage()` work. Prove that values drive rendering: render under a modified system (`TanreiSystem.Tanrei.copy(…)`, passed as `TanreiTheme(system = …)`) and assert the pixels or the layout follow it. Keyboard-focus tests need the `@KeyboardNavigation` rule pattern from `TanreiButtonTest`.
4. Write `Tanrei<Name>SnapshotTest.kt` reading fixtures from the spec (and `Tanrei<Name>PresetSnapshotTest.kt`: one representative fixture per shipped preset, at `<name>/<system-id>/<fixture>.png`); record ONLY those classes — `TANREI_SNAPSHOT_REASON="…" ./gradlew :tanrei:recordRoborazziDebug --tests '*Tanrei<Name>*SnapshotTest*'` (the task records every snapshot test it runs) —, look at every PNG, then verify with `verifyRoborazziDebug`. A fixture whose content is an icon name draws a stand-in glyph from `LocalTanreiIconGlyph` (no icon font is bundled).
5. `./gradlew :tanrei:assembleDebug :tanrei:testDebugUnitTest :tanrei:verifyRoborazziDebug` and `node packages/tools/src/cli.js validate` must pass.

## Snapshot workflow

- `verifyRoborazziDebug` compares; `recordRoborazziDebug` overwrites baselines; plain `testDebugUnitTest` does neither.
- Baselines are recorded and verified on Linux (CI's `compose` job, `ubuntu-24.04`); one recorded on a Mac will not match. Record with the record-baselines workflow (`CONTRIBUTING.md#recording-baselines`).
- Never re-record to make a test pass. A diff is a finding (root `AGENTS.md`).
- Failure artifacts go to `tanrei/build/outputs/roborazzi/`, never into `src/test/snapshots/`.

## Toolchain notes

- JDK 17. Robolectric's SDK 36 image needs Java 21, so tests run on SDK 35 — revisit when the repo moves to JDK 21.
- `ui-test-junit4-accessibility` is enabled, but under Robolectric ATF cannot see Compose's virtual nodes (checks report NOT_RUN). Keep explicit semantics assertions in every component test; the checks run for real in `:gallery:connectedDebugAndroidTest` (needs a device or emulator; `:gallery:assembleDebugAndroidTest` only compiles them).
- `clickable` reports a key press at `Offset.Zero` until a pointer event has told it its bounds (foundation 1.12): `TanreiPress.origin` reads Zero as "no point of contact".
- The `com.vanniktech.maven.publish` plugin only supplies POM/coordinates. Never run a `publish*` task.
