# packages/flutter — local rules

The root `AGENTS.md` is law. This file only adds Flutter specifics.

## Boundaries

- Library code (`lib/`) imports `package:flutter/widgets.dart` (plus `foundation`, `painting`,
  `rendering`, `services`, `semantics` as needed). Never import `package:flutter/material.dart` or
  `cupertino.dart` in `lib/`. Tests use `test/harness.dart` (`WidgetsApp`), not `MaterialApp`.
- `lib/src/generated/` is generated. Never edit or format it. Do not run `dart format lib`;
  format the hand-written paths only (see `README.md`). If a token is missing or does not compile,
  fix `packages/tokens-build/src/emit/dart.js` and run `pnpm generate`. Two files:
  `tokens.g.dart` is the **vocabulary** (system-independent types: `TanreiSystem` and its parts,
  `TanreiPaint`, `TanreiColorRole`; all constructor parameters `required`), and
  `tanrei_system.g.dart` is the **values** of the default system (`const tanreiSystem`). Presets
  and product systems are further value files produced by `emitDartSystem`.
- **Every token flows through the system instance in the theme**:
  `TanreiTheme.of(context).system.<part>`. No static token reads anywhere outside generated code,
  and never `tanreiSystem` directly in `lib/src/components/` or `lib/src/primitives/` (it is only
  the default of `TanreiThemeData.system`). The check:
  `grep -rnE "Tanrei(ButtonTokens|Shape|Space|Measure|State|Duration|Easing)\." lib | grep -v generated`
  finds nothing (keep doc comments free of that spelling too).
- **Colors are paints.** Component color tokens are `TanreiPaint`s; evaluate them with
  `theme.paint(token)` against the current scheme. Never switch on a paint's kind in a component
  and never rebuild a mix by hand. `TanreiPaint.none()` resolves to zero alpha = draw nothing.
- **Sizes and variants are open keys, never enums** (spec BTN-7): a layer may add a size or a variant. `TanreiButtonSize` /
  `TanreiButtonVariant` are generated extension types; a component reads `tokens.sizes[size]` and
  `tokens.variants[variant]` — total lookups that fall back to the axis default and report through
  `debugTanreiReportUnknownValue` in debug builds. Never write a `switch` over sizes or variants,
  and never `assert`/throw on an unknown key. Interaction states are closed: that switch stays.
- **One shape for everything a layer can extend**: named fields for core + `extra` (default empty)
  + lookup by key. The values file of a system without extensions never mentions `extra`
  (`test/systems/extensions_test.dart` guards it; the one exception is
  `TanreiColors(extra: ...)`, which carries the roles a palette declares). Typed accessors for added values
  and a layer's own tokens (`AcmeTokens`) are generated into the system's file, only when needed.
- `test_fixtures/acme_system.g.dart` is generated by `node packages/flutter/tool/generate_acme_fixture.mjs`
  (run from the repository root) from `packages/tokens-build/test/fixtures/acme.system.json`. The
  same run writes `tone_per_state_system.g.dart` and `tone_per_state_expected.g.dart` from
  `tone-per-state.system.json` (per-scheme paints, `test/components/button_per_scheme_paint_test.dart`).
  Regenerate it when the emitter, the vocabulary or that layer changes; never edit or format it
  (it lives outside `test/` because CI format-checks `test/`).
- **A component never computes how a state looks** (spec BTN-3 / BTN-6). It resolves
  the one state it is in with `tanreiInteractionStateOf` and reads that state's tokens:
  `tokens.variants[variant].of(state)` and `tokens.stateTokens(state)` (null at rest). No state-layer
  overlay, no disabled opacity logic, no "if hovered then darken".
- Zero literal design values in `lib/src/components/` and `lib/src/primitives/`: every color,
  radius, size, padding, gap, type style, opacity, duration and easing is a token of the system.
  Structural numbers (`widthFactor: 1`, the opacity 1 of a resting control, alpha 0 = "nothing to
  draw") are fine.
- **Fonts are names, never files, and never CSS.** A font stack arrives as the IR read it
  (`TanreiFontStack { families, generic, system }`) on every `TanreiTextStyle.font` and
  on `system.typefaces`. Never parse or pass on a CSS keyword (`system-ui`, `ui-monospace`,
  `sans-serif`): `theme/text_style.dart` (`TanreiFontStack.resolve`, `tanreiPlatformFontFamilies`)
  is the one place a stack becomes `fontFamily` / `fontFamilyFallback` — no family at all when the
  platform's font comes first. Nothing is bundled, and no test may depend on an installed font
  (goldens use the Flutter test font).
- **Icon style is a token group** (`system.icon`: `familyUnselected`, `familySelected`, `weight`,
  `fillUnselected`, `fillSelected`, `opticalSizeMin`, `opticalSizeMax`). Always go through `system.icon.resolve(size:, selected:)` /
  `family(selected:)` / `fill(selected:)` / `toIconThemeData(...)`; never write a family, a fill
  or an icon weight in a widget, and never assume the set is a variable font (the `acme` fixture
  uses a static one: the family changes, the axes are harmless). The `opsz` clamp is the
  system's `opticalSizeMin`–`opticalSizeMax` (`sys.icon.optical-size.*`, 20–48 for Material
  Symbols); only `GRAD` 0 in `icon_style.dart` is a constant of the font format. A component's icon slot stays a
  slot.
- **Choices of kind are enums on `system.behavior`** (`pressedFeedback`, `focusStyle`).
  A component switches over the enum — exhaustively, no `default:` — and never over a system id.
  **Corner smoothing is an amount**, `system.shape.cornerSmoothing` 0–1 (0 a quarter
  circle, 0.6 the iOS corner, `cupertino`). Every container is a `TanreiContainerDecoration` in a
  `TanreiCornerShape(smoothing:, radius:)` (never a `BoxDecoration` with a `borderRadius`), so the
  easing, the ripple and CSS shadow semantics come for free. The path is Figma's corner-smoothing
  construction, shared with web and Compose — change it only together with them and with the
  formulas in `corner_shape.dart`. The smoothing budget is Figma's, per CORNER (half the shorter
  side, minus the radius), so a pill is exactly the circular capsule; `ContinuousRectangleBorder` and `RSuperellipse` are NOT that
  curve (the measurements are in `corner_shape.dart`).
- **Text styles are by level**: `typescale.display`, `heading1`…`heading6` (h1…h6),
  `bodyLarge` / `body` / `bodySmall`, `label` / `labelSmall` / `caption`, `code` / `codeSmall`,
  `eyebrow`. There are no `emphasized` roles: `emphasized` is a weight step per family,
  `typescale.emphasis` (`TanreiTypeEmphasis`), added by `TanreiTextStyle.emphasized(emphasis)` /
  `theme.textStyle(token, emphasized: true)`. Every `TanreiTextStyle` carries its `family`; never
  derive one from a role's name in a widget.
- **Shadows have CSS semantics.** `TanreiShadowLayer.blur` is a CSS blur radius. The one conversion
  to `BoxShadow.blurRadius` is `tanreiBlurRadiusFromCss` (`primitives/elevation.dart`); never pass
  a token blur to Flutter directly. `level0` is an empty list.
- **A press is held** for `motion.duration.pressHold` (spec BTN-8) with a `Timer`, started when the
  press begins — for pointer, touch and keyboard alike. Tests use the fake clock
  (`tester.pump(duration)`); never `Future.delayed` or a real clock.
- **A typed accessor never throws and never asserts** — series step, spring or color role: the
  emitter generates `this[key] ?? _<system>Declared(...)`, which answers with the declaring system's
  value and reports in debug builds (`debugTanreiReportUnknownValue`). A color role answers with the
  declaring system's color of the SAME scheme (`TanreiColors.scheme`); a spring with the first
  scheme of the declaring system that has it (a `TanreiSpring` does not know its scheme — the
  generated doc comment says which). The untyped `colors[role]` is total too: the `primary` slot
  of the same kind, reported. Springs are a series too (`TanreiSpring.extra`, `TanreiMotion.extra`).
- **Everything that varies by size is on the size axis**: `tokens.sizes[size]` carries the
  container height, paddings, label style, icon size, `containerGap` and `outlineWidth`. There are
  no flat `button.containerGap` / `button.outlineWidth` any more.
- **No asset path outside a package, and no symlink to a source of truth.** Flutter writes an
  asset key `../x` to `<bundle dir>/../x` — outside `build/` — and deletes it there again as
  stale on a later build, following symlinks: an `example/specs -> ../../../specs` link once
  deleted the repository's `specs/`. The gallery reads the specs as described above.
- `pubspec.yaml` keeps the exact line `version: 0.0.0`; a version-sync script rewrites it. Never
  run `flutter pub publish`.

## Naming idioms

- Widgets: `Tanrei<Component>` (`TanreiButton`). A prop bound to a token axis (`axis` in the spec)
  is the generated open key type `Tanrei<Component><Axis>` (`TanreiButtonVariant.filled`); any other
  enum prop is a Dart enum `Tanrei<Component><Prop>` with lowerCamel values matching the spec.
- Spec `disabled` maps to a nullable callback (`onPressed: null`), never to an `enabled` flag.
  Events are `on<Verb>` callbacks. Slots are `Widget` parameters (`child` for the default slot).
- The idiomatic names for each component are recorded in the spec's `platforms.flutter` block.
  The parity checker greps the implementation file for the widget name, the mapped prop names and
  each enum value, so keep those names literal in the file.

## Interactive widget recipe

`Semantics(container: true, ...)` > `TanreiTapTarget` > `FocusableActionDetector` >
`GestureDetector` > `Opacity` (the state's opacity token) > `TanreiFocusRing` > container
`DecoratedBox(decoration: TanreiContainerDecoration(...))` > content.

Do not rebuild it: mix `TanreiPressableStateMixin<YourWidget, TanreiControlVisuals>` into the
state (with `TickerProviderStateMixin`), implement `onPressed`, `stateTransitionDuration`,
`rippleDuration`, `stateCurve` and `lerpVisuals` from the component's tokens, and build
`Semantics` > `TanreiTapTarget` > `buildPressable(child: Opacity > TanreiFocusRing(visible:
isKeyboardFocused) > TanreiControlContainer(key: pressContainerKey, ripple: rippleFor(...)) >
TanreiControlContent)`. Read `variant.of(drawnState)` for label / outline / elevation,
`variant.of(containerState)` for the container color, and pass the result through
`animateVisuals`. `button.dart` is the reference; a control whose visuals are not a container
(a switch) supplies its own `V`. The notes below say what the mixin does.

- Semantics sits outside the tap target so the accessibility node has the 48 px size.
- Interaction state lives in a `WidgetStatesController`. `WidgetState.focused` is set from
  `onShowFocusHighlight`, so it is true for keyboard focus only (`FocusManager.highlightMode`).
- Provide Enter / Space shortcuts on the detector itself so the widget works without `WidgetsApp`.
- Resolve the state's tokens into concrete visuals once per build and interpolate between the
  previous visuals and the new state's with the component's `motion*` tokens. Entering pressed
  applies immediately; a theme or system change is not a state change and is not animated.
- Answer a press as `behavior.pressedFeedback` says (`pressable.dart`): the state UNDERNEATH a
  press is `tanreiInteractionStateOf(states - {pressed})`; `ripple` and `dim` keep its container
  color, `none` draws it entirely. Hold the press for `motion.duration.pressHold`.
- Respect `MediaQuery.disableAnimationsOf`: no transition at all.
- Tests that hover need `FocusManager.instance.highlightStrategy = alwaysTraditional`
  (`FocusableActionDetector` reports hover only in the traditional highlight mode).

## Adding a component

1. The spec and `comp.<name>` tokens exist and `pnpm generate` has produced `Tanrei<Name>Tokens`
   and the `TanreiSystem.<name>` field. The emitter reads axes and per-state groups from the IR
   (`ir.axes`, and `axis` / `key` / `member` / `state` on a token), never from token names;
   non-deprecated tokens only. Each axis becomes a key type, a per-value group, and a holder
   (`Tanrei<Name><Axis>`, `...Tokens`, `...s`).
2. Implement `lib/src/components/<name>.dart` from the primitives; export it from the barrel.
   Add one entry to `galleryComponents` in `example/lib/main.dart` (fixture props → widget).
3. Write `test/components/<name>_test.dart`. Every behaviour id (`BTN-1`, ...) appears literally in
   the name of the test that covers it. Include tests that render with a modified system
   (`tanreiSystem.copyWith(...)`) to prove values drive rendering. Add `meetsGuideline` checks (android / iOS tap target,
   labeled tap target, text contrast).
4. Golden tests iterate the spec's `fixtures` (read from `../../specs/<name>.spec.json`) and write
   `goldens/<name>/<fixture-id>.png` through the 2x `RepaintBoundary.toImage` capture used in
   `button_test.dart`.
5. `flutter analyze` (zero issues), `flutter test`, format check. Then `pnpm check` at the root.
6. Do not change the spec's `platforms.flutter.status` yourself unless the change is reviewed;
   the status must never claim more than exists.

## Goldens

Record deliberately: `TANREI_SNAPSHOT_REASON="…" flutter test --update-goldens <file>` — on Linux, where CI verifies them (the record-baselines workflow, `CONTRIBUTING.md#recording-baselines`); a golden recorded on a Mac does not match. Never re-record to make a failing
test pass; a diff is a finding. Baselines use the Flutter test font (boxes), so they verify
geometry and color, not glyph shapes; and `flutter test` draws shadows solid
(`debugDisableShadows`), so they verify a shadow's offset, spread and color, not its blur. The blur
is verified by sampling, not by a baseline (`test/primitives/shadow_blur_test.dart`): a test that
needs real shadows sets `debugDisableShadows = false` inside `try` and restores it in `finally`.
